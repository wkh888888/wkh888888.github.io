Cognition 的 Devin Fusion：前沿模型做规划、便宜模型干活，第三方实测每任务省 36%–43%

AI Coding
来源：Cognition 官方发布（9/12）· Artificial Analysis Coding Agent Index v1.5 独立实测 · AGI Hunt 2026-09-12

Fusion 的结构很直白：一个前沿「lead」模型负责计划、解读歧义与最终评审，一个便宜的「sidekick」负责探索、实现、跑测试并回报。两个 agent 各带独立工具与独立持久化上下文，交接只传三样东西——任务简报（含约束与验收标准）、执行结果、lead 的反馈，而不是整段对话历史。

这样设计是为了躲开两个坑：一是简短的 issue 描述并不能暴露任务真实难度，二是在单个会话中途换模型会让整个 prompt cache 失效。两边上下文各自存活，就不用跨模型边界复制工具历史。

关键数字来自第三方而非厂商。Artificial Analysis 把 Fusion 纳入其 Coding Agent Index，这是该榜单第一次收录多模型 coding agent：

配置Index 得分每任务成本对比基准
Fable 5.1(xhigh) + SWE-2(medium)61.7$7.90Claude Code 同模型 62.2 / $12.40（省 36%）
GPT-6 Astra(xhigh) + SWE-259$4.54比 Fable 配置再省 43%、快 31%

Cognition 自己给的头版数字是「基准成本降 39%」，并称自家工程团队 88% 的合并 PR 由 Fusion 自动路由完成、无人干预。Cognition 上一个极端例子：Astra lead + 每百万 token 0.75 美元的 SWE-2，跑出 63.4 分、单任务 2.34 美元。

同日还有两条同构的信号：Sakana 发布 Fugu Max / Fugu Ultra v2，把每个任务路由到「能干完的最便宜模型」，宣称近旗舰质量、成本低 2–6 倍；微软工程师详解 GitHub Copilot 的 HydraFusion 引擎——每个 prompt 按推理深度、代码生成复杂度、调试难度、工具编排需求四轴打分，再选三条执行流之一并分阶段派模型。

为什么值得关注：这是 coding agent 竞争维度的一次位移——不再是「谁家模型分高」，而是「谁能把质量-成本帕累托前沿往前推」。三家（Cognition / Sakana / 微软）在同一天拿出同一形态的解法，说明路由层已经从技巧变成标配。对你手上的项目，最实际的读法是：把「美元/完成一个任务」而不是「每百万 token 单价」当成选型指标，Fusion 的第三方数字正是按这个口径出的。
口径边界：① 基准成本 ≠ 生产成本。FrontierCode / DeepSWE / AA Index 跑的都是范围清晰、验收标准明确的任务集；真实工单充满模糊描述、半残测试集和没人写过的隐式约定，路由器完全可能把本该留给前沿模型判断的活派给 sidekick。② 88% 自动路由是 Cognition 拿自家代码库做的 dogfooding，不保证迁移到你的仓库。③ 拆开看 Fable 配置的成分：Repository Q&A 上 Fusion 反而更高（65.9 vs 64.8），DeepSWE（63.1 vs 64.3）和 Terminal-Bench（56.1 vs 57.6）略降——总分打平掩盖了内部的一升两降。
可做的动作：Fusion 现在推荐搭配的 sidekick 正是 09-11 推送的 SWE-2，而 Cognition 给 Pro/Max/Teams 订阅用户免费用一个月（约到 10 月中）。免费的 sidekick 模型等于把试错成本降为零——想验证多模型路由在你的仓库里成不成立，这是最便宜的一次机会。

Claude Code 上线 claude plugin eval：Skill 到底有没有用，第一次有了可测量的数字

AI Coding
来源：Claude Code v2.1.269 发布说明（9/11）· Anthropic 官方 Plugin Evals 工作流文档 · @ClaudeDevs

命令做的事是一次消融实验：每个测试用例默认跑两遍——一遍加载插件（with），一遍不加载（without），两者分数之差叫 Δ（delta）。

结果形态判断该做什么
WITH 高 / W/OUT 低 / Δ 大插件确实在干活保留，并补回归测试守住
WITH 高 / W/OUT 也高 / Δ≈0基础模型本来就会冗余，该删
WITH 低 / W/OUT 也低 / Δ≈0插件没解决问题重设计
WITH 反而低于 W/OUT插件在帮倒忙查约束、工具调用、上下文污染

六种 grader：免费四种（regex、tool_used、tool_order、file_exists，从 transcript 和磁盘算），计费两种（llm 按你写的评分标准判、baseline 对比参考答案）。官方示例：6 次运行、74 秒、$0.41，某用例 WITH 1.00 / W/OUT 0.33 / Δ +0.67。

Anthropic 明确点名了最常见的失败形态：Δ 接近 0，同时 tool_used: Skill 判定失败——意思是用户用自然说法提问时，Claude 根本没选中你的 skill。这是 claude plugin validate 抓不到的（它只查 manifest 语法），语法完全合法、运行时从不触发。

更关键的是它能进 CI：--threshold 0.8 --max-cost-usd 20 --no-publish，分数不够或超预算直接让构建失败。

为什么值得关注：把这三天的推送串起来看，Skill 生态正在走完一条完整的成熟路径——09-10 比谁装得多（superpowers 28.4 万星）→ 09-11 讨论怎么编排（Subagents vs Skills，胜负取决于有没有输入输出契约）→ 今天问有没有用（Δ 几分）。第三步是分水岭：前两步可以靠感觉，第三步不行。而且 Δ 这个口径比绝对分数诚实得多——它直接回答「这段指令是资产还是装饰」。
可做的动作：① 在插件根目录跑 claude plugin eval init，它会读你的插件、问「什么算好结果」、自动提议用例和 grader 并试跑一遍。② 至少配一个 tool_used: Skill grader——专治「从不触发」这个最普遍的暗病。③ 涉密代码或 prompt 记得加 --no-publish，报告默认会发到 claude.ai。④ 把 --threshold 挂到 CI 上，Skill 的静默腐化（升级 Claude Code、三个月后有人改了一句提示词）会在 PR 里暴露，而不是等用户来骂。

Anthropic 威胁情报报告：也门武器小组用 Claude Code「取代人类软件工程师」写导弹制导软件

AI Coding
来源：Anthropic 威胁情报报告（美东 9/10 发布，被称为「迄今最详细的一份」）· Bloomberg / IBTimes / 钜亨网转述

Anthropic 发现一个位于也门北部的威胁行为者小组，同时推进三个武器项目：一枚用商用「手机级」飞控 + 末段寻的制导火箭、一型标称射程超 2000 公里的多级弹道导弹、以及一个含高超音速滑翔体方案的导弹家族。

报告原话：「这些操作者使用 Claude Code 取代人类软件工程师，开发用于制导、导航和控制（GNC）的软件。」具体工作包括——把开源自动驾驶系统集成到手机级飞控、编写控制与位置估算软件、调整控制参数、跑固件构建流程、做飞行仿真。

用法尤其值得注意：同时开多个 Claude 实例并分工，一个写代码、一个做调研、第三个审前两个的产出，就像一个首席工程师给小团队派活。

结果层面：他们确实试射了一枚制导火箭，但「似乎失败了」；数小时后他们回到 Claude，试图分析失败原因。Anthropic 称没有证据表明他们成功部署了可投入使用的武器，但发现他们已经建了一套不依赖 Claude、也不依赖 MATLAB 之类工程环境的离线仿真工具链。

绕过手法与防护效果：隐藏真实目标与软件最终用途、把工作拆分到多个会话，让任何单次对话都看不出完整的武器研发意图。Anthropic 的原话是——「我们的安全防护机制拦截了他们的许多请求，但并非全部。」目前相关账号已封禁，情报已共享给公共及私营部门伙伴。

Anthropic 未直接指认该小组属于胡塞武装（也门北部大部分地区由胡塞控制，媒体据此关联）。这份报告共涉及也门、中国、俄罗斯相关的六起常规武器相关调查，另含无人机集群、电子战、军购与武器研究等软件用途。

为什么值得关注：把这三天的推送排成一列，Agent 的角色已经走完三幕：
日期事件Agent 的角色
09-10GitSpawn：一个 .git/config 劫持 7 款主流 Coding Agent受害者
09-11PaperCut / Kimsuky：数百个 Agent 批量打洞、写钓鱼武器
09-12也门小组用 Claude Code 顶替工程师写 GNC 软件劳动力本身
第三幕的分量在于：它不是「AI 帮坏人写了个脚本」，而是非国家行为体第一次把 coding agent 当作工程团队的替代品——稀缺的不再是武器设计知识，而是「有没有人能落地实现」。同时注意那句「拦截了很多，但不是全部」和「已建离线工具链」：封号是滞后的，能力已经转移出去了。
口径边界：① Anthropic 是当事方也是披露方，报告由其内部调查驱动，封号与防护有效性属于自述。② 未点名胡塞武装，归属是媒体推断。③ 试射失败、无证据显示形成可实战武器——把它读作「能力门槛在下降」的趋势证据，而不是「AI 造出了导弹」。

Skild AI 首次商用部署后 10 个月做到 1 亿美元 ARR，同时公开炮轰行业「Demo 文化」

具身智能
来源：Skild AI 官方博客《The Hidden Pillar of Robotics》（9/9）· Humanoids Daily / Securities.io 转述 · FutureX Physical AI Daily Issue 117

数字本身：年化经常性收入（ARR）突破 1 亿美元，距离第一次真实商业部署只过了 10 个月；今年 1 月 C 轮融资 14 亿美元时披露的口径还是约 3000 万美元。客户 60+ 家付费企业，覆盖电子装配、餐饮、仓储、数据中心巡检，点名包括 富士康、三井物产、住友电装、G10 Fulfillment。

收入结构比总额更有信息量：移动底盘只占 10%、Fetch 方案占 4%，绝大部分来自工业操作与专项物理作业——和 Foxconn / NVIDIA 一起把 Skild Brain 用在双臂 manipulator 上装配 Blackwell 系统（插busbar、放限位块、拧 16 颗螺丝且带接触力阈值）；与住友电装攻线束装配这块「被认为不可能自动化」的硬骨头；与三井物产在日本供餐（日均 140 万份）的厨房做摆盘试点。

联合创始人 Deepak Pathak 与 Abhinav Gupta 随里程碑发了一篇檄文，几句话很扎人：

  • 「5% 准确率和 99% 准确率，各剪一条成功视频，看起来是一样的。」
  • 去年教模型煎蛋：煎出第一个蛋用了一周，让它在不同鸡蛋、不同环境下稳定下来又花两个月；「把最后 5% 提上去花的力气，远大于做出前 95%」。
  • 「即便 99.9% 准确率，只要慢十倍，就没法部署。」产线上十个工位机器人占了一半，只要有一个工位慢，整条线的吞吐就被它锁死。
  • 「哪怕只有 50% 准确率，你也能挑出一条好看的镜头。要部署，你得处理剩下那 50%，那难得多。我们决定奖励部署。」

他还提了 physical RSI（物理递归自我改进）：部署数据回流基座模型，让下一次部署的起点更高。收尾一句是：「Demo 的时代结束了，部署的时代开始了。」

为什么值得关注：这是和昨天主榜第 4 条严格镜像的一组对照——09-11 梅卡曼德 CEO 指控同行靠「数据采集中心 + 关联交易」造收入，09-12 Skild 用 60 家付费客户和 1 亿美元 ARR 给出「真收入长什么样」。在监管收紧（09-10 证监会窗口指导）、二级出清（宇树市值回撤逾 2400 亿）的背景下，具身赛道的估值锚正在被强制校准：能拿出 ARR 的才配谈估值。Pathak 那几条关于「最后 5%」和「慢十倍」的判断，也完全可以当成甲方评审机器人方案时的提问清单。
口径边界：① ARR 是公司自报口径，未经审计，且「年化」是把当前收入折算成年，不等于已到账收入。② 客户名单里既有规模化部署也有试点（住友是「推进中」、三井是「试点」）。③ 檄文的立场不中性——它既是方法论宣言，也是融资与销售材料，批判 Demo 文化对 Skild 自身有利。

HuRo：把人类视频「机器人化」拿去做 VLA 预训练，真机任务完成率 51.5% → 80.3%

具身智能
来源：arXiv 2609.10706（Jinho Jeong 等）· FutureX Physical AI Daily Issue 117（09/12）· 代码与数据已开源

具身智能最卡的瓶颈一直是真机数据——遥操作采集贵、慢、规模上不去。HuRo 的切入点是：把现成的人类视频转换成机器人对齐的数据来预训练 VLA。

做法是汇集五类人类视频源，转成约 63 万条机器人对齐片段、合计 1.42 亿帧，构成 HuRo 数据集。作者要验证的是两件事：机器人化的人视频能不能支撑 VLA 预训练，以及能不能随规模良性增长。

答案是能，且涨幅不小：

场景预训练规模扩大前扩大后
四项真机任务 · 整体完成率51.5%80.3%
分布外（空间与视觉条件变化）34.9%72.2%

分布外那一栏是重点：涨了 37.3 个百分点，比分布内还猛，说明靠人视频堆出来的多样性确实在补泛化，而不只是把训练集拟合得更好。代码与数据已开源。

为什么值得关注：这条和昨天主榜第 5 条（理想把 Mach VLA 2.0 压回 2022 年的 Orin 平台推给近百万存量车）刚好构成具身落地的两半：一个解决「模型怎么落到已售出的旧硬件上」，一个解决「训练数据从哪来、怎么便宜地规模化」。如果机器人化人视频这条路走得通，数据成本的量级变化会直接改写小团队的入场门槛——毕竟人视频是互联网上少数几乎无限的货源。
口径边界：① arXiv 预印本，未经同行评审（好在数据与代码已公开，可复现）。② 只验证了四项真机任务，样本面窄，能否推广到长时程、富接触、高精度装配类任务未知。③ 「机器人化」这一步本身有对齐损失，人视频与机器人本体之间的形态差异（尤其是手部自由度）仍是不小的鸿沟。

Trail of Bits 开源 Coop：给 Claude Code / Codex 的一次性隔离 VM

Rust 写的 CLI，每个 agent 会话跑在按需创建、用完即毁的 VM 里，给足 Docker / git / 编译器 / 包管理器权限但不碰宿主机。关键差异是 VM 级隔离而非容器——容器与宿主共享内核，VM 有自己的内核，攻击面完全不同。缺口也很明确：目前只支持 Claude Code 与 Codex，缺企业策略下发与集中审计日志。和主榜第 3 条是同一天的一体两面。

Anthropic 开源 Model Hardware Standard（MHS）：把 MCP 的思路用到物理设备上

9/11 研究预览。定义一套共享规范，让 agent 能发现并安全操作显微镜、液体处理站、机械臂、实验激光等设备——每个设备通过标准化驱动暴露读写命令与机器可读安全上限，可经 MCP / CLI / 代码调用且与模型无关。宣称把实体 AI 集成时间从数周压到数小时。MCP 统一了 agent 到软件，MHS 想统一 agent 到硬件。

ReactHuman：MLLM 当人形大脑，突发危险约三分之一答错，且不随模型规模下降

盘子滑落、刀子掉下来这类需要临场反应的场景。17 类事件、1000+ 可用 240Hz 刚体仿真复现的场景，还故意放了外观与物理属性冲突的物体（泡沫做的铁砧、钢做的苹果）。被测的七个 MLLM 大约三个里错一个，而且模型越大错误不减少。数据集已上 Hugging Face——和 09-11 的 SWE-Bench Pro Verified 属于同一类「审计式基准」，只是这次审的是具身大脑。
