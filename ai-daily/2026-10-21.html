DeepSeek 开源 DeepInfer：把推理栈连同「每卡每小时 38 美元」的账本一并交出来

AI Coding
DeepSeek 官方公告与开源仓库（10-20 傍晚）；澎湃新闻 / 中新经纬 / 第一财经 / 中国基金报（10-20 至 10-21）；vLLM 官方确认（Apache 2.0 致谢）

10-20 傍晚（昨日本期日报 15:38 收稿之后），DeepSeek 在官方渠道宣布把内部大规模云服务推理框架 DeepInfer 全面开源，同时开源生产级 Token 编解码组件 deepseek-recipe。这是全球头部大模型企业中首家主动交出原生生产推理栈的公司。

  • 账本（自报）。基于 DeepInfer 已实现 DeepSeek V4.1 Flash 的高吞吐低延迟服务；单一集群服务吞吐 155 万亿 Tokens / 天，整体收入为每卡每小时 38 美元（按谷价口径）。
  • 能力面。高性能算子 + 深度优化推理引擎，支持分布式推理、推测解码、SWA Bounded Replay、结构化输出，可在英伟达与华为昇腾平台运行。
  • 协议与出身。Apache 2.0；vLLM 项目官方确认 DeepInfer 最初主要构建于 vLLM 之上，另受 SGLang 与 TensorRT-LLM 启发，并公开致谢开源社区。配套的 deepseek-recipe 支持主流大模型 API 协议，处理逻辑与 DeepSeek 官方 API 完整对齐。
  • 交付边界。官方仓库说明本次提供离线推理与大规模服务所需核心能力；要搭完整在线服务，开发者仍需自补 KV 缓存系统、推理阶段分离部署、跨副本负载均衡等组件。新模型推理代码与后续优化将继续在该框架内开源。
  • 行业含义（媒体推论）。推理框架此前是原生部署与社区部署成本差异最大的系统层原因；在负载调度合理的前提下，云厂商部署非原生 DeepSeek 调用的成本存在低于官方原生的可能性。

这为什么值得看。开源深度推进了一层：10-18 ① 推的是权重开源（DeepSeek V4.1 Flash-1017），这次是部署栈开源。对自建推理的团队，权重开源只省了调优，系统层没开源就只能照抄别人的成本结构；现在连调度与编解码逻辑都给了，等于把「为什么你们比官方便宜」这个答案的参考实现一并公开。

更值得注意的是它把 MaaS 的定价权摆到了桌面上：如果推理栈可以被第三方复现，官方 API 每百万 token 的价格就不再只由算力成本决定。对照 10-20 ① MiniMax M3.1 Flash 把 agent 综合成本打到前代三成 —— 一边降价，一边把定价所依赖的那层系统逻辑免费送出。

口径提醒。155 万亿 Tokens / 天与每卡每小时 38 美元均为 DeepSeek 自报，未见第三方复现；「谷价」为特定计价场景，非通用市场价；「非原生部署可能比官方更便宜」是媒体推论，非实测结论；官方仓库明确说明完整在线服务需自建组件，落地成本不含在内；vLLM 的确认说明相当一部分能力来自社区，DeepInfer 的增量价值在于整合与调度，不是从零发明。

可以行动。如果你的推理成本正卡在官方 API 报价上，这是第一个值得算一遍的对照组：拿自家负载在 DeepInfer 上跑一遍吞吐与延迟，再对比官方账单，差额就是这套开源给你的上限收益。同时盯住官方 API 定价是否随之调整 —— 那是这次开源真正想撬动的东西。

Cursor 把插件发进 Claude Code 的市场：竞品 harness 开始借对手的货架分发自己

AI Coding
GitHub cursor/plugins 仓库与 PR #709（作者本人经 GitHub API 一手核实，10-21）；clauday 技术分析（10-20 前后）

Cursor 官方插件仓库 cursor/plugins 的 .claude-plugin/marketplace.json 里，owner 写的是 Cursor、联系邮箱是 plugins@cursor.com，对外暴露两个插件：origin-apps（基于 Cursor Origin API 构建应用）与 pstack（严格、可并行的代理开发工作流，源码路径 harness/pstack/claude-code）。Cursor 卖的是与 Claude Code 竞争的 harness，却把自己的插件挂进了 Anthropic 的插件市场。

  • 仓库实况（10-21 一手核实）。13,267 star、1,307 fork，最后推送 10-21 03:32（UTC）；marketplace 列出 103 个条目，其中 17 个为一方插件（含 continual-learning 增量更新 AGENTS.md、thermos 并行子代理审查、ralph-loop 迭代循环、orchestrate 大任务分派、advisor 重大决策前咨询更强模型、cli-for-agent 让 agent 可靠调用 CLI 等），另约 55 个为第三方集成（该数字来自第三方分析，非仓库自报）。
  • PR #709 的内容（已合并）。10-18 提交并合并，新增 /create-formal-verification-skill，作者注明由 Cursor agent 撰写。它要求 agent 选仓库里最难验证而破坏后最伤用户的那个承诺作为目标，而不是挑最容易的那个；选工具并说明理由；在故意破坏的代码变体上证明该属性确实会失败；然后把检查写成项目内局部 skill，留给下一个 agent，让它能判断改动是否触及被验证的代码、用一条命令重跑、区分真实 bug 与建模错误。skill 明确禁止为了通过检查而弱化属性或模型。
  • 它为什么留在目标层。skill 只规定「什么算好结果」（模型部分、证明部分都要指到可打开的代码；必须先看到属性在破坏变体上失败；交接要写明边界、假设与未覆盖项；检查要能一条命令、工具版本可复现重跑；被验证代码变更时要触发下一次复核），把工具选择留给 agent —— 并点名 TLA+ 只是并发与分布式设计的常见起点。PR 自述的评测在 6 个从未见过的开源仓库上盲评（pg-boss、swr、HikariCP、client-go、cJSON、arrayvec）：4 个并发/分布式形态仓库均值 29.0 对早先草稿 26.5，cJSON 与 arrayvec 均值 26.0 对 22.0；在 TLA+ 不适配的两个仓库，skill 在 4/4 次运行中改选 CBMC 与 Kani。
  • 背景。Android 上周也已把 skills 发进 Claude Code 与 Codex 市场；Cursor 这么做信号不同 —— 它是直接竞争者。

这为什么值得看。这是分发权的一次转移：skill 文件正在成为新的分发单元，harness 退化成「在哪跑」。过去一家 AI coding 工具的护城河是自己的编辑器与运行时；现在连 Cursor 都愿意把自己的工作流方法论，塞进竞争对手的包管理器里换取触达。

它和前两期的验证主线构成三解，且各占一层：10-19 ③ Sphinx 强制人类在 push 前先答出理解题（谁来读），10-20 ② Claude Code 团队把阅读交给机器、人类只做风险分级（谁来判），本期这条是谁来发 —— 而且发的是「怎么自己造一个检查」的方法，而不是某个具体工具的用法。对想把验证留到自己仓库里的人，这比装一个插件更值得抄。

口径提醒。star / fork / 条目数为 10-21 经 GitHub API 一手核实，第三方分析文章写作时为 12,705 star，不同时点快照；约 55 个第三方集成来自第三方分析，仓库页面未列完整清单；PR 自述的评测样本极小（每仓每版本 n = 1，部分 n = 2），作者自己也写明「把单次差距当线索而非结论」，且在 cJSON 与 arrayvec 的「检查强度」一项上分数低于早先草稿；PR 明确只改提示词与文档，不改运行时与既有 skill；/create-formal-verification-skill 设置了 disable-model-invocation: true，只能手动调用，不会自动触发。

可以行动。抄两条就能用：① 在自己的仓库里立一条「选最难验证而非最容易验证」的检查项，让 agent 挑那个破坏后最伤用户的承诺；② 要求所有落地的检查必须先在故意破坏的变体上失败一次，否则不算通过。再加一条交接规范：写明边界、假设、未覆盖项，以及被验证代码变更时谁来触发复核。

Vercel 开源 durable-harness：agent 的状态从进程里搬进日志，崩溃后接着算账

AI Coding
Vercel Labs vercel-labs/durable-harness（10-20 发布）；Vercel 官方博客 Making every harness durable；aicoder / deniz.in / creatorstoolbox 技术分析（10-21）

10-20，Vercel Labs 开源 durable-harness（Apache 2.0，npm 版本 0.0.1-beta.6，README 标注实验性、API 可能变）。它把 Vercel 内部给 eve 与 Workflow SDK 用的持久化能力，做成适配器嫁接到第三方 harness 上：Pi、OpenCode、Codex、Claude Code、fx（Claude Code 与 Codex 需额外沙箱，且被标记为实验性）。

  • 机制。每个 session 变成 Workflow SDK 的一个 run；每次模型调用与工具调用，先写 intent、执行完再写 outcome，全部进同一个 durable log；每个 turn 背后还有一条队列消息，函数崩溃或超时后队列把 turn 交给新函数，新函数读日志从断点继续。
  • 不重复计费。已完成的模型调用结果直接从日志读回，不会为同一次调用再付一次 token 费；模型保留此前调用的记忆而不是重做。
  • 工具自声明重放策略。每个交给 agent 的工具要声明崩溃后的行为：标 safe 的（读文件、查 CI 状态）崩溃后自动重跑；标 never 的（退款、发 PR 评论）永不重跑，模型只被告知「这个调用可能已经发生」，由它自己判断要不要核。Vercel 的例子是加定价页：文件读取与 CI 状态查询 safe，PR 评论 never。
  • 会话镜像与可移植。Claude Code 的 transcript、Codex 的 rollout、OpenCode 的 event store 会被镜像进日志，新函数或新 Sandbox 可以据此重建会话；日志、队列与流合并在 Vercel 称为 World 的接口后面，本地开发用文件、Vercel 上用 Vercel World、自托管可指到 Postgres / MongoDB / Redis / Turso，改两个环境变量即完成迁移。文件系统有三种模式：virtual（存进 session 日志）、virtual + durable:false（内存临时）、sandbox（独立 Vercel Sandbox，workspace 落在 Drive 上）。
  • 它想解决的痛点。harness 原本是为长驻本地进程设计的，会话在工作区同一块磁盘上，断点续跑只要再发一句提示；一旦搬到云上跑几分钟到几小时的 turn，持久化 VM 也记不住「哪些模型与工具调用已经完成」，超时或崩溃就丢活，重跑还要再烧一遍 token。

这为什么值得看。这是「agent 常驻」这条线的第三个解法，而且解的是最硬的一环：10-13 ① Codex 常驻守护进程解决的是进程别退出，10-15 ① OpenCode 2.0 后台服务化解决的是agent 常驻，durable-harness 解决的是状态常驻而进程可换 —— 计算层变成临时资源，状态全在日志，跨机器恢复。

更值得注意的是它把「完成与未完成」变成了可审计的账：intent 与 outcome 成对落盘，等于给每个 turn 留了一份可回放的执行凭据。这正是 10-20 ② Claude Code 团队「给 Claude 可执行的验证」诉求的运行时版本 —— 那篇解决怎么验，这篇解决验完之后怎么留痕、怎么不重复花钱。

口径提醒。Apache 2.0、npm 0.0.1-beta.6、README 自标 experimental 且 API 可能变，均为仓库事实；「已完成的模型调用不会被二次计费」是厂商的设计描述，无第三方测试；Vercel 未公布性能或可靠性基准、恢复延迟与开销数字；Claude Code 与 Codex 需额外沙箱且标实验性；never 类工具靠模型自觉核验，不构成强幂等保证；本地开发默认文件存储，跨机器恢复仍需自建一致性的后端。

可以行动。两件今天就能做的：① 给现有 agent 流程补一份「工具重放策略表」，逐个标注 safe / never —— 特别是退款、发通知、写外部系统这些副作用动作，必须走 never 并让模型先核对；② 试用前先跑一遍账：同一任务崩溃重启后，确认已完成调用确实没有被二次计费。若成立，再考虑把长任务从本地搬到常驻环境。

NVIDIA 开源 Flora：机器人数据标注压到 Astra 级的 1/125 成本，500 块 GPU 每天处理 20 万小时视频

具身智能
NVIDIA 机器人研究负责人 Jim Fan 于 X 发布（10-21 01:02）；NVIDIA GEAR 研究页 research.nvidia.com/labs/gear/flora；RoboHorizon 报道；中文技术号转述（10-21）

10-21 凌晨，NVIDIA 机器人研究负责人 Jim Fan 在 X 上宣布开源模型套件 Flora，定位是「给机器人数据引擎规模化供料」。三个模型分别对应机器人数据的三个环节：

  • Flora-Captioner 看单帧图像生成场景描述；Flora-TempSeg 处理视频，定位某个动作的精确起止时刻；Flora-Rewarder 看视频片段写出「成绩单」，给出带原因的反馈信号，而不只是一个通过或不通过。
  • 产能口径（自报）。性能达到 Astra 级别，成本只有 Astra 的 1/125（Astra 为 Google DeepMind 的机器人模型系列，此处作性能参照物）；已在 NVIDIA 内部数据引擎投入使用，500 块 GPU 每天处理并标注 20 万小时视频。
  • 用途。Jim Fan 明确「我们用它来训练 NVIDIA GR00T」—— Flora 相当于 GR00T 的数据加工厂：把原始机器人视频与人类第一视角视频，转成带时间戳的指令、密集的进度奖励（供质量控制与强化学习后训练）与评分量表（供真实世界基准测试）。
  • 开放程度。模型权重完全开放，已上 HuggingFace；官方强调「现在权重也归你了」。
  • 同期开源潮。10-16 Meta 放出 Muse Spark Open（816B 总参 / 42B 激活 / 1M 上下文）；10-20 DeepSeek 开源 DeepInfer（见主榜 ①）；10-15 NVIDIA 发布 Nemotron 3.5 Super VL、10-14 把 Run:ai 平台整体开源。

这为什么值得看。机器人赛道眼下最缺的不是本体，是数据：大模型能靠互联网文本吃饱，机器人没有「互联网视频」这种现成燃料，只能靠遥操作采集、仿真合成与人工标注，成本高到成为主要瓶颈。Flora 把「把原始视频变成训练信号」这一步做成一个可下载、可改写的工程件，等于把标注产能从人力预算里搬到了 GPU 预算里。

和 10-20 ⑤ Ropedia W0 合读更清楚：W0 回答「人类视频能换多少性能」（缩放曲线），Flora 回答「造这些训练信号要多少钱」（单位成本）—— 两条合起来，机器人数据这件事才第一次有了可算的预算表。对国内做具身数据工厂的公司，这套权重意味着可以省掉自建标注团队的一大笔钱，代价是数据管线的竞争会更卷。

口径提醒。「Astra 级别」与「成本 1/125」均为 NVIDIA 自报，跨厂商对比的训练数据、任务集与计算口径未公开，无法独立复现；20 万小时 / 天、500 块 GPU 是内部部署口径，非可购买的对外服务；权重开放，但训练管线、标注规范与内部数据均未开放；RoboHorizon 对三个模型职责的描述与 Jim Fan 原帖表述一致，但与官方研究页细节仍需逐条对照。

可以行动。如果你的团队正为标注产能发愁，先做一次对照实验：拿自家同一批机器人视频，跑 Flora-TempSeg 与 Flora-Rewarder，与现有标注流程比单位成本与时间戳精度。重点看 Rewarder 的失败原因是否可用 —— 能说清「为什么失败」比一个分数值钱得多，那才是强化学习后训练真正吃的东西。

特斯拉年报表述里写进「已为 V3 Optimus 大规模量产做好准备」，但官方时间表今年已四次后移

具身智能
特斯拉向 SEC 提交的 2026 年年度股东大会材料与最终委托书（美东时间 10-19 周一）；FourWeekMBA 申报文件核对；新浪财经 / 中新经纬 / 中国财富网（10-20 至 10-21）

10-19（美东时间周一），特斯拉提交年度股东大会材料与 2026 年最终委托书，股东大会定于 12 月 3 日。据第三方对申报文件的核对，年报封面列出四项成就：累计交付超 1,000 万辆车、在美国推出纯视觉 Robotaxi、累计部署超 130 吉瓦时储能，以及「已为 V3 Optimus 大规模量产做好准备」——这是特斯拉首次以书面形式这样表述。

  • 文件没给的。未披露任何产量、价格或交付时间。
  • 同一份文件的正文更保守。董事会主席 Robyn Denholm 在致股东信中写的是：持续投资规模化所需基础设施，包括建设内华达州 Semi 工厂、Optimus 的首批生产线，以及训练超级智能系统的新增数据中心产能 —— 产线仍被描述为在建项目。委托书回顾 2025 年进展时写的是「对为量产而优化的 Optimus 机器人设计的进一步完善」，而不是开始生产。
  • 官方时间表今年四次移动。1 月的 Q4 材料称第三代是首款为大规模量产设计的产品、计划 2026 年底前开始生产、最终规划年产能 100 万台；3 月马斯克称今年夏天开始生产；4 月 Q1 财报给出产线位置（弗里蒙特 Model S / X 产线退役后由新线替代）；7 月 Q2 财报称弗里蒙特工厂已开始 Optimus 施工、预计今年晚些时候投产；到 10 月，措辞变成「量产就绪」。
  • 尚未落地的事实。截至 10 月中旬，特斯拉仍未公开发布第三代 Optimus，也没有公布规格、价格或预订渠道。10-19 马斯克在社交平台称，Optimus 与 Cybercab 将构成特斯拉价值的「绝大部分」。
  • 治理侧的一个新细节。最新的委托书把员工股权奖励与 Optimus 工厂 rollout 直接挂钩；机器人核心供应商新剑传动在上市审核问询函回复中称特斯拉机器人设计方案接近定型、即将进入量产周期。

这为什么值得看。这是一份把「叙事」和「交付」分开的好样本：措辞在往前推（从「今年夏天生产」到「量产就绪」），可交付的事实没有跟上（无产量、无价格、无交付时间、产线仍是在建项目）。同一天里，A 股人形机器人概念股集体走强，浙江荣泰、宁波东力、大业股份等盘中涨停，恒立液压披露多款行星滚柱丝杠与直线驱动器已批量生产供应 —— 供应链的预期已经按「量产已在眼前」定价。

它与 10-19 ⑤ 人形收入榜（前五全为中企、上半年 3.6 万台 / 5.4 亿美元）是同一件事的两面：收入榜证明机器人已经开始卖，年报措辞证明最大玩家还在准备。真要把这条读成可交易的结论，得盯住 12 月 3 日股东大会上会不会出现具体数字。

口径提醒。「量产就绪」是特斯拉自己的措辞，文件明确没有披露产量、价格与交付日期；委托书正文与年报封面的口径不一致，不能混用；今年四次时间表移动均为公司前后表述，第三方分析据此判断「量产就绪不等于量产」；截至 10 月中旬 V3 仍未公开发布，官方规格、价格、预订渠道均无；「特斯拉机器人团队到拓普、三花、均胜审厂」为 10-08 期已推旧闻，本期不重复计价，仅作背景；新剑传动「接近定型」为供应商对监管问询的回复，非特斯拉口径；12 月 3 日股东大会前一切表述仍可能更新。

可以行动。看多机器人链上，把观测口径从「产能规划」换成「可交付证据」：出厂台数、单机成本、实际交付客户、售后与备件体系。三条硬指标任意一条出现，才算从「量产就绪」走到「量产」。在此之前，审厂、扩产、股权挂钩这类信号只能当情绪看，不能当订单看。
