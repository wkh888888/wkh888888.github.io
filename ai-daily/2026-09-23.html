HarnessTax：同一个模型换个壳子，成功率几乎不动，账单最多差 5 倍——而最省的那个只给了四个工具

AI Coding · 中间层定价
来源：Arena 研究博客（9/16 发布）· UC Berkeley Sky Lab · harnesstax.github.io · 作者 Melissa Z. Pan、Shuo Yang、Negar Arabzadeh、Wei-Lin Chiang、Ion Stoica、Matei Zaharia · Victorino Group / AI Insiders / AINews / Codearia Academy 解析 · AGI Hunt 9/23 转述

这是第一次有人把 harness（那个决定「有哪些工具、系统提示写什么、每轮往回发什么」的壳子）当成一个独立于模型的成本变量来做受控测量。

  • 配置：7 个模型 × 3 个 harness = 21 对。harness 是 Claude Code 2.1.224、Codex CLI 0.146.0，以及 Pi 0.85.1——一个 MIT 许可的极简 agent，只有 read / write / edit / bash 四个工具，约 10.6 万 GitHub 星。基准是 SWE-bench Lite 与 Terminal-Bench 2.0。
  • 跑法：每个组合 30 道抽样题 × 3 次，100 turn 上限，容器断网，成本按 9 月 1 日直连 API 价目表统一计算。
  • 结论：成功率几乎不动，账单动得厉害。harness 对成功率的平均影响在 SWE-bench Lite 上是 ±2% 内、Terminal-Bench 2.0 上约 ±5%；作者原话是「同一个模型能以最多 5 倍的成本达到相近的成功率」。

最干净的一对是 Claude Fable 5 在 SWE-bench Lite：Claude Code 解决 97.8%、每次 $1.33；Pi 解决 96.7%、每次 $0.67。而 turn 数是 15.3 对 15.4——步数一模一样，所以差距不是「多想了几轮」，是每一步都贵一倍。

税从第一次调用就开始收：Claude Code 声明 23 个工具、首轮上下文 27,011 token；Pi 是 4 个工具、1,972 token，差 13.7 倍。这一块与任务无关，但每一轮都要重发。

最反直觉的一对是 GPT-5.6 Sol 在 Terminal-Bench 2.0：Claude Code $1.355 / 71.1%，Pi $0.421 / 83.3%——便宜 3 倍，还高 12 分。把 6 个 Anthropic / OpenAI 模型 × 2 个基准共 12 组比较摊开，有 9 组的最高成功率不是由模型厂商自己的 harness 拿到的。

为什么值得关注 —— 过去选 Claude Code 还是 Codex 还是 Cursor，讨论全落在「里面那个模型谁强」。这份数据把箭头掉了个头：账单的大头在壳子不在芯。对按 token 付费跑 agentic coding 的团队，最便宜的一个动作可能不是换模型，而是把最省的那个 harness 拿来跟默认项对跑一遍。

更关键的是它给了一个可操作的量：每个 resolved task 花多少钱，而不是「通过率」。这两个指标今天第一次被明确分开。

三条立刻可落地

① 先量你自己的首轮上下文（系统提示 + 全部工具定义）。这是每轮重发、与任务无关的固定支出，也是最容易白花的部分。

② 拿一个最短的 harness 与默认 harness，在同一批内部任务上各跑 30 题，看的是每解决一题花多少钱，不是通过率。

③ 别急着把 subagent / hooks / MCP 拆掉——见下方边界，这项实验刻意把它们排除在外了。

「省 50%」是聚合口径，不是每个模型都成立。几何均值上 Claude Code 约为 Pi 的 2.0 倍（SWE-bench Lite）/ 1.5 倍（Terminal-Bench 2.0）、约为 Codex 的 1.6 倍；「最多 5 倍」是 21 对里最宽的那一段价差，不是某一对模型的常态。AGI Hunt 转述的「75%」实际来自论文里的另一句——12 组比较中有 9 组最高成功率由非自家 harness 取得，不是全部 21 对。

实验刻意剥掉了你装 harness 的理由。无 subagent、无 hooks、无 MCP、断网、direct-API 计价、每个基准仅 30 题抽样；作者自己写明两个基准开源、可能已进训练数据。它证明的是「在最简配置下壳子很贵」，不证明「壳子没用」。

Arena 赞助了实验的 API 开销；团队称计划公开 profiling traces。研究发布于 9/16，9/22–23 才在技术与中文圈集中传播，非当日首发。

长程 agent 的两份体检报告：引用核查率最低 7.1%，指令遵循从 94% 掉到 41%——掉的是悬崖不是斜坡

AI Coding · 中间层失效
来源：EMNLP 2026 主会论文（AGI Hunt 9/23 转述）· r/LocalLLaMA 开发者的 847 次运行记录（AGI Hunt 9/23，页面底部附利益披露）· TianPan 长期运行 agent 上下文退化综述

第一份（同行评审）：EMNLP 2026 主会论文检查深度研究报告里的引用，发现大量句子并不被它所标注的引用支撑——引用召回率在 NVIDIA AI-Q 上是 58.7%，在 TrajectoryKit 上是 7.1%。作者还给了一种算法，能把每个引用错误一路追溯到引入它的那个 agent。

另一项用 JEV 当裁判检查网页检索引用：模型每任务大约引 8 个来源，没有任何一次运行 8 个全过；典型失败形态是「一句话其实由多个来源合成，却只挂了一个来源」。

第二份（社区实测，证据强度见下方边界）：一位开发者记录了 847 次 agent 运行，指令遵循率从窗口刚开时的 94% 掉到填满时的 41%——作者强调这是悬崖不是斜坡。注意力是 U 型的，所以窗口变大主要是把「被忽略的中间段」变大；有些团队把 60% 以上的 token 预算花在每一轮重新注入同一块内容上。

激进压缩会反噬：把一段 18,282 token 的对话压到 122 token，效果比完全没有记忆更差——摘要保住了故事，丢掉了可执行的事实。

还有一种无声失败：记忆层里躺着 3,000+ 文档，面板显示 91 条记忆，但每一次检索都返回空，而且不报错。

为什么值得关注 —— 两份报告打的是同一处：agent 跑得越久，我们对它中间那段的控制越弱。第一份说「引用这种最该可核查的东西，核查率只有 7.1%–58.7%」，第二份说「指令这种最基础的东西，到窗口后半段只剩四成」。

合起来的含义很实际：长程任务的结果不能只看最终产物，得看它是第几轮产出的。而「上下文越大越好」这条默认假设，在这两份数据里都站不住。

一条今天就能做的自检（转述者给出）：拿同一个任务，量它在第 5 轮和第 50 轮的准确率。如果掉了，先分辨是注意力悬崖还是压缩丢事实——前者要的是缩短有效上下文，后者要的是给压缩加「事实存活率」检查，而不是只盯 token 数。

两份证据强度差很多，不要混用。EMNLP 那篇是主会论文、可检索到系统名与数字。847 次运行那组出自 r/LocalLLaMA 的开发者自述，且 AGI Hunt 在转述页底部明确披露：「作者本人是 memory 产品 Maximem Synap 的作者，847 组数据来自另一位 r/LocalLLaMA 开发者」——有产品利益关系，也不是同行评审。18,282→122 token 与「3,000+ 文档 / 91 条记忆 / 检索全空」两条同样出自该帖。

数字可用，但请当作一份高质量的现场日志，而不是结论。U 型注意力本身有多方独立佐证（lost-in-the-middle 系列研究），可以分开采信。

NVIDIA 与 Google 在同一场会上把机器人底座免费送出去：一个做成 agent 能调的 skill，一个走「机器人界的 Android」剧本

具身智能 · 中间层开源
来源：ROSCon 2026（多伦多，9/22）· NVIDIA 官方博客与 GitHub · Unite.AI / SiliconANGLE / Silicon Report / Singularity.Kiwi · Forbes（John Koetsier，9/22）· Intrinsic 公告 · FutureX Issue 128

NVIDIA Isaac ROS 5.0：最大变化是把机器人领域知识打包成 Isaac Skills——可复用工作流，官方措辞是「开发者和 AI agent 都能用」。新增内容包括 FoundationStereo 微调 skill（让 agent 把立体感知模型适配到你的相机与环境）、FoundationPose 的 agent-ready 推理库（官方称物体位姿跟踪快 5.5 倍），以及把 pick-and-place 从一堆示例代码变成独立可调用的 skill。支持 ROS Lyrical + Ubuntu 24.04，算力覆盖 Jetson Orin Nano 到 Jetson Thor，免费开源。NVIDIA 还向 ROS Lyrical 贡献了标准数据接口 rosidl::buffer。

NVIDIA 机器人仿真产品市场经理 Katie Washabaugh 在 ROSCon 的说法很直白：「机器人开发里有非常多的摩擦，把管线接起来这件事摩擦太大了。」另一句更实在：「配置（setup）看起来是低垂的果实，操作（manipulation）则像是机器人开发里还没开垦的地方。」

Google Intrinsic Core：以 Apache 2.0 放出控制、运动规划、抓取规划、仿真、位姿估计、相机标定六块，ROS 兼容；Intrinsic 称与真实部署中日常使用的是同一套能力，不是精简演示版。同时发布 Open Machine Tending Solution——CNC 机床上下料的开放参考设计，开箱支持 FANUC 与 Universal Robots。Intrinsic 给出的背景数字：美欧有数以万计的精密零件加工车间，只有 8% 用了任何形式的自动化。

福布斯的框架值得单独记：皮查伊今年 2 月把 Intrinsic 叫作「机器人界的 Android」，七个月后剧本照演——免费给出人人都需要的一层，收钱的是上面的先进模型、Flowstate 与工业级云。Intrinsic 公告原话：用 Core 做的方案「自动适配 Intrinsic 的其他产品，包括我们的企业服务（含先进 AI 模型、Flowstate 与工业级云服务），无需重构或重写代码」。

一个耐人寻味的细节：NVIDIA 公布的 Isaac ROS 采用方名单里包括 Intrinsic——而后者几小时后就开源了自己的底座。

为什么值得关注 —— 机器人行业最贵、最重复、也最难守住的那一层（驱动、运动学、标定、碰撞路径），今天被两家同时免费送了出去。

对关注 AI coding 的读者，真正的变化在 Isaac Skills 那半句：这层第一次被做成 agent 可以直接调用的接口，而不是给人读的文档。谁把「管线」变成 agent 可调的 API，谁就拿到了下一代机器人开发的默认入口——这是 NVIDIA 在数据中心用过的同一套打法（送软件、卖芯片），风险则是整个行业的命运被绑到一家公司的路线图上。

5.5 倍是 NVIDIA 自报数字。多家转述均标注为 vendor-reported、仍需独立复现；我在官方公告与转述中未找到该基准的具体配置（硬件型号、模型规模、对比基线），采用前请自行核对。

同名不同物：Isaac ROS 5.0 与今年早些时候 Perceptron AI 的开源权重模型 Isaac 0.5 无关，别混。

福布斯同时指出：Intrinsic Core 开放的这一半，与 DeepMind 的 Gemini Robotics 2（人形 / 双臂灵巧操作）目前尚未看到明确接口——Gemini Robotics 的公告里没提 Intrinsic，SDK 里也没提 ROS。两半还没接上，这是判断这次开源成色的关键变量。

GPT-6 Astra 直接当机器人策略：42 个任务跑 2,100 次拿到 22.48%，压过 40 个公开 policy，但卡点不在「想」在「手」

具身智能 · 中间层极化
来源：arXiv:2609.24170（9/21 提交，Wenbo Zhang 等 12 人，24 页）· FutureX Physical AI Daily Issue 128 · 中文聚合转述（9/23）

论文题目就是态度：《An Unexpected Robot Policy: Early Evaluations of GPT-6 Astra on RoboDojo and Beyond》。它问的问题很硬：一个通用大模型能不能不做任何任务微调，直接当机器人的策略（policy）用？作者称之为 LLM-as-policy。

  • 做法：在 RoboDojo 全部 42 个任务上，用官方 50 episode/任务的协议跑 Astra 与 GPT-5.5（DeepSeek-Flash 用 10 episode/任务），与 40 个公开 policy 对比。
  • 结果：GPT-6 Astra 在 2,100 次试验中拿到 22.48% 平均成功率 / 28.97 Score，高于排行榜上每一个公开条目。同样的后处理下，GPT-5.5 只有 0.88%，DeepSeek-Flash 1.92%。
  • 但能力画像高度极化：需要语义理解、不要求高精度的任务泛化得很好；需要精密控制、动态控制或复杂双臂协调的任务表现很差。
  • one-shot 演示在整体上没有任何收益——只在个别交互轨迹里观察到扰动下的回合内修正。

为什么值得关注 —— 这是「通用大模型直接当机器人策略」第一次被放进完整基准，而不是单次演示（承接 09-21 那条 Astra 开机械臂：那次是一次成功，这次是 2,100 次）。结论有两层。

好消息：决策层开始通用化了。同一个大脑跨过 42 个任务，压过了 40 个专门训练出来的 policy，而上一代 GPT-5.5 在同样流程下几乎交白卷（0.88%）——这是一个代际跳变，不是渐进改进。

坏消息：22.48% 这个绝对值本身说明离可用还远，而且卡点极其明确——不在「想不想得到」，在「手够不够准」。这正好给国产具身划出了窗口期：语义 / 规划这条线会被通用模型吃掉，视触觉、力控、精密执行这条线短期吃不掉。

「超过 40 个公开 policy」的参照系要看清——比的是 RoboDojo 公开排行榜上的条目，22.48% 是这批里的第一，不是「接近可用」。GPT-5.5 的 0.88% 也说明这个协议对「非为动作设计」的模型几乎不友好，不能读成两代模型差 25 倍。

中文聚合流传的「抓取类 20 次成功 19 次 / 精细嵌入类骤降至 10%」，我在 arXiv 摘要与 FutureX 转述中均未找到对应表述，采用前请核对论文正文表格。

论文结论措辞是「初步证据（initial evidence）」，且明确写了「可靠的精密与动态控制在所评测设定下仍是局限」。

Atlas 开进了现代的真产线，干的是零件排序；目标是 25,000 台，眼下的状态是「还在练习」

具身智能 · 中间层还在攒
来源：The Korea Times（9/22）· FutureX Physical AI Daily Issue 128

波士顿动力在现代汽车集团美国工厂 HMGMA（佐治亚州，萨凡纳附近，生产 Ioniq 5 / Ioniq 9 等电动与混动车型）内部开设了机器人元工厂应用中心（RMAC）。

Atlas 在那里做的是装配前零件物流与排序（parts sequencing）——把零件按装配顺序排好。这是真实的汽车产线，不是模拟线。

时间表与目标：明年该训练中心要搬进一栋大约 10 倍大的新楼，并开始探索汽车以外的行业；现代的目标是在未来几年内，于现代与起亚的全球工厂部署 25,000 台 Atlas。

但 Korea Times 与 FutureX 都写明：目前这仍是训练与测试阶段，距离节拍稳定的量产作业还有相当距离。

为什么值得关注 —— 一句话里的张力：一边是 25,000 台的部署目标，一边是「还在练习」。

把它和今天第 ④ 条放在一起看，具身智能当前的位置就很清楚了：大脑刚开始能跨任务（22.48%），软件栈刚开始免费（第 ③ 条），本体里最先进的那一台刚开进真车间，但干的是排序练习。三个层次同时处在「刚跨过门槛、还没到可用」的同一段——这比任何一条单独的融资或出货数字都更能说明行业真实进度。

「25,000 台」是现代的目标数字，不是订单也不是已交付量，且未说明实现年限；「10 倍大」指新训练中心的建筑面积。

RMAC 内的作业为训练与测试性质，不等于 Atlas 已承担产线节拍。把它与 09-16 智元在龙旗连续并线五个月、09-21 智元 300 台进长隆这类「已常态化运行」的条目对照时，请注意两者不在一个阶段。

phantom-kv：18MB 的 KV 张量，按请求装卸模型的拒绝行为

向 KV 缓存注入约 18MB 训练好的 key/value 张量，使拒绝行为可以按单个请求解除；关键在于卸载缓存后原始权重逐字节恢复，与重写 checkpoint 的 abliteration 路径不同。如果成立，refusal 就从「模型固有属性」变成「可随请求装卸的缓存状态」，讨论的落点会从「能不能去掉」转向「谁来管这 18MB」。边界：AGI Hunt 转述，我未检索到论文、代码或作者信息，「逐字节恢复」是转述中的主张，未核实。

RoboDawn：不用任何机器人训练数据，VLM 闭环直接控臂

arXiv:2609.22966（Meng-Hao Guo 等）。把机器人控制拆成一组离散的平移 / 旋转 / 夹爪指令，由 agentic VLM 观察、推理、执行并按结果调整。RoboTwin 2.0 C2R 上 zero-shot 53.2%，加一条上下文演示升到 73.6%，高于 π0.5 的 46.0%；真机在 Franka 臂上验证了放块入筐与叠块。与第 ④ 条是同一天的两种路线：④ 让通用大脑直接吐动作，这条把动作离散成 VLM 好写的「指令集」。注意 73.6% 是 one-shot 后数字。

Cognex 5 亿美元现金收购 RealSense

机器视觉厂商 Cognex 以自有现金收购深度相机公司 RealSense，基础价 5 亿美元，预计四季度交割。以色列 Globes 报的「超过 6 亿」包含三年 5,650 万美元现金留任计划与约 5,000 万美元限制性股票。RealSense 两年前从 Intel 分拆时季度营收仅 700–800 万美元，Cognex 预计其 2026 年营收 8,000–9,000 万美元、同比增长超 50%；Intel 仍持 20% 并将随交易退出。值得注意：RealSense 同时是 NVIDIA Isaac ROS 生态里 AgenticROS 的赞助方。8,000–9,000 万为 Cognex 预测值。

InstinctFlash：机器人模型第一次有了专用的 serving 运行时

General Instinct 开源，面向 VLA、扩散策略与「感知-控制单次前向」的混合架构，而不是给文本 / 多模态 LLM 用的 vLLM / TensorRT-LLM。官方称典型 VLA 策略在 RTX 4090 上端到端 <10ms、Jetson Orin 上 <30ms；支持 action chunking 预分配缓冲与流水、INT8/FP8 量化感知服务、C++ / Python API 对接 ROS 2，并强调确定性优先于吞吐。与 09-17 的 APXInf 端侧推理引擎是同一层的两个方向。边界：两个数字为项目自报，未找到第三方复现；且它比 TensorRT 更不通用。
