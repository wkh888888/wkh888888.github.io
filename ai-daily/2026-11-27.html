让 agent 拿 31 个真实数据源做一张《文明》地图：7 小时写出 4.5 万行代码，最新鲜的样本不是游戏，而是数据对账

AI Coding · 长程产出
Karpathy 博客与 X（@karpathy）· karpathy.ai/usaciv · newfacedesign、AIstify 转述 · 本人自述口径

11 月 25 日美东晚间，Karpathy 放出一个可以点开玩的网页：USACiv——把真实美国套进《文明》的策略游戏界面。他用 Claude Code 桌面版、Opus 5.5 开 ultracode，耗时约 7 小时、产出约 4.5 万行代码，宣传片也是 Claude 做的。

  • 数据源是真的：模型下载并解析了 31 个公开来源，含人口普查局、BEA、BLS、EIA、NOAA、USGS、国防部、国家公园管理局、FAA、FEMA 与 CDC；海拔、土地覆盖、GDP、就业、电厂、矿山、港口、机场、军事基地、货运流与灾害史，统一对账到 25 公里六边形网格上。
  • 游戏语言只是壳：黄金对应 GDP、区域对应当地产业专长、公民对应真实劳动力、奇观按游客量和研发经费选出国家公园与大学。他说圣何塞约四分之一的劳动者是工程师、程序员或科学家，全国是十四分之一。
  • 规模：19 个观察图层、524 个都市 City View、9 个主题顾问，Explorer 可把 3100 多个县的任意一列拉成表格与散点图。代码 MIT 许可，数据与运行说明一并公开，发布一天浏览超 200 万、收藏约 1.3 万。

为什么值得关注：这是本周最具体的一份「agent 长程产出到底能交付什么」实物。它的难点不在写代码，而在把 31 套口径各异的公共数据对账到同一套网格，再翻成自洽的游戏语义——数据整理、可视化与界面设计一次跑通。对照 11-21 速览① 那个 2.5 万行 Rust 操作系统，同样是把大代码量压进一个会话，这次多了一层真实数据的约束。

也接得上 11-22 ② 那笔反直觉的账：那边说用 agent 的开发者写代码多 25.5 倍、发布只多 30%。Karpathy 这次交出的是能直接点开、带数据的成品，而不是提交数。

需要留意：这是可视化器，不是完整游戏，Karpathy 自己说可以继续扩成游戏；他也承认 Claude「决定跳过几个州和地区」。7 小时、4.5 万行是个人自述，不是可复现的通用基准，且他开的是 ultracode、用掉了大半周额度。数据各有条款，宗教图层需单独署名。把它当「一天能做出什么样的数据产品」的上限样本，别当成「七小时就能替代一个数据团队」。

可以怎么用：想让 agent 交付真实数据产品，先把对账规则写清楚：数据源清单、统一坐标或主键、缺失值是留空还是置零。Karpathy 这份里最值得抄的一条是——缺失或抑制的数据标成不可用，而不是填成零。给 agent 明确的数据契约，比事后检查图表好看得多。

不换模型、不改输出，把长文与 Agent 的吐字速度最高拉快 4.2 倍：草稿模型直接复用主模型已经算好的缓存

AI Coding · 推理效率
腾讯混元官方公告与开源仓库 · arXiv:2611.34776 · GitHub Tencent/AngelSpec · 11-26 发布 · 官方自测口径

11 月 26 日，腾讯混元开源新一代投机采样草稿模型 DFly2。它不是新大模型，也不替换 Hy4 flash，更像挂在旁边的加速器：主模型权重不变、输出逐字一致，变的只是把原本串行的多次前向压成一次批量验证。

  • 关键做法：草稿层的每个 KV 直接读配对稀疏层的缓存（KV Share），并只看该层 indexer 选出的至多 2048 个位置（Index Share）。于是草稿 token 最多关注约 2K 个 key，注意力开销与上下文长度脱钩，零额外 KV 显存；不参与 prefill，P 到 D 只多传一个末层隐状态。
  • 成绩：19 个公开评测集上，单项最高 4.2 倍（AgentLongBench 64K、A12B），长上下文约 3.2 倍、Agentic 四项平均约 3.2 倍，比旧方案 DSpark 高约 25% 到 30%；Agentic 场景接收长度最高提升 68.5%，在 WorkBuddy 真实任务上领先 DSpark 10.4%。
  • 工程账更值钱：128K 上下文、FP8 MLA 配置下，比单层 MTP 少传 98.5 MiB（约历史缓存载荷的 1.44%），两端各少存 98.5 MiB；32K 输入、512 输出、512 并发时，端到端输出吞吐比 MTP 高 26%。

为什么值得关注：长上下文这两年先解决「塞不塞得下」，现在开始解决「塞进去之后跑不跑得动」。DFly2 的思路不是再造一个聪明的小模型，而是把主模型已经算过、已经付过算力的 KV、稀疏索引、权重和末层隐状态挨个拿回来用。这跟 09-08 ① Spotify 的 shunt 是同一个命题的两半：那次在输入侧把读文件交给便宜模型，这次在解码侧不新增任何缓存。

更关键的是它已在 DeepSeek-V4.1-Flash、GLM-5.3-Flash 和 Hy4 flash 三种稀疏实现上验证过，属于方法级开源，不是某一家的专属补丁。对把整个代码库、几十轮 agent 轨迹一次塞进模型的团队，这可能比再堆一倍参数更划算。

需要留意：4.2 倍是 AgentLongBench 单项峰值，官方给出的长上下文均值约 3.2 倍；短文相对 DSpark 的接收长度提升只有约 4%，别指望日常短聊有感知。它依赖目标模型现成的稀疏 KV 与 indexer，稠密注意力模型无法直接受益；模型卡明确写着 vLLM 投机解码支持仍在进行中。所有数字来自官方评测，第三方复测与生产环境表现尚未公布。无损指的是输出一致，不是零成本——草稿层本身仍在算。

可以怎么用：如果你的 agent 工作流卡在长文档或整库代码上，先量两件事：单次请求的上下文长度分布、以及每 token 的输出耗时。若 p90 上下文已过 32K 且输出等待占大头，可以拿 DFly2 在你自己的任务集上测接收长度与端到端吞吐，别只看峰值加速比；短上下文占比高的场景，优先级应该排在提示词与缓存命中之后。

OpenAI 承认 GPT-6.2 上线初期按折扣价计费：同样工作量 Astra 额度消耗快 40%，同日 DeepSeek 把单轮成本摆上账单

AI Coding · 成本账本
IT之家引 OpenAI Codex 与 ChatGPT 负责人 Sottiaux 表态，及 DeepSeek 网页端灰度页面 · 11-27 · 厂商口径

11 月 27 日两件小事凑成了同一条线。其一，针对用户抱怨「额度突然不耐用」，OpenAI 的 Sottiaux 承认 GPT-6.2 上线初期按折扣价计费；修复后完成同样的工作量，会消耗更多额度——Astra 触及使用上限的速度快 40%，Sol 快 25%。

  • OpenAI 表示不追溯扣费，向 Go、Plus、Pro、Business 各提供一次额度重置；12 月 31 日前 Business 用户可免费使用 Fast Mode。
  • 其二，DeepSeek 在网页端与 App 灰度「本轮消耗额度」详情：按输入缓存命中（0.02 元／百万 tokens）、缓存未命中（1 元）、输出（4 元）三档展示用量与折合金额，价格与 API 持平，个人对话仍免费；页面底部同时显示上下文占用进度。

为什么值得关注：成本正从黑箱变成明账。一边是被迫纠偏的折扣计费——用起来「变贵」其实是回到原价；一边是主动把单轮 token 用量和金额摊给用户，连上下文占用进度一起显示。接 11-25 ① 那笔「同一模型单任务账单差 5.6 倍」，那次是第三方量出不同外壳的成本差，这次是厂商直接把账单放到使用界面上。

对用 agent 跑长任务的人，这件事的实用价值很高：当长对话的成本和容量上限变得可见，你才有数据决定该压缩上下文、换缓存策略，还是干脆换个模型。

需要留意：消耗加快不等于涨价，是折扣口径恢复到原价，且 OpenAI 的补偿与口径都是自述、没有第三方核验。DeepSeek 的详情页仍在灰度，个人对话此刻免费，展示金额是「按 API 计价折算」的估算，不等于真扣钱。另外「额度重置」这个说法在 09-22 那期也出现过——那是另一家公司因仓库百科异常上传而做的补偿，同词不同事，别混为一谈。

可以怎么用：今天就去你的主力工具里找「用量／消耗」页面，记一周真实账：每个任务吃掉多少额度、长对话里缓存命中占多少。如果工具不显示，就自己按输入、缓存命中、输出三档粗算。发现额度消耗异常时，先确认是不是折扣期结束，再决定要不要迁移工作流——这一次 OpenAI 的情况就是计费口径变了，不是模型偷懒。

首批人形机器人运进汽车工厂，但先只干两个工位的活：沃尔沃让 Aeon 用模仿学习练取放，2027 年才谈真实工况上岗

具身智能 · 工厂验证
IT之家、The Next Web · 11-26 · Hexagon 提供本体 · 厂商计划口径

沃尔沃已把首批 Aeon 人形机器人运进比利时根特工厂，目前用模仿学习训练它们完成零件的高精度取放，计划自 2027 年上半年起在真实工况下逐步上岗。

  • 本体参数：由 Hexagon 提供，高约 1.6 米、重 60 公斤、最高时速 8.6 公里，靠轮子移动，最大搬运 10 公斤。
  • 训练路径：从两个固定工位起步，逐步增加零件数量、扩大移动范围，并与工厂现有自动化系统交互。
  • 公司口径：沃尔沃首席制造官 Nilsson 说，人形设计让它可以直接融入现有生产流程，目标是承担体力消耗最大的工作。

为什么值得关注：汽车工厂仍是人形机器人最现实的验证场——工位标准、安全体系完备、人工成本明确，比家庭场景更早能算出账。这条的价值不在机器人会走，而在它从两个固定工位起步、先模仿学习再谈上岗的节奏：把「进厂」拆成训练、试点、正式部署三段，而不是发布会一次演示到位。对照 11-22 速览④ 精灵 G2 进手机测试产线，那边是 3C 工序，这次是汽车零件取放，同样是拿具体工位当考卷。

它也接得上 11-23 速览④ 那条逻辑：agent 进车间前先在虚拟副本里改、工程师审完证据才准动手。这边是机器人在现场里先学，但同样没有跳过验证。

需要留意：当前只是训练和验证，不是生产线正式部署；2027 年上半年（另一家外媒写「2027 年中期」）是计划节点，不是承诺交付。关于 Hexagon AEON 我们此前提过一次——10-04 那期专门澄清过「莱比锡工厂的 AEON 试点为 2026 年 3 月宣布」，那是 1.65 米／60 公斤／24 传感器、测试高压电池装配的旧节点；这次是比利时根特工厂、首批运入、模仿学习、新的试点时间表，属同一机器人平台的不同阶段，不是那条旧闻的重复。厂方没有披露机器人数量、训练周期与验收指标。

可以怎么用：以后看到「某某机器人进厂」的新闻，先分清三件事：在训练、在试点、还是正式上岗；具体几个工位、做什么工序；有没有可核对的验收指标。这三问能过滤掉大部分演示叙事。真要跟踪这条线，接下来该盯的是根特工厂是否公布工位数量、训练周期与 2027 年试点验收标准。

南极不需要会走路的机器人：韩国把底盘做成轮履可切换，目标一次补给跑 200 公里、机械臂搬 100 公斤

具身智能 · 极端环境
韩国机器人融合技术研究院（KIRO）项目公告 · 硅基纵横、今日头条 11-27 转述 · 研发目标口径

韩国机器人融合技术研究院启动极端环境作业机器人平台 KAREX-M 研发。它的思路很反潮流：不追求双足人形，而是采用轮式、履带式可切换底盘，配液压机械臂与双臂操作系统，面向南极等极端环境做设备运输、安装和维护。

  • 项目周期：2026 年至 2030 年 12 月，获政府 60 亿韩元资金支持。
  • 硬指标：单次补给后在 100 公里半径内实现 200 公里移动；机械臂在 3 米作业范围内操作总重 100 公斤的物体。
  • 不是从零开始：建立在第一代 KAREX 的南极实测之上——2024 年曾在南极单次自主行驶 54 公里，30 天累计 267.74 公里。

为什么值得关注：这是对「具身智能＝人形机器人」的一个有用反例。南极真正需要的是可靠的长距离移动、运输和安装，不是像人一样走路；轮履可切换加液压臂，恰好对准这些约束。它有上一代机器人在南极跑出来的里程数据打底，不是纯概念。接 11-20 ⑤ 那句「叙事从跑得快跳得高转向能不能稳定交付」，这边直接给的是公里数和公斤数。

跟 11-25 ⑤ 灵掘 2.0 也是同一个方向的两面：那边用空铲率量化「活干完没」，这边用移动半径和负载量化「能不能在这种地方干活」。场景定义能力，而不是能力去找场景。

需要留意：这是研发项目启动，200 公里移动与 100 公斤负载是 2030 年的目标值，不是已经实现的成绩；目前可核对的只有第一代 2024 年的 54 公里单次与 267.74 公里累计。南极环境对可靠性要求极高，实验室或平原跑通的数据不能直接外推。项目也不面向商业出货，别把它当成一条量产或融资新闻来读。

可以怎么用：做具身选型或评估时，先写清楚环境的硬约束：地形、温度、续航补给半径、要搬多重的东西，再决定本体形态。如果任务不需要人际交互与通用操作，专用底盘加专用机械臂往往比通用人形更早能交付。跟踪 KAREX-M 的合理指标，是它能否在 2030 年前把那两个目标值在南极真实环境里跑出来。
