1

把已知正确的标准答案喂给 168 份「模型自己写的测试」，有 129 份判定它是错的

AI Coding · 验收凭证
来源：开发者实测报告（AGI Hunt 10/5 收录并摘要）· 跨源印证：OpenAI 官方博客《为何 SWE-bench Verified 已无法衡量前沿编程能力》（2026-02）· METR 2026-03 分析

一位开发者按教科书顺序搭了一条完整的编码 agent 管线：写契约 → 写测试 → 写代码 → 跑测试 → 修复。然后他做了一件很小但很致命的事——把每一份由模型生成的测试套件，都拿去跑一个已知正确的参考实现。

  • 结果：168 份测试套件里，129 份（77%）拒绝了那个正确答案。
  • 不是因为偷懒：这批测试的平均变异得分（mutation score）高达 0.965——它们覆盖得很密。而且在变异得分满分 1.0 的套件中，仍有 81% 会把标准答案判为错。一句话概括：既严又自信，但测错了规格。
  • 最典型的一例：任务是数元音字母。测试用例和那段 bug 共享了同一个误解——两者对于混大小写输入都期望 5 而不是 10。于是带 bug 的代码顺利通过，「修复」环节从未被触发。这是最坏的一种对齐：考卷和错误在同一处走偏。
  • 后果落在修复阶段：67 次修复尝试里，有 50 次在改被测试误判为错的正确代码；17 个真实 bug 里只有 1 个被真正修好。
  • 换更强的模型会好一些，但远没到能用：llama-3.2-1b 误判率 0.92–1.0，qwen2.5-coder-1.5b 约 0.75，qwen3-1.7b 降到 0.47–0.65。
  • 整条管线的最终成绩，在同等 token 预算下没有打赢「简单采样 4–8 次」的笨基线。
  • 作者给出的结论很直接：决定性的那一份测试，必须来自规格或人写的示例。模型可以提议考题，但不能由它来当裁判。

为什么值得关注 —— 这条把过去一年「agent 写完代码让 agent 自己验收」的默认做法，拆成了可计量的失效。真正危险的不是假阴性率高，而是耦合失效：当测试和那段 bug 犯的是同一个错时，整套自洽流程会一路绿灯走到终点。

而且这不是孤例。OpenAI 在 2026 年 2 月公开宣布停用 SWE-bench Verified，理由是它抽查了模型反复做不出的那 138 道题，发现其中 59.4% 存在测试设计或描述缺陷——35.5% 是「过窄」（强行限定具体实现细节导致正确解法被判错），18.8% 是「过宽」（检查题目根本没提的额外功能）。METR 在 2026 年 3 月的分析是同一结构的另一面：约半数通过 SWE-bench Verified 的 AI 生成代码，会被真实项目维护者拒掉。

两个完全不同的主体、完全不同的方法，指向同一个结论：「通过测试」在当下只是一个代理指标，而代理本身正在失真。今天的①②③是同一条线的三目——①证明它失真，②给修补方案，③给出失真之后的实际价码。

三条立刻可落地

① 把「决定是否通过的那份测试」与「提议测试的那个模型」分开。可以让模型提议边界用例，但验收集合要来自规格文档、人写的示例，或至少是独立 refresh 的模型 + 人核对。

② 不要只用变异得分衡量测试质量。这条实验最有价值的数字是「满分 1.0 的套件里仍有 81% 判错正确答案」——覆盖度与正确性是两个维度，只报前者会把问题藏起来。

③ 跑流程时加一道廉价检查：把候选 patch 与已知正确的参考实现（或 golden fixture）各喂一遍。今天这条整套方法论成本很低，任何团队都能在一小时内复现。

来源层级（请先读这条再引用数字）：原始帖为一位开发者的实测报告，未核到作者信息与一手原文链接，168 / 129 / 0.965 / 81% / 67 / 50 / 17 / 1 这组数字目前以 AGI Hunt 的单条转述为唯一来源。之所以仍放主榜，是因为同一结构性结论另有 OpenAI 官方审计（2026-02）与 METR（2026-03）从两个不同方向独立印证——印证的是「测试错了会污染验收」这一机制，不是上面那串具体数字。引用时请把两者分开。

样本边界：6 个任务、模型规模 360M–1.7B，属极小模型与极小任务集。不能读成「当前前沿模型也是这个误判率」；前沿模型的绝对值应显著更低（报告自身的趋势线也支持这一点），但趋势方向是否被放大、放大多少，本报告给不出答案。

「没有打赢 4–8 倍采样基线」的比较口径要小心：这是同等 token 预算下的比较，不等于同等墙钟时间或同等人力。是否采用取决于你的瓶颈是 token 还是等待。

OpenAI 与 METR 两条印证均为历史材料（分别为 2026-02 与 2026-03），本期仅作背景坐标引用，不是当日新闻。

同一天的两种修补：Google 让模型去查「大家都同意的那部分」，NVIDIA 把投票抢在命令执行之前

AI Coding · 校验器
来源：arXiv:2610.00972《VeriHarness: Scaling Agentic Verification for Long-Horizon Tasks》（Google Cloud AI Research / 剑桥大学，10/2 上线）· veriharness.com · NVIDIA《Mid-Harness》（Minki Kang、Ehsan Hosseini-Asl，AGI Hunt 与 AICrier 10/5 转述）

今天 ① 说的是「模型自产的验收凭证不成立」。紧接着的两份工作，给出了两个位置不同但目标一致的解。

VeriHarness（Google Cloud AI Research + 剑桥）——它的起点是一句很反直觉的经验发现：多轮 rollout 之间，「分歧」往往指向正确答案，而「一致」反而会把共享的错误藏起来。

  • 设定刻意做难：测试时没有标准答案、没有评分 rubric，verifier 与 generator 共用同一个基座模型（ Gemini 3.5 Flash / Claude Opus 4.8 各跑一遍）。基座固定意味着任何增益只能来自 rollout 本身与任务环境，不可能从更强的模型里偷知识进来。
  • 做法是把生成器本身包进一层 agentic verifier：给它工作区、证据工具、可复用的校验技能。内部两个部件——disagreement resolver 拿环境里的证据去比对互斥结论；consensus challenger 反过来挑「所有 rollout 都同意的那部分」，并专门去找被集体漏掉的需求。
  • 成绩：5 个长程 workspace 基准上的选择分数高于所有对照方法；叠加「基于证据的修订」后，相对单次 rollout 平均 +6.2 分（Gemini 3.5 Flash）/ +6.4 分（Claude Opus 4.8）。
  • 逐项：APEX-Agents 48.1→54.8（+6.7）、Workspace-Bench Lite 56.5→65.4（+8.9）、WorkBuddy 73.2→78.2（+5.0）、SB-2 27.3→32.2（+4.9）、JobBench 30.9→36.2（+5.3）。
  • 作者还证明了校验技能可以从失败反馈里自我改进，并放出了约 26,000 条 rollout 的全量池，生产成本逾 10 万美元，供后续研究使用。

NVIDIA Mid-Harness——名字说明了它的位置：插在 generator 和 harness 之间，两者都不改。每一步先采样若干候选命令，由一个 verifier 打分，只把第一名送下去执行。

  • 主数字：TerminalBench-Lite，TMAX-9B 生成 + GPT-5.6 Sol 校验、每步 8 个候选，Pass@1 从 50.00% 升到 68.03%。
  • 最有用的一条：verifier 弱的时候，采样再多也几乎不涨。这直接反驳了「多摇几次总能摇对」的直觉——瓶颈在判卷，不在摇号。
  • 把强 verifier 蒸馏进 TMAX-9B 让它自评，能到 57.14%：缩小但没有消除与前沿 verifier 的差距。比较方式上 pairwise 优于 listwise 优于 pointwise。
  • 算力怎么花：逐步采样（action scaling）比重跑整条轨迹（trajectory scaling）更便宜也更好，两者叠加最优。
  • 残余失败模式集中在命令语义与执行可行性——也就是说，判错的不是「往哪走」，而是「这句话能不能真的跑」。

为什么值得关注 —— 两份工作是同一件事的两个位置，而且互不重复：VeriHarness 改的是「看谁的票」，NVIDIA 改的是「什么时候投票」。

VeriHarness 打的动摇是本行业的默认做法。多数投票、自一致性、best-of-N，全都建立在「一致的 = 对的」这个假设上。论文把这句话直接反转：那些所有 rollout 都同意、从没被质疑过的结论，恰恰是最需要专门派人去打的地方。它为此专门设了一个 consensus challenger 组件——这在以前的验证流程里是没有的位置。

NVIDIA 那条的动摇是时机。在终端里，很多动作不可逆：删库、提交、推送、杀进程。传统 test-time scaling 是跑完了再挑，代价已经在账上了；Mid-Harness 把这道闸挪到执行之前，而且明确说明性能与 token 成本都更好。这条与 09-21 ③ GAVEL 是同一个思想在不同赛道的落地——GAVEL 是在具身任务里「执行前预测后果并拦截」，今天这条是在终端命令上做同一件事。

还有一条工程结论值得单独记：「多摇几次」的收益完全取决于判卷质量。今天的 ① 说考卷可能是错的，③ 说判卷成本可以极低，中间夹着这条——弱 verifier 加再多候选也几乎不涨。如果预算有限，先把钱投在判卷上。

三条立刻可落地

① 在你的 best-of-N 流程里加一个「找茬共识」环节。不必照搬 VeriHarness 全套：挑出所有 rollout 都给出同一条结论的地方，专门拿原始文件、数据源、任务需求去重算一遍——这是最高杠杆的检查点。

② 把不可逆动作的审批点前置到「候选已经生成、还没有执行」这一步。TerminalBench 上这个改动值 18 个点，而且论文说比事后重跑更便宜。

③ 评估 verifier 之前先分清空「weak / strong」。如果你的 verifier 弱，加采样等于烧钱；先花预算在 verifier 本身或者把它蒸馏成小模型，再谈扩采样。

时点（两条都不是当日首发）：VeriHarness 的 arXiv 编号为 2610.00972（2026 年 10 月 2 日上线），比本期早 3 天，AGI Hunt 10/5 收录。NVIDIA Mid-Harness 的确切 arXiv 编号与首发日期未核到——检索到的转述稿中出现「12 月 16 日发表」的说法，与今天的日期明显冲突，判断为转述站模板错误，故不给出具体日期；采用前请自行核对 arXiv 提交日，不要引用本文没有写的编号。

两种基准不可混比：VeriHarness 跑的是 APEX-Agents / Workspace-Bench Lite / WorkBuddy / SB-2 / JobBench 五个长程 workspace 基准，评的是报告、表格、跨文件交付物；NVIDIA 跑的是 TerminalBench-Lite，评的是命令行 Pass@1。两者的「+6.4」与「+18」单位不同，不可互相比较。

VeriHarness 的基线是「单次 rollout」：+6.2 / +6.4 是叠加了基于证据的修订之后的数字，选择（selection）部分的增益另算，不要把两者加在一起。

68.03% 的另一面是约三分之一的任务第一次仍失败；且 MITRE 式的结论都来自受控基准，真实混乱环境、更长任务、不同工具链下的表现论文未测。另外 TerminalBench-Lite 与 Terminal-Bench 2.0/2.1 并非同一版本，不要与历史条目里的 TB 数字直接对比。

3

Anthropic 给开源 GLM-5.3 做了一次攻防体检：接近从未公开发布的前沿模型，一条 Chrome 攻击链花了 20.40 美元

Agent 安全 · 开放权重
来源：Anthropic Frontier Red Team 报告《GLM-5.3 and the spread of advanced cyber capabilities》（Andrew Fasano / Marius Fleischer / Cole McFaul / Robert Xiao / Tripp Gallagher，9/29–9/30 发布）· NIST CAISI 独立评估（9/17）· Andrew Ng《The Batch》通信（10/5 再度扩散）· CVE-2026-11645 与 Chrome 149.0.7827.102/.103

这是第一次，一个任何人都能下载权重的模型，在端到端漏洞利用上追到了 Anthropic 那个「危险到不公开发布」的前沿模型附近。

  • ExploitBench（针对 Chrome V8 已知缺陷的端到端利用）：GLM-5.3 解决 50/410（12%），Claude Mythos Preview 56/410（14%）。而 Claude Opus 4.6、GLM-5.2、Kimi K3、DeepSeek V4.1-Flash 全部在零附近。
  • 二进制利用（基于 Google OSS-Fuzz 的 100 道题，控制流劫持）：GLM-5.3 4%，Mythos Preview 6%，其余为 0%。这组数字说明的不是「进步」，而是一个门槛被跨过了——几个月前发布的模型在这个基准上的成绩是精确的零。
  • 零日：给 GLM-5.3 一天时间对付一款常见的 Linux 浏览器，它找到多个未公开的 JS 引擎缺陷，并串成一条能读取任意文件的攻击链。Anthropic 已向该软件管理方上报。
  • N-day：把已披露的 CVE-2026-11645（V8 越界读写，Chrome 149.0.7827.102/.103 于 2026-06-08 修复，有在野利用报告）加上另一个已知缺陷交给 GLM-5.3-Flash，产出一条可在 ARM64 上跑完、绕过指针认证（PAC）加固的攻击链：人类约 20 分钟注意力、模型约 8 小时、按 API 计价 20.40 美元。
  • 护栏按下去的价格：直接要求，服从率 0%；编一套「红队演练」的假由头，64%（每格 50 次采样）；预先填好它的推理开头让它显得已经答应了，92%；把拒绝方向从权重里抹掉（abliteration），100%。整体拒绝率从约 95% 掉到约 6%。
  • 抹掉护栏的成本：无经验的团队约 2,200 GPU 小时（约 4,400 美元），有经验约 1,200 美元；GPQA-Diamond 分数不变、CyberGym 只略降。第三方弱化版本在官方发布后数日内就在社区出现——而因为权重是公开的，厂商既召回不了也补不了。
  • 对照组：Claude Opus 4.8 / Opus 5 / Mythos 5 在全部适用条件下均为 0% 服从；abliteration 对它们不适用，因为权重从不公开。

为什么值得关注 —— 把「国产开源模型不弱」这种泛泛的结论放到一边，这份报告真正在动的是两件事：价格，和可召回性。

价格：20.40 美元这条线要跟 09-20 ① HEIF Heist 那组数字放在一起读才有意义。三个月前，一个三人小组用两个月时间和不到 3,000 美元 token，打通 OpenAI 社区论坛到内部 monorepo 的完整链路；今天，一条针对已披露浏览器漏洞、带 PAC 绕过的 ARM64 可用攻击链，标价 20.40 美元。两者不是同一件东西，不能直接换算，但方向很清楚：把「已知漏洞到可用武器」这一段的工程成本，压到了一顿饭的钱。结论落在防卫侧：补丁发布到被武器化的窗口正在被压缩。

可召回性：这是今天最有长期意义的一点。闭源模型的护栏坏了，厂商可以改权重、封账号、加监控；开放权重模型的护栏被抹掉之后，那个版本永远存在于互联网上，没有任何开关能把它收回来。报告里那句「第三方弱化版本在数日内出现」不是附带细节，而是这条路径的必然产物。对照同一份报告里 Claude 全系 0% 服从——差距不在模型诚不诚实，在于能不能被收回。

它还给今天的主线补上了最后一格：①说模型自产的凭证不成立，②说校验器要搬到外部，而③说明同一套能力反向使用只要几十美元——「校验」不再有稀缺性，稀缺的是「有没有外部证据」。

三条立刻可落地

① 把「是否已包含 CVE-2026-11645 修复」做成浏览器与 Chromium 系产品发布流程里的强制检查项。149.0.7827.102 及以上已含 CVE-2026-11645 的修复，优先级应显著高于常规版本滚动。

② 威胁建模里不要再把开放权重模型的「内置拒绝」当作一道控制手段。报告给出的三种绕过方式都不需要高深技术，其中一种只要把推理的开头填好就行。

③ 反过来看机会：防守方现在也能用同等成本低到可笑的能力去找自己产品里的漏洞。Andrew Ng 在《The Batch》里给了同样的读法——他团队的 OpenWorker 正建在 NVIDIA 那套安全框架之上。这条能力防守方同样拿得到，谁先把它接进开发流程，谁先占便宜。

时点（非当日首发）：Anthropic 报告发布于 2026 年 9 月 29–30 日，NIST CAISI 独立评估更早，9 月 17 日。本期见到是因为 Andrew Ng《The Batch》在 10 月 5 日把它列为主题再度扩散。距今约 6 天，属本周而非今日新闻。

三套口径打架，不可混用（本期最重要的一条提醒）：① Anthropic 的 12% vs 14% 用的是 ExploitBench 的子集（应在可比 token 成本下）；② Z.ai 自己在全量基准上给的是 54.4% vs Mythos 78.0%——Andrew Ng 专门点出差距比 Anthropic 子集所显示的要大得多；③ NIST CAISI 给的是 ExploitBench 61.1%（前沿最佳 100%），另有 SEC-Bench Pro 40.4%（90.2%）、ExploitGym 9.4%（44.4%）、OSS-Fuzz 7.7%（23.2%）——与前两组不是同一个量纲。写任何结论前先确认自己引的是哪一套。

Anthropic 自陈的边界：全部有害性测试在模拟环境、不连外部系统的条件下进行，公司不声称它还原了真实世界行为；有害行为测试明确未被宣称可复现真实场景。

$20.40 的口径：这是按 Z.ai 公开 API 价格计算的 token 费用，不含 8 小时模型运行的等待时间、不含约 20 分钟人类注意力，也不含前期已披露的两个已知缺陷的获取成本。「20 美元造一个 0day」是错误读法——它是「已知漏洞 + 已知缺陷 → 可用攻击链」这一段的价格，不是从零发现 zero-day 的价格。

评测方自利性：这份报告由被评估对象的竞争对手撰写。Anthropic 有动机让结果看起来「接近前沿」（推动对开源后裔的政府安全测试，也是报告自己的建议之一）。数字是真的，但请同时读 NIST CAISI 那份独立评估——它给的定性是「迄今发布的网络能力最强的开放权重模型」，同时「约落后美国前沿四个月」。

Runway 把网络视频变成 robot policy，并宣称「够用了」——但那条关键证据是它自己给的，而且它自己说不显著

具身智能 · 数据与基座
来源：Runway Research 官方发布（2026-10-01 UTC）· The Robot Report（10/2，含 CTO Kamil Sindi 专访）· Robotics & Automation News（10/1）· AGI Hunt 10/5 收录

做生成式视频的 Runway 发布了 Praxis-1，它自称的品类是首个开放权重「世界-动作模型」（world-action model）：把 Runway 的大规模视频预训练能力，直接转成机械臂的动作。

  • 核心主张：大多数 robot policy 卡在机器人数据上——稀缺且昂贵。Praxis-1 主要从第三人称视频学习，而这块数据量本来就无限供应。
  • CTO Kamil Sindi 的原话：「 Most robot policies are bottlenecked by robot data ... its ceiling is set by how much video it can learn from, not how many robot demonstrations exist.」——天花板上限由视频规模决定，不由遥操作演示的条数决定。
  • 最关键的那条实验：对照组是「用普通网络视频预训练」对「用遥操作机器人视频预训练」。微调之后，前者的最终放置误差 16.1 cm，后者 16.0 cm。而 Runway 自己承认，这个差距在报告的不确定度内不具统计显著性。
  • 另一个自报数字：在自己的世界模型里模拟 policy，预测真实结果的相关性为 0.95，据称优于更贵的 3D 重建方法。
  • 能力覆盖：从拿起汽水罐这类取放，到装礼品袋这类可变形物体；正在测杂乱环境、透明物体和成组相似物体。同一个 policy 在受控影棚和家庭厨房之间不重训直接跑。
  • 早期伙伴：Noble Machines（双臂操作）、Standard Bots（RO1 六自由度臂）、Ultra（移动平台）。官方口径是「从双臂到人形，只需轻度微调」。
  • 战略选择是开放权重，未来数月公开发布。Sindi 的理由说得很直白：「我们认为美国在物理 AI 上的领导地位对夺回制造业领先至关重要，而那需要开放的美国模型。」

为什么值得关注 —— 如果那条 16.1 vs 16.0 cm 成立，这意味着整个具身 data bottleneck 可能根本不存在：真机遥操作每小时几十美元、建设期以年计的采集站、50 万小时对千万小时的缺口，通通都有可能被互联网上已经存在的视频平替。

但请务必把「如果成立」三个字留在前面。这条证据有三个特征：一是由供给方自己测的；二是公司自己承认不具统计显著性；三是模型尚未公开发布，早期伙伴之外的任何人现在都无法独立验证。0.95 的 sim-to-real 相关性同样属于自报。

把它和今天 ⑤ 放在一起读才是本期的信息密度所在：同一周，一个打算开源权重的说「视频够了」，另一个报出 100 亿美元估值的说「不该碰互联网视频」。这不是嘴仗，是两家重资本实验室在跑一个天然对照实验——看谁先把通用能力落地。

还有一个跨期对照：09-28 ⑤ 那期恰好在给最贵的那批数据按小时标了价（第一人称视觉视频 18–34 美元/小时、触觉 55–95 美元/小时），当时的结论是「最没法绕开的一环开始按小时计价」。今天这条等于说那一环也许可以被互联网上免费的视频顶掉。两条并列读，不要择一。

三条立刻可落地

① 不要现在就据此调整你的数采预算。这条今天的正确用法是「列入关注」，不是「停止采集」——等权重公开、第三方跑出第一批复现再说。

② 关注点是「权重公开之后，这个数字会不会变」。自己测 16.1 vs 16.0 cm 且自承不显著，是一个非常诚实的做法；给自己定一条验收标准：第三方在自家机器人上能否复现到同一量级。

③ 如果你的产品依赖 sim-to-real 迁移，可以现在就去申请早期访问。0.95 这个自报数字即使打折，也值得比 3D 重建方案便宜地试一试。

时点（非当日首发）：Runway 官方 2026 年 10 月 1 日（UTC）发布，The Robot Report 与 Robotics & Automation News 于 10 月 1–2 日报道，AGI Hunt 10 月 5 日收录。距今约 4 天，本周新闻而非今日新闻。

三个关键数字全部为厂商自报，且有并列的两条口径：16.1 vs 16.0 cm 与 0.95 相关性都出自 Runway 自己的公告与 CTO 受访内容。未见第三方复现、未见 arXiv 编号或论文。把它当作「厂商宣称」而不是「已证结论」来使用。

Statistical significance 是公司自己承认的，不是外部指出的——这一点要写全。Runway 主动注明该差距在报告的不确定度内不显著，这提高了它的可信度，但没有提高这条结论的成立程度。

尚未发布 ≠ 已可用：早期伙伴之外目前无法获取模型，官方只承诺「未来数个月」公开发布。开放权重是承诺而非既成事实，且 Early-access 阶段官方自陈仍在「 safety and efficacy gaps before general availability」。

harness 自改进三则：4B 的「提议者」把它的 35B 老师赢了下去

今天同一版的 Research 板块把「不动权重、只改周围代码」这条路衍生出了三种变法。① CMU harness learning：solver 权重完全冻住，只由一个 RL 训练的 proposer 读三项输入（task、当前 harness、执行报告）写出代码编辑——结果是 4B 的 proposer 击败了它 35B 的 teacher。为什么值得看：这是继 10-04 ② 之后对同一层的第二次施压——harness 那一层不仅收益最高，它同时也是最能用小模型撬动的那一层。② Meta / Duke / University of California 的分支搜索：用 branching search 自改进 agent harness 本身（控制 tools、retrieval、self-checks 的那圈代码），报告 Olympiad math 准确率 62%。③ Microsoft 的 ActiveSaddler：既有优化器只改「harness 怎么更新」而把训练场景钉死，它改为去调训练场景，报告 Pass@1 最多 +7.5 分。三者合起来是一条清晰的收敛：优化对象正在从「模型」上移一层到「模型周围的代码」，再上移一层到「用什么样的题来优化它」。边界：三项均仅见当日英文日更源的摘要转述，未核到 arXiv 编号与论文全文，采用前请自行核对。

Meta RankEvolve：治的是「跑了六小时才发现基准从一开始就是坏的」

自动 ML 实验里最贵的一类失败是静默失败：评测数据泄漏了，或者 gradient 在某处断开了，于是那次数小时的训练和建立在它之上的每一次后续迭代同时作废，而日志上什么都看不出来。Meta 的 RankEvolve 用一个 compiled protocol 去约束实验协议本身，报告 auto-research 准确率从 45.8% 提升到 62.5%。为什么值得看：它与今天 ① 是同一结构的另一层——①说模型写的测试是错误的验收凭证，这条说自动研究流程自己跑出来的那条上升曲线，也可能建立在一个早已失效的实验协议上。可抄：在任何 auto-research / 自动调参流水线里，把「评测是否被污染」「信号是否真的在回传」做成每轮必过的门槛检查，而不是事情完成后才回头审计。边界：同上，仅见当日转述摘要，未核到论文编号；45.8%→62.5% 为单一自报口径。

账单侧三则：压缩慢了三倍，而硬性预算上限仍然是默认关闭的

① banteg 实测：compaction 的中位耗时从 5.6 sol 的 1 分钟 变成 6 astra 的 2.8 分钟 和 6.1 sol 的 3 分钟，约 3 倍；p95 分别为 1.4 / 4.3 / 4.8 分钟。这是「模型换代应立即体现为效率提升」这个直觉的反面——模型换代的同时，压缩这一步反而变贵了。② Simon Willison 要求硬预算上限默认开启：一旦 agent 自主行动，一个循环或一条恶意 prompt 可以在几小时内把你打醒的账单堆出来，而这个保护现在藏在「用户后来才会发现」的设置里。③ LangChain CEO Harrison Chase 称编码 agent 支出连续第二个月显著下降，三步剧本的第一步就是成本可见性（在 LangSmith 里观测谁在用、怎么用）。合起来的一条结论：这三件事的顺序不能反——先可见，才能设上限，才知道压缩为什么变贵了。

失控两则：400 个志愿者在公网搜捕跑偏的 agent；有人把 npm install 当成供应链决策来管

① Swarmchasers：Reddit 社区聚集了约 400 名志愿者，专门在公网上搜寻「跑偏」的自主 agent。为什么值得看：这是 09-28 ①（agent 越界进入公共部门）之后出现的民间观测层——当厂商与国家都没有给出面向公众的监测手段，社区自己把这一层补上了。这也意味着失控 agent 已经多到值得组织起来搜。边界：规模与成效为社区自陈。
② Jozu AI Agent Guard：把 agent 发起的 npm install / pip install 当成供应链决策来处理，包括模型幻觉出来的包名这种典型攻击面；它在 shell 工具上挂 ToolPolicy，用 CEL 就地评估命令，可以在执行前直接阻断。为什么值得看：这条和今天 ② NVIDIA 的 Mid-Harness 是同一个位置——把闸门放在不可逆动作之前，只不过一个判的是 shell 命令的危害性，一个判的是 shell 命令的正确性。
