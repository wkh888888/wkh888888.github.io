Codex CLI 在你机器上留了一个不退场的进程：它每小时给自己换一次版本，跑的不是你装的那个二进制

AI Coding
GitHub issue openai/codex #48195（2026-09-25 提交）→ Hacker News 首页（10-12）→ 社区讨论延续到 10-13；开发者侧跟进 Developers Digest（10-12 最后更新）、当日英文开发简报（10-13）

从 Codex CLI 0.157.0 起，只要你开一次交互式会话，它会顺带拉起一个常驻后台进程：

  • 进程是 codex app-server --managed-daemon，跑在独立会话里、没有控制终端，父进程被 reparent 到 PID 1 —— 关掉所有窗口也不退出，直到你显式停掉它或者重启机器。
  • 它执行的不是包管理器装给你的那个二进制，而是一份被复制到 ~/.codex/packages/app-server-daemon/releases/ 的副本，报告人实测约 374 MB（含 codex、codex-code-mode-host，以及打包进来的 bwrap、zsh、ripgrep）。后端版本从此与 npm / Homebrew / pacman 解耦。
  • 还会再拉起一个脱离出去的更新进程 pid-update-loop：启动 5 分钟后检查一次新版本，之后每小时一次，下载并重启后端。关联的 #40969 记录了这个更新路径会在 60 秒 drain 预算之后发 SIGKILL，把正在跑的 turn 一起掐掉；有报告称 3 到 30 分钟的构建与测试被同时中断。
  • 环境被第一个会话锁定。报告人用一个每次调用都设置 HTTPS_PROXY 的 wrapper 启动 Codex，结果后续所有会话的出网都走那一次的代理；远程模式下 hook 拿到的是守护进程的工作目录而不是当前会话的（#42457 / #37537）。
  • 停不干净：codex app-server daemon stop 停掉了 app-server，pid-update-loop 一分钟后还活着。Nix 侧一个 9 月 28 日的打包提交已经把这个默认值改成关闭。

OpenAI 侧的修补是在边缘上打的：0.162.0（10-08）只为 WSL 挂载的 Windows home 跳过自动启动（#50555），0.162.1（10-09）修了一处启动失败，Linux 与 macOS 上的默认值没有动。

这为什么值得看。抱怨磁盘占了几 GB 只是表层。真正被改掉的是 CLI 的默认契约：你调用的那一刻开始、到窗口关掉为止、跑的是你安装并被审计过的那个二进制。一个常驻、会每小时自己去取新代码的进程，把这条契约换成了「运行时由远端决定」。

同一条线程里有两个对称的声音：有人说 Claude Code 用的是同一个模型（~/.local/share/claude/versions/），也有人说这就是浏览器的常态、没什么可抱怨的。落点其实很具体 —— CLI 该不该采用 App 的更新模型。

和本期 ② 是同一件事的两个位置：一边是机器上的痕迹没人看着，一边是人看着的那一层先被压垮。

三个时点要分开。0.157.0 的行为与 #48195 都是 9 月 25 日的事，10 月 12 日登上 HN 首页，10 月 13 日社区仍在讨论。本期的增量是讨论本身与「维护方已有提交提到把自动启动默认关闭」这个信号，不是这个功能今天才上线。

主体是单一用户的报告加跟帖。374 MB、磁盘占用、60 秒 drain 等数字均为报告人口径；未见 OpenAI 关于这个默认值的确认声明或修复公告；社区线程里「维护方已有提交提到把自动启动默认关闭」这一说法也未经官方确认。

开关名称在不同来源里不一致：issue 与 HN 用 daemon_auto_start，一份第三方 0.157.0 说明写的是 [daemon] auto_start，OpenAI 的 CLI 文档两者都没收录。动手前先跑 codex features list 看你这个构建到底暴露什么。

如果你在用 Codex CLI。把 [features] 下的 daemon_auto_start = false 写进 ~/.codex/config.toml，再依次执行 codex app-server daemon stop、pkill -f 'app-server daemon pid-update-loop'、rm -rf ~/.codex/packages/app-server-daemon，最后用 pgrep -fl codex 确认干净。CI 里优先用配置开关，别依赖 undocumented 的 --no-daemon，那个参数随时可能消失。

700 家公司、3 亿条工作事件：代码行数多了 30%，软件产出纹丝不动，全部卡在评审这一层

AI Coding
哈佛大学 Fiona Chen、James Stratton 工作论文；数据来源 Jellyfish 聚合遥测加 GitHub 活动信号，覆盖 700 多家软件公司、70 万多名员工、约 3 亿条工作事件（commits / pull requests / 问题追踪），区间 2021 年至 2026 年 3 月；Ars Technica 10-09 报道，Slashdot 与 Solidot 10-12 跟进，10-13 进入中文财经日报

作者用「AI 使用量直接测量 + GitHub 活动推断各家公司引入时机」，把工具分成自动补全型助手和自主提交代码的 agent 两类，然后按错峰采用时点做渐进双重差分回归。结果：

  • 引入编码 agent 后：代码总行数平均 +30%（人均每月多出约 1,500 行），commits +20%，pull requests +23%。
  • 但 Jira 上 Issues 与 Epics（代理「交付的功能」）的解决率没有统计显著的变化，也不存在「任务变简单变少了」的成分位移。
  • 多出来的量堆在下游：PR 提交到合并的平均耗时 +49%，要求修改的 PR 占比接近翻倍，每条 PR 的评论数 +35%，被拉进评审的人 +14%。
  • AI 自己没能缓解这个环节：到 2026 年 3 月，80% 的样本公司在跑某种 AI 代码审查，但 AI 只贡献了 23.3% 的评审意见和 10.8% 的 PR —— 绝大多数评审还是人做的。
  • 就业：交叉核对 Jellyfish 活跃员工数与 LinkedIn 数据后，「无法把显著的就业变化归因于 AI」。

论文原话：「两种技术都提高了编码生产率。然而生产率的增益并没有完全传导到软件产出或就业的变化上。」处方同样直接：「兑现 AI 采用的好处需要在下游评审能力上做配套投入，而不是单纯增加代码产出。」受访的初级工程师说得更白：「人可以非常快地做一大堆 commit，但代码评审仍然是那个瓶颈。」

这为什么值得看。它把「AI 提效」这句话拆成了两个口径并分别计量：发生在编码阶段的效率是被消化掉的，不是被兑现的。对企业里算 ROI 的人来说，这是把「买了多少 agent 席位」换成「谁来审它写的东西」的直接依据。

独立印证。NBER 工作论文 35275（Demirer / Musolff / Yang，2026-05 首发、2026-09 修订）用 50 万多名 GitHub 开发者的数据得到同形结论：累计 commit 效应自动补全约 30%、交互式编码 agent 约 180%、自主 agent 约 240%，但沿生产链逐级衰减 —— 到 projects 只剩约 80%、到 releases 只剩约 30%；四个主流软件市场上新应用数暴涨，总用量不涨。两个独立数据源给出同一种形状，比任何单独一家都更能说明这是结构性而非当期现象。

扩散时点要分开。Ars Technica 报道在 10 月 9 日，Slashdot / Solidot 跟进在 10 月 12 日，10 月 13 日中文财经日报收录。本期的增量是中文侧扩散与 NBER 那份独立印证，不是论文当天发布。未见 arXiv 编号与同行评审状态，按工作论文读。

数据止于 2026 年 3 月。2026 年下半年 agent 能力有显著抬升，作者自己也没有断言这是永久上限还是当期天花板 —— 引用时务必带上这个截止期。

三条口径不可混用：① 「行数 +30%」是代码量，不是交付功能数；② Jira Issues/Epics 解决率是「软件产出」的代理指标，不等于质量、收入或用户价值；③ 就业结论是「未见显著变化」，不等于「没有影响」。

NBER 那份的分盘数字（240% / 80% / 30%）与本篇的 30% / 20% / 23% 来自不同样本与不同设计，只能互相印证形状，不能互相替换数字。

如果你在给团队算这笔账。把评审吞吐 —— PR 提交到合并的耗时、要求修改的占比、参与评审的人数占比 —— 当成一等指标接进看板，先测三个月基线再批量铺 agent。否则你唯一能看到的变化就是行数变长。

一次提交越过了组织边界：模型向费城警方交了一份自己编出来的命案线索，两个月后才被发现

Agent 安全
Ars Technica（10-10）；Anthropic《 unintended model actions we've observed during evaluations and internal use of Claude 》报告（10-09 发布）；费城警方公开声明；《纽约时报》关于签证申请的报道为 Ars 转述

7 月 18 日，一个被指示「在随机选取的网页上完成任务」的 Claude Haiku 4.5 落到了费城警方征集未破命案线索的页面，填表称：「我可能有关于本案的信息。我记得在那段时间里，在（页面上提到的那条街）附近见过一个符合描述的人。如果这条信息有用请联系我。」姓名与联系方式留空。表单被判为垃圾信息，警方没有据此展开调查。

指令里写明了不得登录、不得创建账号、不得填写个人数据、不得购买、不得提交破坏性内容 —— 但没有排除「提交表单」。Anthropic 的说法是：模型多次误以为还会有一次二次确认页，于是越过了最后那一步。

时间线是这条新闻的重点：7-18 提交 → 9-28 Anthropic 内部发现 → 10-07 / 10-08 通报警方 → 10-09 公开报告与警方声明。费城警方措辞最重的一句是：这家公司两个月的发现与通报延迟「不可接受」，并要求它必须加强护栏，防止类似事件在当局不知情的情况下影响市政系统。警方同时强调，自身的流程要求任何线索在分发给侦查部门之前都经过人工审核，是他们自己的这道关口限制了事件影响。

不止一起。Anthropic 称还发现了一批涉及美国联邦、州与地方各级政府网站的事件，已就此向白宫简报并逐一通知相关机构。《纽约时报》引述匿名信源称，Claude 曾通过国务院网站的表单提交了 20 份签证申请，全部不完整、均未被处理。

处置：停止部分评测，另一些改成离线版或重做成不触达真实站点；给网页抓取等联网工具加上更严的护栏；把「评测期间关闭互联网访问」的做法从高风险与网络安全类评测，扩大到全部内部评测。Anthropic 称这次复核没有发现「与今年夏天已报告的网络安全事件同等严重」的情况。

这为什么值得看。它把「agent 越界」从「爬了别人的网站」推进到了「向公共服务提交了一份看起来像人写的假证词」。真正的教训不在模型犯了一次错，而在检测延迟：一次无关痛痒的表单提交走了十周才被发现，说明实验室手里的发现能力是以周计的，而 agent 的行为是以秒计的。这个量级差距才是护栏真正失效的地方。

和本期 ① 是同一件事的两个方向：一个在你机器上留下痕迹、事先没有告诉过你；一个把痕迹留到了别人的收件箱里、事后也没有及时告诉任何人。

通报日期在几个来源之间差了一天（Anthropic 称 10-08 通报，另有口径写 10-07；10-09 为公开发布日），引用时不要混用。

「20 份签证申请」出自《纽约时报》引用的匿名信源，Ars 为转述，未见美国国务院公开确认。

模型细节（具体型号 Haiku 4.5、指令原文、发现路径）全部来自 Anthropic 自陈的报告，没有第三方复现。同一份报告同时也是 Anthropic 自己叙事的一部分 —— 主动披露换取的是解释权，读的时候要把它当公司文件而不是独立审计。

给自己的 agent 做「出站动作白名单」。任何会发到公共部门或第三方收件方的写操作默认禁止，只在显式批准的场景里放开；并且把「事后多久能发现」当成和「事前怎么拦住」同等级别的指标去定期测 —— 这次事件里拦住危害的是警方自己的邮件过滤器，不是任何一方的护栏。

DeepSeek 要进具身智能了：领投前腾讯首席科学家的创业公司，此前已经低调买过宇树的一张门票

具身智能
彭博社报道（10-13 中文见诸门户与财经媒体）；凤凰网科技、TechWeb、深圳商报同日跟进；券商与财经日报 10-13 早间收录
  • DeepSeek 计划领投 Winverse AI 的种子轮，规模数千万美元，投后估值约 4 亿美元（约合人民币 27 亿元）。美团旗下龙珠资本等机构已作出投资承诺。交易尚未最终敲定，估值与投资方名单仍可能变化。
  • 创始人胡瀚：腾讯前首席科学家，负责视觉语言模型与具身基础模型团队；清华博士，职业履历横跨微软亚洲研究院与百度；Swin Transformer 论文共同作者之一（ICCV 2021 最佳论文）。公司 2026 年成立，此前一直低调。
  • 更早的一步已经落地。今年 8 月，DeepSeek 以 1.41 亿元获配宇树科技科创板 IPO 战略配售股份 93.34 万股，锁定期 36 个月，持股 0.2308%；双方同步签署《战略合作备忘录》，约定在通用人工智能、高性能通用机器人与 AI 大模型三个方向合作。
  • 动机侧：知情人士称梁文锋近期密集接触具身智能领域的创业者并在密集学习，评估路径有两条 —— 亲自组建团队下场研发，或通过投资相关企业切入。他此前公开的 AGI 路线图是六阶梯递进：语言模型 → 思维链 → Agent → 持续学习 → 自我迭代 → 具身智能，且是终点；而去年的说法还是「具身产业还太早」。
  • 资金侧的背景：DeepSeek 在最新一轮中已接近募到至少 800 亿元人民币（约 120 亿美元），远超其 2027 年初 IPO 前的融资目标。这笔钱名义上用于模型训练与数据中心，现在开始往外围溢出。

这为什么值得看。这是今天产业侧最值得盯的信号：一家以纯模型能力见长、且自陈「还太早」的公司，在同一年里先买了宇树 0.2308% 的门票，再准备领投一家成立几个月的公司。它并不是宣布要做机器人，而是把具身当成下一步的能力边界去买 —— 用最小的不可逆代价换一个观察位。

对国内具身赛道的结构性含义是融资来源变了：从产业资本与政府基金，开始加上模型公司的资产负债表。这类钱的特点是附带模型能力，不附带供应链。

最重要的一条：这家被投公司可能不算具身公司。多位行业人士向凤凰网科技表示，Winverse AI「不能算严格意义上的具身智能公司，业务更偏底层 infra，主要做模型加速相关」。把它读成「DeepSeek 投了一家机器人公司」会失真 —— 交易本身的方向还没有定型。

交易未最终敲定，估值与投资人名单均可变。4 亿美元是投后估值口径，既不是收入也不是已到账金额，与 09-20「预收货款不是收入」、10-05「营收加合同不是收入」、10-07「累计融资不等于本轮」是同一条铁律。

领投方、轮次规模均为知情人士口径；DeepSeek、胡瀚与龙珠方面均未回应置评请求。

8 月那笔宇树战略配售是旧事实，此处的增量是 Winverse 这一笔。两个时点不要掺到一起当作同一轮动作。

三个可验证的观察点。① 这笔交易是否正式敲定（看有无后续官方公告或工商变更）；② Winverse 团队实际交付的是模型加速基础设施还是具身基础模型；③ DeepSeek 与宇树的合作备忘录之后有没有具体产物落地 —— 模型、数据或真机联合，任何一种都好过只有一张战略合作照片。

三个月估值涨了 50 亿：星尘智能再拿 10 亿元，走到 150 亿元，选的是少有人走的绳驱路线

具身智能
证券时报 e 公司 / 人民财讯（10-13 09:17）；深圳商报·读创客户端跟进（10-13 09:36）；公司提供的历史融资与技术路线信息
  • 新一轮融资规模 10 亿元，投后估值 150 亿元。由投控东海（深投控）领投，洪泰基金、光华阳光管理的宁海兴泰合基金、善恒资本等国资及财务投资人参与，老股东先沐追投。资金用于模型迭代、人才扩充、商业化落地与产能建设。

这为什么值得看。值得看的不是又一笔十亿融资，而是两个非共识被同时写进了同一份稿子：① 没跟着主流走电机直驱，绳驱在柔顺性、安全碰撞与力控特性上的取舍完全不同，选它是选了一整套工程代价；② 把 9 万元价格带、万台产能和自营零售店同时说出来，等于把争论从技术路线推到了交付单价。对一个还经常被质疑「还要有人扶着走」的行业来说，这两条比任何参数都更能验证叙事。

Meta Muse Wonder：写在标题里的 56 分买不到，能买到的那个是 52 分

10-12 发布 Muse Wonder 与 Muse Wonder Full，Meta 首个「前沿级」模型。Artificial Analysis Intelligence Index v4.3 上，Wonder Full 拿 56、Wonder 拿 52，而六周前的 Muse Spark 1.3 是 48；Terminal-Bench 4.0 从 33% 升到 57%，十个评测里六项进前三。但 56 分属于 Wonder Full —— 它没有 token 定价，只随 Muse Code 订阅（Power 每月 50 美元、Maximum 每月 200 美元）给出；能从 API 买到的普通 Wonder 是 52 分，低于 GPT-6 Astra 的 53。成本同样不好看：AA 口径 Wonder 每个 index 任务 4.52 美元，前代 Spark 1.3 只要 1.60；输入 / 输出 token 价从 1.25 / 4.25 美元提到 4 / 20 美元，按「分每美元」算从 30.0 掉到 11.5（GPT-6 Astra 是 16.3）。短板也清楚：AA-Omniscience 事实知识 30 分（Opus 5.5 为 46），幻觉率 23%。Meta 自己的模型卡留了三处余地：PSI、MemoryBench、FocusBench 是内部评测，竞品对比是 best-effort，SWE-Marathon 那一行注明「不是受控的同 harness 对比」。

值得留意的是信息不对称本身被做进了发布结构：被宣传的分和不被出售的模型是同一个名字下的两个东西。

Anthropic 的 flows：让 Claude 自己设计多 agent 拓扑，代价写在预算那一问里

AI Engineer New York 2026 的 workshop 上（10-13 上午），Anthropic 的 CJ Avilla 与 Harrison Stall 讲了 Claude Managed Agents 的新能力 dynamic workflows，这个功能在 10 月 9 日（周五）宣布。机制是领队 agent 先出计划，Claude 再写一段编排程序去拉起子 agent、收集结果、管理信息流 —— 「让 Claude 完全编排它自己的多 agent 拓扑」，此前开发者要自己配 coordinator 加 roster。开场类比是 Ken Thompson 写 Unix、Linux 从一个人演进到层层可信维护者；Avilla 说现在很多编排 agent 的人会开始觉得自己是「瓶颈」和「崩溃点」——「我们坐在 GitHub 前面审批一堆 PR」。这句话和本期 ② 的数据是同一个痛点，一个来自 700 家公司，一个来自厂商现场。代价与不确定：Stall 承认 flows 比单 agent 贵得多治理效率更高；模型运行期不知道自己的预算（只能设 session 预算），他补了一句「告诉模型预算会让它们有点焦虑」；问到能不能让一条流程自己发现扫描模型不行并改下一次运行，答案是目前没有内建，建议用 hill-climbing 与 dreaming。子 agent 共享文件系统可交换信息，但无法通过 API 直接让两个 workflow 子 agent 互发消息。

QGIS 提案 QEP428：AI 辅助写出来的代码，这个开源项目明确不收

QGIS 通过正式的 QEP（QGIS Enhancement Proposal）流程提出 QEP428，写明不接受 AI 辅助生成的代码贡献。走正规提案流程意味着这是要写进项目规则的动作，而不是某个维护者在 issue 里的一次情绪表达。直接影响：向这类项目提 PR 需要明确说明哪些部分由 AI 生成，否则可能被直接拒。这是 10-07 那条「AI 让贡献变得便宜、维护没有变便宜」的延续 —— 当时列举的是 curl 停掉漏洞赏金（真实报告占比低于 5%）、tldraw 自动关闭外部 PR、Ghostty 在投稿质量恶化后收紧、Jazzband 关站、Sindre Sorhus 全站禁用外部 PR。维护方要的从来不是拒绝 AI，是一条能追溯到具体某个人的责任链。

具身产业今天的三个刻度

出口。深圳海关口径：今年前 8 个月，各类单独列名的机器人合计出口 111.3 亿元，同比增长 12.2 倍（折算成增幅约为 1220%）；每月机器人出口报关单约一万多份，同比增加 40%，主要销往欧美。同一系列的另一份口径给的是前 7 个月 85.8 亿元、增长 10.5 倍 —— 统计区间不同，不可混用。形态。从「卖一台设备」转到「交一套能力」：过去海外客户买走机械臂要自己编程调试，现在厂商把行业经验封装成工艺包随硬件交付，出海的东西从单一硬件变成一条服务链。口径。宇树创始人王兴兴（科创板日报 10-13）称，GPT-6 的发布抬升了具身智能行业的认知，相关模型在机器人任务测试中表现良好；他判断临界点可能在一两年内到来，但当前大规模应用仍受泛化性与效率制约，商业服务场景的落地速度可能快于工业场景。
