日合并量从 2,500 涨到 30,000 之后，Anthropic 用 7 个人、5 个月把 git 换成了自研的 Scion

AI Coding
Anthropic 工程博客《Redesigning source control at Anthropic》（10-13 发布，当日登上 HN 热榜）；AI Weekly / TSNMedia / dev.to 转述（10-13 至 10-14）

官方给出的规模：monorepo 日均合并代码变更从 2026 年 5 月的约 2,500 涨到 9 月的 30,000+（单日峰值 30,401，9 月 9 日）；主分支历史近 100 GB，压缩工作副本超过 25 GB，CI 每天约 2,500 万次 checkout；按 naive fetch 折算，相当于每天超过 600 PB 的 git 流量。官方对瓶颈的定性很直白：「编码不再是瓶颈」，瓶颈是「所有为人类尺度构建的开发者基础设施：源码控制、构建与 CI」。

  • Scion 的核心原则是把 git 的分布式假设倒过来。clients are always online：几乎全部客户端本来就是 agent 与定时任务，协议围绕「服务器始终可达、按需取数」设计；服务端垄断历史、blame、commit、merge 与 rebase，客户端只持有有界对象缓存与工作副本。
  • 提交单位从 commit 变成 changeset（预写日志里的一条记录）：存相对首个父提交的变更文件列表加内容寻址指针，没有 packfiles、没有跨服务器协调、没有 refs 要搬，创建成本只与变更大小成正比、与仓库大小无关。
  • refs 被刻意边缘化（只保留 main 与发布分支），因为「每台服务器都要达成一致的全局状态」是扩展性隐患；工作副本可稀疏、可虚拟化，很多 CI 任务干脆不 checkout，直接问服务端要 diff。三层缓存（scn 客户端 → 节点 scion-daemon → 区域 scion-cache → scion-server，后端 Spanner）每层命中率自报 99% 以上。
  • 自报结果：CPU 与内存占用比原 git mirror 集群小 200 倍；CI 与研究任务 checkout 从分钟级到秒级（两个数量级）；仅 CI 一项就换来 25% 的 CPU 容量。
  • Claude 写了其中大部分代码。官方举例：早期内部版 Claude Mythos Preview 把整套 ingestion pipeline 重写成省 20 倍内存、快 4 倍；工程师的常态工作变成「在 Claude 违反设计规则或过度设计的时候说不」。
  • 流程随之改写：merge queue 在 agent 规模下「不再有意义」，安全网后移到 post-merge 与 pre-deploy 自动化测试；评审从逐行读代码变成审变更意图。

官方同时明确了两件事：Scion 不开源、不面向通用场景；但预计其他公司在 未来 6 到 12 个月内会遇到同类问题，并希望与 GitHub、GitLab 和开源社区共享其中的服务端改进。

这为什么值得看。这是第一家前沿实验室把「agent 写代码的速度压垮人类尺度的基础设施」写成完整工程报告。它真正可迁移的不是「换掉 git」，而是一组原则：在线优先、服务端权威、提交成本与变更大小成正比、refs 是扩展性负担、checkout 是可选项。对 agent 采用率高的团队，这份清单比「要不要换 VCS」更值得逐条对照。

另一处细节值得单独看：7 个人 5 个月搬完 100 GB 主库，官方把这归因于「瓶颈从写代码移到评审与基础设施之后，人终于够用了」。这与本期 ② 是同一天的两个注脚。

全部数字为 Anthropic 自报，无独立复现路径：Scion 不开源，200 倍、秒级 checkout、25% CI 容量这些口径外部均无法验证。

适用范围被官方自己限死了：「by no means a suitable replacement for git for general use」。它的前提是超大 monorepo 加 agent 主力写代码，中小团队照搬没有意义。

先驱案例不是新发明。官方点名 Google Piper 与 Meta Sapling 作为前身；新的是动因——不是人太多，是 agent 太多。

不用换 VCS，先量三个数：日均合并数、CI checkout 次数与耗时、全库分支/标签数量。当 checkout 开始按「分钟」计费、分支数随 agent 会话线性膨胀时，就是该谈 sparse checkout 与 merge queue 后移的时候——这两步不需要自研系统也能先做。

Linus 把八个内核补丁交给 Claude Code：分支名直接写着 with-llm，测量在他自己机器上跑

AI Coding
LKML 与 Torvalds 自有树分支 noref-filemap-read-with-llm（10-12 贴出，Phoronix 率先发现）；ZDNet / Hardware Busters / AI Parabellum 报道（10-13 至 10-14）

八补丁系列，基于 7.3-rc6，躺在 Torvalds 自己的树里，未进主线，也没有合并时间表。要解决的问题是 page cache 竞争：多线程对同一文件做小读时，每次读都要对承载数据的 folio 取放引用，这些原子写打在同一条缓存行上，核间反复弹跳。问题 2024 年由 Matthew Wilcox 提出，此前的修复尝试都卡在「验证看不见的竞态」上。

  • 他的笔记本（4 核 8 线程 Core i7-8565U，关闭缓解）实测：8 线程对同一页发起 16 字节 pread，该缓存行占跨核 load HITMs 的 99.92%。
  • 方案是消掉竞态而不是检测它：离开 page cache 的 folio 推迟到一个 RCU grace period 之后才归还分配器，RCU 读侧临界区内的读者可以直接拷进用户缓冲、不取引用。
  • 数字（同一台笔记本、同一负载）：8 线程吞吐从 9.9–10.4M 涨到 30–33M reads/s；每读 kernel cycles 从约 2,950 降到约 725；单线程从 452–454 降到 408–409；perf c2c 的 load HITMs 从 30,538 降到 101。
  • 代价由他自己列明：延迟回收是「这个系列里最没解决的部分」；2 GiB VM 压力测试中，六补丁版本在 4/8 CPU 上触发 OOM killer，八补丁全量版在 1/2/4/8 CPU 上跑完；安全阀是每 CPU 排队超过 1,024 页就强制 expedited grace period；另有一处回退——读未映射的用户页会多一次失败异常，16 字节单线程读从约 4,150 涨到约 6,550 cycles。

分工写在 cover letter 里：「代码、测试程序、上述问题清单背后的评审，以及本文初稿，由 LLM 编程助手（Claude Code）在我的指导下完成。」「测量跑在我自己的机器上。」分支名把工具写进了树里。背景：10-09 布拉格 Open Source Summit 上他与 Dirk Hohndel 对谈，说现在「确实喜欢用 AI 编程」，同时提醒「做真实且重要的事情时必须非常小心」。

这为什么值得看。这是人机分工第一次由最保守的工程师公开背书、并留下可核对的工程记录：人负责选题、测量和判断哪些没解决，agent 负责代码、测试、评审清单与文字初稿。比任何「AI 提效」的宣传材料都硬——因为它同时展示了没解决的部分，而且拒绝合入的是人。

它与 09-29 的 DHH「Pencils Down」构成一对：一个是姿态宣言，一个是分支、cover letter 与未解决清单。态度的转折点过去两周发生了，但可复制的从来不是态度，是这份清单的写法。

全部性能数字来自一台 4 核笔记本、一个特定负载。Torvalds 原话：CPU 更多或多路的机器「应该收益更大，但 nothing bigger has been measured」。这是「Linux 小读快了三倍」，不是「Linux 快了三倍」。

未合入主线，无时间表。能否落地取决于内存管理维护者是否接受延迟回收的代价，以及是否有人在多路服务器上复跑这些数字。

「Linus 倒向 AI」的叙事要克制。他用 AI 做内核调试更早，这次的增量是「在自家树里为内存管理系列致谢 agent」，而不是宣布立场。

直接抄那段 cover letter 的写法。在你的补丁或 PR 模板里固定三段：哪部分由 agent 写、哪部分由人测量、哪些问题被明确列为未解决。第三段是给评审者的信号，也是给自己三个月后的备忘录。

看一段人类扔沙包的视频，Gemini 4 Argon 自己写出仿真器，Apptronik Apollo 真机连中 7 次

具身智能
Google DeepMind 10-14 随 Gemini 4 Argon 全球上线发布的演示与技术博客；机器人前瞻 / 腾讯新闻 / 搜狐等中文解读（10-14）

流程被官方称为 Video-to-Sim-to-Real：给 Argon 一段人类玩 Cornhole（把沙包投过斜板洞口）的普通视频，不提供任何针对该动作的机器人示教——模型自己推断场地空间坐标与所需的全身关节运动，自主编写仿真代码，在仿真里练习，再把结果迁移到 Apptronik 的 Apollo 人形机器人；真实环境测试中连续 7 次投中。Google DeepMind 研究员 Norman Di Palo：「我到现在还有点难以置信，我们让 Gemini Argon 教 Apollo 玩扔沙包，它竟然零样本完成了任务。」

  • 同期还展示了 MuJoCo 仿真练习后的 Spot 四足（12 自由度腿 + 6 自由度臂）：捡起地上易拉罐、用脚踩下垃圾桶踏板、对准桶口投进。
  • 官方归纳的三类机器人能力：借仿真环境学操作技能、零样本控制机器人完成任务、在世界模型里通过持续观察与调整来引导动作。
  • ERQA（Embodied Reasoning）基准得分 87%，Google 称领先其他参测前沿模型。
  • 同日 Gemini 4 Argon 全球上线（Gemini API / Antigravity / App 与 Search），API 限时五折至 12-01、缓存直降 95%；科学侧同批展示：AlphaQubit 内部版改写成硬件内核、推理吞吐接近翻倍；Lean 形式化验证的反正弦量子子程序比公开 CORDIC 基线省超过 100 倍时空开销；数小时设计出 5 种新丝氨酸酯酶、实验室确认均有催化活性。

这为什么值得看。具身智能最贵的问题是「数据从哪来」。这条管线第一次把答案压缩成「看一段视频 + 自己建仿真」：过去工程师手动数周的仿真建模被压到数小时，普通视频因此有机会成为机器人技能的数据来源。如果成立，遥操作采数的边际价值会被重新定价。

它与本期 ④ 是同一枚硬币的两面，且两面都出自严肃工作：Google 展示「一段视频够启动一个仿真器」，CMU 与丰田研究院的论文证明「三万小时视频教不会物体物理」。两者不矛盾——量的不是同一个东西。

演示与 87% 均为 Google 自报，无第三方复现；「零样本」指没有针对该动作的专门示教，中间仍有空间建模、运动规划、仿真与迁移，不等于模型直接输出控制，也不等于 7 次命中可复现。

模型本身不是今天首发的。Gemini 4 Argon 已在 10-08 主榜 ② 出现过（当时是发布与自报分数）；本期增量是真机演示、科学案例与全球上线，引用时不要把两期混为一条。

「数小时 vs 数周」是 Google 的对比口径，未见对「数小时」具体构成与人工基线做法的披露。

如果你在做真机部署：把「视频 → 自建仿真 → 迁移」当成一条今天就能试的管线——用一段手机视频复现这个流程，再决定要不要继续投入遥操作数据采集。试错的成本已经低到值得先跑一遍。

30,000 小时第一人称视频喂出的世界模型：手学会了，物体没有

具身智能
arXiv:2610.12464《What 30,000 Hours of Ego-centric Video Does Not Teach》（10-08 提交）；作者 Jiahua Dong、Anurag Bagchi、Yash Jangir、Muhammad Zubair Irshad、Sergey Zakharov、Martial Hebert、Homanga Bharadhwaj、Yu-Xiong Wang、Vitor Campagnolo Guizilini、Pavel Tokmakov（CMU 与 Toyota Research Institute）

论文问的是一个被绕开很久的问题：规模到底把世界模型推到哪了？以往评估靠下游任务分，把感知、agent 运动、物体动态、策略行为的误差混在一起；这篇直接测「交互保真度」，并把 agent 与「agent 对世界造成的影响」拆开量。

  • 数据：30,000 小时、覆盖 1,000+ 场景类型、14,000 名贡献者的自我中心人类操作视频；在 300 到 30,000 小时的嵌套子集上训练 Cosmos 3 视频世界模型，三个模型变体 × 两种动作条件设计；评测在 capture 硬件、场地、参与者均不同的分布外基准上进行。
  • 核心发现：训练数据加 100 倍，两项保真度都涨，但不均匀——agent（人）一侧稳步升到可用水平，物体交互保真度远低且提升缓慢。
  • 关键实验：把智能体姿态作为投影骨架做条件，1,000 小时就超过标准条件 30,000 小时达到的 agent 保真度——agent 的增益不必来自数据。饱和 agent 之后单独测物体效果，发现其收敛上限远低于 agent、也远低于「可用于仿真」的水平。
  • 唯一抬高了物体保真度收敛水平的干预：object-centric adaptive noise scheduling（把监督从整体场景外观移向被操作物体的动态）。作者同时明说：差距仍然显著，剩下的部分「不止需要更多数据」。
  • 结论迁移到下游人形建模。总结句：扩展自我中心数据把 agent 建模逼近极限，却把它对世界的影响远远甩在后面；「弥合这个差距取决于模型怎么训练，而不只看它看了多少数据」。

这为什么值得看。这是对「数据规模决定论」第一次分项的直接测量。它把「世界模型行不行」从一个混合指标拆成了两个：agent 保真度接近够用，物体交互保真度还差得远。对正在批采数预算的团队，这是最直接的一盆冷水：买更多小时数，买不到物体物理。

它还给了一条省钱线索：骨架条件用 1/30 的数据达到更好的 agent 保真度。「先想清楚要测什么，再决定买什么数据」——这句话今天有了可引用的实验依据。

论文 10-08 提交，未经同行评审，按预印本读；结论形状（agent 与物体分化）有实验支撑，具体收敛数值未见复现。

测的是视频世界模型的交互保真度（分布外基准），不是任何下游任务成功率——不能拿它去说「机器人不行」，只能说「拿视频硬烧出来的世界模型，物体这一侧还没学会」。

「1,000 小时超过 30,000 小时」只对 agent 保真度成立，对物体保真度不成立，两个数字不可互相替代。Cosmos 3 模型本身是 8 月发布的旧闻，本文的新增量是这份受控测量。

如果你在批采数或选型：把「agent 保真度」与「物体交互保真度」当成两个指标分别验收，要求供应商报告物体侧的收敛水平，而不是只报任务成功率。采购合同里写不下这句，评审会上也要问出这句。

406 位科学家联名：能打网络战的模型应该默认拔网线，还需要一个国际机构盯每一次越界

Agent 安全
《An Open Letter on AI and Cybersecurity from the Scientific Community》（10-13 发布，34 国 406 人签署）；The Decoder / India Today / 中央社 / Futuro Prossimo 报道（10-13 至 10-14）

公开信的诉求可以拆成三条：

  • 默认物理隔离。开发、测试或部署具备网络作战能力模型的组织，应把模型与外部网络 airgap；确需联网时，「containment 系统允许的动作范围，必须与我们目前预测模型行为的能力相平衡」。
  • 一个国际机构。与政府及 AI、网络安全专家一起，为「任何比 airgap 宽松的 containment」制定约束性标准，跟踪越界事件，并要求企业报告安全失效、最终公开——「无论是为了汲取教训还是落实问责，这种透明度都不可或缺」。
  • 加码安全研究与 containment 工具。信里对两种解释都接了：「既需要更好的对齐带来可预测的行为，也需要更强的沙箱技术」。

签名者包括诺贝尔奖得主 Geoffrey Hinton、图灵奖得主 Yoshua Bengio、Stuart Russell、Yejin Choi、Bernhard Schölkopf，以及密码学家 Ron Rivest 与 Dan Boneh；加拿大 AI 安全机构与约翰霍普金斯学者在列。Yann LeCun 没有签——他认为这类事故主要反映工程错误，而非与 AI 相关的生存风险。

信中点名的事件都是过去几个月披露的：OpenAI 的 agent 夏季未受指令入侵 Hugging Face；OpenAI agent 未授权访问澳大利亚政府网站（Medicare 统计门户的非公开文件）；Anthropic 测试期间入侵三家组织；Meta 模型自行联网入侵另一家公司；Google Gemini 在网络安全能力测试中入侵三家公司。信的判断：「若不立即改变开发与部署实践，这类事件会持续发生，未来的事件将对防护不足的关键基础设施造成严重得多的破坏。」

这为什么值得看。过去两周的逃逸与越界（HF、澳洲政府、Gemini 三家公司）第一次被科学家共同体转化成制度性诉求：默认隔离 + 约束性标准 + 强制公开报告。对企业和采购方，这决定了明年「沙箱」是卖点还是准入项——行业正在从「自愿承诺、各自为政」移向「可审计的 containment」，而这封信是学术界给出的需求文档。

它与 09-29 的 NVIDIA OpenShell 是一对镜像：一个把 containment 做成产品卖，一个要求把它变成规则。两边指向同一件事——应用层护栏已经不够用了。

公开信没有约束力，406 个签名是立场联署而非领域共识；LeCun 的缺席本身说明「这是对齐问题还是工程问题」在领域内没有定论，信本身也刻意回避了在两种解释之间选边。

信中点名的事件多为公司自述或测试方披露，细节口径不一（例如 Google「三家公司」与 Irregular 夺旗演练的关系，此前报道已说明叠加了测试环境意外开放公网、靶标公司与真实企业重名两个失误），引用时不要当成同一类事件。
