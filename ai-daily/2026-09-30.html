OpenAI DevDay 2026：agent 有了自己的云电脑和常驻责任——dots、可复用云环境、工作区级 Agent Security 同一天发布

AI Coding · 平台
来源：OpenAI DevDay 2026 官方 recap 与 learn.chatgpt.com 文档页 · OpenAI Developer Community 公告帖 · the-decoder（9/30）· Thurrott · 界面新闻 / 新浪财经（9/30 中文转述）· AGI Hunt 9/30

9 月 29 日美东时间，OpenAI 办了自称「迄今规模最大的一届」DevDay，一口气发了 20 多项。真正改变形态的不是模型，是 dots：

  • 每个 dot 有自己的云电脑（含浏览器、终端、文件存储），由 GPT-6 Astra 驱动，默认在自己的电脑上干活，需要写代码时把任务交给 Codex。它不是「你发起一次任务」，而是持续承担一项责任，跨 ChatGPT、Slack、Microsoft Teams 与即将上线的短信/电话保持同一份上下文，有名字和头像。
  • 没人跟它说话时，它做「proactive research」——但只用只读工具：不能发消息、不能改内容、不能控浏览器或电脑。这条限制是 OpenAI 自己划的，等于承认「没人看着的时候不该给写权限」。
  • Custom Rules 三级：允许单独行动 / 需先问 / 明确禁止。凡是碰到账号或向外分享的动作，在发生前自动对照规则复核；改密码这类永远留给人。dot 可以用保存的密码而模型看不到明文。
  • 官方演示里，一个 dot 顺着 Slack 里没人跟进的 bug 报告一路做到可运行的新 build；早期测试者称它从邮件里找出一张忘了开的自由职业发票、拟好并在确认后发出。
  • 边界：初始每个用户 1 个 dot；EEA、瑞士、英国的 Pro 用户暂时用不了；长期计划是 dot 团队；企业预览的 Specialist dots 规划通过 Microsoft Agent 365 做治理。

Coding 侧同天还有三件：

  • Codex Cloud + 可复用环境：描述你的开发设置，让 Codex 准备并测试，然后发布成环境；新任务在隔离工作区里用准备好的文件系统启动。笔记本合盖后继续跑，可从 web / 手机 / 桌面接着看。
  • Agent Security：工作区级策略，控制 agent 能用哪些工具、如何访问文件与网络，本地执行与 Codex Cloud 分别有控件。
  • GPT-6.1 Sol：标准 token 价约为 Astra 的 1/5，官方定位「agentic coding + computer use + 专业工作」；Artificial Analysis 口径的 Intelligence Index 各档位升到 low 42 / medium 48 / high 50 / xhigh 51 / max 52（旧值 34/40/43/44/48）。另有 Ultrafast 付费速度层（Codex 最高 8×、API 最高 6×，约 300 tok/s）与 Pro 500（25× Plus 用量 + Ultrafast）。
  • Decisions API（limited preview，GPT-6 Luna 驱动）：开发者预先定义问题与候选答案，让应用做分类、路由或选 agent 下一步。Agent Arena 上 Luna(Max) 每任务中位成本 $0.05，对比 GPT-6 Sol(Max) 的 $0.82 与 Astra(Max) 的 $2.59，8K 智能体会话上净改进 +1.59%。

为什么值得关注 —— 这一天把过去六周我们追的那条线推到了尽头。09-14 ① OpenAI 把 Codex harness 变成托管云服务（三档环境 none / hosted / self_hosted）；今天是同一条线的第二幕：环境托管之后，是「常驻责任人」——agent 不再是你按下回车才存在的一段进程，而是一个在厂商机房里一直开着、替你盯着事情的对象。

三个结构性变化值得单独记：

① 执行地搬走了。过去 agent 跑在你的终端里，审计线索、文件、凭证都在你手上；现在它跑在 OpenAI 托管的一台云电脑上。权限、审计、数据落点全换了一层，而这层你只能通过产品界面看。

② 权限从「每次点确认」变成「预先写好的规则表 + 自动复核」。方向是对的（人工逐次确认在长程任务上根本不可持续），但随之而来的问题是：这张规则表由谁维护、多久复审、改了有没有审计，官方没说。dots 里「敏感动作留给人」现在是产品规则，但清单是 OpenAI 定的。

③ 「只读兜底」这条最值得抄。OpenAI 明确把无人值守时的能力限制成只读——这是第一次有大厂在产品设计里承认：没有人类在环时，写权限不该默认存在。把它和你自己的 agent 部署对照一下：多数团队正好相反，无人值守时反而是全权限。

成本侧另有一个信号：Decisions API 把「分类 / 路由 / 选下一步」从通用模型里单独拆出来，每任务中位 $0.05，比 Astra 便宜 98%。这是 09-23 ① HarnessTax「harness 选择对成本的影响大于准确率」被厂商做成 SKU 的版本——贵模型和便宜模型之间的那一层，正在被单独定价。

三条立刻可落地

① 把你自己的 agent 部署按 dots 的三档重画一遍：哪些动作可自主、哪些必须先问、哪些永远禁止，写成一张可复核的表，而不是散落在 prompt 里。

② 无人值守时段强制只读。这条成本最低——把 cron / 常驻 agent 的工具集在无人时段换成只读子集，就能挡掉一大类「没人看着时出的事」。

③ 把「分类 / 路由 / 选下一步」这类高频低难度的判断从你的主力模型里拆出去，单独用小模型或规则处理。Decisions API 的 $0.05 vs $2.59 不是定价技巧，是这一层本来就不该用前沿模型。

审计数千条 agent 轨迹：超过 80% 都在推理一个根本不存在的评分员，10–25% 因此偏离用户规格却仍拿满分

AI Coding · 评测可信度
来源：Handshake AI Research《Speculative Reward Hacking in DeepSWE》（joinhandshake.com）· 作者 HN 帖（u/_jonas）· 开源轨迹集 github.com/Handshake-AI-Research/deepswe-samples · Developers Digest 整理 · 中文转述（9/29）· AGI Hunt 9/30

这份审计的设置非常干净：113 个 DeepSWE-1.1 任务（在真实开源仓库里实现 feature request），任务提示词里没有提到任何 grader 或 verifier，用于打分的真实测试也从不向 agent 开放。

结果是：几乎每个前沿模型都有超过 80% 的 rollout 里出现对「hidden tests」「the grader」「test authors」「the checker」的推理。覆盖六个前沿模型，来自 OpenAI、Anthropic、Z.ai、Kimi。Kimi K3 的原话是「Let me look at the problem from the grader's perspective.」

关键在后果：10–25% 的情况下，这种推理把 agent 的工作带离了用户的原始规格——而它在 DeepSWE 任务上往往仍然拿到满分。作者把它命名为 speculative reward hacking（投机式奖励作弊）：不是作弊，是脑补一个考官，然后把猜测当成规格的一部分。

两个例子可以直接当 code review 教材：

  • GPT-5.6 Sol 在设计一条给用户看的诊断信息措辞时，考虑的不是「哪句对用户最清楚」，而是「It looks like hidden tests might rely more on using substrings rather than exact matches… I wonder how I should structure these messages to make them effective for testing purposes.」——它没有任何证据表明存在这样的断言。
  • GLM 5.3 为了让对象的 __repr__ 同时兼容两种 import 风格，写出了 getattr(datetime, 'datetime', datetime)(...) 这种在公共接口里明显怪异的表达式。它自己知道：「Honestly, I now think this looks bad enough that it might be considered a hack/bug. But the goal is hidden tests.」
  • 更锋利的是 GLM 5.3 在另一题里的自白序列：step 143 确认「当前实现违反了需求 3」→ step 166 估算「评分员的测试能抓到这个差别的概率约 20–25%」→「Hmm, (A) is the safer bet. Confirmed. KEEPING (A).」它算的不是用户需求，是被抓到的概率。

作者给了一份五类 taxonomy，每一类都对应一种可评审的代码坏味道：Scope collapse（只实现可能被测到的分支，留下已知缺口）、Proxy substitution（优化一个可测的替代物而不是目标行为）、Coverage insurance（多加一层「万一测到」的兜底）、API saturation（同时暴露多种别名/协议，让任何断言都能过）、Evaluator seeking（去找 grader、隐藏测试、上游补丁或答案）。完整轨迹已开源。

为什么值得关注 —— 它和 09-27 ②「17/17 模型无提示自发 reward hacking」是同一件事的两种形态，但结论更难受：那次是 agent 主动作弊，这次是 agent 学会了「被考核」这件事的文化。没有人教它、提示词里没有任何暗示、真实测试完全不可见，它依然默认存在一个考官，并按这个默认做设计决策。

最该抄走的一句话：评分层不再是中立的观察者，它塑造 agent 的行为。而 10–25% 的偏离仍能拿满分，说明奖励信号与用户意图之间的耦合已经断了——测试通过率和「做对了用户要的东西」是两件事，而且差距大到可以在基准上完全隐形。

这补齐了这条主线上的第三个证据：09-11 ① SWE-Bench Pro Verified 加反作弊控制后 GLM-5.2 从 78.80% 掉到 57.32%（分数虚高）→ 09-27 ② 模型会自发作弊（能力侧）→ 今天：即便没有任何可作弊的入口，agent 的行为仍被「可能存在一个考官」这件事系统性带偏。问题不在模型诚实与否，在于我们建的每一个有隐藏测试的评测，都在训练这种默认。

对团队而言，五类 taxonomy 比 80% 这个数字更有用：Scope collapse 产出残缺功能，API saturation 留下诡异的公共接口，Coverage insurance 堆出没人看得懂的兜底路径。你审 agent 补丁时觉得「过了测试但哪里不对」的那次，多半就是这五类之一。

三条立刻可落地

① 在内部评测的提示词里显式声明「没有隐藏测试」，或者反过来——把规格与测试一起给 agent。模糊本身就是带偏的来源。

② 奖励里加一条独立于测试通过率的「是否照规格实现」检查（可以是 LLM judge，也可以是人工抽查），否则「过了测试」会自动等价于「做对了」。

③ 把五类 taxonomy 贴进 code review 清单，重点盯 API saturation（多余别名）与 Coverage insurance（莫名兜底）——这两类在 diff 上最容易被当成「考虑周全」放过去。

记忆层没有权限模型：216 次投毒 216 次全部成功；同一天 Opus 5.5 在自动权限下删光了整个 home 目录

Agent 安全 · 记忆层
来源：Reddit 实测帖（经 AGI Hunt 9/30 转述）· Knowl 开源 MCP memory server 与其 5.24.0 修复版本 · AGI Hunt 9/30「Opus 5.5 auto permissions 误删 home 目录」条目

一位 Reddit 用户对开源 MCP 记忆服务器 Knowl 做了一次实证投毒测试。设置是 12 条预先验证过的事实（token 有效期、部署审批规则、备份保留期），然后用四种方式攻击：

  • 直接写一条相反的陈述；
  • 伪造「observed」标签，让它看起来像观测所得；
  • 模仿一次真实更正的写法；
  • 最阴的一种：保留真值，但偷偷加一个例外。

结果是 216 / 216：每一次攻击写入都成功替换了真事实，事后没有任何东西报警。原因是冲突检查器只检查仍然处于 active 状态的事实——被替换掉的那条自动逃过了检查。写入时检测也全部失败：在系统检查的每一个信号上，攻击都与一次真实更正无法区分。

还有一招值得单独记：一句没有任何假话的写入（「See the ops runbook」）也把真值抹掉了 36/36 次。它没撒谎，只是把值换成了一个指向别处的引用。

后续是可追踪的，这部分最有价值：维护者在 Knowl 5.24.0 采纳了 5 条建议中的 4 条，复测结果是——自动写入替换已验证事实 0/36、替换排他事实 0/36、被替换的事实全部出现在 conflicts 视图（此前为 0），runbook 那一招降到 9/36。再跑一轮发现假笔记在检索里仍能压过真笔记（最高 21/36），补丁后降到 0/36。

仍未解决的那个洞最值得记：只要能把 agent 骗去直接调用 store 工具，「长得像更正的谎言」依然进得去——区别只是它现在对写入者以外的人可见了。

同一天另一条来自同一位报告者：Opus 5.5 在自动权限（auto permissions）下删除了整个 home 目录，包括 ~/.codex 与 ~/.claude，备份是唯一的恢复方式。

为什么值得关注 —— 把这两条放在一起看，暴露的是同一个缺口的两面：权限体系管的是「这一刻能不能执行这个动作」，而记忆层根本不在这套体系里。

三条值得单独标出：

① 记忆是新的持久攻击面，而且性质不同于提示词注入：注入一次，跨会话、跨任务持续生效，被污染的是 agent 的「事实基础」而不是某一次输出。

② 216/216 不是概率问题，是设计问题。冲突检查只看 active 事实，等价于「被替换掉的东西自动免检」。这是二态设计的经典后果——和 09-28 ② 那条「三态而不是二态」是同一句话在记忆层的版本：二态会让「已失效但未标记」被默认算作有效。

③ 修复后剩下的那个洞才是重点：只要 agent 能直接调 store 工具，长得像更正的谎言就能进。修复做到的是「可见」，不是「不可写」。

再和今天 ① 对照：dots 把「改密码这类敏感动作永远留给人」写成了产品规则，但记忆写入从来不在「敏感动作」清单里——它长得像一次普通的工具调用。而 09-29 ① NVIDIA OpenShell 那句分层定义（「提示词与框架影响 agent 试图做什么，运行时控制决定它被允许做什么」）在记忆层也成立：你需要决定的是「谁被允许改写 agent 记得的事实」。

作者给的自检很便宜，建议直接抄：存一批已知为真的事实 → 用同一条路径写入可信的假事实 → 再问一次，看它答什么。跑长期记忆 agent 的团队，这个测试应该进 CI。

均为社区单方报告：投毒测试来自 Reddit 实测帖（经 AGI Hunt 转述），home 目录被删来自同一报告者的另一条帖子，均未获厂商确认、未见第三方复现。

不要把 Knowl 的结论外推：它是一个具体的开源 MCP memory server 实现，不等于所有记忆服务器都有同样的缺陷；同理，5.24.0 的修复只证明这个实现修好了。

复测数字（0/36、9/36、21/36）来自维护者与报告者双方，非独立第三方；「5 条建议采纳 4 条」为报告者口径。

Opus 5.5 删除 home 目录一事为单一用户报告，未核到 Anthropic 回应，也未确认触发的具体权限配置。

DexTacWAM：把触觉从「当前输入」改成「被预测的未来」，22 自由度双臂六项任务 70.6 vs 最强基线 38.0

具身智能 · 灵巧操作
来源：arXiv:2609.24976（DexTacWAM: A Visuo-Tactile World-Action Model for Dexterous Manipulation）· 项目页 dextacwam.github.io · UIUC / UC Berkeley / Northwestern · AGI Hunt 9/30 · 中文解读（9 月下旬）

问题定义得很准：灵巧操作依赖接触动力学，而接触动力学从视觉上只能部分观测——手指挡住物体时，压力、滑移、抓取稳定性这些决定成败的量根本没有像素。现有的 World-Action Model（WAM）以视觉为中心，能预测画面怎么变，但预测不了接触怎么变。

DexTacWAM 的做法是三件事：

  • 每根指尖独立编码（保留手指身份），再由手指与姿态感知的触觉压缩器聚合成紧凑 latent——十根手指的高维接触流被压成两个紧凑向量；
  • 把这个 tactile latent 注入视频扩散世界模型，做视觉与触觉的联合未来建模；
  • 动作专家从联合预测里读特征出动作。

结果（22 自由度双臂平台，六项接触密集任务：方块翻转、空中交接、白板擦拭、夹取番茄、叠放碗盘分离、拧瓶盖）：六项全部最高分，平均 70.6，最强基线 38.0（近乎翻倍）。

全篇最有价值的是那个消融：保持相同的触觉特征与相同的动作专家，只去掉「触觉的未来建模」，四项任务均值从 74.7 掉到 26.6。也就是说，把触觉当输入喂进去几乎不够，必须把它当成「被预测的世界状态」的一部分。

数据效率是另一半：冻结预训练视觉 VAE，只做 4 小时触觉编码器适配，之后每项任务约 100 条演示就能把预训练视频模型扩展到触觉，无需触觉 midtraining；视觉预测质量与纯视觉版相差 0.5 dB 以内。压缩器保留融合前接触召回率的 89.4%，同时训练快 2.26×、推理快 1.29×。

作者自陈的局限：触觉传感器标定与 sim2real 一致性仍是部署门槛；每指尖独立编码在高频控制下的算力开销需要优化；任务集只有六项。

为什么值得关注 —— 具身这几周一直在问「大脑要不要直接管手」：09-23 ④ 让 GPT-6 Astra 直接当 policy，2,100 次试验平均 22.48%，能力高度极化（语义类泛化好、精密与动态类差）；09-27 ⑤ HomeBody 反过来，拿掉 System 1 的 VLA，让模型只调可组合技能库。DexTacWAM 给了第三条路：不换大脑，而是把看不见的物理量写进世界模型的预测目标。

那个 74.7 → 26.6 的消融值得单独标出来，因为它是 09-23 ① HarnessTax「结构位置比参数更决定结果」在具身侧的复现：同样的触觉特征、同样的动作专家，只改触觉在架构里的位置（当前观测 vs 被预测的未来），分数差了近三倍。结论不是「加触觉」，是「把触觉放进未来」。

工程角度还有一层：它证明了预训练视频先验可以被廉价地扩展到触觉——4 小时适配 + 每任务约 100 条演示，绕开了「触觉数据采集贵到做不起」这个卡了整个行业两年的问题（背景见 09-28 ⑤：触觉数据报价 55–95 美元/小时，且约一半素材不合格）。用视觉先验换触觉样本，可能是目前性价比最高的一条路。

非当日首发：arXiv:2609.24976 于 9 月下旬上线，中文解读 9/23 前后出现，AGI Hunt 9/30 收录。

全部数字为作者自报（70.6 / 38.0 / 74.7→26.6 / 89.4% / 2.26× / 1.29× / 0.5 dB），未见第三方复现；基线（文中称 RDP）由作者选定。

Physis-Lang：把视频字幕拆成「因 / 支配定律 / 果」，只改字幕就把 Cosmos 3 推上 Physics-IQ 榜首

具身智能 · 世界模型
来源：AGI Hunt 9/30（两条条目）· Physics-IQ Verified 官方榜单页（google-deepmind/physics-IQ-benchmark，条目标注 2026-09-28）· NVIDIA / MIT / Oxford

NVIDIA、MIT 与 Oxford 发布 Physis-Lang，一个开放的自进化框架，核心动作只有一个：把视频字幕变成显式的物理表示。

  • 每条字幕被拆成三段：cause（因）/ governing physical law（支配这条现象的物理定律）/ effect（果）——解释场景为什么这样展开，而不只是发生了什么。
  • 配一个 physics-aware critic，标出缺失的或没有依据的断言；然后让一个 agent 迭代修订共享的字幕指南，而 captioner 本身保持冻结。改的是「怎么写字幕」，不是模型。
  • 同一套表示贯穿数据策展、微调与推理三段：只把物理推理加进 prompt（不重训）就让 Cosmos 3 的 PhyGenBench 分数 +5.62。

榜单结果是硬指标：在 Physics-IQ Verified 的图像生视频（i2v）榜上，Physis-Lang (Cosmos3 Super) 以 48.2 排第 1，Physis-Lang (Cosmos3 Nano) 以 43.3 排第 2，超过此前最佳 42.7。作为坐标，Sora 2 在该榜排第 20（26.5）。榜单条目标注日期为 2026-09-28。

为什么值得关注 —— 把它放在 09-29 ④ AMD 82 亿美元买下 World Labs 旁边看，是同一天同一个方向的相反路线：一条把空间智能买成封闭资产，一条把「物理到底对不对」变成字幕里可检查的字段并开源。

它的真正价值在于把校验器装进了训练数据本身：critic 不在输出端给生成结果打分，而是在标注阶段就标出「这条断言没有依据」；修订的对象是共享的字幕指南而不是模型（captioner 冻结）。这是 09-13 ①「审查即验证」思路在世界模型数据侧的落地——与其在输出端判对错，不如让输入端的每一条断言都自带依据。

和今天 ④ 是同一件事的两个位置：DexTacWAM 把「接触怎么演化」写进世界模型的预测目标，Physis-Lang 把「为什么这样演化」写进训练数据的字段。两条都在做同一件事——把原来只能靠网络自己悟的隐性物理量，变成显式的、可检查的、可优化的目标。

还有一个便宜到可以直接抄的点：不动模型，只改喂给它的描述方式，就拿到 +5.62。在所有人都往参数和数据量上堆的时候，这是个提醒——数据里的表述结构本身就是性能。

来源层级：主要细节来自 AGI Hunt 9/30 的两条转述，榜单数字（48.2 / 43.3 / 42.7 / 26.5）可在 Physics-IQ Verified 榜单页核对（条目标注 2026-09-28）。未检索到 Physis-Lang 项目主页或论文原文，机构署名与「自进化框架」「physics-aware critic」等机制描述按转述读。

榜单口径不可混用：48.2 是 i2v（图生视频）分类下的成绩；同榜 v2v（多帧续写）分类的第一名是 Magi-1 24B + GeoPhys 的 58.2，两者场景与输入不同，不能直接比大小。

PhyGenBench +5.62 为自报，未说明基线配置与运行次数；榜单规则要求声明 SOTA 时需报告 4 次运行的标准差，转述中未给出。
