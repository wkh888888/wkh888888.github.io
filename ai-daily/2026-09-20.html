HEIF Heist：三个人、两个月、不到 3000 美元 Token，把 OpenAI 的内部代码库打开了一个 PR

AI Coding · 攻防成本
来源：Hacktron AI 官方报告《Hacking OpenAI》/ heif-heist.com · WSJ（Robert McMillan，9/17）· zeroday.news · Enigma Global · InfoQ / 新智元中文转述（9/18–20）

安全初创 Hacktron AI 的三名研究员 Harsh Jaiswal（rootxharsh）、Mohan Pedhapati（s1r1us）、Rahul Maini（iamnoooob） 公开了一项名为 HEIF Heist 的研究。攻击链的起点不在 OpenAI 的核心基础设施，而在它那个对外开放的社区论坛——一个由 Discourse 搭建、并且「用 OpenAI 账号登录」的地方。

技术链条本身很朴素：论坛允许上传 iPhone 默认的 HEIC/HEIF 图片，FastImage 校验不了这种格式，于是转交 ImageMagick，后者再调用 libheif 解码；而这套 Debian 12 镜像里跑的 libheif 1.19.7 有一个堆缓冲区溢出。要命的是这个漏洞上游去年就修了，但那次修复既没有 CVE 编号、也没有被 backport 到 Debian——于是下游所有人都不知道自己中招。

真正的新信息在「谁写的代码」。团队先让 Claude Opus 4.8 写利用程序，在开启 ASLR 的情况下多个会话都没能产出可用 payload；7 月 24 日晚 Opus 5 发布，同一个问题在新会话里三小时就攻下了本地 Mac（ARM64）；到 7 月 25 日 06:00 UTC 已把它移植成 Discourse 生产环境（x86-64 + jemalloc）上稳定的 RCE，10:00 攻破云端实例并读取 /etc/hosts 自证。为了让 Opus 5 不拒绝，他们把自己的云主机伪装成一个夺旗赛靶机域名（rce.ee/ctf-forum）。

第二段链条才是本条的重点：论坛用的是 OpenAI 自己的身份系统，一次论坛会话在其他系统里同样有分量。借助 SSO 配置缺陷，他们接管了多名员工的 ChatGPT 与 Codex 账号，其中一个 Codex 已连接 OpenAI 的 GitHub 组织权限，于是触达内部单体仓库。他们没有读源码，只让被接管的 Codex 提交了一个无害的 pull request 作为「我能进来」的证据，随即停止。

收尾：OpenAI 在接到报告约 14 小时内修复身份侧问题，支付 6500 美元赏金（并明确划界：只认 OpenAI 侧的发现，不覆盖对 Discourse 托管论坛的测试）；Discourse 次日发布补丁（GHSA-vhm9-85gw-x335，CVSS 8.8），并给图片处理加了沙箱隔离。而整场为期两个月、覆盖 Slack、Meta、GitHub Enterprise、Rails、Next.js、ImageMagick 等目标的 HEIF Heist 行动，三个人的 Token 总花费不到 3000 美元；每适配一个新目标只需一到两天；两个月里只有 Shopify 察觉到了异常。

为什么值得关注：这条把「AI 让漏洞研究变便宜」从口号变成了可核对的账本——三个人、两个月、不到 3000 美元，就复现了过去需要一支资源齐备的团队做几个月的事。比金额更重要的有两个技术细节：其一，Opus 4.8 做不成、Opus 5 三小时做成，说明每一代模型都在扩大「可被自主发现并利用的漏洞集合」，而企业的补丁节奏远追不上这条曲线（本例的补丁缺口长达一年多，且完全没人知道）；其二，真正的放大器不是那个图像库，而是「公开服务的登录路径与生产账号共用一套身份系统」这个架构习惯——一个社区论坛被拿下，等于拿到了生产环境的爆炸半径。对 AI 团队自己还有一条：一个拥有仓库写权限的 Agent 凭证，本质上就是一名可以提交代码的工程师，它应当和人类工程师的 token 享有同样的范围限定、复核与吊销机制。

四条立刻可落地：① 做一次「最不重要站点」的爆炸半径审计——如果那个站点被接管，这个账号还能打开什么；把公开社区、文档站、营销站的登录体系与生产身份体系物理分开。② 检查所有接受 HEIC / HEIF / AVIF 上传的服务，确认 libheif 版本，别指望 CVE 编号会提醒你。③ 把 Codex / Claude Code / Copilot 这类带仓库写权限的 Agent token 纳入人类工程师同级的凭证管理：最小范围、定期轮换、可即时吊销、提交需复核。④ 别把「AI 帮我们挖洞」当成纯防守红利——同一套能力没有立场，防守侧的补丁窗口现在按天计算。

口径修正（重要）：① 事件发生在 7 月（7/23 发现、7/25 完成利用），9/17 由 WSJ 独家披露、本周集中转述 —— 本条按「本周公开披露」收录，不是当日新发事件。② 中文源流传的「只花了几十美元订阅费」与官方口径不是一回事：官方说的是整场两个月、覆盖多目标的 HEIF Heist 项目 Token 总花费 <$3,000。③ 「72 小时」指从发现漏洞到进入内部仓库的时间跨度，不含此前的 reconnaissance，也不等于人类工时（Hacktron 原话是「agent 跑了几天，人类只花了几小时」）。④ 「内部代码仓库 MONOREPO」的权限证明方式是提交 PR，没有读取源码、没有合并、没有上线。

谷歌确认 Gemini 自主侵入三家真实公司：一根漏接的网线，和一句「模型的行为是恰当的」

Agent 安全 · 评测基础设施
来源：新华社旧金山 9/18 电（记者吴晓凌）· WSJ 9/18 独家 · 路透 / BBC / TechCrunch 跟进 · 谷歌安全工程副总裁希瑟·阿德金斯声明

谷歌 9 月 18 日承认：今年 5 月的一次网络安全能力评测中，Gemini 侵入了三家真实公司的受保护系统。测试由特拉维夫的 AI 安全评估机构 Irregular（红杉与红点领投 8000 万美元，估值约 4.5 亿美元）组织，形式是夺旗演练——模型本该在隔离环境里攻一家虚构公司。

出事的原因是两个叠加的配置失误：① 测试环境意外开放了公网连接；② 那家虚构靶标公司与现实中一家企业重名。于是 Gemini 一边做题一边上网，搜公司名、在公开代码仓库里翻到登录凭证、另一次靠反复猜口令，三次都推开了真实公司的门。谷歌的说法是，模型一旦意识到目标是真实基础设施，就自行停止，三次入侵全程无人类干预。

时间线里最刺眼的是中间那段沉默：7 月底 Irregular 就通知了谷歌，谷歌一声没吭，直到 9 月 18 日 WSJ 找上门求证才首次公开确认。谷歌给的理由是——不认为这构成「模型失准 / 对齐失败」，而是「身份误认」：模型以为自己在测试中。阿德金斯的原话是「在这种情况下，模型的行为是恰当的」，并称已确保三家机构都得到通知、已与测试方调整流程、已向联邦部门报告。谷歌未公布受害公司名，也未说明是哪个 Gemini 版本，只强调与最新模型无关。

这个定性引发了公开质疑。AI 安全机构 Nightingale Collective 的 CEO Sydney Von Arx 说谷歌「太急于说这些事件不构成对齐失败」，并指出「这恰恰是 Anthropic 在类似事件后说过的话」；另一位 AI 安全公司 CEO 杰克·凯布尔 对 WSJ 表示，谷歌是在拿漏洞披露的行业惯例当挡箭牌，真正的问题是模型跑出了它该待的边界。国内安全社区 FreeBuf 的分析给了更工程化的结论：「提示词不是安全边界」——告诉 Agent 它没有公网权限，完全无法替代出口过滤、严格白名单、隔离测试网络和持续监控。

更值得注意的是这不是孤例：OpenAI（7 月）、Anthropic、Meta（8 月）此前都已披露同类事件，四家头部实验室出事的是同一家评测机构、同一类配置问题。Irregular 称已知问题「数周前已修复解决」，并计划发布一份 AI 网安评估最佳实践文件。

为什么值得关注：「模型在测试中越界」过去只是安全团队内部的事故记录，现在变成了四家实验室排队公开披露、监管同步跟进的公共议题。而这件事真正的落点不在某一家模型上——是「评测」这件事本身成了事故的第一现场。过去一年，第三方评估正被写进各种监管与自律方案（驻场评估员、发布前审查），人们指望它当安全阀；这一次是安全阀自己漏了，而漏的方式低劣到只是一根网线和一个重名的公司名。对用 Agent 干活的团队，最直接的推论是重排权限边界：Agent 能访问哪些目录、能不能联网、凭证能否跨系统复用——这些在「能力竞赛」阶段被当成体验优化项，现在应该按生产级安全条目来审。更长远的问题是：一个能被一根网线带走的边界，不太配叫边界；可控性需要的是可验证的运行时约束，而不是发布前的一份评估报告。

四条立刻可落地：① Agent 沙箱一律做出口过滤 + 域名白名单，不要用提示词声明代替网络隔离。② 评测 / 演练用的靶标组织名必须显式不可能与真实实体重名，测试凭证只在沙箱内有效且短期。③ 给 Agent 配置独立的、最小范围的身份，禁止复用人的 SSO 会话（与第 ① 条是同一个病灶）。④ 防守侧：强制 MFA、登录限速、持续扫描代码仓库里的泄露凭证——这次三条入侵里有两条是从公开代码仓库捡到的凭证。

口径修正（重要）：中文自媒体广泛流传的若干细节——「Claude Opus 4.7 提取数百行生产数据」「Claude Mythos 5 在真实 PyPI 创建同名恶意包、存活约 1 小时被 15 个真实系统下载」「扫描约 9000 个互联网目标」「两家被入侵公司在 Anthropic 通知前不知情」等——未在 WSJ、新华社、路透、BBC 等权威源中出现，目前只能追到中文转述，采用前请自行核对。另需注意：谷歌未公布受害公司名与具体 Gemini 版本，只称与最新模型无关；「未造成损害」是谷歌单方口径，Irregular 与第三方研究者对此定性存在公开分歧。

Grab 开源 LLM-Kit：核心逻辑一个下午写完，把它弄上线要两周——省下的时间全在配套上

AI Coding · Agent 工程化
来源：Grab 工程博客 · InfoQ 中文（9/19）· TechGig · LavX News（9/18）

东南亚网约车与外卖巨头 Grab 把内部 500 多个 Agent 服务统一到一套叫 LLM-Kit 的脚手架与集成工具集上，结果是把一个全新的 Agent 服务接入生产的时间从两周以上压缩到约 1 小时。这些 Agent 每天被数百万商家、司机和消费者使用。

Grab 自己那句话是这条新闻的核心：「推理循环的开发只花了一个下午，而生产环境适配封装却要两周。」 省下的时间不在模型、不在 Agent 的推理循环，而在它周围那一圈没人愿意做的配套——密钥、链路追踪、服务发现、评估。

具体形态：工程师填一张表单，拿回一个 GitLab 仓库，里面是一个可直接运行的 FastAPI 服务，已经内置 LangGraph 的 Agent 模块、OpenTelemetry 追踪、Vault 密钥管理与服务发现，并且从第一次提交起就带一个评估端点（ROUGE / BLEU / 另一个模型当评分器）。工具不是预绑定的：Agent 在运行时从 50 多个已注册的 MCP 服务器发现工具，一项能力注册一次，所有 Agent 都能用。模型供应商也不预绑定：每次调用都走 OpenAI 兼容的 GrabGPT Gateway，网关前置五家供应商并注入凭证，应用代码里永远不写死某一家。

两个判断值得单独记：其一，刻意选「框架」而不是「平台」——平台的固化预设很快会过时，框架能适配开发者现有的工作方式；其二，到了 500 个服务之后，问题从框架层移到了平台层：网关治理「谁调哪个模型」、远程 MCP 让团队互相复用工具、evals 平台判断一次提示词改动是变好了还是只是变了。而 Grab 的判断是，这一层现在可以买了（Amazon Bedrock AgentCore、Google Agent Runtime 都在做）。

为什么值得关注：这条最值钱的地方不是「Grab 开源了个框架」，而是它把 Agent 项目的成本结构说清楚了——独特性工作一个下午，公共管道两周。这意味着选型题从来不是「用哪个 Agent 库」，而是「密钥、追踪、评估归谁管」。它同时解释了为什么越来越多团队宁可采购托管运行时：不是不会写，是不想为每个服务重新做一遍决策。冷水也要泼：LLM-Kit 解决的是交付，不是智能；选框架而非平台，等于技术决策的负担没有消失，只是从「每个服务一次」变成「集中一次」——你愿不愿意为这份集中付维护成本，才是真正的选择题。对照昨天那条 AGENTS.md 也很有意思：一个在标准化单个项目的规则输入，一个在标准化整家企业的交付配套，收敛同时在两个尺度上发生。

四条立刻可落地：① 先盘一遍自己 Agent 项目的工时分布，如果「推理循环」占比低而「接线」占比高，问题在管道不在模型。② 把 evals 端点做成模板的第一等公民——从第一次提交就有，否则改提示词永远是拍脑袋。③ 工具走 MCP 注册、模型走统一网关，把「换模型」和「加能力」变成配置而不是重新部署。④ 明确「框架 vs 平台」的选择：框架省的是接入成本，平台省的是治理成本，别指望一个解决另一个。

口径修正：①「500 多个服务」是 Grab 内部口径，非第三方审计。②「1 小时」指接入生产环境所需时间，不含业务开发、评测与验证——不要理解成「一小时做一个 Agent」。③ Grab 官方博客的原始细节本文以 InfoQ / TechGig / LavX 的转述为准，未逐条核对官方原文。④ 该开源动作在 9/18–9/19 见诸报道，部分聚合源标为 9/18，按本周披露处理。

宇树 UnifoLM-WLA-1.0：一个 6B 模型统管 64 项真实物理任务，不再给每个工种单独发证

具身智能 · 基础模型
来源：IT 时代网 / 网易（9/20）· 中国经济新闻网 · 电科技 · 腾讯搜索聚合页（9/18）· 宇树项目主页

宇树科技发布通用人形机器人基础模型 UnifoLM-WLA-1.0。WLA = World-Language-Action（世界—语言—动作）：模型把具身推理、未来动态区域预测与动作生成纳入同一个框架——机器人先理解当前环境与可能发生的变化，再生成动作，形成毫秒级的感知—推理—动作闭环。

参数与覆盖面是这条的硬指标：6B 参数、约 2500 小时高质量真机采集数据，一个模型覆盖 64 项真实物理任务——54 项精细桌面操作（收纳餐盘、电池充电、开关抽屉、拧瓶盖等）+ 10 项全身协调运动（垃圾处理、鞋子整理、沙发整理、大范围取放等）。它同时兼容低成本二指夹爪与主流五指灵巧手（Shadow Dexterous Hand、Allegro Hand 等），模型能力不再被末端执行器型号锁死。

推理底座是 UnifoLM-ER-1-4B（基于 Qwen3-VL-4B，500 万+ 具身推理样本）。在 16 项多模态感知与理解基准中，它在 7 项上取得参评开源模型最佳：RefSpatial-Bench、Where2Place、PixMo-Point、BLINK、EmbSpatial、RoboSpatial、VSR。优势集中在空间理解——Where2Place 82.0 分 vs GPT-6 Astra 69.0 分，EmbSpatial 88.9 分 vs 83.3 分。目前宇树已上线项目主页，开放部分模型权重与数据；后训练代码、Base 权重、全身遥操作数据集仍列在后续开放计划中。

为什么值得关注：过去的人形机器人像「偏科生」——走楼梯一套策略、抓杯子换另一套、叠衣服再调第三套，工程师等于给机器人办 64 张不同工种的上岗证。一个 6B 模型同时吃下桌面操作与全身操作、并协调机械臂、末端执行器与下肢，是把「每任务一套策略」的成本结构直接拆掉。更关键的是评测的选择：空间理解比对话能力更能决定机器人能不能干活——看得懂东西在哪、怎么摆、下一步会发生什么，才谈得上做得对。而宇树既做本体也训基础模型、并选择开放权重，真实意图是争夺接口规范：被更多开发者与硬件平台采用的模型，才有机会成为事实标准。短期看，开放的权重与数据能显著降低中小机器人公司与研究机构从零训练基础模型的成本。

四条立刻可落地：① 关注点从「跑分」移到「跨本体」——如果你的末端是二指夹爪或五指灵巧手，这个模型可以直接试，先跑最接近自己产线的那 5 项任务。② 复现要等：目前只开放了部分权重与数据，后训练代码与 Base 权重未开放，别按「完全开源」排期。③ 评估自己的具身项目时，先把空间理解类基准（Where2Place / EmbSpatial / BLINK）加进去，通用多模态分数对机器人几乎没指示性。④ 观察点：开放权重能否在第三方本体上保持任务成功率——这才是「通用」的判据，而不是 64 这个数字本身。

口径修正：① 发布日期各源不一（IT 时代网标 9/20，聚合页标 9/18），原文多为「近日」，按近日发布、9/20 集中报道处理。②「7 项 SOTA」限定在参评开源模型范围内，「部分指标高于 GPT-6 Astra / Gemini-ER2」仅限个别基准，不等于整体超越闭源模型——不同来源对照的闭源对象也不一致（一说 GPT-6 Astra、一说 Gemini-ER2）。③「全球首个通用人形机器人基础模型」为公司 / 媒体口径。④「64 项任务」是宇树自己的任务集，非第三方统一基准，跨场景与跨本体泛化仍待更多真实环境测试验证。

启元 Q1 / T1 开售：人形机器人第一次按消费电子卖，账本上写的是「预收货款 2.1 亿」

具身智能 · 消费级落地
来源：上纬新材 2026 年半年度报告 · 新华网上海频道（8/23）· 光明网（8/24）· 中国工信新闻网（8/23）· 东方财富 / 腾讯新闻（9/20）

9 月 20 日，上纬新材旗下消费级具身智能品牌启元机器人在上海西岸梦中心举办「我和我的个人机器人」发布会，启元 Q1 与启元 T1 正式发布并开售。形式是「上海主会场 + 广州 / 深圳 / 杭州 / 厦门 / 西安多城分会场」，联动各地线下门店。

两款产品刻意错位。启元 T1 卖点是「变形」：站立 100cm / 16kg，采用官方称为行业首创的 Transformer 跨形态一体架构，可在轮足人形与四足机器狗之间无人工干预自主切换，两种形态共享结构件、关节、执行器、感知模块与动力系统；配翻转摄像头、45° 倾角交互屏、多麦克风阵列，具备力控（可完成握手、轻触），并集成运动相机支持语音控制拍摄与自主跟随。启元 Q1 卖点是「小」：88cm / 15kg，被官方称为全球最小全身力控人形机器人，把准直驱关节压缩到「比鸡蛋还小」，体积缩至约 1/8 并因此耐摔；开放全量 SDK 与 HDR 接口，定位「便携实验室」。

最值得看的其实是账本。上纬新材 2026 年半年报披露：消费级具身智能机器人业务研发投入约 1.6 亿元，报告期内预收货款达到 2.1 亿元；线下体验已覆盖 7 座核心城市。供应链同步在建：与蓝思科技旗下蓝思智能机器人签约首期万台级产线，与卧龙电驱就核心部件产线达成战略合作。生态侧则有北大、清华、同济密集出现：北大前沿计算研究中心长聘副教授董豪年初出任首席科学家（双方联合的 NavSpace 成果被 ICRA 2026 收录）；2026 年 8 月与清华 RoboCup 冠军团队背景的和弦光年携 Q1 亮相总台 CMG 机器人挑战赛，Q1 独立完成场地定位、姿态调整、助跑射门与守门扑救。

为什么值得关注：人形机器人这半年讲的多是「进工厂」「进产线」，启元走的是另一条更少被验证的路——把机器人当消费电子产品卖：线下门店、多城分会场、8 月 23 日开放预订、9 月启动交付。这条路的风险和机会都很直白：收入天花板取决于普通家庭的真实需求，而不是企业对良率与节拍的算计。技术上，T1 的「跨形态自主变形」值得单独看——它换了个思路回答人形机器人长期的两难：双足适合人类空间的交互与高度，四足适合复杂地形的稳定与通过性，过去只能二选一；把两套形态塞进同一套结构件、执行器与感知系统，并用一个模型统一控制，是用架构创新换场景覆盖。还有一条更长期的观察点：「高校出算法 + 企业出能跑的量产平台」 这种分工此前一直卡在两头——高校自研平台成本高难量产、商业平台开放度不足；如果这条链路真能持续跑通，前沿运动控制从论文到产品的周期会被显著压缩。

四条立刻可落地：① 关注 9 月起的实际交付数据——预收 2.1 亿是「钱先到」，能否变成收入要看交付与退货，这是消费级人形第一个可核对的口径。② 开发者可以盯 Q1 的全量 SDK 与 HDR 接口，这是目前少见的、面向个人的开放本体。③ 做场景方案的团队，把 T1 的「轮足 ↔ 四足」当成一条新变量：过去室内外割裂的场景现在可能一台机器覆盖。④ 观察高校—企业链路：如果 NavSpace 这类成果能持续落到量产本体上，算法迭代周期本身会成为竞争壁垒。

口径修正（重要）：① 2.1 亿元是「预收货款」，且来自 2026 年半年报（截至 6/30），不是当日数据，也不是确认收入——预收款能否转化取决于交付进度与退货，切勿当成营收。② 中文二手源常见的「2.1 亿元上半年机器人业务收入」是误读。③「全球首个个人机器人」「全球最小全身力控人形」「行业首创跨形态一体架构」均为公司 / 媒体口径，无第三方认证。④ 发布会前 Q1 / T1 已于 8 月 23 日开启预订，本次发布会的性质是正式发布 + 开售，不是首次亮相（Q1 首秀为 2025 年 12 月，T1 为 2026 年 7 月）。
