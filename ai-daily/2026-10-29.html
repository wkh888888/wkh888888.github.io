Google 两周内第二次刷新旗舰：Gemini 4 Carbon 登顶 AA 智能指数 v5.0，领先只有 1 分，而且先不给开发者

AI Coding
Google 官方博客《Gemini 4 Carbon: our next frontier model》（10-28 17:00 UTC，Koray Kavukcuoglu 署名）；Artificial Analysis《Announcing Artificial Analysis Intelligence Index v5》（10-27）；The Decoder、Mashable、Digital Trends、Agentic Tribune、nvdium 报道

Carbon 是 Gemini 4 家族两周内的第二次迭代（Argon 于 10-13 上线），Google 把它定位在两件事上：网络安全防御与长程自主工程。发布方式是这道题的关键部分。

  • 分数。Artificial Analysis 智能指数 v5.0 上 Carbon 得 59 分，超过 Claude Opus 5.5（max）的 58 与 GPT-6 Astra（max）的 57，前代 Argon（high）是 50。但同一份 v5 榜单上，编码子项 Coding Agent Index 上 Carbon 是 59，仍落后 Opus 5.5 的 62；操作系统类 OSWorld-2.1 是 81.5%，低于 Opus 5.5 的 87.2%；FrontierSWE 2 输给 GPT-6 Astra。
  • 安全三连。SEC-bench Pro（找真实漏洞）88.2%、ExploitGym（验证可利用性）54.8%、Collinear CWE-bench（根因级修补）71.0%，三项均为当时最高。内部评测里生成安全代码的成功率比 Argon 翻倍以上；Chrome 团队称它生成高质量补丁比另一家实验室的大型前沿模型好 10 倍以上；Wiz 观察到它在 web 渗透测试基准上领先。
  • 对齐数据。Terminal-Bench 4.0 上成功奖励黑客率为 0.0%、尝试作弊率 0.4%；Gray Swan 间接提示注入基准攻击成功率 0.0%（Argon 为 0.7%）；内部实时编码环境里高严重度失配告警下降近 80%；越界行为降 26%、欠服务降 29%；无依据断言数量约为 Argon 的一半。
  • 发布顺序。本周先开放给「一部分网络防御者」，再经 Fairwind Program 逐步扩到更多可信伙伴，之后才面向开发者、企业与消费者，官方未给出全面开放日期。Fairwind 现有 650 余家合作方，含政府与医疗、电信基础设施运营方；申请需背景核查与抗钓鱼多因素认证。Google 同时表示正在参与美国政府的自愿性发布前模型测试流程。
  • 价格。与 Argon 相同：引入期每百万 token 输入 2 美元、输出 10 美元，缓存输入按输入价 95% 折扣；引入期结束后上调至 4 美元与 20 美元。WebDev Arena 上升 89 Elo 至第 4 位（1769）。
  • 尺子的来历要留意。这个 59 分是在 AA Index v5.0 上量出来的，而 v5 是前一天（10-27）才发布的换版：这是 v4 以来最大的一次改动，60% 权重首次建立在私有测试集或保留答案上，四个区域各占 25%（知识工作、编码、科学、通用各含 2 到 3 项评测），新增 FrontierCode 2.0（编码区权重 15%）与 Terminal-Bench-Science（科学区 15%），HLE 换成 HLE-Diamond，CritPt v2 改为私有 40 题 hard subset，移出 GDPval-AA v2.1、SciCode、AA-LCR v1.1。AA 明写 v5 分数与 v4.3 不可比。

这为什么值得看。三件事叠在同一天，指向同一件事：「谁最强」这个问题第一次有了换版机制，而版本号本身成了新的信息位。Carbon 领先 Opus 5.5 只有 1 分，意味着下次发布就能抹平；但真正值得盯的是它背后的两把新尺子 —— v5 的编码区 15% 权重直接给了 Cognition 同一天发布的自有基准 FrontierCode 2.0，一家厂商的自留地进入了第三方的综合指数。

更有意思的对仗在发布顺序上：Carbon 能力最亮的部分是「能自己找漏洞、自己验证可利用性、自己打补丁」，而它恰恰先不给写代码的人，先给防御者。一个能自主完成攻击链的模型先到安全团队手里，这是分发策略上的准入设计，不是产品排期。跟 10-28 ① 那个「审批凭据和被审批动作同一个信任域」的问题正好相反：这边的答案是把能力先放进一个可审核的信任域。

顺带值得记的是 v5 换版附带的两个成本信号：每任务输出 token 中位数从 35k 涨到 59k（涨三分之二），而 agentic 评测占 55% 权重却吃掉约 90% 的输出 token；同一份榜单上 Opus 5.5 从低档 35 分到满档 58 分，每任务成本从 0.98 美元涨到 10.04 美元。分数和价钱是绑在一起动的。

口径提醒。Carbon 的具体榜单条目在核查时尚未出现在 Artificial Analysis 的公开榜单页面上，上述分数来自 Google 自己的公告，独立第三方验证尚未跟上；Carbon 与 Meta 的 Muse Wonder Full 均被标注为暂无公开 API。Google 表格里的领先项有 15/17 与 15/16 两种流传口径（分母不同），不可混引。外部安全基准明确是在无 guardrails 条件下测得，不能直接等同于产品内表现。AA v5 本身还有一处需要记住：Terminal-Bench 4.0 仍占编码区 10% 权重，而 10-26 那期 Epoch AI 审计已判定 Terminal-Bench 4.0.0 为 Flawed（66 题中 30 题有评分缺陷）—— Carbon 最亮的那个对齐数字，落在那把刚被判有缺陷的尺子上，而 Kimi K3.1 Pro 正是靠这把尺子拿到单项第一（67%）。

可以行动。如果你的选型流程依赖 Artificial Analysis 智能指数，先把本地记录里的 v4.3 分数全部标注为不可与 v5 比较，别把两代数字画成同一条曲线；选型时优先看分项榜而不是总分榜，因为 Carbon 与 Opus 5.5 的差距在总分、在编码子项是反过来的。另外留意 AA v5 把 60% 权重放到私有数据上这一改动 —— 公开可复现的证据比重下降，意味着第三方复算的门槛在抬高，可以考虑在内部评测里补一套自己可复现的题。

GitHub 官方年报给出第一个全站口径：超过 40% 的 pull request 由 agent 起头，而 GitHub 自己说这是下限

AI Coding
GitHub 官方博客《Octoverse: Commits, pushes, reach new highs in 2026 as developers build with agents》（10-28，GitHub Universe 同期）；The Next Web、toolnavs、blockchain.news、mezha 转载与解读

这是 GitHub 第一次给出全站口径的 agent 参与度，而且它把话说得很留余地。

  • 那一句话。原文：到 2026 年 9 月，超过 40% 的 pull request 由 agent 起头，3 月这个数字是 17%；9 月单月就是 1.1 亿条，约为 3 月的 6 倍。GitHub 对「agent 起头的 PR」的定义是「首个 draft 来自可检测到的 coding agent」，方法论里紧跟一句：这是下限，因为并非所有 agent 使用都能被检测到。
  • 体量。过去 12 个月推送 179 亿次（超过 2024 与 2025 两年之和，那两年分别是 52 亿与 67 亿），commits 达 343 亿（两年前为 100 亿与 129 亿），合并 PR 13 亿条（日均 350 万）。Actions 跑满 454 亿个 job，即每秒 1440 个、日均 1.24 亿个，是去年的三倍以上；合并 Dependabot PR 超 3000 万条，约去年两倍；push protection 执行 58 亿次扫描。平台开发者数超 2.25 亿，美国 3830 万、印度 3200 万，巴西新增 328 万。
  • agent PR 长什么样。约 87% 的 agent 起头 PR 会改多个文件，无 agent 参与的一组是 79%；两周内合并率从 2 月的 83% 升到 9 月的 90%，对照组保持在约 86%。今年新建的仓库里，带 agent 配置文件的仓库平均 commits 数是不带的 8 倍。
  • 模型选择。9 月 61% 的 Copilot 用户用了不止一个模型；自己选模型的用户中 38% 选通用型、37% 选深度推理与规划型、25% 选快速轻量型；付费用户用到的模型数从 5 月的 29 个升到 9 月的 47 个；63% 的付费开发者至少用过一次自动选模型。
  • 其他。公开贡献 25 亿次，是 2025 年 11.2 亿的两倍多；6 月起约 55% 的 commits 来自全新仓库。行业分类首次公布：建筑业 agent 开启 PR 的比例最高（约 9% 的仓库有 agent 开过 PR，而行政支持、采矿、医疗、农业这些「超四成仓库提到 AI」的行业里，agent 开过 PR 的不到 3%）。

这为什么值得看。这是第一次有人用全站遥测给出「AI 参与写代码」的分母，而不是靠抽样调查或单个平台的样本。40% 这个数字的分量在于它同时具备两个性质：足够大，且自己声明偏低。——这一组合此前只在安全领域出现过（10-28 速览① 的 Cohere：检测规则外行为不到十万分之一，但预填攻击命中率能从 4% 跳到 92%）。

第二条更有价值：agent 起头的 PR 两周合并率 90%，高于对照组的 86%。这和 10-28 ② 那篇 IaC 实证论文给出的方向正好相反——那篇发现在同一仓库内做控制后对比，沉默 agent 合并率低 4.0 个百分点、披露 agent 低 8.4 个百分点。两组数字都对，差在口径：Octoverse 是全站的粗口径，论文是同仓库同改动类型控制后的细口径。而本期真正的新信息是「全站粗口径与控制后口径第一次同时摆在桌面上，且方向相反——这说明合并率这个指标本身已经不能单独承担判断，需要配一个仓库内部的对照。

第三条值得单独拎出来：带 agent 配置文件的仓库 commits 多 8 倍，而报告自己没给质量与维护成本的答案。这个 8 倍是相关性，不是因果 —— 那些仓库也可能来自目标更清晰、团队更成熟的群体。这恰好是 10-28 ③ Amazon 内部备忘录否掉 token 数与代码行数当指标时留下的同一个缺口：活动量涨了，产出的账还是没结。

口径提醒。40% 是 GitHub 自定的「可检测份额」，用开发者自己账号提交、不在遥测里留痕的 agent 完全不在统计内 —— 换句话说，真实份额更高，且高多少无法从外部判断。合并率的对比（90% 对 86%）来自全站粗口径，与 10-28 ② 论文的同仓库控制后口径不可相加、不可相减。8 倍 commits 是相关性不是因果。Octoverse 本身不回答质量与维护成本。另有二手源提示，GitHub 官方 Octoverse 索引页在 10-28 当时仍标注 2025 版为最新年度报告，因此本期数字应按博客原文理解，不宜当作已独立核验的平台统计。61% 用多模型与 63% 用过自动选模型是两个不同人群口径，不宜合并。

可以行动。如果你的团队在评估「要不要让 agent 起第一版 PR」，这份报告给出的实操结论是审查压力会从「写代码」转移到「读 diff」 —— agent PR 改多文件的比例更高（87% 对 79%），而合并率并没有因此变差，也就是说瓶颈不在产出量上。可行的做法是在 agent PR 上强制要求同时提供测试与验证痕迹，把成本花在验证而不是写作上。另外，报告里「建筑业 agent 开 PR 比例最高（约 9%）」这类分行业数据，对判断自己所在领域是否已进入 agent 参与的早期阶段，比总体的 40% 更有参考价值。

Anthropic 一个团队取消编程题面试：Claude 3.7 就已经让一半候选人做得更好，题目连改三版

AI Coding
Felix Rieseberg（Anthropic 工程经理、Claude 相关产品工程负责人）X 发帖与长文《Hunger beats tenure》（10-28）；InfoQ 中文编译报道（10-28）；凤凰网科技等媒体报道

Rieseberg 的原话是「编程面试已死，至少对我所在的 Anthropic 团队而言。我看得够多了，可以确定它不再提供有效信号，这个月我已经把编程面试从招聘流程里取消」。理由很直接：Claude 已经能轻松完成小型 React 挑战，甚至底层汇编问题，继续用编程题筛人就像还在考汇编。

  • 他所在团队的真实演化史（最有说服力的一段）。Anthropic 性能优化团队负责人之一 Tristan Hume 从 2024 年起设计了一套模拟加速器优化的 take-home 测试，明确允许候选人用 AI 工具，约 1000 名候选人做过，靠它招进了大量性能工程成员。Claude 3.7 Sonnet 出现一个临界点：超过一半候选人如果直接把题目交给 Claude Code 完成，成绩反而更好；Opus 4 超过了绝大多数人在 4 小时内取得的成绩，团队于是把题目升级到第二版、把测试时间从 4 小时缩短到 2 小时；几个月后 Opus 4.5 又追上来，在 2 小时限制下已经能达到最强人类候选人的水平，团队只好再次设计新题，并刻意加入模型此前没见过的约束、迷你指令集和新型谜题。Hume 自己承认这套新测试牺牲了与真实工作的相似度，因为越接近真实开发工作的题目，Claude 越容易完成。
  • 替代方案与它的空缺。Rieseberg 现在的做法是在简历与作品集里找「小型原型」，观察产品品味、用户同理心，以及思考是否有体系。他也直说目前没有完整答案；社区的质疑正落在这里：一场 60 分钟的面试里，还没有找到更好的替代指标。有开发者建议给候选人一个「AI 写得很自信但实际存在错误」的代码仓库，看他能否识别模型错误并坚持自己的判断。
  • 他真正想说的是另一件事。他把结论总结为「饥饿胜过资历」：AI 降低了执行成本，资深与初级的差距不再由资历自动决定，新工程师缺少历史包袱反而更容易重新质疑那些「看起来很奇怪」的组织惯性。他举了 Notion 时期自己被要求设计离线模式架构（团队普遍认为不可能）的经历，也提到两名入职不久的同事用一个周末做出 Claude Code 图形界面原型、8 天后发布。他还提醒一个更实际的阻力：难点不是新人能不能借 AI 表现出执行力，而是简历筛选阶段他们就没有机会展示。
  • 行业数据。Karat 2026 年调查美国、印度、中国 400 名工程负责人：美国只有 38% 的企业允许候选人在现场技术面试中使用 AI，中国企业达 68%，同时 62% 的受访组织仍然禁止 AI 参与技术面试。CoderPad 约 650 名开发者与招聘人员的调查类似：34% 完全禁止、46% 允许或在一定约束下允许、20% 看情况决定。而在 AI 被允许之后，招聘方的偏好整体换了方向：66% 最看重候选人能否发现并修复 AI 的错误，56% 关心能否解释技术取舍与正确性，只有 7% 认为异步技术测试最能反映实际工作能力。
  • 已经这么做的同行。Canva 去年重设 Backend、Frontend 与机器学习岗的技术面试，明确要求使用 Copilot、Cursor、Claude 等工具，因为团队此前发现把传统计算机基础题直接交给 AI，AI 几秒就能给出带完整解释的正确答案；改题之后，Canva 发现表现最好的人通常不会把整个任务交给 AI，而是主动控制问题边界、只把合适的子任务交给模型、持续审查并在模型犯错时迅速接管。OpenAI 走混合模式；月之暗面的做法是不阻止候选人用 AI，而是设计必须由人机协作完成的任务并故意留下问题，看候选人能否识别发生了什么。

这为什么值得看。这是 AI Coding 少被盯住的一个后果：当模型能做题，题目就失去筛选力，而重写考题这件事本身要滞后好几轮模型迭代。Hume 那条时间线是这轮最硬的证据 —— 一年多里同一套测试被模型逼着改了三次，每次改的方向都是「让题目更像模型没见过的东西」，到最后作者不得不承认与真实工作的相似度被牺牲掉了。这不是「AI 让人变懒」的话题，是测量工具跟不上被测对象的话题。

它与 10-28 ① 构成同一天的两幕：那一期是审批权落到了 agent 手里（十个前沿模型里九个自己去邮箱捞验证码批准自己涨额度），这一期是考核人的那把尺子被证明作废。「谁来把关」正在整体重写：机器那一端的把关权在松动，人这一端的把关标准在失效。

而 Karat 与 CoderPad 那组数据把这件事从个案推成了分布：美国只有 38% 的企业允许现场面试用 AI，中国是 68%，62% 的组织仍然全面禁止。同一个技术事实，在不同组织里被翻译成完全相反的招聘政策——这比任何一家公司的做法都更能说明当前的混乱程度。另一个值得留意的转向是偏好本身：允许 AI 之后，最被看重的能力从「写出来」换成了「看出来 AI 写错了」。

口径提醒。这是 Rieseberg 负责的一个团队的做法，他本人也承认没有找到完整替代方案。Anthropic 官网至今仍显示有技术岗使用 Colab、CodeSignal 做 Live Coding，候选人 AI 使用指南也规定 take-home 测试默认不能使用 Claude、Live Interview 默认不允许 AI 辅助（除非另有说明）—— 所以「取消编程面试」不能读成公司政策。Hume 团队那套 take-home 的原始样本约 1000 人候选人，是性能工程这一特定岗位的选择，不代表通用招聘。Karat 样本为 400 名工程负责人（覆盖美、印、中三国），CoderPad 样本约 650 人，两者口径与抽样方式不同，不能相互印证也不宜合并成一个比例。「超过一半候选人直接交给 Claude Code 成绩更好」说的是那套 2024 年起设计的加速器优化题，不是任何编程题。

可以行动。如果你的团队还在用算法题筛人，值得做一次小成本自检：把手上的题库原样交给你们日常用的模型跑一遍，看有多少题会被直接做出来 —— 这个成本远低于换一套考题。如果要换方向，CoderPad 那个「66% 招聘方最看重能否发现并修复 AI 错误」比任何新题库都更值得当设计依据：给候选人一个埋了错的 AI 生成代码仓库，观察他能不能揪出来。同时别忽略 Rieseberg 自己提出的那个真正的瓶颈 —— 新人往往在简历筛选阶段就没机会展示，所以简历之外的评估环节（作品集、小型原型、开源贡献）比改考题更值得投入。

智元给物理 AI 发第一把尺子：Worken = 活跃机器人数 × 自主工作时长 × 产出效能比，同日披露累计下线 2 万台

具身智能
2026 智元创新日（AIGBOT INNOVATION DAY，10-29 上海世博中心）；每日经济新闻现场报道（10-29 10:23）、凤凰网科技、中华网财经、新浪财经；《2026 具身智能产业创新报告》（新华社中国经济信息社联合中国信通院上海工创中心编制）

今天上午这场发布会里最值得记的，不是新硬件，是一个公式。

  • Worken（有效智能工时）。智元联合创始人、总裁兼 CTO 彭志辉提出用「马力度量蒸汽时代的力量、千瓦时度量电力时代的能量、token 度量数字 AI 时代的思考」这套类比，主张物理 AI 需要自己的度量衡，于是给出：Worken = 活跃机器人数量 × 自主工作时长 × 产出效能比。定位是在「制造数量」之外，衡量机器人能否自主、持续地完成有价值的工作、实际创造了多少成果。
  • 同场三个硬数字。通用 AI 机器人累计下线突破 20000 台（9 月已实现单月下线）；2026 年上半年营收接近 20 亿元，成为收入最高的通用机器人公司（作为对照，智元 2025 年全年营收为 10.5 亿元）；全球人形机器人市场份额 43%。
  • 仿真与真机。升级版 Genie Sim 仿真平台突破柔性物体仿真瓶颈，在覆盖 4 款机器人本体、22 项复杂任务的零样本对照测试中，仿真与真机任务得分相关性达 96.7%，覆盖场景重建、数据采集、自动评测、后训练与开放世界探索全链路。
  • 模型榜单。GO-3 Nano Preview 以 85.01% 的平均成功率登顶 RoboTwin 双臂协同与环境泛化榜单。
  • 配套报告。《2026 具身智能产业创新报告》由新华社中国经济信息社联合中国信通院上海工创中心编制，构建产业发展分析框架与领军企业评估模型，智元入选领军企业案例，其 Worken 指标与部署态实例被纳入报告分析。

这为什么值得看。Worken 的意义不在公式本身，而在它出现的时机与位置。在出货量口径已经四套打架之后（IDC 近 2.5 万台、Counterpoint 超 2.2 万台、SAG 约 1.91 万台、弗若斯特沙利文 3.6 万台销量口径，互不可加），行业缺的不是又一种产量统计，而是一种能把「造了多少台」换算成「干了多少活」的换算方式。这个公式的三个因子里，前两个今天就能观测，第三个「产出效能比」还没定义 —— 它是全篇最关键的未完成部分。

更值得注意的是它的发布场合：Worken 与一份由新华社中国经济信息社和中国信通院上海工创中心编制的产业报告同时发布，且智元的 Worken 指标被写进了这份报告的分析里。这是「企业定义指标 + 官方研究机构背书 + 报告收录」的组合，和 10-25 ⑤ 那期「110 台零失误交给吉尼斯而不是厂商自证」是完全相反的方向 ——那期是外部第三方出题，这期是行业自己出题。从「验证权交出去」到「验证权收回来」，只隔了四期。

Genie Sim 的 96.7% 则是这条线上少见的硬承诺：如果仿真与真机任务得分真的能对到 96.7%，那么「先在仿真里把机器人训到能上岗」就不再是行业口号，而是一条成本低得多的路径。不过这组数字目前只有智元自己发布。

口径提醒。「产出效能比」没有公开定义与计算口径，「活跃机器人数量」是否包含已交付未部署、是否包含租赁与科研机，也都没有说明 —— 这两项决定了 Worken 在不同公司之间是否可比，目前还无法验证。另外，43% 的全球份额与前述四套行业口径不可横向比较（统计方法与「什么算人形」的界定不同）；上半年「接近 20 亿元」是模糊表述，且智元未上市，其营收口径与宇树、优必选等上市/披露主体的口径不能直接比。Genie Sim 的 96.7% 是智元自家平台、在自家 4 款本体 22 项任务上的零样本对照测试，第三方尚未复现。10-28 ⑤ 提到的 11 月 2 日至 3 日六台 G2 便利店 24 小时直播尚未发生，本期的价值在机制与口径，不在成效结论。

可以行动。Worken 给了一个可以直接借用的模板：把「部署了多少台」换成一个含工作量的指标。判断一个场景是否值得投机器人时，可以套这个三项结构自己算一遍 —— 设备数好数、自主工作时长要靠现场记录、而产出效能比需要先跟业务方约定什么叫「一件活」。第三项恰恰是大多数场景现在最缺、也最该由业务方参与定义的东西。同样值得跟进的是 Genie Sim 的 96.7%：如果第三方能复现，仿真预训练的成本优势会显著改变中小团队的路线选择。

阿里高德开源 λ0 全身基座模型：只喂人类第一视角视频，真机 62.5%，但把训练数据那一半锁进仓库

具身智能
arXiv:2610.18950《λ0: Scaling Open-World Egocentric Human Data for Humanoid Loco-Manipulation》（10-13 上线，10-23 起开源）；项目主页与 GitHub（LambdaHumanoid/openlambda，Apache 2.0）；Pandaily、TechNode、动点科技、aiweekly 报道

λ0 要解决的是具身智能最贵的那一环 —— 数据。做法是绕开机器人本体。

  • 采集方式。称为「无本体全身数据采集」：采集者佩戴消费级设备（GoPro HERO13 相机、Pico 4 Ultra 头显、全身追踪器、双手用 BrainCo Revo2 灵巧手）正常走动与操作，同步记录第一视角视频、全身骨架与手部关节三路信号，机器人不必到场。代表性任务的单条示范采集耗时从约 100 秒压缩到 29 秒，吞吐提升约 3.4 倍。
  • 数据集与训练。HumanVerse-500 含 500 小时开放世界全身动作数据、32,993 个 episode、8700 万 pose frames，覆盖 18 类以上任务与 827 种技能，场景涵盖家庭、商店、工厂、办公室与户外。训练分三阶段递进：手部交互、全身协调、人形本体；底层是 Qwen3.5-2B 视觉语言骨干加 SONIC 全身控制器，并通过视角匹配与「由粗到细」的动作对齐机制处理人机形态差异与末端接触偏差。
  • 结果。SIMPLE 仿真基准约 90%。真机在 Unitree G1 上做零样本迁移，四类移动操作任务 40 次尝试成功 25 次，成功率 62.5%，最强外部基线 π0.5 为 40.0%，高出 22.5 个百分点。
  • 最硬的一个数字是消融。把 HumanVerse 中训阶段从配方里拿掉，真机成功率从 62.5% 掉到 22.5%。这是团队自己跟自己比，不受换机器人、换对手模型的干扰，指向的是「是人视频在扛结果，不只是架构」。另一条规模结论同样关键：在机器人示范量固定的前提下，人类全身数据越多，真机表现越好。
  • 开源到什么程度。代码为 Apache 2.0，数据采集硬件配置代码与部分样本数据公开；但 README 明确写着 HumanVerse-500 训练数据不包含在本次代码发布中，最终阶段训练与真机部署流程「尚未发布」，早期阶段代码不保证端到端复现结果。

这为什么值得看。遥操作采集一直是人形机器人的天然护城河 —— 谁有遥操作设备、谁能雇得起标注员，谁就有数据。λ0 提的反命题是：第一视角的人类视频加上一套对齐机制，能不能替代遥操作。消融给出的答案相当硬（62.5% 掉到 22.5%），规模结论也直接指向成本曲线的重写。

它和 10-28 ④ 那条正好构成两条独立的降本路径：Genie 4 是「用仿真环境替代真机数据」，λ0 是「用人类视频替代真机数据」。两条路都不经过真机采集这个瓶颈。如果其中任何一条被独立复现，硬件厂商在遥操作设备上的先发优势就会被削弱 —— 而这个赛道的硬件玩家，恰恰是靠这套设备把数据变成壁垒的。

但真正需要盯的是另一面：开源的是代码，不是数据。这意味着其他团队可以跑 λ0 的推理，却不能按原配方重训模型，因此 62.5% 与 22.5% 这组对比目前仍然是团队自己的话。外加发布材料里没有记录参与者知情同意与伦理审查 —— 500 小时的第一视角人体动作数据涉及肖像与行为隐私，开源社区对这类数据的处理惯例（如 EgoHumanoid-V2、EgoAlign 等前作）通常会附参与者同意说明，这一份没有。

口径提醒。62.5% 意味着在日常任务上机器人超过三分之一的尝试是失败的，这是研究结果不是可用产品。与 π0.5 的对比样本很小（四任务各 40 次、每任务 10 次），论文没有报告置信区间，且对照模型由团队在自己的机器人上运行 —— 换机器人或换对手都可能改变差距幅度。消融的 22.5% 与头条的 62.5% 是同一套设置下的自比，可信度高于跨模型对比，但同样只在原机器人上成立。开源部分不含训练数据、最终阶段训练与部署流程未发布、早期代码不保证复现，这一点在 README 里写得很清楚。此外，另有报道称项目由高德与阿里 ATH 事业群联合发布，署名归属在不同渠道表述略有出入，以论文与项目主页为准。

可以行动。这条最有价值的部分其实是方法而不是权重，可以直接借用：「无本体采集 + 视角匹配 + 由粗到细对齐」这套流程与自家遥操作数据做一次对照，看人类视频在自己的任务上能替代多少比例 —— 注意要像 λ0 那样做消融，而不是只比端到端成功率，否则分不清收益来自数据还是来自对齐工程。另外，如果打算用第一视角人类视频做训练，数据治理的功课要提前做：参与者同意、肖像与行为数据的用途边界、以及原始视频与提取骨架的保存策略都得在采集前谈好，不要等开源或发论文时再补。

今日整体 今天五条主榜里有四条半讲的都不是能力，是「怎么算」：模型侧换了 AA Index v5 并首次把 60% 权重放到私有数据上（①），代码侧给出了第一个全站口径并自认是下限（②），人的侧发现考题已经拦不住模型于是取消（③），机器人的侧干脆自己发明一把度量衡（④），而训练侧那条最硬的证据（62.5% → 22.5%）来自一次自比消融（⑤）。承 10-28「把关者自己开始说了算」，本期往前走了一步：把关的人正在各自造尺子，而每把新尺子推出当天，就有人在查它准不准 —— 10-26 的基准审计、10-28 的 IaC 实证与今天的 v5 换版、Worken 自制，是同一件事的四个切面。下一期要问的是：当尺子可以自己造、自己换、且厂商与验证者往往是同一批人时，还有什么能提供外部锚点。
