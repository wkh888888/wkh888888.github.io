Grok 4.7 上线：分数涨了、价格没变，但涨得最多的那项恰好是自家考场的，而每任务吐的 token 翻了一倍多

AI Coding · 考场归属
来源：x.ai/news/grok-4-7（9/21 美东）· 官方对比表 · Artificial Analysis 智能指数与 Coding Agent Index · Singularity.Kiwi / AI Tech Daily / TheOutpost / Decrypt · 中文聚合转述（9/22）

拖了一个多月的 Grok 4.7 终于上线，官方给它的定位很直接：「目前最强的编程与知识工作模型」。上线渠道铺得很满——Cursor、Grok Build、Grok API、GitHub Copilot，覆盖 VS Code、Visual Studio、JetBrains、Xcode、Eclipse。

价格确实是它最硬的牌：输入 2 美元 / 输出 6 美元每百万 token，与 4.6 完全持平，对比 GPT-5.6 Sol Max 的 4/20 与 Fable 5.1 Max 的 10/50；另有输出速度翻倍、价格也翻倍的快速版（4/12）。

官方跑分里进步最亮眼的三项：Terminal-Bench 4.0 从 20.3% 升到 38.0%（接近翻倍）；EEBench 电气工程 53.0% → 64.0%（超过 Fable 的 56.4% 与 Sol 的 39.4%）；Harvey 法律 Agent 19.6%（Sol Max 只有 2.5%）。其余：CursorBench 4.0 46.3%（4.6 为 40.4%，Sol Max 41.7%，Fable 5.1 Max 51.8%）；DeepSWE v1.1 71.0%（4.6 为 65.2%，Sol Max 72.7%）；AA-Briefcase 多小时办公 1546 → 1657（Fable 1678）；HealthBench Pro 56.7%。窗口 500K。

但把两份口径叠起来看，故事就变了。Artificial Analysis 只给了 46 分的智能指数，落后 Fable 5.1 Max、Claude Opus 5、GPT-6 Astra、GPT-5.6 Sol Max 与 Meta Muse Spark 1.3 Max；它自己实测的 Terminal-Bench 约 26%，而 Astra xHigh 是 59.6%、Opus 5 约 49%。更关键的是账：AA 测出 Grok 4.7 xHigh 每个任务输出约 81,000 token，4.6 High 是 36,000，GPT-6 Astra Max 只有 27,000——比自家上一代多 125%，比 Astra 多 196%；跑完整轮指数评测累计吐了约 2.4 亿 token，中位数是 9,200 万。标价没涨，但每个任务可能更贵。

于是「最强编程模型」这个说法的成色，就取决于你认哪个考场。Grok 4.7 相对 4.6 领先幅度最大的 CursorBench，由 Cursor 自建，而 Grok 4.7 首发即进入 Cursor；中文聚合称 SpaceX 已于上月收购 Cursor（该说法未能在权威源核实）。而在第三方独立口径下，它只比上一代高 2 分、且明显更啰嗦。官方自己的措辞其实很克制——「在价格性能比上处于前沿」，不是全面领先。

还有两个值得记的信号。一是竞争单位变了：官方把「在困难任务上工作更久、更仔细地检查自己的作业」写进公告，长任务稳定性正在取代单次问答正确率成为卖点；Box 给的理赔案例是模型核对一笔 200 万美元索赔，找出 8.2 万重复发票、6.4 万遗漏抵扣和一个可能相差 14.3 万的免赔额问题。二是延迟的性质变了：4.6/4.7 原定 8 月，一再推迟， reportedly 卡在额外的强化学习调优上——不是算力不够，也不是评测没做完。

为什么值得关注：这条的价值不在「谁更强」，而在它把「这是谁家考场的成绩」这个问题摆成了明面上的必答题。过去两年我们习惯把厂商对比表当事实表读，但今天同一款模型在两个考场里的差距足够大：官方表上 Terminal-Bench 是 38.0% 且「接近翻倍」，AA 实测是约 26% 且排在 Astra 与 Opus 5 之后；官方表上领先幅度最大的是自家渠道自建的 CursorBench。当模型发布方同时拥有考场、阅卷权和分发渠道时，跑分就不再是测量，而是营销素材。

第二个更实用的点是token 账。AA 那个 81,000 vs 27,000 的数字意味着：在长任务 agentic 负载下，「$2/$6」这个标价几乎不携带信息，真正要做决策的是「每个任务多少钱」。这跟 09-14 那条「同模型不同工具账单差 70 倍」是同一件事在模型侧的复现——单价便宜和任务便宜是两回事。

三条立刻可落地：① 看任何模型发布会，第一句先问「这是谁家考场」——厂商自建基准只配当参考项，必须有第三方独立口径对照才能进决策。② 评估成本一律换成「每任务美元」而不是「每百万 token 美元」，尤其对长任务 agentic 负载，啰嗦的模型会把标价优势吃干净。③ 把「长任务稳定性」单独列成验收项（跑完 20 步、50 步之后还记不记得原始目标），它正在取代单次正确率成为真正的差异点。

口径修正（重要）：① 2.1 万亿参数（较 4.6 的 1.5 万亿增约 40%）出自 Decrypt 等媒体报道，未见于 xAI 官方公告，采用前请自行核对。② 「SpaceX 已于上月收购 Cursor」仅见于中文聚合，未能核到权威源，本条不作事实陈述。③ Terminal-Bench 的 38.0% 与约 26% 分属不同口径（官方 High Effort 自测 vs AA xHigh 实测），不要混用。④ 81,000 / 36,000 / 27,000 是 AA 智能指数评测下的输出 token 量，不是你的生产负载，只用于横向比较相对量级。⑤ Grok 4.7 9/21 美东发布、9/22 凌晨进入中文视野，本条按当日发布处理。⑥ 本条不含 CursorBench 之外其他自建基准的归属核查。

智谱 ZCode 静默打包整个工作区上传：4.2 万文件里 .git 占 86.6%，加密私钥只在服务端，72 小时后开源自救

Agent 安全 · 数据边界
来源：ferstar 逆向报告（blog.ferstar.org，9/18）· 第一财经《一个 313MB 加密包，撕开智谱等 AI 编程工具安全暗门》（9/21）· 凤凰 WEEKLY 财经 · 华尔街见闻 · 红星资本局 · 界面新闻 · 观察者网 · 新浪财经 · 智谱 ZCode 官方公告与 GitHub 仓库 zai-org/ZCode

这一切的起点是一次磁盘清理。9 月 18 日，付费订阅用户 ferstar 在清理一台 256GB MacBook Air 时发现 ~/.zcode 占了 700 多 MB，里面躺着一个 313MB 的加密包。照旁边那份明文清单统计，包里有 42,411 个文件，其中 .git 目录占 86.6%——LFS 缓存 56.8%、Git 对象库 29.6%、reflog 0.2%，真正的源码和文档只有 13.4%。

加密本身挑不出毛病：内容走 AES-256-CTR，密钥再用 RSA-OAEP 包一层。问题出在钥匙上——公钥由服务端随上传凭证临时下发，私钥从不下发。ferstar 拿本机所有私钥去解那层信封密钥，全失败。也就是说，连用户本人都打不开这个从自己硬盘上生成的包。那个 313MB 的包因为太大连续失败 564 次，一直卡在本地重试队列；删掉也没用，半小时内会重新打包一份，计数从 564 变成 565。

整条链路是这样的：客户端先向 zcode.z.ai 申请 /api/v1/snapshot/upload-credential，服务端回一串 阿里云 OSS 表单签名 + 动态 object key + 大小上限 + 本轮 RSA 公钥；本地 tar.gz 打包并流式加密后表单直传 OSS，绕开智谱自己的业务服务器，OSS 再回调后端登记。

最扎手的是关不掉。设置里两个看起来相关的开关，逐一比对代码后发现都不管这件事：「优化体验」只控制数据是否授权用于模型训练，「仓库快照索引」只控制服务端收到后要不要建索引——打包和上传照常跑。负责捕获和上传的 sidecar 在客户端启动时被无条件实例化，唯一前置条件是登录态；触发点是每次向 AI 提问之前和任务结束时，单个活跃会话最多记录到 62 次捕获。

企业侧的对账更硬。9 月 19 日，太原承明科技公开发函（承明〔2026〕法函字第 1 号），称独立取证确认上传系自动触发、批量发生：6 个工作区、34,549 个文件、约 425MB，其中最大的「客户端默认工作区」打包于 9 月 14 日 22:57:06，涉及 32,932 个文件、约 4.11 亿个明文字符，含完整源代码、系统架构、版本控制全量历史、数据库访问口令、云服务凭证及证书、员工个人信息。函件还指出：9 月 18 日 00:28:33 仍检测到上传行为，而客户端当时已是 3.12.3 版本；并提出网络请求指向注册于新加坡的实体，质疑数据出境。智谱相关人员对红星资本局的回应是四个字：「不实消息」。函件共 12 项要求，限期 10 月 10 日前书面答复。

智谱的应对是72 小时三步：9/18 群内致歉（归因「代码库索引」功能，称 Wiki 生成后数据立即销毁）+ 补偿一次周额度重置；9/19 推 v3.14.0，更新日志「问题修复」栏第一条写着「修复仓库百科异常上传的问题」；9/21 正式开源（Apache-2.0，github.com/zai-org/ZCode）并公布两份第三方审计——中国信通院确认 zcode-prod 阿里云 OSS 存储桶处于「云端零数据」状态，绿盟科技确认桶内全部数据对象及存储桶本身已删除、v3.14.0 未发现可触发本地仓库快照或文件外发的功能路径。9/20 晚，MaaS 平台上线「数据内容不留存」（Batch API、Files API 及法定 30 天留存为例外）。

开源首日 GitHub 破 5.5k star、1.6k fork，但仓库只有两次提交：一次空的初始提交，一次一次性导入 6,973 个文件的 feat: open source，Issues 是关着的。股价同步反应：9/21 港股盘中一度跌 5.58%，界面新闻发稿时报 742.5 港元、跌超 4%，总市值约 3,620 亿港元。

还有一处耐人寻味的痕迹：华尔街见闻翻出更早一条——9 月 16 日的 v3.12.2 更新日志里写着「优化仓库快照上传的内存占用」。一条「意外行为」，不会有人专门去优化它的内存。而核对官方更新日志页，现在能找到 3.11.2（9/4）和 3.12.3（9/17），唯独没有 3.12.2。

为什么值得关注：这是 AI 编程工具第一次被逐字节拆解它到底拿走了什么，而答案是「几乎全部」。.git 占 86.6%、源码只占 13.4% 这个比例是整条事件的题眼：企业 Git 仓库里同时存在未发布功能、客户信息、内部架构、部署配置，以及历史提交中已经删除的密钥。用户以为自己授权的是「AI 读取完成任务所需的代码」，实际发生的是整个项目完整「底裤」离开本机，而且用户连打开验证的钥匙都没有。

第二个要点是「开源」到底证明了什么。智谱这 72 小时的应对（致歉 → 修版本 → 开源 → 两份第三方审计 → 数据不留存）在同类事件里算相当完整，速度也值得肯定。但把结论说清楚：把中转桶删掉，能证明的只是这个桶现在是空的。9 月 18 日之前究竟传了什么、有没有落进备份、谁还能解开那些密文，外部既无法倒推也无法证伪——而且这两份审计是厂商自己邀请的第三方做的。更现实的一条：开源的版本不是用户当时运行的那一版，如果用户真正跑的那一版与开源版本存在差异，审计的价值就要打折。

第三个要点是这不是孤例。今年 7 月安全研究者 cereblab 对 Grok Build CLI 抓包：一次 12GB 测试仓库，模型请求通道传输约 192KB，存储通道实际上传约 5.10GiB，差约 2.78 万倍，马斯克承认属实并承诺删除、随后服务端关闭上传并开源。此外 GitHub Copilot 自 4/24 起默认可将代码片段用于训练、Cursor 代码库索引默认开启且曾修高危逻辑漏洞。共同点不是某一家坏，而是「权限扩张的速度远快于边界设计」。

四条立刻可落地：① 企业采购 AI 编程工具，把「数据出站可见、可控、可审计」写进准入项，而不只是加分项——重点问三件事：上传什么、谁能解、保存多久。② 别信界面开关。去抓包验证，看是否有独立于模型推理通道的存储/上传通道；这次两个开关都不管这件事。③ 对已使用的工具，做一次本地目录体积排查（ferstar 就是从清理磁盘发现的），失败重试队列里可能就躺着证据。④ 把 .git 目录与含凭证的配置文件纳入出站敏感清单——泄漏价值最高的往往不是当前源码。

口径修正（重要）：① 42,411 文件 / 313MB / 564 次失败来自 ferstar 个人逆向记录；34,549 文件 / 约 425MB / 6 个工作区来自 承明科技单方取证，两组数字分属不同主体与不同工作区，不要混用。② 「上传数据立即销毁」「从未用于模型训练」是厂商口径；信通院与绿盟的两项审计由智谱邀请，且其结论只覆盖「当前存储桶为空」与「v3.14.0 无可触发路径」，不能回答历史传输记录、访问权限与密文是否曾被解密。③ 「数据出境至新加坡」为承明科技单方指控，智谱对媒体回应「不实消息」，截至发稿无监管结论。④ 「v3.12.2 更新日志含『优化仓库快照上传的内存占用』」由华尔街见闻报道，该条现已无法在官方更新日志页检索到，采用前请自行核对。⑤ 智谱 2026 上半年营收 9.54 亿元、开放平台及 API 贡献 8.25 亿元（占 86.5%）来自半年报，与本次事件无因果关系，仅作商业背景。⑥ 本条未亲测，机制描述全部来自逆向记录、媒体核对与官方文本。

桌面入口同日三发：Kimi Code Desktop、阿里 Qoder 登鸿蒙 PC、华为云码道上鸿蒙编码大模型——卖点从「更强」换成了「看得见」

AI Coding · 入口之争
来源：kimi.com/code 与 Moonshot 官方发布说明（9/21）· 界面新闻 / 网易科技（Qoder 上线鸿蒙 PC）· 华为云码道 CodeArts 官方公告 · 第一财经（Kimi K3 接入 Amazon Bedrock）· AlphaSignal · 虎嗅《Kimi 向左，Claude、GPT 向右》（9/19）· 中文聚合（9/22）

9 月 21 日同一天，三家把 AI 编程的入口往前推了一格，抢的是同一个位置：开发者每天打开的第一个窗口。

Kimi Code Desktop 1.0 上线，macOS（Apple Silicon 与 Intel）和 Windows 同步，入口 kimi.com/code。它不是把 CLI 套个壳——用的是同一个 agent core，Desktop、CLI、VS Code 插件三者共存、共用本地设置与订阅体系，老 CLI 用户的本地任务会直接出现在桌面端。模型是旗舰 K3（2.8 万亿参数、最高 1M 上下文）。

真正值得看的是它把「授权级别」做成了产品。四档工作模式：Plan（先出方案、确认后动手）、Goal（围绕目标长程推进，可暂停/恢复/取消）、Swarm（主 Agent 拆任务调度 Subagent）、Tower（实验性，多 Agent 并行，需显式 /tower on 或 /tower base-branch 才启用）。三档权限：Always Ask / Ask When Needed / Never Ask。界面把工具调用、执行进度、逐文件逐轮 diff、终端输出、内置浏览器、Git 状态与 PR 状态全放进一个窗口，还支持截图标注「指哪改哪」。另外它不绑自家模型——可配 Anthropic、OpenAI、Google 及 DeepSeek、千问等兼容接口；secondary_model 子代理默认开启，可通过环境变量或配置项关掉。

阿里 Qoder 同日登陆鸿蒙 PC 应用市场，成为鸿蒙 PC 生态首款 AI 编程智能体工作台：内置多款模型并用智能路由平衡效果与成本，接入近 200 个连接器、70 多个插件、2 万个技能，全球用户超 600 万，任务从编程扩展到文档处理与数据分析。

华为云码道 CodeArts 同日面向鸿蒙开发者一次上线三项能力——鸿蒙编码大模型 + 码道鸿蒙智能体 + 鸿蒙开发者实践中心，官方称其为「全球首个且唯一专为鸿蒙生态打造的 AI 编码智能体」。模型融合超百万鸿蒙原素材、10 万+ 高质量数据，高频开发场景组件覆盖 100%，与 ArkTS 及鸿蒙开发范式深度适配。官方四个数字：千行代码错误率降低 80% 以上、一次编译通过率提升 78% 以上、单次任务 Token 消耗降低 20% 以上。智能体内置 DevEco CLI，可直接调用鸿蒙端侧模拟器。鸿蒙已注册开发者超过 1,100 万。

同日还有一条相关动作：Kimi K3 接入 Amazon Bedrock，此前传闻的与海外云厂商收入分成合作正式落地（国内此前已上架阿里云百炼并达成类似合作）——这是中国大模型公司首次以分成模式向全球头部云输出模型能力。

时间线上有个耐人寻味的巧合：ZCode 静默上传事件 9/18 曝光，三天后 Kimi 上线 Desktop，官方通稿反复强调「清晰可见、随时可控，Agent 执行任务的每一步都能看到」。中文聚合据此解读为「针对信任问题设计」——这是媒体解读，不是官方表态，但方向值得记：CLI 里 Agent 干了什么要敲命令翻日志才能还原，图形界面把过程做成默认展示，可见性从「用户自己去挖」变成「系统默认给你看」。

为什么值得关注：三家同日抢入口，说明 AI 编程的产品形态正在收敛为「桌面客户端 + 多 Agent 编排」。命令行只服务极客，网页端只能问答，只有桌面端能同时握住文件系统权限、终端、浏览器和 PR 状态——这恰好是一个能独立跑完整任务的 Agent 所需的最小闭环。

但比形态更重要的转向是卖点变了。过去比的是「模型多强」，今天比的变成「你敢不敢让它干」。Kimi 把授权做成四档模式 + 三档权限、把 diff 和工具调用做成默认可见；华为把「一次编译通过率」这种生态内可验证指标当主数字——这两条指向同一件事：当 Agent 能力越过某个阈值，瓶颈就从「能力」滑向「授权」。

还有一条容易被忽略：Kimi 不绑自家模型。它把自己定位成「多模型开发工作台」——你不用 Kimi 的模型，也可能为了这套执行界面留下。这是入口之争里更聪明的一种打法：赌界面而不是赌模型。

三条立刻可落地：① 选型时把「权限分级粒度」列为硬指标——能否按任务风险切换（先出方案 / 长程推进 / 多 Agent 并行），比模型跑分更能决定你敢把它用在哪个仓库。② 优先选过程默认可见的工具：工具调用、diff、终端输出、Git 与 PR 状态应在同一个窗口里，而不是要你去翻日志。③ 关注「一次编译通过率」这类生态内指标——通用榜单可以被刷，垂直生态里的编译/规范通过率是更难短期反超的壁垒。

口径修正（重要）：① 「Kimi 针对 ZCode 信任问题设计」是中文聚合结合时间线的解读，非官方表态，仅作观察角度。② 华为云码道的「错误率降低 80%+、编译通过率提升 78%+、Token 降低 20%+」均为官方自测口径，未披露测试集与基线，不要与第三方榜单混用。③ 「全球首个且唯一」「首款」均为厂商自我表述。④ 鸿蒙注册开发者超 1,100 万、Qoder 全球用户超 600 万来自厂商公布，非独立统计。⑤ 反向坐标需一并看：虎嗅 9/19 指出 Kimi 已有 Kimi Work 桌面端、现在再做 Code 是「做加法」，而 Claude 把 Chat 与 Cowork 合并、ChatGPT 把 Codex 并入桌面应用是在收敛——入口之争的终局是收敛还是分裂，尚无定论。⑥ 本条三家均为 9/21 发布，9/22 进入中文聚合视野。

清科灵境 OASIS WAM 登顶 RoboLab：考场是英伟达的，成绩由平台实测，不是团队自己交的

具身智能 · 交出考场
来源：36 氪《中国具身智能又跑出一匹黑马：清科灵境 OASIS WAM 登顶 RoboLab》（9/21，腾讯新闻转载）· RoboLab 全球高保真仿真基准平台榜单 · 清科灵境官方资料与商业计划书要点 · 开放原子开源基金会（Dora 捐赠）

RoboLab 全球高保真仿真基准平台公布最新排行榜，在覆盖 120 个视觉-语言-操作任务的综合评测中，由清科灵境（Synkrotron）联合中国科学技术大学研发的 OASIS WAM（世界动作模型）拿到综合排名第一。

先把这份榜单的性质说清楚，它才是重点。其一，RoboLab 基于 NVIDIA Isaac 与 NVIDIA Omniverse 构建——考场、考题、阅卷都在英伟达手里。其二，它采用动态随机生成场景、可变语言指令、可控环境扰动，没有固定训练题库，靠背规则刷不了分。其三，本次成绩是清科灵境开放调用接口、由平台实际完成测试确认后形成的，而不是团队自行提交的离线分数。

同榜对手包括 NVIDIA、Google、Physical Intelligence 等头部团队，OASIS WAM 是榜单上唯一的中国团队。

技术上，WAM 接收机器人当前 RGB 图像、关节状态、夹爪状态以及语义指令，生成一段连续动作，同时预测这段动作执行过程中场景的视觉变化，并与高层 VLM 协同解决任务级推理——比如「四块积木该按什么顺序叠」这类问题。低层动作模型能学会「抓住积木、移动到目标位置、松开夹爪」，却未必能理解四个动作之间的任务顺序，这正是 WAM 想补的那一层。

公司背景：清科灵境 2019 年由姚期智院士孵化（前身为深信科创），创始人兼 CEO 杨子江为宾夕法尼亚大学博士、中国科学技术大学计算机学院教授，联合创始人兼 CTO 潘余曦曾任 Cisco、Uber 数据科学团队负责人，首席科学家 Moshe Vardi 为多院院士。技术底牌三张：WAM 世界动作模型、混合数据平台、Dora 机器人原生操作系统——Dora 于 2022 年联合 Futurewei 推出并捐赠开放原子开源基金会，官方称时延 0.9μs、比 ROS2 快 17 倍（另一口径为「时延降低近 20 倍、内存占用减少 90%」）。产业侧：与工信部电子第五研究所共建「场景训练—性能验证—标准输出—产业推广」闭环，与星海图签署 AI4S 科学具身战略合作，已在医院及第三方检测机构用于血液样本检测。

为什么值得关注：这条的分量不在「赢了谁」，而在「考场是谁的」。具身智能这一年最不缺的就是演示视频，缺的是可复现、可复测的工程证据。RoboLab 这次的三重约束——考场在英伟达的 Isaac/Omniverse 上、题目动态随机生成、成绩由平台实测而非自提交——把「自说自话」的空间压到了最小。在对方的考场里拿第一，比在自家演示里拿满分难一个数量级。

它和今天第 ① 条恰好构成正反两面：Grok 4.7 是在自家渠道自建的考场里刷出最大涨幅，OASIS WAM 是把考场交给对方还拿了第一。同一天，两种截然相反的取证方式，而这个对比本身比任何单项成绩都更能说明「分数该怎么读」。

当然也要看到边界：这是仿真基准，不是真机。官方与 36 氪都未公布具体分数，也没有给出真机或产线上的对应表现。真正要等的是下一步——仿真成绩能否与真实产线对齐。

口径修正（重要）：① 官方与报道均未公布 OASIS WAM 的具体分数，只有「综合排名第一」，任何具体数值都应视为未披露。② 该成绩是仿真基准结果（NVIDIA Isaac + Omniverse），不等于真机表现，Sim2Real 差距未给出。③ Dora 的性能口径两套并存（「0.9μs / 比 ROS2 快 17 倍」与「时延降低近 20 倍、内存占用减少 90%」），出自不同官方材料，不要混用。④ 「榜单上唯一的中国团队」「世界动作模型国内进展最快」为报道与厂商表述。⑤ 本条 36 氪 9/21 首发，榜单具体统计截止日未披露；榜单名次会随时间变动，引用时请注明时间。⑥ 公司背景部分（姚期智孵化、团队履历、产业合作）来自公开资料与商业计划书要点，非本次榜单披露内容。

大晓机器人进加油站便利店：75 厘米通道、2 米高货架，具身智能开始接「排班」而不是接演示

具身智能 · 真实验收
来源：科技日报（9/21）· 新浪财经 · 上观新闻 / 解放日报 · 中国石油上海销售公司 · 大晓机器人官方资料

9 月 21 日，大晓机器人与中国石油上海销售公司宣布达成战略合作，启动首个加油站便利店场景的全闭环具身智能机器人项目，首店 昆仑好客便利店（中国石油振兴店）已进入试运营。

流程是打通的：消费者美团下单 → 订单经中国石油数智平台进入作业系统 → 机器人依据订单与库存信息完成商品识别、拣选、搬运、打包与放置，并同步更新订单状态；到店消费场景下，机器人也参与商品取放与履约准备。运营环节覆盖商品仓储、分拣、补货、上架、订单拣选及装箱履约，打通「前置仓—门店—订单」链路。

关键在约束条件：75 厘米宽的通道、2 米高的货架。这不是实验室里摆好的台面，而是便利店最难看的那部分活。

技术侧：开悟世界模型 Kairos 3.1 作决策系统，自研轮臂升降式履约机器人作执行终端，通过「晓满」即时零售场景解决方案接入中石油数智平台与门店业务体系。公司此前的家底包括环境式数据采集方案 2.0、具身超级大脑模组 A1，以及晓满、晓新、晓途三项行业级解决方案，走的是 ACE 研发范式（环境式数采 + 世界模型）。

双方明确说，下一步要验证的是多 SKU、高密窄仓、柔性包装、订单高峰等复杂条件下的稳定性，以及夜间和高峰时段的服务效率，并基于真实运营数据持续优化模型与本体，沉淀模块化、可快速部署的标准化方案。规模坐标摆在那：全国约 11 万座加油站、10 万余座公共充电站。

为什么值得关注：这条的价值是可量化验收。通道宽度 75 厘米、货架高 2 米、SKU 持续增长、订单波峰明显、夜间补货与高频理货——这些硬约束让演示式取巧彻底失效。你可以精心摆一次成功的视频，但没法在每天几百单、货位会调、商品会变、订单结构随时波动的门店里长期假装。

第二个要点是验收单位变了。前面几条讲「谁出题、谁阅卷」，这里出题的是真实业务：单店跑通不算数，要「从单店验证到网络复制」——也就是能不能排班。加油站便利店的价值还在于它同时具备三个属性：空间窄、SKU 多、营业时间长，恰好是仓储式机器人最难受也最需要人的组合。

第三个要点是数据回流。双方明确说要用真实运营数据持续优化世界模型和本体——这类场景的真正产出可能不是「省了多少人力」，而是一套别人拿不到的、带真实分布的动作语料。

口径修正（重要）：① 本条为战略合作 + 首店试运营，不是规模化部署；报道未披露机器人台数、单量、履约成功率、人效对比等任何量化运营指标。② 「全国约 11 万座加油站、10 万余座公共充电站」是行业公开数据的规模背景，不等于该项目可触达规模——首店之后能否复制到中石油上海乃至全国网络，官方表述是「计划」与「探索」。③ 「全闭环」「首个」均为厂商与报道表述。④ 「商汤科技联合创始人王晓刚任董事长、陶大程院士任首席科学家」仅见于聚合报道，本条未逐一核实。⑤ 大晓机器人的世界模型能力未披露第三方评测成绩，Kairos 3.1 的表现目前只有厂商口径。⑥ 本条 9/21 发布、9/22 进入聚合视野。
