一次例行维护让 OpenAI 全站停摆 211 分钟：两个只读副本同时失效、认证层被拖垮，峰值失败率 75%——能力越往上堆，越怕底座上一次不起眼的抖动

AI Coding · 基础设施
OpenAI 状态页复盘（美西时间 11-21 13:48 至 17:21）· 凤凰网 AI 日报 11-23 整理 · 赛迪顾问数据交叉

11 月 21 日美西时间 13:48 到 17:21，OpenAI 经历了一次持续 211 分钟的全站中断。触发点是一次例行维护：Primary API 所用的 Postgres 数据库两个只读副本同时失效，而这两个副本并非闲置备份，而是承担实时查询的承载组件。由于 Primary API 同时提供整个技术栈的用户认证与服务间认证，一次数据库故障被放大成了公司级中断，ChatGPT 与 API 请求失败率峰值达到 75%，付费与免费用户同时受影响。

  • 影响面：API 侧的 Chat Completions、Fine-tuning、Embeddings、Images、Audio、Realtime、Files 等接口，以及 ChatGPT 的对话、登录、搜索、文件上传与语音模式全线波及。
  • 恢复过程：跨区域拉起替换副本均未成功，最终与服务商协作在同一区域新建两个副本才恢复——容灾预案在真实故障面前没有按设想生效。
  • 后续动作：暂停同类维护、调整连接抖动配置、增加按比例摘流的功能开关，并测试 100% 流量走主库。

为什么值得关注：这是今天最容易被当成「运维八卦」略过、其实最该读的一条。所有 coding agent 都跑在这几家的基础设施上：你手里的 agent 能不能提交、能不能登录、能不能调工具，取决于一层你完全看不见的认证与数据库。能力再强，底座抖一下就全部归零。

把它和赛迪顾问在同一批报道里披露的数字放一起看更有意思——今年上半年国内智算日均投入超过 18 亿元、万卡级集群半年新增 10 个，但全国智算芯片平均利用率只有约 30%。供给侧在猛堆算力，可用性建设却还是老问题。11-15 ① 的密钥泄露也是同一个形状：一处失守，全局遭殃。

需要留意：211 分钟、75% 失败率均为 OpenAI 状态页复盘口径；赛迪的 30% 利用率是机构口径、样本与方法未公开，两者只是并置不是因果；「测试 100% 流量走主库」是计划而不是已上线。把这条读成「OpenAI 不行了」会越过证据。

可以怎么用：把 agent 依赖的外部 API 当成会挂的组件来设计：关键流程留降级路径与重试上限，别把认证令牌的刷新押在单一服务商的状态页上。团队若自建 agent 网关，把「认证与业务查询分离」和「副本失效时的摘流开关」写进验收清单，而不是等故障发生后再补。

把 agent 的「手」和「脑」拆开：谷歌用隔离微虚拟机把密钥挡在沙箱外，斯坦福给每个动作装上可回滚的提交——让 agent 犯错之后还能收场

AI Coding · 运行时安全
谷歌工程博客《Inside Agent Compute Engine》· InfoQ、aiagentnews 11-22 · 东北大学与斯坦福 Shepherd 论文（计划 12 月投 NeurIPS）· 多源交叉核实

谷歌公布 Agent Compute Engine，把 AI 智能体放进隔离的微虚拟机里运行，支持检查点挂起与恢复。核心设计是边界：API key、OAuth 刷新令牌等凭据不进入沙箱，留在外部的 Agent Gateway，由其认证请求后再注入密钥。谷歌工程师说，编排 harness 完全运行在沙箱外，只向沙箱下发明确指令，这条边界形成确定性的审计链，把每一次工具调用与沙箱内的计算活动对应起来。

  • 内部已在用：这套平台已用于 Gemini、Gemini for Business、Antigravity 与模型评估；配套的还有开源的 Agent Substrate 运行时，以及 Agent Registry、SPIFFE 身份与 OpenTelemetry 可观测性。
  • 尚未交付：服务还没上线，计划未来数月预览、未公布定价；外部开发者指出深度文章没有给出它本身的启动时间、价格与密度数字，报道里引的性能数字属于 Agent Substrate，不能混用。
  • 斯坦福 Shepherd 走另一半：把 agent 的每个动作、状态与环境存成受版本控制的提交，让「回滚」获得与代码仓库相同的语义；meta 智能体可拦截动作、撤销或升级给人类，对外动作先落沙箱、确认后执行。

为什么值得关注：这两件事是同一命题的两半：agent 越来越能自主执行，问题就从「它会不会做对」变成「它做错时我们能不能收住」。谷歌管的是运行时的物理边界——沙箱里没有可偷的凭据；斯坦福管的是时间上的边界——任何一步都能退回去。

它和 10-19 ③ 的检查点工具、10-28 ① 的审批代签是同一条线的推进：那时是给 AI 代码设检查点、发现人在环审批会被 agent 代签；这次把检查点下沉到运行时与动作层，并且明确把「脑」留在外面。11-22 ① 的推理轨迹上锁也是同一个方向——先划清哪部分不能被 agent 碰。

需要留意：Agent Compute Engine 尚未上线、无定价、无自身性能数据，AWS 与 Azure 已有同类服务，现在判断优劣为时过早；Shepherd 是论文、计划 12 月投稿，未见独立复现。两者都是架构主张，不是可立即采购的产品；「审计链」「可回滚」都是设计目标，实际强度要看实现。

可以怎么用：搭 agent 运行时，先画一条明确的边界线：凭据和编排逻辑放在沙箱外，沙箱内只留执行所需的最小权限；每个写入型动作生成可回放的记录，配一个不经过模型的紧急停止。如果现在还在让 agent 直接拿着长期有效的 API key 跑代码，这两条就是最值得先补的。

一次压缩之后 agent 记住了 77% 的决策，却只留下 0.2% 的 shell 命令：43 次真实对话的比对，暴露了长期任务最难查的一种失忆

AI Coding · 上下文与记忆
Reddit 一手观察，经 Clauday《Ideas Radar 2026-11-23》整理 · 同源观察见同刊 bug verifier 条目

一位用户把 43 次 Claude Code 的上下文压缩与磁盘上的原始对话逐条比对，得到一个刺眼的结果：压缩后 prose 形态的决策有 77% 存活下来，而 shell 命令只剩 0.2%。也就是说，agent 记得「当时决定怎么做」，却忘了「当时具体敲了哪条命令」。那些精确命令其实还在本地的多吉字节日志里，只是没有人会手工去翻。

  • 为什么重要：长期任务里真正可复用的，往往是那条跑通的命令或那个文件路径，而不是一段叙述性的总结；压缩把它们换成了转述，下次再要用就得重新试。
  • 同一个 radar 里的旁证：Claude Code 加 Playwright 找 bug，能抓到 18 个种入 bug 中的 15 个，但每次运行平均 3.15 个误报；加了「必须复现两次才上报」的关卡后，误报降到 0.41。
  • 两条指向同一处：agent 的输出需要一层可核对的留痕，而不是只信它自己的总结。

为什么值得关注：上下文压缩一直被当成「省 token 的技术活」，这条数据说明它同时是一个可靠性问题：决策和命令的存活率差了几百倍，agent 的记性是有选择性的。11-08 ① 讲过 Anthropic 把 agent 记忆拆成四层、明确排除上下文压缩摘要；这条给出了排除的理由——压缩摘要留下的那部分，恰好是不含精确命令的那部分。

它和主榜②是镜像：那边在讨论怎么把动作变得可回滚，这边发现连「做过什么」都没被完整记下来。没有可检索的原始记录，回滚与审计都无从谈起。

需要留意：这两个数字来自个人在 Reddit 的一手比对与另一条社区观察，经聚合媒体整理，样本是 43 次压缩和单个开发者的项目，没有同行评审，也不能推广到所有模型与所有压缩策略；0.2% 是 shell 命令的存活率，不等于「agent 忘了 99.8% 的工作」。把它当成提醒去查自己的日志，而不是当成普遍定律。

可以怎么用：别把压缩后的摘要当成唯一真相：让 agent 把跑通的命令、改过的文件路径单独写进一份可检索的日志或技能文件，压缩之后仍可查。评审 agent 产出的 bug 时加一道「必须复现两次」的门槛——这条经验几乎零成本，却能直接砍掉大部分误报带来的返工。

上游减速器第一次摊开账：具身收入一年涨了 12 倍，单价却从 1256 元跌到 598 元——繁荣的另一面是价格两年腰斩、毛利率掉到 48%

具身智能 · 供应链账本
纽氏达特创业板招股书（11-13 过会、11-15 提交注册）· 凤凰网 AI 日报 11-23 整理 · 拟募资 8.23 亿元

行星减速器厂商纽氏达特 11 月 13 日创业板过会、15 日状态更新为「提交注册」，拟募资 8.23 亿元。招股书第一次把具身智能这条供应链的价格摊开：具身领域收入从 2023 年的 30.70 万元增至 2025 年的 9662.82 万元，同比增长 1235.46%，占主营 19.47%；2026 年上半年为 5938.91 万元。2025 年智元创新是第一大客户、销售 3702.15 万元，优必选为第三大客户、2448 万元。

  • 价格侧：具身领域平均单价从 2024 年的 1256 元降到 2025 年的 849 元，2026 年上半年进一步降到 598 元，两年腰斩。
  • 利润侧：综合毛利率从 55.49% 降到 48.05%，2025 年单年降约 4.55 个百分点，而可比公司均值只降 0.39 个百分点；2025 年扣非归母净利润 1.46 亿元，仍低于 2023 年的 1.72 亿元。
  • 用价格换量：招股书承认对部分头部客户「给予了更加优惠的价格」——大客户放量是用让利换来的。

为什么值得关注：过去三期我们连续记了三种账：11-20 的出货账、11-21 的订单账、11-22 的产能账，都是「卖了多少」。这次第一次换到「卖多少钱」——收入涨 12 倍的同时单价腰斩，两个数字放一起才是完整的生意。

它给「具身很热」提供了一个冷静的注脚：上游零部件被头部客户用订单换价格，量起来了但利润率在掉。这和整机厂公布出货量是同一枚硬币的正反两面，看具身公司时不能只取其中一面。

需要留意：全部数字来自招股书与聚合整理，收入与单价的口径（是否含其他品类、按件还是按套）需以原文为准；1235.46% 的增速基数只有 30.70 万元，倍数好看但绝对额有限；「头部客户优惠价」是公司自述，让利幅度未披露。不要把单价下降直接读成「技术不值钱」，也可能是产品结构与规模效应的结果。

可以怎么用：看具身供应链公司，把「收入增速、单价走势、毛利率、前五大客户集中度」四列并排看，缺一列都容易误判：增速配上单价腰斩，意味着增长靠降价换量。评估整机厂时同理，问清它的量是以什么采购价拿到的，量价一起看才不会被单一指标带偏。

机器人开始自己改自己：约 57 小时跑完 165 轮真机实验、攒出 80 个版本，酒店洗衣场景里牛仔裤滞留在烘干机的比例从 48% 降到 32%

具身智能 · 具身 RSI
大晓机器人酒店洗衣场景展示 · 凤凰网 AI 日报 11-23 整理 · 同主体此前场景见 09-22 加油站便利店

大晓机器人在酒店洗衣场景展示了一次具身递归自我改进：约 57 小时完成 165 轮真机实验、形成约 80 个版本，把牛仔裤留在烘干机筒内的比例从平均 48% 降到 32%。同一批报道里，CoRL 2026 上伯克利团队的 SuperMimic 用可微世界模型把训练压到单卡约 3 小时，但那属于 11-16 ③ 已推过的旧进展，这里只作背景不计入本条。

  • 值钱的是过程不是结果：48% 到 32% 本身不算惊艳，罕见的是把「发现失败—改策略—再上真机」跑成了一个有轮次、有版本号的循环，并且给出了小时数与轮数。
  • 同一个主体换场景：09-22 ⑤ 记过大晓进加油站便利店，那次讲「接排班而不是接演示」；这次把自我改进的机制搬进了酒店洗衣。
  • 线索在延长：10-28 ⑤ 智元 Genie Master 让机器人在真实便利店里自己定位失败、改策略、沉淀经验；这次多了一条「多少小时、多少轮、多少个版本」的账。

为什么值得关注：具身领域过去两年最缺的不是单次成功率，而是「变好」这件事能不能被量化。57 小时、165 轮、80 个版本，让「机器人自己改自己」从口号变成了一条可对照的曲线——虽然终点只有 32%，但斜率是可读的。

它也和主榜③形成有趣的对照：编码侧的 agent 压缩后丢了精确命令，具身侧却把每一轮的失败与版本都留了下来。同样是要从失败里学习，一边在丢失记录，一边在积累记录。

需要留意：57 小时、165 轮、80 版本、48% 到 32% 均为厂商展示口径，未见论文或第三方复现；「牛仔裤滞留率」的样本量、初始条件与统计窗口未公开，不能与别的场景的成功率横比；「具身 RSI」是公司表述，是否构成严格意义上的递归自我改进仍有争议。把它读成一次有量化记录的场景试错更稳妥。

可以怎么用：评估具身公司的「自我改进」能力，别只听演示，直接问三个问题：一轮迭代要多少小时、总共跑了多少轮、每个版本改了什么。答得出这三个数字的团队，比只给最终成功率的团队更可信；把这组数字也用在自己团队的 agent 流程上——记录轮次与版本，比盯着单次结果更能看出系统在不在进步。
