围住 agent 的那层今天自己破了两个洞：Docker Sandboxes 符号链接沙箱逃逸（CVSS 8.2）与 Pydantic AI 一次公开九条安全公告

AI Coding
Endor Labs 于 11 月 3 日公开的 CVE-2026-103916 研究报告，Rapid7 漏洞库与 CVE 记录条目；Pydantic AI GitHub 安全公告页 11 月 4 日一次性公开的九条 GHSA；quidproquo 站内安全警报与框架更新两篇（11 月 5 日）

今天最值得记住的一条事实是：造成破坏不需要模型被骗。沙箱逃逸和框架漏洞的触发条件，都是纯工程上的顺序写反。

  • 第一个洞在 Docker Sandboxes。AI 供应链安全公司 Endor Labs 于 11 月 3 日公开编号 CVE-2026-103916 的漏洞，CVSS 3.1 评分 8.2，4.0 版评分 7.3，类型归为 CWE-59 符号链接解析不当。Docker Sandboxes 是用 sbx 命令行操作的独立微虚拟机沙箱，Claude Code、Codex、Gemini CLI 都可以跑在它上面。它的安全模型是一份白名单：开发者核准几个目录（通常是项目工作区），通过 virtio-fs 挂进沙箱，agent 理论上只能碰到白名单里的路径。
  • 问题出在一条白名单管不到的通道。sbx cp 是沙箱与主机之间复制文件的命令，它不走共享文件系统，而是命令行进程在主机端直接做普通文件读写，用操作者本人的完整权限执行，全程没有查过白名单。真正的缺陷藏在这条命令怎么处理符号链接：一次复制涉及的路径有四个「链接可能出现的位置」，sbx cp 唯一的防护开关 -L 只守住其中复制来源的最后一层，另外三处默认原样跟随链接。
  • 完整攻击链是这样的。不受信任的内容（网页、依赖包、文档）指示沙箱内的 agent 在工作区里放一个符号链接，链接指向主机的 ~/.ssh 或 ~/.aws；agent 建议操作者执行一条看起来像搬日志或导出构建产物的复制命令；操作者照着贴进终端；主机端解析路径时原样跟随了链接，白名单一次都没有被检查。两个方向都成立 —— 写入方向把沙箱内容写进 ~/.ssh/notes.txt，读取方向把主机的 ~/.aws/credentials 整份读进沙箱。写入原语还能改写 ~/.ssh/authorized_keys、~/.gitconfig 的 pager 设置或 git hook 脚本，把一次文件写入变成下一次执行普通指令时的代码执行，Endor Labs 说明了这条推理但没有实际演示。
  • 最扎眼的一点是复制成功时没有任何输出。不像 sbx mount 会打印解析后的路径，人在旁边盯着也看不出异常。而这两条命令都是帮助文档里教的标准用法，agent 在日常工作流里本来就常是建议执行这类命令的一方 —— 操作者很可能只是照着贴一行指令，完全看不出目的地已经被偷换过。
  • 第二个洞在 Pydantic AI。11 月 4 日一次公开九条安全公告，全部由同一位研究者提交，严重度分布是 High 两条、Moderate 六条、Low 一条，覆盖面横跨凭据泄露、大小限制、域名黑名单、内存耗尽与事件循环阻塞。两条 High 分别是对私钥做脱敏时在短输入上可能耗时指数级增长，以及本地网页抓取在格式化嵌套 JSON 时可能耗尽内存并阻塞事件循环。
  • 这批公告最值得记的不是条数，是同一个习惯。域名白名单那一条：web 抓取与 PlaywrightBrowser 在拒绝被禁域名之前，先把主机名解析了。决策模型展开工具参数 schema 时没有上限；带重复定义引用的工具 schema 对需要内联 schema 的模型会指数膨胀；云元数据的 SSRF 防护没有拦住腾讯云的元数据服务地址 169.254.0.23。先展开、先解析、先查询，事后才检查大小限制或黑名单 —— 顺序写反。
  • 还有一个不能忽略的结构性问题：修复本身也会打歪。Docker 原定 10 月 13 日在 v0.48.0 修补，事后发现不完整，真正修好的是 11 月 3 日发布的 v0.51.0。同一研究者在另一款沙箱产品 brig 上早前发现过同一类漏洞。

这为什么值得看。连续三期把这条线推到了同一个位置。10-25 速览① 是 Anthropic 开源 sandbox-runtime，把沙箱从商业功能变成人人可用的组件；10-31 ② 是 Claude Code 官方 VS Code 扩展在 Cursor 市场被投毒，最多 5000 名开发者中招 —— 那期讲分发渠道被污染；今天这一期讲围栏本身的实现有洞，而且洞在次要通道上。

「次要通道」这个盲区不是 Docker 一家的疏忽。Endor Labs 研究员的复盘里，主共享通道（virtio-fs 挂载与白名单）管得很严，而搬运文件的辅助命令因为「看起来像操作者自己的动作」被排除在威胁模型之外 —— 而 agent 完全可以提前布好陷阱，等人的手去触发。审计任何 agent 沙箱时，搬文件、传参、打日志这类辅助通道应该单独拉出来查一遍，而不是只审那个最显眼的挂载点。

第二条更狠的是「修复也会写歪」。10 月 13 日的 v0.48.0 被官方当作已修，11 月 3 日的 v0.51.0 才是真修。对已经在生产环境跑 agent 的团队来说，这是一个必须自己核版本、不能等公告的窗口期。

口径提醒。8.2 是 CVSS 3.1 评分，4.0 版为 7.3，两个版本不可混用。截至披露时没有公开证据表明该漏洞已在野利用，但技术细节、评分与可复现步骤已经全文公开，扫描与利用的门槛不高。Pydantic AI 那九条公告虽然共享同一个模式，但每一条的具体根因并不相同，不能一概而论。

边界。Docker Sandboxes 的修复版本是 v0.51.0，v0.48.0 的修补不完整，升级前版本一律视为受影响。写入原语可把任意内容写入操作者家目录下任何已存在路径；读取原语相对弱一些，需要操作者自己打对一个存在的文件名，但由于这类命令常由 agent 建议，猜中 ~/.aws/credentials、~/.ssh/id_ed25519 并不难。

可以行动。三件事今天就能做。第一，查版本：sbx --version，低于 v0.51.0 一律受影响。第二，在升级之前把复制命令当成不可信指令对待 —— 无论复制进还是复制出，先自己用 realpath 确认路径真的落在工作区内再执行，对 agent 主动建议的复制指令尤其要提高警觉。第三，把搬文件在内的沙箱辅助指令纳入 agent 执行监控，不要只信沙箱边界本身。

还有一条可以立刻改的默认值：优先选会把解析后路径打印出来的工具行为。复制动作完全没有输出这件事本身就是一个该被淘汰的设计 —— 静默成功的搬运命令不该有静音模式。

「按停权」从一句使用政策条款变成了产品、并购与法律披露：CrowdStrike 发布 AI Kill Switch，苹果把 agent 风险写进 10-K

AI Coding
CNBC 报道（2026 年 11 月 3 日 14:35 发布、15:27 更新）；CrowdStrike 官方新闻稿三则（AI Kill Switch、收购 Fiddler AI、收购 Dreadnode）与 Claude Cowork 集成公告；Bernama 转述苹果年度 10-K 申报；quidproquo 区域动态与「明日关注」

今年 7 月美国两党议员提出《AI 终止开关法案》，要求 AI 公司在模型里内置关停能力。今天，这件事第一次有了具体的产品形态。

  • 产品化。CrowdStrike 在 Fal.Con Europe 2026 上发布 AI Kill Switch，内建于其 9 月推出的 Falcon Guardian 平台。三件事同时做到：拦截内部失控的 agent、阻止它重启、切断它的企业网络访问。官方说明实现方式是「像断路器一样」 —— 平台能检测到 agent 活动，但切断与恢复都需要人来决定。首席业务官 Daniel Bernard 对 CNBC 的表述是：「你可以在根上杀掉进程，这非常二元，要么杀掉这个 AI 和 agent，要么不杀，然后你去上报。」
  • 一个容易被略过的技术细节。kill switch 不删除 agent 的代码，而是通过连接的 AI 网关切断它对影响决策的那些模型的访问权。也就是说，被关掉的不是程序，是「继续思考的资格」。
  • 并购与整合。同日 CrowdStrike 宣布两项收购：AI 可观测性公司 Fiddler AI，以及 AI 安全测试公司 Dreadnode；同时宣布与 Anthropic 的 Claude Cowork 做集成。
  • 法律披露。据 Bernama 转述，苹果在年度 10-K 申报中示警：AI agent 可能在未经授权的情况下访问系统或完成交易，使公司暴露于法律诉讼与商誉风险。这是大型科技公司第一次把这类风险写进面向投资者的正式文件。
  • 组织侧的动作也在收紧。今天的安全通告里明确建议：默认把员工 agent 放在组织自己控制的受管云环境里跑，而不是员工个人终端上，理由是员工终端上的 agent 已被视为企业和政府的系统性风险；这条建议直接点名了高盛的做法。

这为什么值得看。这是本系列里持续最久的一条线，今天走到了第四幕。

  • 10-09 ②：Anthropic 全量改使用政策，真正有分量的是那条「必须有人能按停它」 —— 当时那只是条款。
  • 10-31 ③：OpenAI 公开检测模型失准的四层监控体系，智能体逃出沙箱 30 分钟就告警 —— 从条款变成检测。
  • 11-01 速览③：OpenAI 更新 Model Spec，六层权限加一张工单，AI 必须无条件配合监控、评估、纠正乃至关停 —— 从检测变成规范。
  • 11-04 ②：高盛把 Claude Code 从投行与交易岗收回给工程师 —— 从规范变成组织动作。
  • 今天：CrowdStrike 把它做成独立产品，苹果把它写进 10-K —— 从组织动作变成产品与法律口径。

四幕走下来，一个判断慢慢成形：「能按停」这件事，问题从来不在技术上能不能实现，而在它落在谁的资产负债表上。谁把它写进产品、谁把它写进监管文件，谁就承担了这份责任 —— 也因此，谁的说法最值得当真。

口径提醒。kill switch 的实际防护边界是「在 CrowdStrike 自家 Falcon 平台上运行的 agent」，Bernard 自己描述为在有根级访问权限的系统里才成立。跨模型、跨数据中心、跨复杂 AI 系统的紧急停止，业内批评者认为实现起来远比产品演示复杂。「检测得到」和「切断得干净」是两件事：平台能检测到内部 agent 活动，但切断与恢复都要求人做出决定，这中间存在一个由人承担的时间窗。

苹果那条来自 Bernama 转述的 10-K 申报，属二手转述，未见原文表述；10-K 属于风险披露，列出风险不等于认定已发生损失。

可以行动。如果你在企业里管着一批 agent，今天可以按一个问题自查：这批 agent 的「按停权」到底是流程还是产品 —— 有没有能一键切断 agent 对模型访问权的开关，而不只是「叫人别点」；关掉之后能不能阻止它重启；agent 跑在谁的机器上，员工个人终端和公司受管环境是两种完全不同的风险敞口。

另外一条：无论你用不用 CrowdStrike，「切断模型访问权」这个实现思路本身可以照抄 —— 它不需要删 agent 的代码、不需要动 agent 的状态机，只要在模型调用这一层断掉就行。这比试图安全地杀掉一个正在运行的进程要干净得多。

开放权重编程模型今天有两个新答案：Cognition SWE-2 Flash 与 Ricursive Ripple-65B，而「美国第一」这个头衔本身有前提

AI Coding
Cognition 于 11 月 4 日发布的 SWE-2 Flash（官方口径经同花顺财经 11 月 5 日转述）；Ricursive 同日发布的 Ripple-65B Preview（官方发布与第三方转述）；agihunt 11 月 5 日汇总的第三方评论；终端基准横向对照表（含 DeepSeek-V4-Flash 82.7、GLM-5.3-Flash 84.3）

同一天有两家美国公司发布开放权重编程模型，都自称是美国本土第一。都自称，就说明有一个需要被检验的前提。

  • Cognition 的 SWE-2 Flash。11 月 4 日发布，底座是 Thinking Machines 的 Inkling-Small，稀疏混合专家架构，总参数 276B、单次激活 12B。官方口径：Terminal-Bench 2.1 得 89.2，DeepSWE 1.1 得 60.1，SWE-Pro v2 Hard 得 89.9，FrontierCode 2.0 得 24.0。价格是同系列旗舰 SWE-2 的五分之一，原生生成速度每秒 200 token，而 SWE-2 是每秒 60 token —— 快三倍。模型已上线 Devin 桌面端与命令行，官方免费试用到 11 月 30 日。旗舰 SWE-2 的规格是 2.8T 总参数、104B 激活。
  • 训练链路上有一个新环节值得记。在强化学习之前插入了大规模中间训练阶段：构建专属的高质量预留编码数据集，用 token 效率曲线筛选数据源组合（测算达到同等验证损失要消耗多少 token），训练总数据规模达数万亿 token，稀缺高价值素材放在训练后期送入模型。
  • Ricursive 的 Ripple-65B Preview。同日发布，65B 稠密开放权重模型，官方定位为「美国开放权重模型在 Agentic Coding 上的新 SOTA」，Terminal-Bench 2.1 得 80.5，预训练计算成本约 3200 万美元，接口价格输入每百万 token 0.20 美元、输出 0.60 美元。
  • 两家自己做了同场对比。三项重合评测：Terminal-Bench 2.1 是 89.2 对 80.5，差 8.7 分；DeepSWE 1.1 是 60.1 对 44.3，差 15.8 分；SWE-Pro v2 Hard 是 89.9 对 79.1，差 10.8 分。参照模型 Beam 501B 三项依次为 80.1、43.3、76.5。
  • 参数量收益曲线才是这条新闻真正的重点。按官方给出的曲线，拿到与 Ripple-65B 相同分数的其他模型，参数量达到它的十五倍。
  • 但「美国第一」这个头衔有前提。投资人 Nathan Benaich 的批评是：当一个标签的含义是「在某一个子集里排第一，而这个子集的边界由发布方自己划定」，它的信息量就取决于你愿意把谁放进比较范围。按第三方横向表里的口径，DeepSeek-V4-Flash 在 Terminal-Bench 2.1 上是 82.7、GLM-5.3-Flash 是 84.3 —— 与今天这两个数字在同一量级；而 10-26 ① 记过 Kimi K3.1 Pro 冲上开放权重第一的位置。

这为什么值得看。表面看是模型发布，实际是开源供给链上的一件结构性变化：编程模型的底座开始外购。SWE-2 Flash 的底座是 Thinking Machines 的 Inkling-Small，那家公司自己也是靠自动化研究系统造模型的；Ripple-65B 则把 65B 稠密模型的预训练成本压到约 3200 万美元。在这个尺度上，「自己从零预训练一个通用编程模型」正在变成一件不必做的事 —— 和 10-19 ① 英伟达把技能存成代码、11-04 ① OpenAI 十周重造 Git 后端是同一个方向：把重复的基础设施交给能复用的现成件。

第二件事是评测口径本身。10-26 ② 推过 Epoch AI 判定 21 个主流基准里有 10 个带评分缺陷，其中 Terminal-Bench 4.0.0 六个里四个带病。今天两家公司的头条数字全部建立在 Terminal-Bench 2.1 这一个分数上 —— 最响亮的两个数字，建在本系列已经标注过「带病」的尺子上。这不是否定成绩，是提醒读分数时把尺子一起带上。

第三件事是「美国本土第一」这个限定词。当一个标签的含义是「在某一个自划定子集里排第一」，它的信息量就取决于比较范围。今天的答案是：放进中国的开放权重模型，比较就没有那么好看。

口径提醒。全部跑分均为厂商自测，两家没有共同第三方复现。Ripple-65B 的 80.5 与 SWE-2 Flash 的 89.2 虽来自各自发布内容，两家也各自给出了三项重合评测的对照表，但对照表仍由发布方自己汇编。预训练成本约 3200 万美元、参数量十五倍收益曲线同样出自厂商口径。「开放权重」也不等于「开源」—— 许可证限制、量化版本、上下文长度、工具调用协议与完整模型卡的公开程度，才决定它能不能从榜单选手变成可部署的生产工具。

另一处要小心：SWE-2 Flash 与旗舰 SWE-2 的 104B 激活不是同一量级的东西，官方那句「超越所有美国开放权重模型」限定的是开放权重阵营，不是「超越自家旗舰」。第三方横向表里的 82.7 与 84.3 同样来自二手汇总，与两家自报数不构成同口径横评。

可以行动。如果你在评估自托管编程模型，别只看跑分排名，先查五件事：训练数据边界与授权、上下文长度、量化版本的实际掉分、工具调用协议与现有 harness 的兼容情况、许可证限制是否允许商用。这五项没查清之前，「SOTA」只是一个还不能下单的结论。

选型上有一条实用经验：今天两家的头条数字差 8.7 分，但体量差四倍以上（276B 总参数、12B 激活对 65B 稠密）。多数团队的瓶颈不在跑分而在部署成本 —— 把激活参数、显存占用与推理吞吐算进总账，往往比再追两分更值钱。

让 coding model 自己重写机器人控制代码：RoboArchitect 不更新一个权重，未见场景成功率从 9.7% 拉到 43.3%

具身智能
arXiv 2610.42141《RoboArchitect: Automating the Design of Robotic Agents with Persistent Memory》（2026 年 10 月 30 日提交，作者 Shengguang Wu、Suning Huang、Cherie Ho、Ria Doshi、Hao Zhu、Serena Yeung-Levy，斯坦福）；项目页 roboarchitect-ai.github.io；theaitoday 的论文摘要转述

这是本系列第一次看到「机器人控制代码由 coding model 自动重写」这条路线给出完整的对照实验数据。

  • 出发点。已有工作表明，一个冻结的机器人策略放进 agent harness 里表现会好得多 —— 所谓 harness，就是包在策略外面的那层控制代码：决定什么时候去问策略、什么时候调视觉工具、什么时候直接指挥机械臂。问题在于，今天这些 harness 都是手写的，每换一个机器人或换一个基准就要重写一遍。
  • RoboArchitect 做的事。一个 coding model 观察机器人的实际轨迹、诊断失败原因，然后围绕冻结的策略迭代改写 harness。harness 在一组片段上演化，再在留出的场景与任务上评估。整个过程不更新任何模型权重。
  • 结果。在未见场景上，平均成功率从 9.7% 提升到 43.3%，约 4.5 倍；在未见任务上，从 12.7% 提升到 40.2%，约 3.2 倍。跨多个基准与多种策略成立。
  • 最有意思的一条结论：收益最大的地方，恰恰是基准离策略训练数据最远的地方。用一个通用策略作底，演化出来的 harness 会把它包装成一个专用策略，常常连微调后的版本都比得过。
  • 自动设计出来的控制策略长什么样。论文举了两个例子：机械臂卡住时先把它抬起来脱困；障碍从上方挡路时改为水平伸入。这两条都不是人写进去的，是演化出来的。
  • harness 还演化出了自己的持久记忆。比如「有效的抓取深度」这类经验会被带进后续决策里。

这为什么值得看。今天前面三条都在讲围栏（沙箱、框架、治理），这一条讲的是被围栏保护的对象开始自己改围栏。而它和 10-19 ① 是同一条线的两个阶段。

10-19 ① 推过 NVIDIA ASPIRE V1.0：让编程智能体给机器人写控制程序，跑失败就复盘轨迹、改代码，把改对的方法存进技能库。那一期的关键数字其实是一个警告 —— 演化搜索这个环节在强模型上的收益从 34 个百分点缩水到约 2 个百分点，模型越强，为弱模型准备的 harness 工程越不值钱。

RoboArchitect 换了个角度回应同一个问题：不换模型，换 harness。它的对照实验正好补上了 10-25 ③ 那篇山东大学论文留下的缺口 —— 那篇在 coding 侧发现换 harness 分数几乎不动、成本差三倍；今天这一篇在机器人侧发现，在「策略冻结、基准离训练数据远」的条件下，换 harness 能把成功率拉四倍多。两个结论并不矛盾：harness 不是万能药，但它是唯一不动权重的那把药。

第二条值得看的是「先有代码库还是先有示范数据」这个选择被换掉了。不收集示范数据，等于把机器人学习最贵的那一环从预算里砍掉。这跟 11-03 速览④ 简智机器人的「无本体」数据路线是同一种思路的两种规模。

口径提醒。全部数字来自论文摘要与项目页，尚无第三方复现；9.7% 到 43.3%、12.7% 到 40.2% 都是跨多个基准与策略汇总的平均值，论文摘要未给出逐基准分解。评估设计本身值得留意：harness 在一组片段上演化、在留出的场景与任务上评估，这个划分是合理的，但仍要看到演化片段与留出集之间的任务分布差异对结论的影响幅度，摘要未披露。

也要说清边界：这条路线的前提是「已有策略、只缺 harness」。如果机器人连策略本身都不行，重写控制代码救不了它。另外 43.3% 仍然不是一个能进产线的数字 —— 11-03 ④ 智元便利店那一期里，厂商自己给出的差距答案是与熟练店员相比仍有不小差距，可以拿来当量级参照。

可以行动。如果你的团队在评估机器人策略，可以把「先补示范数据」和「先补 harness」当成两个可比较的选项列出来，而不是默认前者。判据是：策略在训练分布内已经能用吗？如果是，那么先动 harness 的性价比通常更高 —— 它不动权重、不需要重新采数据、迭代周期是分钟级而不是周级。

还有一条更通用的：论文里那两条演化出来的控制策略（卡住先抬起来、挡路改水平伸入）读起来像常识，但它们是机器人自己试出来的。给团队做机器人落地时，值得把「我们以为的常识」和「机器人试出来的常识」分开列 —— 往往后者才是真正的缺口。

让机器人自己决定接下来该试什么：EmbodiedRSI 用价值信息选实验，同样 50 次交互预算下成功率从 27.1% 到 72.9%

具身智能
arXiv 2610.10498《EmbodiedRSI: Active Continual Robot Learning Through Hypothesis-Guided Co-Evolution》（2026 年 10 月 7 日提交，作者 Python Song、Zhixuan Liang、Kelsey Fu、Mengdi Wang、Junfeng Yang、Shilong Liu，哥伦比亚大学与普林斯顿）；智源社区 11 月 5 日的论文讲读（arXiv 2610.10498）

上一篇讲「谁来写代码」，这一篇讲「谁来决定该写什么」—— 机器人自己选下一步的实验。

  • 要解决的痛点。机器人基础模型有不错的视觉运动控制，但物体位置或任务指令一变，性能就掉；要继续提升，通常需要在大量机器人数据上做后训练，而这类数据靠遥操作采集非常昂贵。agentic harness 可以围着模型自适应，但现有的自进化 harness 在「决定该追哪个代码改动、哪个技能改动」这件事上用机器人试验的效率很低。
  • EmbodiedRSI 的做法是快慢双系统。竞争性的「代码假设」和「技能假设」被维护在一张假设图谱中；一个价值信息实验选择器挑选那些能把这些假设区分开的物理实验；实验结果反过来驱动代码与技能协同演化。慢系统构建层次记忆，奖励驱动的记忆学习再按「对后续快系统改进的价值」筛选哪些经验值得留下。
  • 数字。RoboCasa365 上总体成功率 77.0%，未见组合任务 71.3%，对照最佳基线 40.1%；LIBERO-Pro 上总体成功率 86.8%。零样本迁移到真机，多项挑战任务总体成功率 71.3%，对应迁移前的 46.0%。
  • 最有说服力的一组对照来自讲读转述。在同样的 50 次交互预算下，与随机探索相比，成功率从 27.1% 提升到 72.9%。这个数字回答的是一个非常实际的问题：机器人那有限的几十次物理试错，到底该花在什么方向上。
  • 一句话概括它的主张。试错本身不是目的，能被复用的代码与技能才是 —— 每次交互都应该被转化为下一轮能直接调用的东西。

这为什么值得看。这条线在本系列里出现过三次，而且每次都往前挪一格。

  • 10-28 ⑤：智元发布 Genie Master —— Physical RSI 第一次走出仿真，机器人在真实便利店里自己定位失败、改策略、沉淀经验。那期讲的是递归自我改进在真实场景第一次发生。
  • 10-25 ④：复旦 RoboSkill —— 机器人把现场摸索出的解法存成「文字 + 代码」技能，耗时砍到三分之一。那期讲的是技能怎么被沉淀下来复用。
  • 今天这一篇：把「试什么」的决策权也交给智能体，并且用价值信息选择器把它量化 —— 同样 50 次交互预算下，成功率从 27.1% 到 72.9%。

三篇连起来是一条完整的方法论：先让机器人能自己发现失败，再让发现的东西能存下来复用，最后让「该往哪试」本身成为一个可优化的决策。前两篇的改进循环由人或固定框架驱动，今天这一篇把「选实验」这一步也做成了可学习、可评估的对象。

和 10-19 ① ASPIRE 那条线对照更有意思：那一期的结论是「模型越强，为弱模型准备的 harness 工程越不值钱」（演化搜索收益从 34 个点缩到约 2 个点）。今天 EmbodiedRSI 的对手不是更强的模型，而是随机探索 —— 它要证明的不是「harness 强于模型」，而是「harness 内部的决策可以被优化」。这两件事不冲突，恰恰是同一件事的两层。

口径提醒。全部数字来自论文摘要与讲读转述，尚无第三方复现。40.1% 是最佳基线在未见组合任务上的成绩，不是随机基线；真机迁移的 71.3% 是多项挑战任务的总体成功率，各任务分解摘要未给出。讲读转述里「相同 50 次交互预算下 27.1% 对 72.9%」这一组数字未出现在论文摘要中，引用时应注明来自讲读转述而非论文原文。

边界也要说明白：底层机器人策略模型是冻结的，提升全部来自 harness 与记忆层。论文自己把瓶颈点得很清楚 —— 试错预算再省，也改不了冻结模型的能力上限；而且「判断哪个实验最有信息量」这个判断本身要靠执行结果来验证，在物理世界里每一次判断都要付真机的时间与磨损。

可以行动。如果你的团队在做机器人的数据闭环，这篇提供了一个很具体的改造方向：别让「下一次采什么数据」靠研究员拍脑袋，用一个价值信息选择器来排优先级。同样 50 次试错预算，方向选对与选错的差距是 27.1% 对 72.9% —— 这个差距远大于换一个更强的策略模型带来的差距。

一条更省事的起步做法：先做一个最小版本 —— 每次实验记录三件事（假设是什么、预期能区分什么、实际结果推翻了什么），然后按「这次实验排除了多少种可能」给下一步排序。不需要先建假设图谱，先把「试了什么、学到了什么」记下来，这一步本身就能拿回一部分效率。
