Plugin4Shell：四大编程代理同源漏洞，攻击面从模型移到了「插件市场」

AI Coding · 供应链安全
来源：The Register（9/17）· Air 安全公司报告（9/17）· zeroday.news · TokenPost · 网易/金融界中文转述（9/18）

网络安全初创公司 Air（专注企业 Agent 防护）的三位研究员 Or Nevo、Dor Granat、Niv Hoffman 披露了一枚影响全部主流编程代理的零点击远程代码执行漏洞，命名为 Plugin4Shell，并称其为「首起 AI 供应链攻击」。受影响名单是：Anthropic 的 Claude Code、OpenAI 的 Codex、Google 的 Gemini CLI、以及微软/GitHub 的 Copilot。

成因不落模型，落在「插件市场怎么防止货物被掉包」。 SHA pinning 的设计意图是：把插件锁死在某一个不可变的 commit 哈希上，而不是可被移动的分支名或版本号——这样即使公开插件仓库被攻破，agent 跑的仍是当初审计过的那份代码。Air 发现的是：agent 确实按市场固定的那个 commit 去检出，却从不校验内容是否真的落在那里。攻击者只要控制了插件仓库，就能让 checkout 解析到恶意代码，而 pin 看起来依然被遵守。原文一句说得很直白：「代理检出的是市场固定的精确 commit，但从不验证它落在那里，于是攻击者控制插件仓库后，让检出指向恶意代码，同时 pin 看上去依然有效。」

之所以是零点击，是因为 Claude 与 Codex 的插件自动更新默认开启：上游把被 pin 的 commit 内容换掉，本地插件就在下一次自动更新时被替换成恶意版本。两种攻击路径——① 先向可信市场提交良性插件通过审核，之后再换成恶意内容；② 直接劫持原作者仓库，把恶意版本推给所有已安装的 agent（即绕过 SHA pinning 本身）。第二种已被 Air 此前的 SkillJacking 与 RepoJacking 概念验证演示过。

修复进度严重不齐，这是本条最实的信息：Anthropic 已在 Claude Code 2.1.179 修补，OpenAI 已在 Codex 0.146.0 修补；Google 已弃用 Gemini CLI，明确表示不打补丁，建议迁移到 Antigravity——因此所有存量 Gemini CLI 安装仍然脆弱；微软至今未给 Copilot 发布修复，Air 称早在 6 月就已通报但未获回应。微软自己的口径是近 90% 的财富 500 强在用 Copilot。GitHub 发言人则称 GitHub 不允许创建形似 commit SHA 的分支或标签名，所以「该漏洞无法在 GitHub 上被利用」；Air 反驳：插件市场也可以托管在 Bitbucket 等平台，而 Copilot 同样支持这些平台，因此暴露面还在。

为什么值得关注：攻击者的目标第一次从「模型」移到了「分发通道」。这已经是两周内的第三起 agent 供应链事件（前有 GitSpawn 的 .git/config 一键劫持、再有 PaperCut 的数百个 agent 协同攻击 7 分钟拿下域管），三者指向同一件事——agent 时代的新攻击面，就是 agent 信任并自动执行的每一份外部内容。四家厂商校验设计雷同也说明这不是单点失误，而是行业在「先解决能不能用」时形成的路径依赖：NPM 生态十年前就已把锁文件与哈希校验做成了肌肉记忆，agent 生态却还没有。

四条立刻可落地：① 升级到含补丁的版本（Claude Code ≥ 2.1.179、Codex ≥ 0.146.0），仍在使用 Gemini CLI 的存量实例迁移到 Antigravity；② Copilot 用户不能等官方补丁，先把插件/市场源收敛到自建可控仓库，并关闭自动更新或改用受控白名单；③ 把 agent 的插件与配置文件纳入和 CI 脚本同级的 Code Review——今天一份 skill 的更新比一次依赖库升级更危险；④ 给 agent 的高危动作（外发文件、调用生产凭据）加人工确认门，不要只依赖来源校验。

口径修正（重要）：中文二手源普遍写成「除 GitHub 外其余三家已修复」，与一手报道不符。以 The Register 与 Air 报告为准：Google 明确不打补丁（Gemini CLI 已废弃）、微软未修 Copilot。另需注意：Claude Code 2.1.179 / Codex 0.146.0 是修补落地时的版本号，与今天在跑的 2.1.277 已相差近百个版本，说明补丁早已在流中——真正要确认的是你自己的实例有没有跑在含补丁的版本之后。GitHub 与 Air 对「GitHub 平台是否可利用」存在公开分歧，在未确认之前按「可利用」处理。

Claude Code 2.1.277 起支持 AGENTS.md：不是向 OpenAI 低头，是遵守自己参与共建的规则

AI Coding · 配置标准
来源：Thariq Shihipar（@trq212）X 帖（9/18–19）· anthropics/claude-code 仓库 mods/agents-md · TPS Report · ExplainX · Simon Willison 转述 · IT之家 / 头条「人工智能学家」（9/19）

Claude Code 团队工程师 Thariq Shihipar 宣布：从 2.1.277 起，若目录中没有 CLAUDE.md，Claude 会检查并改用 AGENTS.md，也可在 /config 中关闭该行为。分工被明确划开：CLAUDE.md 承载 Claude Code 特有的工作流、MCP、Sub-agent 与命令配置；AGENTS.md 是让不同工具共享的项目级基础规则——官方网站直接称它是「给 agent 的 README」。两者的关系不是谁替代谁，CLAUDE.md 存在时仍然优先，AGENTS.md 只是 fallback。

比兼容本身更值得注意的是实现方式：Anthropic 没有把它硬编码进核心，而是做成一个内置的 Claude Code Mod。Mods 是即将推出的 harness 定制层，与既有 skills 体系不同，瞄的是「会话外壳与 harness 行为」而非模型能力。源码已公开在 anthropics/claude-code 的 mods/agents-md，由社区贡献者 poteat 提交、官方合并；该 mod 提供 claude-md、claude-md-or-agents-md（默认）、claude-md-and-agents-md、managed-only 四种模式，想两份同时加载或完全回到老规矩都可以自己选。用自家第一方功能跑通这套 mod 机制，等于给第三方写了一个公开参考实现。

背景值得一说。AGENTS.md 于 2025 年 8 月由 OpenAI 联合 Cursor、Google、Factory、Amp 推出；到 2025 年 12 月已被超过 6 万个开源项目与 agent 框架采用（含 Gemini CLI、Devin、VS Code），唯独 Claude Code 读自家格式。为此不少团队靠符号链接或导入语句土法并轨——2025 年 8 月 21 日有人在 Claude Code 仓库提了支持请求，一年多累积了 5000+ 表情反馈、300+ 评论，是该仓库最受关注的未满足需求之一。OpenAI Codex 负责人 Tibo 也在评论区留了句「欢迎来到光明的一边」。

但把它读成「Anthropic 低头」只读了一半： 2025 年 12 月 9 日 Linux 基金会成立 Agentic AI Foundation，Anthropic、OpenAI、Block 同为联合创始成员——Anthropic 捐出 MCP，OpenAI 捐出 AGENTS.md，Block 捐出 goose。AGENTS.md 早已躺在中立基金会里，接入它是遵守自己参与共建的游戏规则，路径与当年各家接入 MCP 一样。同期 Claude Code 还把 Projects 从存放提示词与文档的静态文件夹重构为对话驱动的多 Agent 协作中心：协调器拆解目标，调度多个运行在云端隔离环境的实例并行干活，各自持有独立代码副本与 Git 分支，完成后自动提 PR，线程在用户关掉笔记本后继续在云端跑。

为什么值得关注：这条和主榜①是同一枚硬币的两面——① 讲「agent 读的那份外部内容会被投毒」，② 讲「同一类文件正在被收敛成一份公共说明书」。真正在移动的是格式竞争结束、能力竞争开始：一份 Markdown 靠它筑护城河既困难也不划算，格式统一后，用户比拼的是模型能力、上下文管理与工程体验。对企业还有一层好处——规范写在同一处，审计与更新成本随之下降；对开源维护者更是如此，他们无法预知访客用哪款工具，统一文件名等于统一了接待礼仪。

三条立刻可落地：① 已标准化 AGENTS.md 的仓库不必再为 Claude Code 维护第二份 CLAUDE.md；② 需要 Claude Code 同时加载两份时用 claude-md-and-agents-md 模式，企业内统一下发可用 managed-only；③ 注意 AGENTS.md 也要按「会被 agent 自动执行的内容」来治理——如果这条生效后被塞进任意构建/提交指令，它就是 CI 脚本，得走同级评审。

口径与边界：① 日期有冲突——英文源记为 9 月 18 日发布/宣布，IT之家等中文源记为 9 月 19 日的 X 帖发布，取 9 月 18–19 日区间更安全。② 嵌套目录中的 AGENTS.md 只在文本读取时才附带加载，上下文压缩后需等下一次读取才会重新附带，与原生 CLAUDE.md 的处理并不完全相同。③ Mods 尚未有正式文档说明其 API 边界与 GA 时间，官方也未承诺第三方 mod 的支持范围，不要把生产流程建立在它上面。

Dream-RSI：把探索历史变成可回放模拟器，并把「历史总结」证明是有害的

AI Coding · 自我改进
来源：arXiv:2609.14858（9/14 上线，9/16 二次传播）· Google / Google DeepMind / 马里兰大学 / 弗吉尼亚大学 17 人团队 · CellCog · AlexTech · AILog · AIGC 深度中文解读

Google、Google DeepMind 与马里兰大学、弗吉尼亚大学的 17 人团队于 9 月 14 日把 Dream-RSI（arXiv:2609.14858，《Recursive Self-Improvement through Evolving Worlds》）挂上 arXiv。它问的是一个很朴素的问题：跑过千百次「生成—评估」循环之后，那段昂贵历史为什么只能被认真读一次？

做法不是学一个新世界模型，而是承认跑完的探索历史本身就是那个可以反复进入的世界。一次在线探索会长出一棵「发现树」：根节点是初始工作区，此后每一次「生成、评估」尝试都接进树里，节点记录父节点、工作区快照、评估器诊断与分数。换一个探索策略，就是在这棵树上换分支子集、换顺序、换并行分组、换停止点。因为每个节点的结果早已落盘，评估一条新策略只是读记录，既不重新调用 discovery agent，也不重跑评估器——论文明确写道，回放本身不执行任何新的发现尝试，因此是确定性的。

三段循环：在线探索扩张发现树 → 把树转成回放模拟器池 → 候选策略在模拟器里「做梦」并被评分与挑选，胜出的策略代码回到第一步。整个系统只改探索策略的代码，底层模型、评估器与执行接口都不动（发现侧是 Gemini 3.1 Pro 与 Gemini 3.7 Flash，经 Gemini CLI）。三条战线上的结果：Lasso 求解器用 317 次调用拿到优于 SimpleTES（51,200 次生成）的平均运行时间，差约 162 倍；三项数学优化每题都控制在 1000 代以内，而 SimpleTES 单项预算是 51,200 代；KernelBench 四个 kernel，VGG16 少用约 2.43 倍、LayerNorm 少用约 1.79 倍代次达到同等性能，ConvDiv 与 ConvMax 在相近预算下性能分别提高约 2.09 倍与 1.44 倍。

两个反直觉结论才是这篇论文的真正增益。其一，把历史压缩成摘要塞进 prompt 当语义指引，效果比不用引导还差——两条加了引导的对照线都低于各自对照组。解释是：长程发现本来就并行开着多条线，此时对「未来该往哪搜」施加过强的语义偏置，会把搜索空间压得过窄，牺牲了探索多样性。其二，策略自己学会了调节算力：ConvDiv 上前四个外层轮次每轮评测尝试次数从 110 次主动降到 50 次，第 5 轮性能增速放缓后投入又回到 92 次——被优化的对象不是答案质量，而是「怎么分配算力」本身。

为什么值得关注：它把「历史」从一次性开销变成了可复用的资产，这对于任何正在烧钱做长时程 agent 探索的团队都是成本结构的改变——过去评价一条新探索策略必须完整跑一段真实探索，现在同一段历史能支撑数千次近乎零成本的离线比较。更重要的是那个消融结论：业界默认做法（把经验总结成 few-shot 或系统提示）在这套设置里是负收益。这与最近一周好几条新闻共同指向同一个原则——历史要保持可重演的形态，不要急着压成结论。

三条立刻可落地：① 把发现树当一等公民来建：保存父节点、工作区快照、评估诊断与分数四件套，并留出回放接口；② 历史优先做成可重放环境而不是 prompt 摘要——本文给了明确的反例；③ 除最终分数曲线外，单独画一张「每轮评测尝试次数」曲线，它往往比分数更早告诉你策略有没有真的在变。

口径与边界：① 162 倍不是同模型同预算对比——SimpleTES 用 GPT-OSS-120B，Dream-RSI 用 Gemini 系列，两者相差 162 倍说的是量级差距；真正同等条件下的对照是同一行的固定探索基线，Gemini-3.1-Pro 下 550 次 → 317 次，仅 1.7 倍。② 数学三项的结果是一胜一平一负：Sum-Difference 1.145427 略胜 SimpleTES 的 1.143975，圆堆叠 2.635983 追平最强报告值，而自相关不等式 1.456375 逊于 SimpleTES 的 1.453675（越低越好），论文自己也只说「保持竞争力」。③ 回放是只读的：历史里没走过的分支，回放进不去，任务太短则树还没长起来就结束了。④ 论文 9/14 上线、9/16 在 X 上二次传播（单帖十余万浏览），属本周热点而非当日首发；代码截至 9/16 仍在准备中。⑤ arXiv 上编号相近的 2609.14857（ModularRSI）是另一批作者的不同论文，两组数字不可互引。

Figure Helix 2.5：进 30 个陌生家庭零样本做家务，并第一次给出「人→机器人」迁移缩放律

具身智能 · 数据与泛化
来源：Figure 官方博客 Helix 2.5: Zero-Shot 30-Home Generalization（9/17）· 机器人前瞻 · Superpower Daily · AIBase · AGI Hunt 转载 Adcock 周报

9 月 17 日 Figure 发布 Helix 2.5，称是其迄今最先进的神经网络。评测设计比常见的 demo 严得多：把搭载该模型的 Figure 03 开进 30 个此前从未采集过数据的旧金山湾区民居，在这些家里不采一条数据、不做任何微调或适配，让机器人完成三项全身长程任务——整理客厅（把散落的 13–15 件玩具全部收进人类递来的篮子）、叠毛巾（4 条全部叠好并放进篮子）、铺床（枕头与被子四角归位、被子铺平）。

判定标准毫不留情：不给部分分，全程只用一个固定的模型权重（checkpoint）跑完 30 家，不针对任何一个家调参。为杜绝「背答案」，评测用的玩具、毛巾、床品在实验前单独隔离，并用 AI 加人工复核确认它们从未出现在任务数据里。

最关键的是那个归因实验：架构、优化方式、超参数、下游任务数据、评估条件全部固定，唯一变量是初始化方式——从随机权重开始训练的策略零样本成功率 9%（35/420），从 Index 预训练模型初始化的策略达到 56%（237/420）。官方强调预训练刻意做得很「宽」：任何一个评测任务在 Index 数据中的占比都不超过 1.90%。因为预训练是唯一变量，这道鸿沟直接量出了人类行为数据的贡献。配套的数据效率结论同样锋利：Helix 2.5 只用 Helix 02 一半的适配数据就取得相当成功率——而 Helix 02 当年是直接在评测环境里采数据训练的。

这次真正的方法论旗帜是第一条「人→人形机器人」迁移缩放律。研究团队训练 4 个模型，分别喂 Index 数据的嵌套子集，数据量跨越 8 倍区间，同时保持模型规模与下游训练方式固定。结果是：每翻倍一次 Index 数据，留出集上的动作预测损失可预测地下降；更有价值的是可外推性——只用较小规模的几次训练，就能在开跑前把最大规模那轮的测试损失预测到小数点后四位，而预测误差仅占整个 8 倍区间变化量的 0.54%。弹药方面：Index 于 2026 年 8 月 25 日发布，Figure 已承诺投入 35 亿美元（约 234 亿元）算力，2025 年 9 月完成 10 亿美元以上 C 轮（投后 390 亿美元），2026 年 9 月与 Nscale 签约将在 NVIDIA Vera Rubin 平台部署最多 10 万张 GPU。

为什么值得关注：语言模型敢堆算力，靠的就是有一条能外推的损失曲线——「再加一倍数据能换来多少」可以被预先算进预算表。具身智能现在说自己也有一条。9%→56% 是具体任务的一次胜利，0.54% 才是给钱的人看的那个数字：它意味着在这条曲线上追加投入不再是赌，而是可以算账。另外它把数据路线与遥操作路线的对比摆到了桌面上——9% 那一侧不是模型不行，而是缺那种「从小就见过别人怎么干活」的经验。

口径与边界（三处）：① Index 数据速率三源打架——机器人前瞻引官方称「每秒约产出 35 分钟新人类经验数据」，AGI Hunt 引 Adcock 周报称「每秒 53 分钟、本周 240 万段视频、11.5 万周活」，AIBase 则称「累计 1600 万段视频、26.4 万次下载、4.4 万周活」。三组数字互不一致，采用前请自行核对官方原文。② 缩放律度量的是预测记录的机器人动作的 loss，不是任务完成率，不能直接换算成「数据翻倍成功率涨多少」。③ 56% 只覆盖三项家务任务，且「零样本」指的是家庭与物体没见过，不是说能响应任意请求；距离敢让它进你家独自干活，中间还隔着可靠性、安全、成本与长尾。此外该成果未开源、未见 arXiv 论文，细节以官方博客与附录为准。

丰田 2028 年起每年 1 万亿日元、引进约 40 万台机器人：把具身热度换算成一笔资本开支

具身智能 · 产业落地
来源：路透社（9/18，Daniel Leussink 报道）· 丰田公告 · KSL/观点 · 新浪财经 · AGI Hunt · Bernstein 研报评论

9 月 18 日丰田汽车宣布：预计自 2028 年起每年投入约 1 万亿日元（约 64 亿美元，按 1 美元 = 157.18 日元）用于丰田、集团企业与主要零部件供应商的工厂现代化改造。这笔估算月初已与投资者沟通过，覆盖工业机器人、自动化物流与未来的人机协作产线；为实现该自动化水平，大约需要 40 万台机器人。

这里的口径必须校准：40 万台不是「40 万台人形机器人」。路透原文明写，这个数量包含既有设备的替换与新增、人形与非人形都算，且丰田既未确认一定执行，也未说明会持续多少年。真正的人形代表机型是 ELEY（Embodied Learning robot for Enhanced Yield），2012 年生活支援机器人 HSR 的升级版：两只手各两根手指、整机约 50 公斤、电池或外接电源供电、轮式全向底盘而非双腿，身高可调，既能拾地面物件也能触及高处。

技术核心是丰田研究院（TRI）的 Large Behavior Models（LBM）——一种生成式物理 AI，让机器人从传感器数据直接学习复杂行为，无需大量传统编程即可适应不同环境并持续改进。学习闭环很具体：工人佩戴仿照 ELEY 手指设计的装置照常作业，机器人在旁观察学习；叠 T 恤这项技能经过约两周、约 1500 次重复练习后准确率接近 100%。技能一旦学会，相关数据可以传输到其他工厂的同型机器人，这套回路还能反过来用于培训新员工。

参考坐标：丰田全球运营 60 家工厂，拥有约 1.8 万名内部称为「匠人（takumi）」的资深技工；截至今年 3 月底集团全球员工约 39.1 万人（其中约 34.4 万隶属汽车业务）。副社长兼 CTO 中岛裕树给出的定位是「创造机器人与人类共存、而非机器人取代人类的生产环境」。值得注意的是丰田同时在跑两条相反的路：在加拿大 RAV4 工厂以「机器人即服务」方式租用 Agility 的 Digit（7 台用于制造、供应链与物流），而在全球主战场自研 ELEY 的硬件与控制软件。

为什么值得关注：这是迄今最大规模的工业机器人部署计划之一，且第一次把「具身智能」从一个叙事换算成了有年度金额、有十年周期的资本开支。更值得琢磨的是那条路线分叉：租 Digit 买的是「当下算得过来的账」，自研 ELEY 买的是「没人能替我造、也没人能替我定价的规模」——连丰田级别的工程资源都不认为单一采购策略够用，这对上游执行器、传感器、电池供应商是个明确的价格信号：真正的需求方开始变成能谈下十年产能承诺的整车厂。而 LBM 那条「技能数据跨厂下发」的链路，是可迁移能力的第一次大规模工业化验证：一旦成立，产线效率提升就不再依赖逐工位编程，而是靠数据下发——这与主榜④的缩放律正好互为供需两端。

口径与边界：① 40 万台含既有设备替换与非人形机器人，不要当成 40 万台 ELEY；② ELEY 是轮式双指形态，不是双足人形，「40 万台人形」是常见误读；③ 丰田未确认执行与否，1 万亿日元是年度估算而非已批准预算；④ 中文源普遍给出「约 67 亿美元」，路透按当日汇率折算为 64 亿美元，取哪个都对，但要写明汇率；⑤ Agility Digit「约每小时 30 美元、目标两年回本」为二手转述，以 Agility 与丰田官方披露为准。另参考坐标：中国厂商 2026 年人形机器人全年产量整体预计约 10 万台——丰田一家这张饼，是这个量级的数倍。

WetRobo + Ken Goldberg：瓶颈是软件工程，不是 10 万小时人类示教

WetRobo（arXiv:2609.18435，Sherry Yang 等）是一套可复现的湿实验室 kit：机械臂、培养箱、试剂瓶、培养皿，加上预录的遥操作演示与共享 skill 文件，同一套可在不同实验室间迁移。生物学家用自然语言描述任务，coding agent 观察真实湿实验室、写机器人程序、执行、再按物理世界的试错结果迭代——不需要现场遥操作采集，也不需要新训一个网络。同期 Berkeley 的 Ken Goldberg 把争论挑明了：「Agentic Robotics 的瓶颈是软件工程，不是 10 万小时人类示教」——多 agent coding 写确定性程序、离线纠正、部署轻量边缘代码，模型不坐在内层控制回路里；Stanford 的 Chris Manning 谈 Moonlake 时同样拒绝「一个大神经网络」的押注，理由是物理精度与长程一致性还没到。这与今天主榜②（规则写成 Markdown 而非塞进模型）、③（确定性逻辑外置）是同一件事在不同层的复现。

Meta 发布 Muse for Mac：桌面级个人智能体落地，AI 从聊天框走向操作系统

Meta 官宣 Muse for Mac 即日起推出，个人智能体可在用户明确授权下直接在电脑上完成任务，首批能力包括整理下载文件夹、查找丢失的文件、总结消息与笔记，官方称更多功能即将推出。这条与前日的 vivo 蓝心 Harness、荣耀 MagicOS 11 是同一个趋势：模型不再只是被调用的 API，而是被接进操作系统、获得真实执行权限的一层。差别在于 Meta 走的是「用户明确授权 + 有限的本机任务」这类轻量起步，而 vivo 是把 6000+ 原子技能沉进内核层——授权粒度与能力边界会是这条路上真正的分水岭。
