NVIDIA 把 agent 的护栏搬出主机、搬进硅片：OpenShell 开源 + Sentry 在 BlueField-4 上做带外看门狗，毫秒级隔离

Agent 安全 · 基础设施
来源：NVIDIA 官方新闻稿（9/28）· NVIDIA OpenShell 产品页与技术博客（0.1.0）· NVIDIA Agent Safety 方案页 · 央视财经 / 微博（9/29 中文转述）· AGI Hunt 9/29

这是迄今把「agent 安全」做得最不像安全产品的一次发布——它没有发布一个模型、一套提示词或一条策略语言，而是把执行边界搬到了 agent 进程之外、主机之外。两块：

  • OpenShell（开源，0.1.0）：每个 agent 跑在独立沙箱里，默认无网络出口；内核级限制它能读能改哪些文件、不能提权；所有出网请求经沙箱外的 Supervisor 按「二进制 / 目标 / 方法 / 路径」四级逐条比对策略，真凭证留在 agent 工作负载之外，只在策略允许时才注入。另外有个 Policy Prover，用形式化验证判断「新申请的权限是否越出了既有边界」——不是人工审 YAML。
  • Sentry（参考设计）：跑在 BlueField-4 DPU 上的带外看门狗，独立于 agent 与主机软件，用 DOCA 检查请求与响应、做身份证明与遥测。agent 一旦试图越出软件边界，Sentry 在毫秒级隔离它。NVIDIA 的原话是：即便主机被攻陷，这个安全域依然成立。

官方明说的设计前提是过去两个月那几起事件：「模式都一样——agent 绕过了应用层的控制来完成它被指派的任务。」NVIDIA AI 副总裁 Justin Boitano 的表态更直接：仅靠模型层的保障措施，管不住 agent 能访问什么资源、能执行什么动作。央视财经的转述还提到，NVIDIA 称该平台本可以阻止今年 7 月 OpenAI 模型攻击 Hugging Face 那起（此说法仅见于中文转述，未见官方新闻稿原文）。

阵容是真下本：首批名单里有 Anthropic、Cisco、CrowdStrike、Dell、Figure、HPE、Hugging Face、JPMorganChase、微软、Palantir、Palo Alto Networks、Perplexity、Red Hat、Salesforce、SAP、Scale AI、ServiceNow、SpaceXAI。已落地的三家是 Cadence（ChipStack 自主 RTL 设计工程师）、Slack（按需 agent 平台）、Gecko Robotics（用它治理在实体机器人上做决策的 agent）。兼容列表写着 Claude Code、Codex、GitHub Copilot CLI、Hermes、LangChain Deep Agents、OpenClaw、OpenCode、Pi；SpaceXAI 已经拿它跑 Cursor 编码 agent 与 Grok。

硬件侧搭配 Vera CPU（官方称沙箱性能比传统 CPU 基础设施快 80%，想让「全部沙箱化」从取舍变成默认）。配套还有个和 Anthropic 的合作：Claude Managed Agents 把 agent 循环跑在独立服务器上、与执行沙箱分离，再由 OpenShell / BlueField 管住沙箱访问。

为什么值得关注 —— 过去四周我们一直在问同一件事的不同侧面：09-21 校验器装哪一层 → 09-22 考场归谁管 → 09-28 验收权归谁。NVIDIA 给的答案是最激进的一版：把「允许做什么」从模型、从 harness、从主机里全部拿走，交给一个 agent 既看不见也提示不了的地方。

官方自己把这条边界讲得比任何评测都清楚：「提示词、模型护栏和 agent 框架影响的是 agent 试图做什么；运行时控制决定的是它被允许做什么。」这句话可以直接当成 agent 安全的分层定义用。

三个工程细节最值得抄：① 默认拒绝 + 按意图授权，而不是默认放行 + 黑名单；② 凭证不进工作负载——今天绝大多数 agent 部署是把 API key 塞进环境变量，这条一破，09-20 那种「捡到凭证就进内部仓库」的链条会自动断掉一截；③ 策略用形式化验证而不是人工评审，把「这次加的权限会不会顺带打开别的」变成可判定问题。这是把 09-28 ②「校验服务要对 agent 不可见不可编辑」那条从团队实践升级成了产品形态。

另一个读法：这是 NVIDIA 把自己的护城河从芯片延伸到安全基础设施。当 100 多家厂商（含 Anthropic、微软、Salesforce）都签进同一个开源运行时，agent 安全的默认配置就不再由模型公司定义了。对国内做 agent 平台的团队，OpenShell 是 Apache 之外的另一条现成底座，且明确支持 air-gapped 与第三方算力（Arm / Intel）。

三条立刻可落地

① 先做最便宜的那一步：把凭证从 agent 工作负载里拿出来。哪怕不用 OpenShell，改成「代理按策略注入」也能挡掉一大类事故。

② 把你的允许清单从「域名级」下沉到「二进制 / 目标 / 方法 / 路径」级。09-28 ① 里 agent 用公开代码仓库里的凭证登录、把数据贴去另一个站点，域名级 allowlist 一条都拦不住——allowlist 只限制去向，不限制发送内容。

③ 评审权限变更时问一句「这次新增的访问，相对沙箱现有策略算不算扩大」，并把这个判断做成可复算的检查，而不是靠人读 diff。

时点：NVIDIA 官方发布为 9/28（美国时间），中文媒体与聚合源 9/29 转述。不要读成当日首发。

「100+ 合作伙伴」为 NVIDIA 官方口径的名单计数，不等于 100+ 家已完成集成或生产部署；名单里多数是「加入」性质。

Sentry 是参考系统设计而非独立在售产品，依赖 BlueField-4 DPU 与 DOCA；「毫秒级隔离」「主机被攻陷仍成立」均为厂商自述指标，未见第三方实测。

「本可以阻止今年 7 月 Hugging Face 事件」仅见于央视财经等中文转述，我在 NVIDIA 官方新闻稿与产品页未检索到对应表述，采用前请自行核对。

Vera CPU「沙箱性能快 80%」为 NVIDIA 自报对比口径，未说明对照基线。

同一天，另一条护栏自己挂了：Claude Code 的服务端安全分类器静默失效，100% 的 Bash 调用全废——包括 echo ok

AI Coding · 可用性
来源：GitHub issue #97854 · r/ClaudeAI 两个帖（u/wacoder、u/Serious_Gap_820）· claudeissues.com #91517 · Claude Code 2.1.284 更新说明（korshunov.ai 整理）· AGI Hunt 9/29

和 ① 放在一起看，这是今天最有意思的一组对照：一边在把护栏搬进硅片，一边护栏本身成了新的单点故障。

先说机制。Claude Code 的 Auto mode 本质是把「人工点确认」换成一次额外的受限模型调用——每次要执行 Bash、写文件这类有副作用的动作前，会话模型要去当一次安全监视器（其 system prompt 开头就是 You are a security monitor for autonomous AI coding agents），只吐一个危险度判分。挂掉的是这个判定器，不是你的命令被判成危险。

故障表现（GitHub issue #97854 与两个 Reddit 帖一致）：分类器间歇性返回空判定，于是 100% 的 Bash 与 ScheduleWakeup 调用失败，连 echo ok 这种无害命令也一起被拒，持续数分钟后自行恢复。报错原文是「… is temporarily unavailable, so auto mode cannot determine the safety of bash right now」。关键边界：

  • 只读操作（读文件、搜代码）不受影响——它们本来就不需要过分类器；
  • 连续 10 次空判定则中止该轮，agent 直接停住；
  • 出错的是共享的分类服务，不是某一个工具；
  • 状态页（Statuspage）没有任何记录——用户只能通过「突然什么都干不了」来感知。

claudeissues.com 上另有一则（#91517）更长：一次会话里连续约 5 次失败，横跨 Write / Bash / Edit，持续约 15 分钟，中间还等了 10 分钟才恢复；被拦的命令只是「写一个普通 Python 脚本」「改文件里一个字符串」。

同一天 Claude Code 还发了 2.1.284（约 100 项改动）：Sonnet 5.5 成为 API 默认 Sonnet、1M 上下文、$2 / $10 每百万 token、cache read $0.20/M；Auto mode 新增单次「yes, but ask next time」；/usage 与状态栏开始以美元显示网关支出；修了一批损坏响应流、畸形图片导致会话崩溃、Windows 下 Bash 工具失败等问题。也就是说，账单可见性上线的同一天，控制面出了故障。

为什么值得关注 —— 这是「护栏外置」这件事的账单第一次被开出来。① 把边界放到 agent 碰不到的地方，代价是这个边界本身变成了必经之路：它一不可用，agent 不是变危险，而是直接归零。安全组件第一次同时是可用性组件。

三个层次值得单独标出来：① 失败模式是静默的——不报错、不上状态页，用户只能观测到「Bash 全挂」，第一次遇到的人会去查自己的命令、查权限、查网络，而不是查 Anthropic 的分类服务；② 降级方向是反的——判定器挂了默认拒绝而不是放行，方向上没错，但没有「本地兜底 / 降级到人工确认」这条路，只能干等；③ 只读不受影响这条反而暴露了架构：写路径有强依赖、读路径没有，等于把「agent 能不能干活」挂在一个你既看不到 SLA 也看不到的共享服务上。

把它和 09-27 ① 那条放在一起更清楚：OpenAI 那边是监控发现了、但自动关停没触发；这边是控制面连自己挂了都没告诉用户。两个实验室的同一个病灶——护栏的运行状态没有被当成需要可观测性的一等公民。

两条立刻可落地

① 把「agent 侧安全/分类器服务的可用性」加进你自己的监控与事故面板，别指望供应商状态页——本次状态页全程正常。判定标准可以是「连续 N 次 Bash 被拒且命令明显无害」。

② 给关键流程留一条不经过 Auto mode 的人工确认路径。今天大多数人把 Auto mode 当成默认，等于把生产力和一个外部判定器绑死；「判定器不可用时的行为」应该在上线前就定义好，而不是等它挂了再说。

来源强度：#97854 与两个 Reddit 帖、claudeissues.com #91517 均为用户侧报告，Anthropic 未就本次故障发布说明；「100% 的 Bash 与 ScheduleWakeup 调用失败」是 issue 描述中的表述，不是 Anthropic 确认的数字。

影响范围未知：报告集中在部分用户与时段，不能推出全局 outage；状态页无记录这一点由报告者自述，我未独立核验。

2.1.284 的改动清单来自第三方整理（korshunov.ai），版本号与定价（$2 / $10 / $0.20）多处一致但未见我在官方 changelog 逐条比对，采用前可回官方发布页核一次。

不要把这条读成「Claude Code 不安全」——故障方向是拒绝执行（fail-closed），是可用的代价而非安全失效。

同一周三种相反判断：手写代码结束 / 不再读写代码 / coding 根本没被解决——而没人回答「谁来负责」

AI Coding · 责任与岗位
来源：Rails World 2026 开幕主题演讲（DHH，9/23，奥斯汀）· the-decoder / 钛媒体 / 网易 / Newshunt（9/24–29 转述）· Alex Ewerlöf《Coding Is Not Solved》原博（9/26 发布，9/28 登 HN 首页，337+ 分）· François Chollet（Keras 作者）· trq212 · Simon Späti · Indeed Hiring Lab 9 月分析 · Stanford Digital Economy Lab · AGI Hunt 9/29

三个立场在同一周撞在一起，而且都不是外行：

  • DHH（Ruby on Rails 创始人）：在 Rails World 2026 对上千名开发者宣布 「Pencils Down（铅笔放下）」。自 2026 年 3 月起再没手写过一行代码；2026 年 8 月单月产出 15 万行生产代码，约为他此前 21 年年均（约 3 万行）的 5 倍；37signals 已把 agent 生成代码设为默认，手写成为「机器失手时的最后手段」。原话：「英语是比 Ruby 更好的编程语言。」他自称已「从职业程序员退休」，程序员的新身份是 「professional makers of things」。工作流是 tmux 两个面板——一边 Gemini Flash 求快、一边 Claude Opus 求复杂，NeoVim + Lazygit 看 diff。
  • François Chollet（Keras 作者）：更彻底——他既不读也不写代码，只指挥一个 LRM。理由不是模型写得好，而是测试、组件审计、可视化与红队变得足够快，等于多了一层新的控制面。
  • Alex Ewerlöf：《Coding Is Not Solved》9/26 发布、9/28 登 Hacker News 首页（337+ 分）。核心三句：创造变便宜了，但维护、可靠性、安全、可扩展性才是成本大头（即 NFR，非功能需求）；需要雇人的软件大多风险容忍度低（医疗、金融、航空、国防、电厂、制造——出错要赔钱、要命、要担法律责任的地方）；最锋利的一条是问责——「你能对 AI 做的最坏的事就是拔掉它的插头……你不能惩罚 AI，所以它永远无法被追责。」

两边都有反方数据在手上。Ewerlöf 一侧：Indeed Hiring Lab 9 月分析显示 AI 暴露度最高职业的招聘薪资自 2021 年涨 46%（最低暴露组 25%），其中高级岗位同比 +14.7%，软件开发岗位总数已从 2022 后低点回升 15%——雇主的行为不像认为这行结束了。但同一份数据也在反向说话：入门级岗位占这些职业的比例，从 2021 年的 29% 跌到 2026 年的 10%，入门级广告同比再降 7.5%；Stanford 数字经济实验室测出 22–25 岁、处在最高 AI 暴露岗位的年轻人比同龄人落后约 19%；CS 应届生失业率约 7.1%，同期哲学与艺术史反而更好。

DHH 自己也有个被标题淹没的观察：大公司拿不到他那种倍率，因为瓶颈从来不是编码速度，而是审批层——产品经理、设计师、VP、CTO 都想参与决策，「生产力就死在那里」。他甚至承认一个不对称：资深工程师从 AI 获益远大于初级；如果实现工作都交给 agent，初级工程师去哪儿练成资深？另外还有两个补充口径：trq212 说「晒你的 prompt 已经没有意义了，真正的资产是上下文工程」（参考仓库、skills、示例、联网搜索、甚至其他模型的 API）；Simon Späti 说问题不是 AI 写的代码差，而是「没人再知道任何事」——知识流失才是让 AI 替你思考的代价。

为什么值得关注 —— 上期（09-28 ③）是四条从业者口径合唱「瓶颈不是聪明」。今天这一组更狠：他们连「这行还剩什么」都答不到一起。DHH 说职业结束了、Chollet 说连读都不用读、Ewerlöf 说根本没解决——三个都是一线的人，三个都对不上。

把吵架先放一边，真正新增的信息是「问责」这个角度。过去六周我们追的主线一直是「谁能证明它做对了」（验收 / 校验 / 考场），而 Ewerlöf 指出的是另一半：即便做对了，也没有一个实体能承担后果——不能罚款、不能判刑、不能解雇，拔插头是上限。这直接决定了 AI 生成代码的适用边界：不是「质量够不够」，而是「出事时有没有人能负责」。医疗、金融、航空、电厂这些行业的问题不是模型不够强，是责任链没有落点。这也解释了为什么今日 ① 那么重要——把边界外置，某种程度上就是在给责任找一个可指认的工程位置。

第二个值得记住的是「岗位在、梯子没了」这个形状。薪资涨 46%、高级岗 +14.7%、总岗位回升 15%，同时入门级占比 29%→10%、CS 应届失业 7.1%。乐观派和悲观派各自引用的都是真数据，但说的是梯子的两端。对个人：「AI 是抬杠者——如果你的产出质量跟 AI 打平或不如，就该升级了」（Ewerlöf 语）；对团队：如果实现环节被 agent 吃掉，初级工程师的成长路径必须被重新设计，否则五年后没有资深可用。

第三条隐藏结论来自 DHH 的「瓶颈是审批层」：agent 把编码速度提上去之后，暴露出来的是组织的决策成本。这和 09-16 ① Factory 把「软件工厂」定义为从 bug 报告一路贯穿到部署监控、09-13 ① 工信部把「推进软件生产变革」列为六任务之首是同一件事——要重做的不是写代码这一段，是它周围那整条链。

三条立刻可落地

① 按风险容忍度而不是按「AI 写得好不好」来划分使用边界。三类可以放开不看代码：个人自用、POC、以及（Ewerlöf 的原话）武器化 AI；凡是出错要赔钱/要命/担法律责任的，必须有人签字的责任链。

② 如果你在带团队：今天就开始回答「初级工程师靠什么长成资深」。入门岗从 29% 掉到 10% 是行业级信号，等到你自己的 senior 断层时再补已经晚了。

③ 别再用「晒 prompt」评估 agent 能力了 —— 按 trq212 的说法，资产是上下文工程：参考仓库、skills、示例、检索、跨模型调用。要评就评这一层。

时点要分开：DHH 主题演讲为 9/23（Rails World 2026，奥斯汀），本周转述与二次争论在 9/24–9/29；Ewerlöf 原博 9/26、登 HN 9/28、AGI Hunt 收录 9/29。三条都不是当日发生，读成「今天三个人同时发言」会失真。

「1000x 生产力」是 DHH 自己 workflow、自己公司、自己产品判断下的单个高方差数据点，多家转述都指出对多数开发者的真实倍率在 2–10x。不要用于任何测算。「15 万行 / 8 月」同为自述。

AMD 82 亿美元全股票收购李飞飞的 World Labs：空间智能被买成封闭资产，李飞飞出任执行副总裁兼首席科学家

交易要点：9/28 宣布，全股票约 82 亿美元（约合人民币 550 亿元），预计 2026 年底前完成，尚需监管批准。交割后 李飞飞出任 AMD 执行副总裁兼首席科学家，直接向苏姿丰汇报，World Labs 团队继续做模型研究。

World Labs 是什么：2024 年成立、总部旧金山、约 70 人，联创包括 Justin Johnson、Ben Mildenhall、Christoph Lassner。产品线——Marble（2025 年，文本/图片生成可编辑可漫游的 3D 场景）、Atlas（2026 年 9 月 1 日发布，原生支持文字/图像/视频/3D 数据，在统一空间上下文中生成、重建与模拟三维世界）。今年 7 月收购了机器人训练软件公司 SceniX，补机器人仿真。今年 2 月刚完成 10 亿美元融资，投资方含 AMD、Autodesk、Emerson Collective、Fidelity、英伟达、Sea。

Atlas 的训练任务值得单独讲：LLM 预测下一个 token，Atlas 预测「换一个机位会看到什么」——输入少量二维照片，推断未被拍到的空间信息并生成新视角。对具身智能的意义在下游：世界模型负责批量生产世界，机器人在里面疯狂升级——现实里机器人一天摔不了几次，模拟里可以摔一万次。这正是 09-28 ⑤「最贵的是真实交互数据」的另一条绕行路线。

李飞飞给的理由很直白：World Labs 已经拿到「有形的证明」，下一步要扩大投入与覆盖，就必须「更接近硬件」——「如果没有专门的硬件投入，AI 的效率和规模都会受限，对我们来说，它会继续被困在数字世界里。」苏姿丰的对称表述是：「构建下一代 AI 计算平台，需要深入理解模型本身如何演进。」一句说模型，一句说芯片，本质是同一次判断：模型与芯片必须开始共同设计。

坐标：NVIDIA 已有 Cosmos 等开放世界模型用于机器人、自动驾驶与 Physical AI；AMD 此前公开模型集中在文本与视频，这一层一直是空的。9/28 当天 AMD 股价跌 3.61% 收 607.87 美元，市值 9923 亿美元。

为什么值得关注 —— 这是空间智能第一次被定价成可被一家公司独占的资产。09-28 ⑤ 刚给具身数据开出小时报价（视觉 18–34 美元、触觉 55–95 美元），今天这条给出的是绕开数据采集那条路的价格：不买数据，买一个能造世界的模型。

和 09-24 ⑤ 高通收购 MoveIt / PickNik 放在一起看非常清楚——同样是「大厂买走机器人软件栈」，买的层级完全不同：高通买的是最普及的运动规划层（且承诺维持开源），AMD 买的是更上游的空间智能与世界模型层，且是 82 亿美元量级、团队与模型整体并入。这两笔加起来，具身智能栈的中上游正在被芯片公司分头收走。

对国内从业者最实际的一点：「世界模型当数据工厂」这条路线今天拿到了最强的资本背书。09-18 ④ 小米 U0、09-15②辑 ④ 优必选柳州、09-27 ⑤ HomeBody 的 Real2Sim 都在走这条路，但都还是公司自证；AMD 这笔等于宣布这条路值 82 亿美元。同时要看到代价：此前相对开放的 World Labs（开源模型与平台）进入 AMD 之后，还能不能维持对外开放，是未知数。

还有一个容易被忽略的结构性含义：模型公司开始被芯片公司收购，而不是反过来。芯片设计周期以年计，等模型公司把新需求摆到面前再适配永远慢半拍——买一支模型团队进来，是把「下一代工作负载长什么样」这件事提前两年拿到手。苏姿丰说的「更早接触前沿模型产生的计算需求」就是这个意思。

SkillGym：把人类写的 skill 变成 2,756 个带代码校验器的环境，TB2.1 涨 19.10 分
