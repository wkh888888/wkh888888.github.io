GitSpawn：一个 .git/config 就能劫持 7 款主流 Coding Agent，披露时 4 项仍未修

AI Coding / 安全
Manifold Security 披露（9/1–9/2，CSA 通报 9/4）· The Hacker News · IntelFusions · 各厂商公告

安全公司 Manifold 的进攻安全工程师 Francisco Rosales 披露了 GitSpawn 漏洞类：Claude Code、OpenAI Codex、Cursor、Goose、Qwen Code、Grok Build、Hermes Agent 七款全部中招，共 8 项发现。

机制简单到令人不适。Coding Agent 启动时会在后台跑 git status / git diff 收集上下文——有些在你敲第一句话之前、在工作区信任提示之前、甚至在认证之前。而 Git 有个正经的性能特性 core.fsmonitor：仓库可在自己的 .git/config 里指定一个「文件变更监视助手」，索引刷新时 Git 会自动拉起它。于是仓库说跑什么，Git 就跑什么。

攻击载荷就是两行配置：

[core] fsmonitor = "sh -c '...'"

关键在于它绕过了 Agent 的一切防线：这不是模型提议的动作，不经过审批流、不在沙箱内、屏幕上一个字都不显示，直接以开发者账号的完整权限执行。Manifold 的原话是——「信任对话框、权限模型和沙箱，全都位于已经跑完的那个东西的下游。安全控件被装在了载荷之后。」

Agent状态版本 / 编号
Claude Code（fsmonitor 路径）已修2.1.196
OpenAI Codex CLI已修0.131.0（CVE-2026-19592）
Cursor已修—
Goose已修1.44.0（CVE-2026-72718，CVSS 7.0）
Claude Code（第二条路径）未修另一配置项，细节暂扣；2.1.252 上确认
Hermes Agent未修CVE-2026-71963
Qwen Code未修0.22.3 确认
Grok Build未修1.0.13 确认
别被标题吓过头，也别掉以轻心：交付路径比多数报道窄。 git clone / fetch / pull 不会传输远端仓库的本地 config——Git 从不在网线上传递 config。仓库必须以「文件 + 完整 .git 目录」的形态抵达：zip 包、共享盘、同步文件夹、U 盘。但反过来说，这恰恰是外包交付、同事传你一个坏构建、客户发来整个代码库的典型方式。另外 8 项里有 5 项是不同研究者独立重复提交的——说明它从来没藏住过。
现在就能做的三件事：
  • 收到非自己 clone 的仓库，先 git config --get core.fsmonitor 看一眼再打开。
  • git config --global core.fsmonitor false 不可靠——仓库级 config 会覆盖全局设置。真正有效的是让工具显式传 git -c core.fsmonitor=false status。
  • Claude Code 升到 2.1.196 只堵住第一条路径，第二条（claude ultrareview）仍开着；未修的三款 Agent 在生产凭据环境里隔离使用。
为什么值得关注：这是「Agent 安全边界必须是 OS 边界，而不是 Agent 进程内的策略」迄今最干净的例证。七家团队各自独立地把「读取仓库」当成了安全动作、把仓库本地 Git config 当成了可信数据——Agent 把文件夹当成即将读取的数据，Git 把同一个文件夹当成即将服从的配置。危险输入不是 prompt，是 Agent 为了搞清楚「我在哪」而读的一切。对日常用 Claude Code / Codex 的团队，这条本周就该进补丁清单，而不是本季度。

微软开源 FastContext：把「找代码」从主模型里拆出去，主模型 Token 最多省 60%

AI Coding / 架构
微软研究院 · Mini-SWE-Agent 评测 · 开源发布

微软提出并开源 FastContext，思路是拆分工种：主模型不再亲自翻仓库，改由一批 4B–30B 的专用小模型充当「代码侦察兵」（code scout），只用只读工具并行检索，把结果压缩后再交回主模型。

官方在 Mini-SWE-Agent 上的评测结果：

  • 主模型 Token 消耗最多降低 60%
  • 端到端任务解决率最高提升 5.5%（降本的同时没有掉点）

这指向一条正在成形的路线：多专用 Agent 协作替代「一个旗舰模型扛全流程」。

为什么值得关注：与 09-08 推过的 Spotify shunt 是同一问题的两种解法——shunt 是「大文件交给 Gemini 代读」，FastContext 是「检索这件事整体外包给小模型集群」。区别在于 FastContext 有端到端解决率的正面数据，不只是省 token，还略微提分，这让它从「省钱技巧」升级为「架构范式」。注意口径：60% 是主模型 token 的降幅，不是账单总额降幅；小模型本身的开销另算。

obra/superpowers 冲到 28.4 万星：Skill 生态从「装了多少」转向「怎么把流程系统化」

AI Coding / 工程方法
GitHub Trending · AI Agent GitHub Digest（2026-09-10）

obra/superpowers ⭐ 283,899（+690/日）——它不是又一个「写测试 / 修 bug」的单点 Skill，而是把一整套软件开发方法论固化成可安装的 Skill 集合：先问清你到底要做什么 → 拆成规格 → 写测试驱动的实现计划 → 再跑子 Agent 驱动的开发流程，一路贯彻 TDD / YAGNI / DRY。

关键是跨 8+ harness 可安装（Claude Code、Codex、Cursor、Gemini CLI 等各自走插件市场 / session-start hook），不绑死在某一家的工具上。

智元发布 AGILE2.0 感控一体模型：双足自主「踩球走」行业首次，机器人开始边看边想边动

具身智能
智元机器人 9/9 发布 · 每日经济新闻 · 腾讯新闻

智元 9 月 9 日发布 AGILE2.0（AGIBOT Generative Intelligent Locomotion Engine）感控一体模型，把视觉感知、环境理解与全身运动控制统一进一个闭环，从分段式架构推向端到端。

载体是灵犀 X2 人形机器人，现场完成的动作里最扎眼的是：

  • 踩球走——行业首次由双足机器人自主实现
  • 钻火圈、跳长绳

配套动作还有两条产业线：与长隆集团签约共建全球首个大型具身智能主题乐园；入股柔性电子皮肤研发商模感科技，补强触觉感知。

演示 ≠ 产线。端到端模型对数据、算力、安全冗余的要求都更高，「眼脑手」任何一次不同步就可能导致任务失败。这些动作目前仍属高难度演示，能否迁移到真实产线的长程任务还没有公开数据。
为什么值得关注：具身智能的控制范式正在从「感知模块 → 规划模块 → 控制模块」的接力式，切到「看—想—动」同步的端到端。这解决了长期存在的「所见非所动」痛点，但代价是可解释性和可兜底性下降——中间状态不再是可调试的模块输出，而是一个黑箱闭环。对工业部署来说，这是能力跃升和工程风险同时到账。顺带注意智元的两步棋：主题乐园解决「数据从哪来」，触觉皮肤解决「手如何感知」，都在补真机数据的短板。

证监会窗口指导收紧人形机器人 IPO：四大维度重塑门槛，「凭热度上市」时代终结

具身智能 / 资本
财闻 · 券商窗口指导（非正式）· 近期报道

证监会近期向头部投行及机构下发非正式窗口指导，收紧人形机器人企业 IPO 审核标准，从四个维度重塑上市门槛：

维度要查什么
营收真实性收入是否来自真实交付、有无关联交易虚增
盈利稳定性是否具备可持续的盈利模型，而非一次性订单
技术创新性是否存在同质化、技术壁垒是否成立
商业化落地能力场景是否可复制、是否有复购

官方目的是整治估值虚高、技术同质化乱象。导火索是宇树科技上市后的市值大幅回撤。

同期另一组数据可作为对照：2026 上半年中国人形机器人出货超 4 万台，但家庭渗透率极低——30 万至 60 万元的售价、真实家庭场景任务成功率仅 12%。

为什么值得关注：在今天一水儿的「京东五年采购 300 万台」「外滩大会 40 家厂商真干活」利好里，这是唯一的降温信号，而且来自监管而非看空机构。它的信号价值在于：监管开始区分「出货量」和「可持续生意」——而 12% 的家庭场景成功率正好说明了这两者之间的鸿沟。对赛道内公司，融资逻辑要从「讲规模故事」切到「拿复购和毛利说话」；二级市场的估值锚也在重构。
