英伟达开源 ASPIRE V1.0：机器人把修好的技能存成代码，换上 Astra 底座后 80 项任务 99%

具身智能
NVIDIA GEAR 官方项目页与 GitHub 仓库 NVlabs/ASPIRE（10-16 开源，Apache 2.0）；量子位 / ttm.financial / toolnavs / unifolm 转述（10-16 至 10-19）；论文 6 月首发（转述源记 arXiv:2607.00272）

英伟达 GEAR 实验室 10-16 正式开源 ASPIRE V1.0（Agentic Skill Programming through Iterative Robot Exploration），代码、实验配置与技能库全部放出。它要解决的是一个很别扭的问题：机器人遇到没见过的任务，怎么把动作做对。主流路线是端到端视觉-动作模型（像人练肌肉记忆，数据要得多、迁移难）；ASPIRE 走的是另一条——让编程智能体给机器人写控制程序，程序跑失败就复盘轨迹、改代码，改对的方法存进技能库，下次直接调用。

  • 三件套。闭环执行引擎把每次感知、规划、抓取、控制调用的输入输出连同视觉证据记成多模态轨迹，失败后代理能顺着轨迹定位到底哪一步出错（物体有没有认准、抓取位置是不是偏了、运动规划器有没有给出能走通的路线），而不是只收到一句「失败了」；技能库把验证过的修复蒸馏成模块化条目（定位技巧、感知提示、调试流程）持续积累；演化搜索在单条调试路径走不通时并行生成多套候选程序，拿各自的失败记录互相参照。
  • 10 月更新的看点是「换脑子」。团队把模型后端换成 GPT-6 Astra 后，LIBERO-Pro 的 80 项任务（Goal / Object / Spatial / Long）成功率 99%，Robosuite 7 项代表性任务与 BEHAVIOR-1K 2 项代表性任务全部 100%。Jim Fan 称之为机器人领域「0 到 1 的海啸」。模型 scaling 曲线更说明问题：同样 10 项 LIBERO-Pro 任务，成功率从 15%（GPT-6 Luna）一路到 99%（Claude Opus 5.5），而 Opus 5.5 在三个基准的全部任务上达到 97–100%。
  • 成本与「苦涩教训」。Sonnet 5.5 把每任务成本压到约 12 美元（98.8% 成功率）；而团队精心设计的演化搜索环节，在强模型上的收益从 +34 个百分点缩水到约 +2 个百分点——模型越强，为弱模型准备的 harness 工程越不值钱。真机演示包括 Astra 驱动机械臂在线学习拧魔方（边试边改自己的控制程序）、仿真技能迁移到真机完成桌面清理。

技能还能跨机型迁移：仿真里攒下的经验被用来给另一台真机当编程参考，显著减少调试所需的推理 token。项目页的案例集里，Opus 5.5 和 Astra 学会了撒手把书推到低架子下、清开杂物再拿盘子、倾斜夹爪钩住低把手开抽屉——这些「变通」原先都是 0% 的任务。

这为什么值得看。它与 09-23 ④（GPT-6 Astra 直接当机器人策略，RoboDojo 2,100 次试验 22.48%）是同一条赛道的两条路：那条让模型直接输出动作，这条让模型写代码控制机器人。ASPIRE 给出的答案是「程序是可组合的，动作不是」——会改代码的智能体等于把试错过程沉淀成可复用资产，而工业场景里「为什么这么动」能讲清楚，往往比「动得多快」更重要。

更值得盯的是演化搜索的退场：这是「苦涩教训」在具身侧的第一次量化显形——harness 层的精心设计会被模型能力压缩。它与 10-04 ① Sharpening Tax（后训练把题推向两极）、09-23 ① HarnessTax（harness 决定成本与分数）拼成同一道题的三面：中间层到底值多少钱，取决于模型这头走到哪。

成绩均为项目方自家基准，无独立复测，适合看方向、不适合当行业标尺；论文 6 月首发（当时用 Opus 4.6 取得 SOTA），本期增量是 V1.0 开源与 Astra 底座成绩，arXiv 编号仅见单一转述源、未独立核到编号页。

生成的 Python 以广泛系统访问权限运行，需要隔离环境；「99%」成立的前提是任务边界清楚、环境可控，真实车间的光线、粉尘、来料偏差会重新出题。

两个可操作的观察点：① 拿自己产线的真实任务跑一遍「写代码控制」与现用 VLA 策略的对比，重点看不常见任务（换型、异常料姿）而不是基准任务；② 盯第三方独立复测与 sim-to-real 迁移报告——技能库能否跨机型复用，是这条路线相对端到端模型的真正分水岭。

Anthropic 内部研究：agent 工时已达员工 6 倍，初级技术岗招聘占比从 27% 跌到 9%

AI Coding
The Anthropic Institute 报告《How Employment is Changing at Anthropic》（10-16 发布）；The Decoder / Pivot News / TechsCurrent / Livemint / IT之家转述（10-17 至 10-19）

Anthropic Institute 10-16 发布内部就业研究报告，基于 agent 会话遥测、招聘记录、产出度量、日历、员工问卷与 17 次员工访谈，给出目前最细的一手「AI 进组织」账本：

  • 岗位结构。技术部门初级岗位占比从 2025 年初的 21% 降至 14%；新招员工里初级占比从 27% 骤降至 9%，开放初级岗位降至 6%（2025 年 12 月起降幅尤其陡）。约三分之一的机器学习经理与五分之一的软件工程经理表示因 AI 减少了招聘。非技术部门基本稳定；技术部门占总就业比例从 61% 降至 56%——但技术招聘的绝对人数仍在增长，这是结构变化不是缩编。
  • 工时口径。到 2026 年 8 月，员工部署的交互式 agent 工时已达人类员工的 6 倍（研究部门 19:1）；2026 年 3 月起全公司 agent 总工时首次超过人工。注意口径：agent 工时指推理与活跃工具使用、不含超过 30 分钟的等待；人类按每周 40 小时计——这是运行时间，不等价于人类工时。
  • 产出与「元工作」。工程师人均代码提交量达到六个月前的 5.1 倍，数据科学家查询 3.1 倍、法务合同 3.1 倍、销售成交 1.7 倍；追踪 192 名采用编码智能体的工程师，产出上升且被删除或回滚的代码比例未见恶化。但新负担同时出现：「元工作」（写指令、搭监控面板、审查 AI 产出）占员工交互式 Claude 会话的比例从 10% 升至 22%；非技术员工读完全部 agent 输出可能占去半个工作周。员工正从「执行者」转向「智能体管理者」。

招聘标准随之改写：经理们 increasingly 按独立判断力、适应性与指挥 AI 工作流的能力评估候选人，而非被 AI 自动化的领域执行技能。报告结论相当直白：需要政府层面的再培训与收入支持，因为「对在职者的就业保护，惠及不到一开始就没被招进来的人」。研究者 Nolan Lovett 的「认知公地悲剧」框架被报告引用：今天省下的初级岗位成本，会以 2030–2045 年的专家短缺形式摊给整个社会。

这为什么值得看。09-29 ③ 我们用 Indeed 的第三方统计讲过同一件事（入门级岗位占比 29%→10%）；这次是公司自己把内部账本摊开，而且给出了机制而非仅相关：agent 接走的正是初级岗位的活，省下的工时流向「元工作」，招聘标准从执行技能转向判断力。对用人策略的直接参照是：初级岗位不是等比例消失，是被重新定义为「会指挥 agent 的人」。

与 10-13 ② 哈佛论文（Jira 解决率无统计显著变化）并读更有意思：一边是提交量 5.1 倍，一边是问题解决率不动——产出通胀与真实吞吐之间的缝，正是「元工作」占 22% 的原因。

报告自承 Anthropic 是特例：极度 AI 密集的软件公司、业务高速增长、工具自愿采用，结果不易外推到整体经济；agent 采用者非随机选取，因果性存疑；「6 倍」是运行时间口径，不等于 6 倍人类劳动。

人均创收达 Meta / 谷歌高速增长期 2–4 倍的比较基于截至 2026 年 4 月的内部财务记录与通胀调整后的公开数据，属公司自述；报告同时承认产出量增加不自动等于更好的商业结果。

Sphinx 等「给 AI 代码设检查点」的工具扎堆上线：推代码前，先答对「这段代码出错时会怎样」

AI Coding
Sphinx Show HN（10-18，项目页 sphinx-six-theta.vercel.app，GitHub parthh01/sphinx，MIT）；dev.to/slabb / reveneau / devaitoolkit / my2cents.ai 转述与实测（10-18 至 10-19）

10-18 一批同类工具同日扎堆登上 Hacker News，领头的是 Sphinx：一个 git pre-push hook，在把 AI 生成（或以任何方式产生）的代码推到受保护分支前暂停，读一遍 diff，出一道「行为理解题」——比如「这段代码在出错时怎么表现」「重试时如果第一次扣款超时会怎样」。答对放行；答错，它解释原因并换一个新场景继续。设计上的关键选择：

  • 评审员没看过聊天记录。出题的是一个独立的 reviewer 模型，只通过只读 git 工具看已提交的改动，看不到产生这段代码的对话——所以 quiz 不是拿编码 agent 自己的说法来考它。默认预设用 Claude Code 跑 Haiku 或 Codex 跑 GPT-6 Luna，有现有订阅就零新增账单；也支持 OpenRouter 或任何 OpenAI 兼容端点。
  • 可绕过，但不可隐形。sphinx yolo 可以跳过检查——但每一次跳过都进日志。这一个 flag 把它和今年所有「AI 门禁」工具区分开：绕过留下记录，就不再是不可见的漂移，而是决策轨迹。
  • 边界诚实。README 自称「comprehension practice」而非安全门禁：任何有本地访问权限的人（包括编码 agent 自己）都能绕过 git hook 或让别的模型代答；.env 与密钥默认不读，但贴进普通源码的密钥仍会发给 reviewer；hook 最多阻塞 push 25 分钟，无默认模型调用上限（典型一次检查 5–8 次请求加每次回答一次）。

同期同类还有一整排：MIKE（gVisor 沙箱 + git worktree 里用看板卡片给 agent 派活，Apache 2.0）、Busabase（多个 agent 读写同一份结构化记录，写入以「变更请求 + 字段级 diff + 作者」呈现，MIT）、Termexo（Windows 下统一管理各编码 agent 终端的台面，MIT）、PrimerKit（市场数据工作区，Apache 2.0）。共同前提：agent 生成的代码量已经大到逐行人读不现实，所以检查点被设计成「让提交者证明自己理解」而不是「让机器证明正确」。

这为什么值得看。10-07 ③ 我们讲过「AI 让贡献便宜，维护没便宜」——tldraw 自动关外部 PR、Sindre Sorhus 全站禁用，是把门口收紧到默认不接；Sphinx 是同一焦虑的另一种解法：不挡 AI 写码，只挡「不懂代码就把代码推到生产」，把责任落在人的确认动作上。它与上一代「AI 审查 AI」（查实现）互补——一个查理解，一个查实现，两种失败模式需要两种控制，搞混的团队两个都没有。

支撑数据比工具本身更硬：Anthropic 一项 52 人随机对照实验（经 InfoQ 等转述）里，用 AI 辅助的组在刚用过的概念测验上平均 50%，手写组 67%——低 17%，近两个字母等级；其中把代码生成整个委托给 AI 的开发者得分不到 40%，而只用 AI 问概念性问题的在 65% 以上。工具不是问题，委托深度才是。

HN 讨论的两面都要读。批评方指出：quiz 可被轻易绕过（把问题贴回 agent、直接删 hook）；抓不到 diff 级缺陷（遗留的 debug print、被弱化的断言能通过任何理解测验）；有人预测「confirmation fatigue」和 agent 替人答题。这些批评成立——所以把它当 Level 1 控制（存在、可见、让人慢下来）而不是执行机制。

实测口径：有团队六周跑两个 TypeScript 服务加一个 Hono API，30 天内 14 次推送未过 70% 理解线；大 diff（800 行整段会话产出）问题会变泛。HN 分数不同转述时点不一（227 分 / 76 评论为 48 小时口径），引用时注意时点。

今天就能试的两件事：① 在 solo 项目或周末修复的仓库上装 Sphinx，观察「答不上来」的出现频率——那就是你的理解缺口地图；② 如果团队已有强制人工评审，不必上这类工具；真正缺门禁的是「agent 有写权限、推送直达 main」的路径，先给那条路径装尺子。

Google 开源 Harness²：让 harness 自己改自己，单步最高 +11.5 分且不动一个权重

AI Coding
arXiv:2610.14224（Google Cloud AI Research + Northwestern，Ruiyao Xu 等 8 人）；GitHub google-research/harness2（10-18 开源，Apache 2.0）；MarkTechPost / interestana / clauday 转述（10-18 至 10-19）

Google Research 10-18 开源 Harness²（论文 arXiv:2610.14224），把「harness」——系统提示、护栏、记忆、工具指引、子智能体、技能、脚本、插件这些围绕模型的运行环境——变成可自动调优的工件。核心命题：模型权重不动，只改周围那层。做法是两层递归：

  • 任务级递归（Propose–Probe–Compose）。agent 先用基础 harness 跑任务，编辑器提出两个候选——invariant candidate 针对通用失败（规划、工具使用），domain candidate 针对领域问题——在同一任务上执行，按行为对比组装出更优配置。全程不需要标准答案、不需要外部验证器，这对开放世界（任务没见过、测试时是新的）是关键。
  • Harness 级递归。把每次任务采纳的 harness 与有证据支持的经验教训提取出来，更新那个「负责改进的 harness」本身——系统连怎么改进自己都在学习。

八个可编辑组件各自挂载为文件（system prompt / guardrails / memory / tool guidance / subagents / skills / scripts / plugins），任务级递归还可以横向扩展（k 个候选并行探索）或纵向加深（k 步递进）。成绩：在 JobBench（职业工作）、LAB（法律工作）、WorkBuddy-Bench（办公 / 网页 / 代码）三个专业基准、四个模型-harness 配置上，单步一致提升 GLM-5 与 Gemini 3.5 Flash——WorkBuddy-Bench 最高 +11.5 分、JobBench +4.5、LAB 部分通过率 +11.8 个百分点，且随递归预算继续增长。

一个耐人寻味的细节：执行器默认是 OpenCode，可切 Codex——Google 实验室自己的 harness 研究，跑在两个开源编码 agent 上，而不是自家的 Antigravity。

这为什么值得看。09-23 ① HarnessTax 用受控对比证明「同一模型在不同 harness 下成本最多差 5 倍、成功率 ±5%」；10-04 ① Sharpening Tax 证明后训练会把模型能力压向两极。Harness² 是这条线的下一章：既然 harness 值这个差价，就让 harness 自己进化——而且它明确不碰权重，对闭源模型同样适用（优化环境比微调权重廉价）。

同期还有一整组论文把 harness 变成正式研究对象：Self-Evolving Agent Harness（arXiv:2610.18813，66 页形式化，HF 188 upvotes）、ToolBottleneckBench（arXiv:2610.21098，21 个配置实测发现「可见工具菜单是唯一带来大惩罚的压力」，跟随完成上限截断，上限提高 16 倍消除大部分惩罚——「多数失败终止于 harness 限制」）。harness 不再是模型周围的东西，它成了被研究的对象本身。

官方 README 自带安全警告：executor 网络访问不受限、Codex 以沙箱禁用状态运行，公开基准的评分标准可能在线可访问——评测前必须自行配置网络限制，否则成绩不可信。仓库同时声明「不是 Google 官方支持的产品」。

成绩口径：「最高 +11.5 分」是 WorkBuddy-Bench 上的最好单点，不是平均增益；三个基准均为专业向基准，与编码基准（SWE-bench 等）不可直接换算；论文为 10 月新上线，尚无第三方复现。

人形机器人收入榜前五全是中企：上半年全球 3.6 万台 / 5.4 亿美元，优必选 16.5% 居首

具身智能
弗若斯特沙利文《2026 年全球人形机器人市场研究报告》（10-13 前后发布）；南方日报（10-13）/ 深圳特区报（10-15）/ 证券日报（10-18）陆续解读

弗若斯特沙利文发布《2026 年全球人形机器人市场研究报告》，第一次用「真金白银的销售额」而不是演示视频给全球玩家排座次：

  • 总量。2025 年全球人形机器人销量 3.5 万台、收入 5 亿美元；2026 年上半年销量 3.6 万台、收入 5.4 亿美元——半年超过 2025 全年。统计收入时未计入厂商内部交易及关联交易，只算客户真实掏钱购买。
  • 座次。收入榜前五清一色中国企业：优必选 6.2 亿元 / 16.5%、智元 6.1 亿元 / 16.1%、宇树 5.8 亿元 / 15.3%、银河通用 2.1 亿元 / 5.5%、乐聚 1.5 亿元 / 4.0%，五家合计 57.4%。特斯拉 Optimus、Figure AI、Agility 等海外代表大多停留在原型迭代与实验室小规模试点、以企业内部自用为主，未进前五。
  • 结构。应用分娱乐表演、科研教育、数据采集、生产作业四类，其中生产作业收入增速最突出：2025 全年 0.47 亿美元 → 2026 上半年 0.78 亿美元，半年收入较去年全年 +65.9%。优必选上半年总营收 12.69 亿元（+104.2%），新增订单超 10 亿元（含 3 笔亿元级），空客首批采购 100 台 Walker S2——全球首个进入航空制造领域的人形机器人订单。

报告同时给出商业化成熟度五阶段：技术展示、客户试点、付费部署、常态化运营、规模化复制——当前头部厂商的竞争正从早期的技术展示与性能比拼，转向规模化交付与商业化落地能力的较量。资本侧同频：据源达信息统计，2026 上半年行业融资总额 1041 亿元，超过 2025 全年近一倍；宇树 7 月科创板 IPO 注册生效，越疆、乐聚、云深处等上市申请相继获受理。

这为什么值得看。它与 10-18 ⑤ 信通院报告正好是一对：信通院给的是冷水（技术落后前沿约两代、月均开机不足 10 天、日租金从 2 万跌到千元级、残值缩水近九成），F&S 给的是座次（谁在收钱、收多少）。两份放一起读才是全貌：中国企业在「把机器人卖出去」这一步跑在前面，但让机器人真正干活的长跑才刚刚开始——收入前五全是中企，不等于技术全面领先，更不等于格局已定。

真正的分水岭是两个问题：单台机器人能否从「演示级」（一天跑两小时、三个人盯着）变成「产线级」（一天跑二十小时、一个月不罢工）；千台规模的售后与备件体系能否撑住。筛选器已经从「谁发布了新机器人」变成「谁的订单、毛利、复购率和无故障运行小时数经得起审计」——与 coding 侧「从比模型分数到比落地成本」是同一套逻辑在两条赛道同时上演。

报告 10-13 发布、本周媒体陆续解读，非当日首发；座次与数字以报告原文为准，转述稿中的「深企占两席」等表述为媒体归纳。

三套出货 / 销量口径不可混用：本报告为销量 3.6 万台（收入口径）；10-18 ⑤ 信通院引 Counterpoint 为出货 >2.2 万台（+近 300%）；另有「上半年出货超 4 万台、全球占比 97%」的行业口径（中国经济网今日稿仍在使用）。三者统计范围与「出货 / 销量」定义不同，引用时务必标明来源。
