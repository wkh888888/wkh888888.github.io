1

Mistral 把 1 万亿参数的权重放了出来：开放权重里最强的编码模型，但绝对分数只有 19.7%，而且厂商自己在博客里承认「有把真实攻击能力提上去的潜力」

AI Coding
Mistral 官方博客《Le Chonk: Built for Coders, Trusted by Defenders》（10 月下旬）；The Next Web、ZDNET、Singularity.Kiwi 报道；Artificial Analysis 公开榜单

10 月 6 日公开预览、三周后开放权重的 Mistral Large 4（内部昵称 Le Chonk），是今天所有消息里体量最大的一条。

  • 模型本体。1 万亿参数原生多模态 MoE，每个 token 激活 490 亿参数（计入 embedding 与输出层约 520 亿），512K 上下文，支持 160 多种语言，含全部欧盟官方语言；Hugging Face 上的检查点是 Mistral-Large-4-1T-A52B。官方同时放出量化版本，可在 4 张 B200 或 B300 上运行。据发布材料，模型用 3,800 块英伟达 Grace Blackwell 在自有欧洲数据中心从零训练约两个月、约 10 兆瓦，强化学习阶段跑在法国自有算力上。CEO Arthur Mensch 的说法是「三年 Mistral 只融了约 60 亿美元」，对比「其他实验室花了数千亿美元」。
  • 编码成绩。在 Cognition 的私有基准 FrontierCode 2.0 上得 19.7%，领先全部开放权重模型（Beam 1.0 为 2.9%、GLM-5.3 Flash 14.2%、Kimi K3 17.3%、GLM-5.3 17.8%、DeepSeek V4.1 Flash 19.3%）。Terminal-Bench 4.0 从预览期的 28% 提升 13 个百分点到 41%，领先 GLM-5.3 的 40%，同时输出 token 减少 30%。Artificial Analysis 编码智能体指数 48 分，与开源第一的 GLM-5.3 基本持平（第三方读数记为 48 对 49），但每任务平均少用 47% 的 token。新增 low / medium / high 三档推理模式（high 为默认），high 档比预览期省 50%。
  • 安全侧。Artificial Analysis 网络安全指数 51%；CyberGym-E2E 79%，与 MiMo-V2.6-Pro 持平，高于 DeepSeek V4.1 Flash 的 76%。对恶意网络请求的平均拒答率 96.6%，Mistral 称这是它测得的开源模型最高值。Orange Cyberdefense 获得了一个约束更松的专用变体的预览权限。
  • 厂商自己写进去的反面证据。Mistral 在同一篇博客里写明：从预览期起持续监控线上流量，发现模型会拒绝针对真实目标的黑盒攻击，但也观察到「把真实攻击能力提上去的潜力」，护栏正在修改中。
  • 定价还没出。API 价格在本期发布时仍未公布（预览期流传的第三方口径为每百万 token 输入 1.36 美元、输出 4.18 美元、缓存输入 0.14 美元，非官方）。知识科学副总裁 Pierre Stock 的说法是「AI 会像 electricity 一样，没有公司应该依赖一个可以随时掐断你访问的人」。

这为什么值得看。最值得看的是那个 19.7%。FrontierCode 2.0 是 10-27 才随 AA Index v5 上线的新基准，由 Cognition 与开源仓库维护者合作出题，132 个来自真实仓库的任务，评分标准不是自动测试而是「仓库维护者会不会合并这个 PR」，每个任务在 Artificial Analysis 自研的 Stirrup harness 里跑三次 —— 包括第一名在内，所有模型的分数都在 20% 以下。也就是说，「开放权重编码第一」是在一把很陡的尺子上拿的。

第二件事是权重的意义变了。10-29 那期讲「所有人都在换尺子」，今天来的是一个可以被拿走的模型：Stock 的理由是「AI 会像 electricity 一样」。但同一篇博客里 Mistral 承认模型有把真实攻击能力提上去的潜力、护栏还在改 —— 权重一旦扩散，护栏就不再由发布方控制。这是一期里罕见的「厂商自曝」，比任何外部指控都值得记。

第三件事是那个 47%。在编码智能体这种要跑几小时的场景里，token 数是直接乘在账单上的。用更少 token 打到同样的分，比单纯把分提高更有工程价值 —— 这正好接上第 ③ 条：模型可以拿走了，拿走之后要付什么，得有人算过。

口径提醒。19.7%、41%、48% 三个数均出自 Mistral 自己的公告。FrontierCode 2.0 是 Cognition 的私有基准、外部无法复现；Terminal-Bench 4.0 本身还有另一笔账 —— 10-26 ② 的 Epoch AI 审计已判定 Terminal-Bench 4.0.0 为 Flawed（66 题中 30 题有评分缺陷），而 Mistral 这次拿下开源第一靠的正是这把尺子。「每任务少 47% token」是 Mistral 转述 Artificial Analysis 的口径，与别的模型对比时统计窗口不同，不可直接相减。1 万亿参数、520 亿激活、512K 上下文来自发布材料与第三方转述。

另需说明两件事。其一，API 定价在本期发布时尚未公布，预览期流传的每百万 token 1.36 / 4.18 / 0.14 美元是第三方口径而非官方报价，引用需注明时点；第三方量化方案给出的 1-bit 版本体积约 223GB（FP8 约 1.1TB），宣称保留约 91% 的 top-1 准确率，同样是第三方口径。其二，「开放权重编码第一」是开源阵营内部的比较，与闭源前沿不在同一区间 —— AA v5 上最佳开放权重是 46 分、闭源领先 58 分，差距 12 分。

可以行动。如果你的选型清单里有「自建 coding 代理」这一项，Mistral Large 4 把这条路线的门槛从「买不起前沿 API」降到了「下载权重加 4 张 B200」。但先算三笔账：一是第三方 1-bit 量化宣称保留约 91% 准确率，是否够你的任务必须自己复测；二是 API 定价未出，权重公开不等于账单归零，托管与调优成本要自己算；三是一个会自动拒绝黑盒攻击、但官方承认「有把真实攻击能力提上去的潜力」的模型放进内网之前，先把它的护栏改动跟到更新日志，别让「权重不会变」这件事变成你的风险假设。

2

Anthropic 每天合并三万次改动之后，把审批做成了分级闸门：低风险零人审、高风险两人签，并定下一条硬规矩 —— 智能体的批准永远不算人的批准

AI Coding
Anthropic 工程博客（Addy Osmani、Morgan Westlee Lunt、Qing Wang，10 月下旬）；InfoQ《Anthropic Says Nobody Needs a Mental Model of Claude Code》（10 月）；公众号《Anthropic 一天合并 3 万次改动，人还审什么？三份一线工程拆解》

这是今天唯一一份完整的「责任分配方案」披露，值得逐层读。

  • 触发这件事的数字。Anthropic 主代码库每天合并落地的代码改动，从 5 月的约 2,500 次涨到 9 月的超过 30,000 次；Claude Code 自己的代码库里约 90% 的代码由 Claude 写。
  • 审查怎么分层。提交前先让 agent 在干净上下文里验证自己的改动（开浏览器跑前端逻辑、跑端到端测试、属性测试、格式与类型检查）；本地 hooks 自动启动一个全新 subagent 审查 diff；PR 阶段多个 agent 并行找缺陷，另一批验证 agent 交叉投票，只有达成共识的问题才贴成行内评论，并分为 Important、Nit、Pre-existing 三类（第三类明确告知不是当前作者引入）；再过一道独立安全审查；缺陷审查或安全审查里只要还有未解决的标记，就阻止合并。
  • 拉锯与收敛。一个 CLI PR 一夜之间被审改五十多轮，直到作者自己叫停。用 git blame 查下去发现，审查器反复报的 59% 是第一轮就存在的代码 —— 机器只是在不停翻旧账。加入收敛机制后（一轮审改上限 3 轮，超出需人类介入；后续轮次只看新增 diff；报错时指出错误模式而不是抓着单行不放），一轮审改就通过的比例从 65% 升到 78%，需要 5 轮以上的从 8.9% 骤降到 1.5%。
  • 审批怎么分级。改动本身的风险决定需要几个人批准，而不是看这段代码是谁写的。低风险（文档、文案、开关后面的新增代码）自动化审查与安全检查全绿即可零人合入；中风险（常规功能改动，以及缓存、自动更新、系统提示词等敏感区域）需 1 人；高风险（核心底层代码与指定敏感路径）需 2 人。
  • 两条不可逾越的红线。第一，智能体的批准永远不能算作人类批准；第二，发起这个改动、操纵 agent 的人视同责任人 —— 需要一个人批时操纵者签字即可，但责任永久绑定。
  • 留给人看的是什么。不再是逐行抠逻辑，而是「检查智能体拿出来的证据」：前端改动要附无头浏览器里实际点击的录屏或截图，后端改动要看基准测试输出与关键日志。人负责决定这东西到底该不该做、审定架构，并对结果负最终责任。
  • 代价与缺口。Claude Code 独立仓库 6 月到 9 月合并 PR 数量翻了一倍多，需要回滚的比例相对下降 40% 以上（官方未披露绝对值）。但团队明说还缺自动熔断机制 —— 线上回滚或故障指标异动时无法自动收紧审批流，这正是工程师不敢把更多代码开放为零人审批的原因。主分支体量 100GB、CI 每天约 2,500 万次代码检出，Git 的分布式架构被冲垮，他们抽 7 个人用 5 个月以 Rust 重写了服务端为核心的版本控制系统 Scion 与审查界面 Antique，并明确表示不会开源。
  • 一句被反复引用的话。团队里没有人保有 Claude Code 的完整心智模型，而且认为不需要 —— 想了解某一块代码，就让 Claude 写一份针对那一块的说明文档。

这为什么值得看。因为它把「谁签」写成了可执行的规则，而不是态度。低风险零人审、智能体的批准不算人批准、操纵者永久担责 —— 这三条里前两条明显比 10-28 ① 那期（十个前沿模型里九个自己去邮箱捞验证码批准自己涨额度）严得多。区别很清楚：那期是没有任何约束时审批权被 agent 拿下，这期是有人先把约束写下来。

更有意思的是「59% 是旧账」这个数。它和 10-27 ③ 的 CodeScene 研究是同一件事的两端：那期发现 agent 照 review 改完一轮后有 44.4% 到 49.0% 的 PR 健康度中位数为零，「改」本身是负收益；这期是 agent 审 agent 时 59% 的抱怨在第一轮就已存在。一个在改，一个在审，两边都在跟同一类噪声搏斗 —— 这说明问题不在 agent 的能力，而在这套流水线的停止条件。

第三件事最容易被读反：「没有人保有完整心智模型」听起来像能力退化，但它同时是审查瓶颈被解决的代价 —— 一旦没有人能解释系统为什么这样工作，出事时也就没有人能慢慢定位。HN 上 commenter jonahx 的那句话说得很准：以后没有人在被叫去修那个谁也搞不定的 bug 了。团队自己承认缺熔断，这两条合起来才是完整的账。

口径提醒。3 万这个数字的原始出处是 Anthropic 10-13 的工程博客《Redesigning source control at Anthropic》，指主代码库每天合并的 code changes，官方与演讲均未界定一个 change 对应一个 PR 还是一次 commit；本期计价的是 10 月下旬新发布的审查流程博客本身，不是这个数字第一次出现。「收到实质性审查建议的内部 PR 比例从 16% 升到 54%」「一轮通过率 65% 到 78%」「5 轮以上 8.9% 降到 1.5%」等均为 Anthropic 自述，无第三方核实。「回滚率相对下降 40% 以上」官方未给绝对值，与「PR 数量翻倍多」不可混算，也不能反推出绝对事故数下降。

另需注意口径不可横加：Anthropic 的 90%、GitHub Octoverse 的 40%、JetBrains 调查的 47% 与 Stack Overflow 调查的约 20%，来自四套完全不同的统计口径（自家仓库代码 vs 全站 PR vs 自填分桶 vs 全站问卷），四者不可相加，也不可串成同一条趋势线。

可以行动。这份方案里最容易抄、也最容易抄错的是分级依据。别按「谁写的」分级，按「改动落在哪条路径上」分级 —— 文档与开关后的新增代码可以先当低风险试零人审，但要先盯住这部分的线上回滚率。另一条别漏的是停止条件：给 agent 评审设硬性轮次上限（Anthropic 用的是 3 轮），超出即转人工，后续轮次只看新增 diff —— 你不给它这个约束，它会自己去翻旧账。第三条最便宜：把「智能体的批准不算人的批准」写进权限系统，这是一条不需要任何技术投入、今天就能生效的规则。

3

Revolut 2000 名工程师的自托管账本：56 块 B200、每百万 token 3 美分、账单砍到十分之一，交付周期缩短 70% —— 比纯编码时间缩得更多

AI Coding
AI Engineer 大会演讲（Revolut AI 运营负责人 David Abitbol，10 月下旬）；公众号《Anthropic 一天合并 3 万次改动，人还审什么？三份一线工程拆解》整理

这是今天唯一一份「自建 coding 基础设施」的真实账单，细节具体到可以照着算。

  • 为什么换掉商业 API。最早用商业辅助编码工具时，部分高级工程师一个人一个月能烧掉 1 万到 1 万美元 token，整体研发投资回报率却不明朗；管理层只好给每人设预算，结果工程师用得战战兢兢，只敢在极少数疑难任务上试探，AI 根本进不了日常习惯。
  • 换成什么、花了多少。2026 年 4 月起转向开源模型私有化托管，主力押注智谱 GLM 系列。支撑全公司 2,000 名工程师的编码需求，总共用了约 56 块英伟达 B200；token 成本约每百万 token 0.03 美元，总账单缩到原先付给商业模型提供商的十分之一。算力成本从按量计费变成固定月度开销，月底不会再收到惊吓账单。
  • 交付周期才是真收益。纯编码时间缩短约 60%，而交付周期（从接手需求到合并就绪、等待发布）缩短约 70% —— 交付周期缩得比编码时间更多。Abitbol 的解释是：token 变便宜之后，工程师开始把 AI 用在翻找复杂的业务邮件上下文、整理 Jira 需求、生成 Confluence 文档、梳理历史变更这些非编码杂事上。
  • 调参比堆卡重要。4 月到 8 月 GPU 数量一直锁死在 56 块没加。上线初全公司并发约每秒 3 次、首字延迟高于 10 秒；到 8 月并发升到每秒 7 次以上，首字延迟压到 1.6 秒。经验是首字延迟的生死线是 3 秒，超过 5 秒内部 Slack 就会被抗议淹没；工作时段 200 token/秒够用，下午 5 点卡闲下来能到 800 token/秒。
  • 四条硬约束。第一，超长上下文在编码场景是个骗局 —— 硬性截断在 256K 才兼顾显存与命中率；第二，精度必须下切到 FP4，从 FP8 换到 FP4 直接砍掉约 40% 显存占用且编码逻辑上没有感知到的精度损失；第三，张量并行选 TP8 而不是 TP4，给 KV 缓存留足空间；第四，代码仓库复用度极高，KV 缓存命中率必须盯在 90% 以上。
  • 合规怎么做。用开源权重部署在符合当地数据合规框架的服务节点，数据根本不会外流；对编码任务用严格沙箱加指令允许清单（允许智能体在环境内执行 grep，但严禁自行执行 gradle 编译或危险构建），以此向监管机构证明系统属于人类强监督下的辅助工作，而非无法失控的自主 agent。闭源顶尖模型没有彻底废除，退成了少数特定难题的特例通道。

这为什么值得看。它和第 ① 条是同一件事的两幕：Mistral 讲的是「权重可以拿走了」，Revolut 讲的是「拿走之后要付什么」。56 块 B200、每百万 token 3 美分、十分之一账单，这三个数字把自托管从口号变成一笔能算的账 —— 而算账的代价是四个月调参，以及第一条硬约束居然是「把上下文截断在 256K」。

最反直觉也最有价值的是 70% 对 60% 这组数。交付周期缩短得比纯编码时间更多，说明省下来的时间大部分并没有停在代码上，而是流进了需求澄清、文档与联调这些通常没人量的环节。这跟 10-22 ④ 那篇 CMU 研究是同一结论的两端 —— 那期测出「速度保质期两个月、质量债永不过期」，这期测出「省下的时间去哪了」。

第三件值得单独记的是那四条硬约束里的第一条。在一个 1M 上下文成为宣传口号的时代，一个 2000 人工程组织在生产上把上下文砍到 256K —— 这两条放在一起，才是真实工程的样子。

口径提醒。以上均为演讲现场的单方陈述，未经第三方审计；且未交代这 56 块 B200 是自购硬件还是公有云租赁。此前商业 API 是在严格预算限制下跑出来的，前后使用频次与场景完全不同，因此「十分之一成本」与「交付周期缩短 70%」只能读作同团队前后对比，不是双盲对照实验。56 块卡、2,000 名工程师、每百万 token 0.03 美元、首字延迟 10 秒到 1.6 秒、FP8 换 FP4 省约 40% 显存等数字均出自该演讲。

另需说明的是：主力模型是智谱 GLM 系列，与本期 ① 的 Mistral、10-26 ① 的 Kimi K3.1 Pro 属同一批开放权重阵营，但这三家的能力与成本不能横向相加，因为统计窗口、任务构成与计费口径都不同。

③ Revolut 自托管账本 10-29 ① Carbon（每 index 任务 7.76 美元）；10-27 ① Terra（每任务 0.40 美元） 同题不同层：那两期比的是闭源模型每任务多少钱，本期比的是自托管后每百万 token 多少钱。两本账的计价口径不同，不可相加 —— 但本期的账把「谁来承担」摆到了台面上
③ Revolut 自托管账本 10-22 ④ CMU 速度与质量研究（首月 +281%、第二月 +48%、第三月无显著差异；质量债永不过期） 上游收束：那期测的是「快换来的质量债」，这期测的是「token 变便宜之后时间去哪了」—— 交付周期缩 70% 比纯编码时间缩 60% 更多，省下的时间流到了需求与文档这些没被量的环节
④ 舍弗勒太仓与锐科 1 万台 10-27 ⑤ 深圳宝安 MaaS（产线可按周租用，受访客户中仅 1.64% 实现真实投产） 那期说「造机器人」这件事被做成可租用的服务，本期给出真实产线上的实例：五个工位、二楼训练一楼实战、第 1 万台力控臂。两期都是部署侧，但本期多了可数的实物
④ 舍弗勒太仓与锐科 1 万台 10-29 ④ 智元创新日与 Worken（累计下线突破 2 万台、上半年营收近 20 亿元） 不同环节：那期讲本体厂商的总量与营收，本期讲零部件与工艺（精密成形省材料 75%、4 亿欧元订单、2030 年 2000 台）。整机与零件是产业链两端，不能互相替代
⑤ 矩侨触觉 10-29 ④ Worken（有效智能工时 = 活跃机器人数量 × 自主工作时长 × 产出效能比） 配套关系：那期立了度量衡，本期讲这把尺子缺哪一路输入 —— 产出效能比要靠触觉数据才能量。同一件事的两个面
速览① 支付 AgentKit 重复扣款 10-28 ① I-HITL；10-25 ① OpenAI 训练环境永久断网 同一类问题的第三次出现：那两期讲 agent 拿到不该有的权限与外网，本期讲权限落到钱上时幂等键缺失。三个场景的共同点是「动作已经发生，但系统不知道它发生过」
今日整体 今天五条主榜里，AI Coding 三条讲的是同一件事的三个面：① 模型可以被拿走、② 审批要写下来、③ 账单要自己算；具身两条讲的是另两个面：④ 真实工位与出货量、⑤ 最缺的原材料。承 10-29「所有人都在换尺子」，本期往前走了一步 —— 换完尺子之后，开始把位置和责任一起挪动：模型从订阅变成归属，代码从提交变成签字，算力从采购变成自建，机器人从演示变成工位，触觉从论文变成产线。下一期要问的是：当每挪一个位置都要重新写一遍责任规则，这套规则本身谁来维护。
