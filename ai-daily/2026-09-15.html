智谱再募 393 亿港元，六成投给「完全自训练」：递归自我改进第一次写进了募资用途

AI Coding / 模型
来源：智谱（02513.HK）9/13 公告 · 经济参考网 9/14 · 中国基金报 9/13 · 同花顺/观点 9/14 · 证券时报

9 月 13 日晚，智谱公告新一轮融资：配售新 H 股 + 零息可转债合计净募约 392.74 亿港元（约 50 亿美元）。

  • 股权部分：每股 714 港元配售至多 2196.5 万股，较 9/11 收盘价 793 港元折让 9.96%，占扩大后股本 4.50%，净募约 156.6 亿港元；
  • 债权部分：2027 年 9 月到期的美元结算零息可转债，本金 201.4 亿元人民币，按本金 100.5% 发行，净募约 236.1 亿港元；初始转股价 892.50 港元，较配售价溢价 25%、较公告前收盘价溢价 12.55%；
  • 用途：约 60%（约 235 亿港元）投向下一代 GLM 基础模型及完全自训练（Fully Self Training）体系研发与算力基础设施，约 15% 用于业务拓展/战投并购，约 25% 优化资本结构与补充营运资金，预计 2028 年 6 月 30 日前用完。

「完全自训练」被描述为一个数据自产、环境自造、基础设施自我优化的递归式自我改进闭环。募资结构上，可转债占六成是刻意的：存续期内不付利息，全部资金可投入研发；投资者放弃利息、还愿意以高于市价的价格锁定未来转股。

配套的几个数字：上市不到 9 个月已是第三轮融资，年内累计募资将超 755 亿港元；2026 上半年营收 9.54 亿元（同比 +399.7%，其中开放平台及 API 业务 8.25 亿元、同比 +2736%），同期研发开支 21.31 亿元，期末现金及等价物约 39.94 亿元；股价自接近 3000 港元的高点回撤约 76%。本次配售由海外长线机构主导，前 20 大机构获配股本超 85%、可转债超 88%。

为什么值得看：递归自我改进（RSI）此前一直停留在论文和 demo 层面——09-14 生数 Motus2 也只是「朝 RSI 走了一步」。这一次它变成了一条有金额、有比例、有截止日期（2028/6/30）的资本承诺：六成募资、约 235 亿港元，买的是一个「模型自己给自己造训练数据和训练环境」的闭环。更值得注意的是定价逻辑：零息可转债 + 高于市价 12.55% 的转股价，意味着这批钱赌的不是当期收入，而是两三年后下一代 GLM 的成果——这与「按 ARR 给估值」是两套完全不同的世界观，同日出现在同一家公司身上。
口径与风险：折价近 10% 配股在二级市场通常被读成现金流偏紧的信号；上半年营收 9.54 亿元对研发 21.31 亿元，烧钱速度并未随融资收敛；股价较高点回撤约 76%。「完全自训练」目前仍是公司自我表述的技术路线，尚无第三方可验证的阶段性结果。

Sourcegraph Agentic Batch Changes 正式 GA：一句自然语言，把一次迁移铺到数百上千个仓库

AI Coding
来源：Sourcegraph 官方博客 / changelog（GA：2026-09-14）· Business Wire via Yahoo Finance 9/14 · quidproquo AI Daily 9/15

9 月 14 日，Sourcegraph 宣布 Agentic Batch Changes 正式可用（Sourcegraph Cloud，按合并的 changeset 计费）。它跑在原有的 Batch Changes 执行引擎 + Deep Search 之上，输入是一句自然语言描述的迁移需求，之后走一个闭环：

  • Scope：用代码搜索与 Deep Search 找出所有需要改的仓库，理解每个仓库会被如何影响，生成执行计划；
  • Execute：先在一个仓库上跑通并修正做法，再铺开。能脚本化的就写脚本，需要判断的才路由给 Claude Code / Codex 或任意 coding agent——官方明确说，它「写脚本的次数多于派 agent」，因为一次大迁移大多是同一个改动重复一百遍；
  • React：CI 红了，它去读日志（可配置 BuildKite、GitHub Actions 等 CI 日志来源）、判断原因、补一次 commit；遇到合并冲突则交给 coding agent 处理；
  • Iterate / Check in：一直干到 PR 达到「CI 健康、可合并」状态；卡住或需要决策时停下来问人，人也可以随时插手纠正方向。所有 changeset 仍由工程师审批后合并。

早期用户：Mercari 用一条 prompt 修 GitHub Actions 环境变量注入漏洞，识别出约 80 个潜在受影响仓库——关键在于这些仓库「相似但不同」，脚本化改动会在第一个变体处崩掉；Canva 在 Bazel monorepo 上按代码归属拆分迁移，一个视图里拉起并跟踪 50+ PR 到合并。Beta 期间客户合并了近 1000 个 changeset。

为什么值得看：这是 coding agent 从「单仓库」跨到「代码库级别」的分水岭，但突破点不在模型更聪明，而在终止条件是外部给定的——CI 健康且 PR 可合并，而不是「看起来改完了」。这正对着今天第一辑那条向下的证伪链：Real-SWE 在真私有库上只解出 38.8%、machineslop 说产物没人读得懂，共同病灶是「无停止条件 / 无审计链」。Sourcegraph 把这三件事直接做成了产品结构：覆盖度用 code search 确认、正确性用 CI 判定、进度用 changeset 状态跟踪。另外「能写脚本就别派 agent」这条工程判断，和 FastContext 用小模型当侦察兵是同一类省钱思路。
边界：「近 1000 个 changeset」是 Sourcegraph 自述的 Beta 数据；agent 负责的是把 PR 推进到「可合并」，迁移本身的语义正确性仍由人类审批兜底——它自动化的是推进过程，不是责任。覆盖度依赖 Sourcegraph 已索引的代码范围，未纳入索引的仓库不在 Scope 内。
怎么用得上：如果你手上压着一个「跨几十个仓库的升级 / 依赖替换 / CVE 修复」，先看的应该是它的 Scope 与 Coverage tracking（用代码搜索证明覆盖完整），而不是它能改多快——前者才是这类工具真正的增加值。

字节火山引擎开源 OpenViking：把 agent 的上下文做成可以用 ls / tree / find 打开的文件系统

AI Coding
来源：github.com/volcengine/OpenViking · 火山引擎 Agent 开发者社区 · quidproquo AI Daily 9/15

OpenViking 定位为自进化上下文数据库，把记忆（memories）、资源（resources）、技能（skills）统一挂在一套 viking:// 虚拟文件系统下，agent 用 ls / tree / find 浏览自己的上下文，而不是去查一个黑盒向量库。几个关键设计：

  • 三级按需加载：写入时每份内容被处理成 L0 abstract（约 100 tokens，快速判断相关性）、L1 overview（约 2k tokens，结构与要点）、L2 详情，按任务需要取到哪层算哪层；
  • 目录递归检索：先用向量定位得分最高的目录，再逐层下钻，结果带着上下文一起返回；
  • 检索可观测：每次查询保留目录浏览轨迹，结果不对时能回溯是哪个路径产生的；
  • 会话即记忆：会话提交后异步抽取用户偏好与 agent 经验进长期记忆，写入前与已有记忆比对，决定新建、合并还是跳过——这是「自进化」的部分。

官方给出的 0.3.22 评测：LoCoMo 长对话记忆准确率 OpenClaw 24.20%→82.08%、Hermes 33.38%→82.86%、Claude Code 57.21%→80.32%，输入 token 减少 34.3%–91.0%、查询时延降低 58.45%–66.10%；tau2-bench 上经验记忆让同一 LLM 的任务成功率 retail +6.87pp、airline +11.87pp。已支持 Claude Code、Codex、OpenClaw、Hermes、Cursor、TRAE、OpenCode、Agent Plugins 1.0 及 MCP 客户端。

为什么值得看：它和 09-08 的 Hugging Face Funes 同属「agent 记忆层」，但多做了一件不一样的事——把检索变成可调试的路径。Funes 的价值主张是「保留原文不蒸馏」，OpenViking 则是让每次召回都留下可追溯的目录轨迹，召回错了能查是哪一步走偏。对上下文工程来说，这比再多一个向量库更接近「可验收」。tau2-bench 的 +6.87/+11.87pp 是在同一个 LLM上加记忆得到的，属于不改模型也能拿到的那部分收益。
口径与风险：全部数字来自发布方自述，非第三方复现；提升幅度高度依赖基座起点（Claude Code 原生记忆本就有 57.21%，涨到 80.32；OpenClaw 从 24.20 起步，涨到 82.08）——换到你的 agent 上未必是同一个量级。许可上核心为 AGPLv3（ov_cli 与 examples 为 Apache 2.0），嵌进商业 SaaS 有源码披露义务，集成前先过一遍法务。另有托管版、BytePlus 全球版与自托管版。

优必选柳州超级智慧工厂投产：每 10 分钟下线 1 台，人形机器人开始「用机器人造机器人」

具身智能
来源：人民网广西频道 9/13 · 中国网 9/14 · 柳州市人民政府门户网站 9/14 · 深圳新闻网 9/15

9 月 12 日，优必选工业人形机器人超级智慧工厂在广西柳州北部生态新区投产，定位为全球首个适配万台级产能的人形机器人智能制造标杆工厂：占地 1.4 万平方米（74 亩）、楼高 13.8 米，主要生产 Walker S 系列与 Cruzr 系列，按设计节拍每 10 分钟下线 1 台，年规划产能超万台。

产线本身比产能数字更有信息量：

  • 机器人进自己产线干活：Cruzr Y1、Cruzr S2 承担拆垛、码垛、上料、搬运，靠 3D 视觉与具身决策应对箱体偏移、垛型多变；
  • 总装弃用固定流水线：协作机器人 + 助力机械手 + 无人物流车 + 360° 旋转工装台面，支持 Walker / Cruzr 多系列柔性混线、快速换型；配套行业首创总装展架（自主搬运 / 360° 旋转 / 机械臂自动对位）并以 RFID 接入 MOM 系统；
  • 与西门子共建数字化底座：Plant Simulation 做 1:1 全厂物流仿真（还原车间通道、工位、货架、AGV 参数），基于 Intelligence Center X 联合研发的 Yanshee MOM 做「智慧大脑」，依托机器人唯一 SN 序列号建立全链路一物一码溯源。

时间线：2022 年落户柳州 → 2025 年 6 月广西首台工业人形机器人下线 → 当年实现千台量产 → 不到 9 个月达到万台产能。柳州 1–8 月人工智能终端及机器人产业产值同比 +98.1%。

为什么值得看：09-13 推送小鹏 IRON 时留了个追问——「官宣量产但未披露产量」。今天这条给出了产线侧的答案：设计节拍 10 分钟/台、年规划产能超万台。但更值钱的是产线本身跑通了一次具身智能的工业验证：机器人本体在自己的产线上做拆垛码垛和上料，配合一物一码溯源，制造过程同时也在产出可回流的真机数据——这正是 09-15 第一辑里「巡检—实景数采—回流训练」闭环的工厂版。从「能不能造」到「能不能批量造、且造的过程本身就是数据」，是具身产业化里最难的一步。
注意区分三个数字：「每 10 分钟 1 台」是设计节拍，「年规划产能超万台」是设计产能，两者都不等于实际产出与已获订单。工厂投产解决的是供给侧能力，需求侧（ Walker S / Cruzr 的实际交付量）是另一回事，柳州工厂落地与优必选整体订单规模不能互相推导。

国家数据局：适时推动具身智能数据标准建设——数据缺口 99%，标准从行业自发进入国家统筹

具身智能
来源：国家数据局 9/13 发布（座谈会 9/10 召开）· 中国证券网 · 中宏网 · 行业整理

9 月 10 日，国家数据局党组书记、局长刘烈宏主持召开具身智能座谈会，议题是「数据赋能具身智能发展」。会后表态：将坚持问题导向、加强科学布局和发展引导，适时推动具身智能数据标准建设，指导地方数据系统有序开展相关工作，支持企业加大数据投入。

参会名单值得单独看——不是整机厂商专场，而是覆盖了完整链路：中科院自动化所、北京通用人工智能研究院（基础研究），光轮智能、深度机智（数据服务与训练平台），京东（场景应用方），石景山人形机器人数据训练中心（基础设施运营），星海图、自变量、北京人形机器人创新中心（整机与模型）。国家数据局数字科技和基础设施建设司主要负责人参会，意味着具身数据被纳入国家数据要素体系统筹。

已有的地基：7/24 工信部批准发布《人工智能 关键基础技术 具身智能数据集质量要求及评价方法》（11/1 实施，中国信通院联合 40 余家起草，含完整性、一致性、多样性、真实性等 8 个质量维度）；8/27 市场监管总局批准发布 GB/Z 218.1-2026《人工智能 具身智能数据质量规范 第 1 部分：真实数据》；全国已建成启用 70 余家具身智能训练场；全球首个人形机器人数据集国际标准已立项（中国牵头、12 国专家、立项投票 88% 赞成）。

缺口口径：国内真实物理交互合规数据存量约 50 万小时，商业化需求在数千万小时量级，缺口超 99%；一条 30 秒真机操作数据采集成本 10–15 元，采集 1 小时约 1000 元，凑够 20 万小时需两亿元以上。

为什么值得看：和 09-14 那条「红杉领投 Mecka AI 近 5 亿美元，具身瓶颈从硬件转向数据」是同一件事的两个方向——资本用钱投票，监管用标准投票。标准一旦落地，最先被改变的其实是数采的结算方式：09-13 那条账本（15 万元/台、120–150 元/小时、100 台日产 400 小时、约一年回本）建立在质量口径不统一的前提上，统一口径后，「一小时数据」值多少钱会重新定价——这直接关系到 09-11 以来那场「数采中心 + 关联交易是否虚增收入」的争议能不能有个客观判据。
时点与确定性：座谈会 9/10 召开、9/13 公开，今天进入日报视野；「适时推动」是方向性表述，具体路径与时间表均未公布。上述数据缺口与采集成本为行业测算口径，非官方统计。

安全剥离的开源模型被做成商品，底座是 GLM-5.3

已有商业服务公开出售移除安全训练的开放权重模型，当前基于 Z.ai 以 MIT 许可发布的 GLM-5.3。技术本身不新——开放权重一直可以改；新的是它变成了一个有价签的产品，绕过了此前「既要有能力又要有意愿」的隐性筛选门槛。尴尬之处在许可：MIT 允许几乎无限制地修改，这正是它「真正开放」的原因，也正是许可层面无法阻止这件事的原因。手上已下载的权重不受影响，受影响的是「别人能用同一份权重做什么」。

Scale AI MCP-Atlas：真实 MCP 服务器上，63.3% 的失败是「想错了」而非「调错了」

1000 个人工撰写任务、36 个真实 MCP 服务器、220 个工具；每题暴露 10–25 个工具（3–7 个必需 + 5–10 个混淆项），3–6 次调用，多数需跨服务器编排、约 1/3 含条件分支；跑在 Docker 里的真实服务器而非 mock，按 claim 覆盖率 ≥0.75 判通过，当前最高通过率 83.6%。关键结论：自动诊断显示 63.3% 的失败是认知性的——任务理解、综合、解析、过早停止；不少高分模型在工具调用成功之后，因为提前收尾或综合错误而失败。
