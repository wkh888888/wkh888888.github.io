Pinky：让 Agent 用上你的真手机，但关键一步必须你点头

前面十期推荐的工具都跑在电脑上，这是第一次让 Agent 伸手进你口袋——所以重点不是它能做什么，而是你怎么随时叫停。

先说清楚它不是什么它解决什么痛点核心能力平台与安装电脑端接 Agent连手机一个本机踩到的坑边界与注意适合谁

先说清楚它不是什么

MCP 把电脑端打通之后，手机成了最后一块缺口，也是最危险的一块：里面有支付、有聊天记录、有验证码。最近冒出来一堆「让 AI 玩手机」的项目，Pinky 容易被归到那一堆里，先划清边界：

  • 它不是又一个手机自动化框架。Auto.js、Appium、scrcpy 走的是「我写脚本驱动手机」，Pinky 走的是「任何支持 MCP 的 Agent 通过网关驱动手机」——它自己不含模型、不写业务脚本，只是一层桥。
  • 它不是自带视觉模型的 Phone Agent。Open-AutoGLM、Mika、andee 那类是端上或模型侧的自治智能体；Pinky 明确说自己不带模型，Agent 由你带（Claude Code、Claude Desktop、Codex、Cursor，或任意脚本）。内置那个 Ask Pinky 只是给没 Agent 的人跑单机简单任务，100 步 / 20 分钟 / 2 美元任一到顶就停。
  • 它不是投屏 / 远控工具。投屏只是让你旁观的窗口，真正的动作经过网关的许可检查和逐步记录。
  • 它不是「在提示词里叮嘱 Agent 别乱点」。这是最值得记的一条：审批规则跑在 Pinky 自己的网关里，属于基础设施约束，不是写给模型的自然语言。屏幕上的文字想诱导 Agent 自我批准，它手上根本没有可以拿来确认的东西。

预期摆正：这是个 README 自己标着 pre-alpha 的项目，2026-11-06 建库，写这篇时才第 5 天。它解决的是「信任边界」而不是「自动化成功率」，别拿它当稳定的 RPA 产线。

写这篇时的一手数据（2026-11-11 13:48 从 GitHub API 拉）：DIYgod/pinky，1,732 star / 185 fork / 22 issue，主语言 Go（手机端 Companion 是 Kotlin），Apache-2.0，最新 v2026.1111.13。当天连发了十几个版本，网上流传的「4 天 1.6K star」已经过时；「第一个把 MCP + 真机 + 安全网关都做对」是媒体定性，不是项目自称。

它解决什么痛点

符合下面任意一条，就值得看它：

  • 你已经在用 Claude Code / Codex / Cursor 干活，想让同一套 Agent 顺手把手机上的事办了（回消息、下单前比价、发内容），而不是另开一个专用 App；
  • 你确实想让 AI 碰真机，但一想到它误点「付款」「发送」「删除」就后背发凉；
  • 你不接受把验证码、银行 App、密码管理器暴露给模型；
  • 你希望出事之后能回溯——不是一句「已完成」，而是每一步的截图、录屏和大白话记录。

Pinky 的答案是把「能不能做」和「准不准做」拆开：Agent 负责前者，网关负责后者，人负责最后那一下点击。

核心能力

模块 说明
接入层 任意支持 MCP 的客户端，stdio（pinkyctl mcp）或 HTTP（agent token）；设置里一键接 Claude Code / Claude Desktop / Codex / Cursor / VS Code / Copilot CLI / Windsurf / Gemini CLI
审批门禁 付款、交易、转账默认等你点「允许」；发送、下单、删除、拨号、装 App、跳出 App 的链接、改设置可逐个设为需审批，也可「每步都问」或「只读模式」。按钮按 10 种语言的标签识别
审批流程 命中即返回 approval_pending，手机侧不执行；60 秒无回答默认拒绝；放行前复核按钮是否还在原位，屏幕变过就回 stale 让 Agent 重看
不确定状态 手机中途掉线不硬报成功或失败，返回 uncertain，要求先观察、禁止盲目重试——发消息和付款重试一次代价是真金白银
默认禁区 银行 / 钱包 / 密码管理器对 Agent 不可见（通知栏也灰盒遮盖）；密码框、验证码框禁止输入；验证码在文本和截图里都变成 ••••••。要用银行 App 得单独申请，且只在该次任务内放行
第二屏隔离 Android 13+ 在隐藏的第二屏干活，主屏归你、可以熄屏锁着；老 Android 和 iPhone 用主屏
随时接管 点一下投屏窗口 Agent 立即暂停，Android 上你亲手碰手机也会暂停；全局急停 ⌥⌘.（Win/Linux Ctrl+Alt+.）
解锁 锁屏 PIN 只存本机钥匙串，每次解锁需 Touch ID / Windows Hello / keyring 密码确认，Agent 永远看不到 PIN
审计 每步大白话记录 + 截图 + 带标记的录屏，可导出 HTML 报告；录屏逐帧门控，锁屏、被屏蔽 App、你本人手动操作一帧不录；数据只留本机 30 天
连接 Android 10–17（USB，11+ 可 Wi-Fi 配对）；iPhone / iPad iOS 17.4+（USB 初始化后可切 Wi-Fi）；也支持 iOS Simulator / Android emulator
体积 Go 单二进制，MyGo 直接在 GPU 绘制窗口，无 Electron 无 webview；下载包 16–22 MB，Mac 空闲约 70 MB 内存、0% CPU

我认为最值钱的两个：审批落在网关层（把安全从「模型自觉」挪到「基础设施强制」，这是范式级的差别）和 uncertain 是一等状态（承认边界、诚实回报，比假装成功有价值得多）。验证码掩码和银行隐身则是把最小权限原则真的落到了像素级。

平台与安装

电脑端

平台 要求 安装
macOS 13+，Apple silicon / Intel brew install --cask diygod/tap/pinky，或拖 .dmg 进「应用程序」
Windows 10/11 x64 pinky-setup-*-amd64.exe，免管理员权限；安装包未签名，SmartScreen 需「更多信息 → 仍要运行」
Linux x86-64，glibc 2.29+，GTK 3 .deb 用 apt install ./，其他发行版解压 .tar.gz 跑 pinky

本机实测（2026-11-11，macOS 26.6.2 / arm64）：装前先读了第三方 tap 的 cask 定义，确认只做「下载官方 release zip → 装 Pinky.app → 链 pinkyctl」三件事，没有 postflight 脚本、不装 launchd、不改 shell 配置，带 sha256 校验，才动手。结果：

brew install --cask diygod/tap/pinky
pinkyctl version          # pinky 2026.1111.13

/Applications/Pinky.app 解压后 51 MB，Gatekeeper accepted、Notarized Developer ID（签名主体 NATURAL SELECTION LABS PTE. LTD.），CLI 在 /opt/homebrew/bin/pinkyctl。

接 Agent

任意 MCP 客户端的手工配置（pinkyctl 不是 pinky——后者是 coreutils 里已有的同名命令）：

{ "mcpServers": { "pinky": { "command": "pinkyctl", "args": ["mcp"] } } }

Claude Code 也可以用 claude mcp add --scope user pinky -- pinkyctl mcp。我在 WorkBuddy 里把 command 写成了绝对路径 /opt/homebrew/bin/pinkyctl——非登录 shell 的 PATH 不一定含 Homebrew，写绝对路径省一次「明明装了却找不到」的排查。

连手机

  • Android：开发者选项 → USB 调试 → 插线授权；Android 11+ 可走无线调试 Wi-Fi 配对。Pinky 会提示装 Companion App，把读屏从约 2 秒降到约 70 毫秒。
  • iPhone：插线信任 → 开开发者模式 → 挂载 Apple 的 Developer Disk Image（随 Xcode 提供，Pinky 不自带）。iOS 27+ 手机端什么都不用装；17.4–26 要从 Xcode 装一次 WebDriverAgent helper。

零风险试跑：加 --fake 会用脚本假手机跑通全流程，不碰真机。建议先跑这个。

一个本机踩到的坑

pinkyctl 是单实例转发式 CLI：只要已经有一个 Pinky 实例在后台，任何子命令（mcp / devices）都会被转成「Pinky is already open: showed its window」然后静默退出——MCP 握手那一侧表现为 stdout 全空、退出码 0，很容易误判成配置写错。pgrep -fl Pinky 清干净残留实例后再连就正常了。排查这类问题时用 PINKY_HOME 指到临时目录做隔离，别污染默认数据目录。

干净环境下 pinkyctl mcp 的 initialize 握手返回完整 instructions 和 tools.listChanged 能力，进程保持长连接，实测通过。

边界与注意

  • 最要紧的一条：Agent 有 shell 权限就能绕过它。 README 明确写了，能在你电脑上跑命令的 Agent 可以直接走 adb 碰手机、跳过全部规则。真要用，把它放进没有手机访问权限的沙箱，或者把手机插在另一台电脑上、让 Agent 通过 HTTP 连 Pinky。这层审批只对「老老实实走 MCP」的 Agent 成立。
  • pre-alpha，别上生产。 作者只端到端验证过 Claude Code 在真机上的几条路径，README 直说 some of it still waits for a person to try it；不少功能标注「只在模拟器上试过」。发版极快（一天十几个版本），也意味着随时可能踩到回归。
  • iOS 版本分裂是最复杂的部分：27+ 免装 App 但不能双指缩放；17.4–26 需 WebDriverAgent helper，免费 Apple ID 每 7 天重签一次；17.3 及以下不支持。没有 helper 时只能看屏、读屏和打开 App，点不了也打不了字。
  • 按钮识别不是万能的。高风险按钮靠 10 种语言的标签词表匹配，冷门文案可能漏——官方自己建议开「每步都问」或「只读模式」兜底。
  • 合规风险要自己扛。微信、抖音、小红书、部分银行能检测到无障碍服务、USB 调试和屏幕共享，让 Agent 操作可能违反其条款；部分银行 App 在屏幕共享时直接拒绝运行。
  • 有遥测。默认上报匿名计数与崩溃报告（DO_NOT_TRACK=1 或设置里可关），但屏幕、输入文字、App 名、设备名、PIN、文件名明确不上报。
  • 别把它当跨平台协同工具。文件传输只在 Android 的 /sdcard/Pinky 与电脑之间，iPhone 不支持。

适合谁

项目 路线 有没有网关级人工审批
zai-org/Open-AutoGLM 自带视觉模型的 Phone Agent 框架（26k+ star） 无
mobile-next/mobile-mcp 纯 MCP server，跨平台工具集（10k+ star） 无
phone-harness/phone-harness iPhone 镜像 / adb / 云手机，手机端不装东西 无
kuafuai/andee、wangzan101/Mika 装在 Android 上的自治 Agent APK 无
DIYgod/pinky 桌面 MCP 网关 + 真机操控 有，且是核心
  • 已经在用 Claude Code / Codex 的重度用户：想让同一套 Agent 顺手办手机上的事，又不想把审批交给提示词；
  • 对隐私敏感、又想试 Agent 的人：验证码掩码、银行隐身、逐步录屏、随时接管这套组合，是当前开源方案里少见的完整设计；
  • 做 Agent 安全 / 人机协同研究的人：approval_pending + stale + uncertain 这套状态机，比工具本身更值得读。

不适合谁：只想批量自动化刷任务、不需要人在环的（用 Auto.js / Appium 更直接）；想要一个自带模型、开箱即跑的手机 Agent（看 Open-AutoGLM / Mika）；以及打算给有完整 shell 权限的 Agent 开放真机、却不做沙箱隔离的——那种情况下 Pinky 给你的安全感是假的。

一句话收尾：技术上 adb 和 Xcode 早就做到了「让电脑控制手机」，Pinky 真正补上的是「让它在可控前提下控制」。这个思路对所有高风险 Agent 场景（支付、写操作、删数据）都有参考价值，哪怕你最后不装它。
