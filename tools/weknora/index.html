WeKnora：腾讯把 ima 的知识库开源了，RAG + Agent + 自维护 Wiki

上一期推荐的 ima 是线上托管版，WeKnora 是同一套知识库能力的开源私有化版——数据全部攥在自己手里。

先说清楚它不是什么

  • 它不是 ima 的竞品，是 ima 的「开源版底座」。ima 的知识库能力由腾讯开源为 WeKnora（LLM + RAG 架构），线上 ima 满足不了的「数据不出内网」，交给它。
  • 它不是套壳 GUI。Go 写的完整后端（app / docreader 双服务），带 RESTful API、MCP Server、CLI，是可以集成进自己系统的框架，不只是个网页。
  • 它不自带模型。LLM、Embedding 都要自己配：本机 Ollama 或任意云端 API（OpenAI 兼容即可）。空手部署完只能建库，问答不出结果——这是新手第一坑。
  • 它不是玩具 demo。33k+ Star、4.4k fork、日更级别提交（写这篇时最新 v0.8.0，仓库当天还有推送），2025-07 建库，MIT 协议（第三方组件单独列清单）。

预期摆正：WeKnora 是给愿意运维一套服务的人准备的。只想开箱即用的，回上一期看 ima。

它解决什么痛点

ima 的边界就是云：资料上传腾讯服务器、模型固定混元/DeepSeek、不能接自己的 Key。下面任意一条命中，就该看 WeKnora：

  • 公司文档、客户资料不能出内网，但想要 RAG 问答；
  • 已经有 DeepSeek / Qwen / 混元的 API Key，想用自己的配额、自己的模型；
  • 要把知识库能力嵌进自己的产品（REST API / MCP / 网站挂件）；
  • 团队知识要定时同步（飞书知识库、GitLab、Notion、语雀、RSS 自动同步，ima 库也能导进来）；
  • 想要的不只是问答，还有 Agent 多步推理和自动维护的 Wiki 知识库。

我认为最值钱的两个：数据源自动同步（飞书/GitLab/IMA 库直接同步进来，不用手动传文件）和 Wiki 模式（Agent 把散文档自动维护成结构化知识库，这是普通 RAG 没有的「知识再生产」）。ima 用户注意：WeKnora 支持把 IMA 作为数据源——线上 ima 收藏的资料可以同步进自托管库，两条路是通的。

平台与部署

官方主推 Docker Compose（Git 克隆后 5 分钟起），核心 5 个服务：

git clone https://github.com/Tencent/WeKnora.git
cd WeKnora
cp .env.example .env
docker compose pull && docker compose up -d   # 访问 http://localhost

编排组成：frontend(nginx) + app(Go 后端) + docreader(解析) + postgres(ParadeDB pg17，自带 pgvector) + redis。可选 profile：neo4j（知识图谱）/ minio（对象存储）/ langfuse（追踪）/ full。K8s 有官方 Helm chart。

本机已部署：v0.8.0（2026-09-17 装的 release tarball，非 git clone），源码 ~/projects/WeKnora。 因 80/8080 被 OrbStack 和 homebrew nginx 占用，端口改为 Web 18000 / API 18080，详见仓库内《安装说明-阿墨.md》。

部署三个坑（本机实测，别跳过）：

  1. 别一次 up -d 拉全部：frontend 依赖 app 健康检查，而 app 有 60s start_period，一把梭会判定 “dependency failed to start” 导致 frontend 不创建。正确做法是先起 postgres redis docreader app，等 healthcheck 过了再单独起 frontend。
  2. 国内拉镜像要换源：官方镜像在 Docker Hub wechatopenai/* 命名空间，直连不通，多数国内镜像源对该命名空间 403/404。可用 docker.1ms.run（只有 latest 标签，拉完 docker tag 打回版本号）。
  3. 不配模型不出答案：部署完成只是能登录建库，必须在知识库配置里填 LLM + Embedding（本机 Ollama 或云端 API），否则 docreader 解析了也问不出东西。

边界与注意

  • Docker 是事实门槛。官方文档只提供 Compose / Helm 路径，裸机部署要自己看 Makefile 和 docker/Dockerfile.app 啃，不划算。对「坚决不碰容器」的人是硬伤，想清楚再入。
  • 模型要自己出钱。不自带任何模型，本地 Ollama（吃显存/内存）或云 API（按量付费）二选一。
  • 0.x 版本，迭代极快。从 0.3 到 0.8 功能密度惊人，但也意味着升级可能踩 breaking change——固定版本、升级前读 CHANGELOG。技能沙箱挂 docker.sock 等同宿主机 root，官方明确只建议私有化单机用。
  • 资源占用不小。5 个常驻服务 + ParadeDB，轻量机器（<4C8G）别勉强。
  • 和 ima 的分工：资料要公开传播/团队轻协作 → ima；数据必须留在自己机器上、要接自己的模型、要嵌进自己系统 → WeKnora。也可以都要：ima 当移动端收藏入口，WeKnora 当内网知识底座，用数据源同步打通。

适合谁

  • 对数据主权有要求的团队：金融、政务、法务、医疗——文档不出内网 + 自选模型，这是它的主场；
  • 有运维能力的个人开发者：想搭「自己的 ima」，愿意花半天调 Docker 和模型配置；
  • 要集成 RAG 能力的开发者：REST API / MCP Server / 网站挂件 / IM 机器人，四种接入方式现成；
  • ima 重度用户：想把 ima 里的收藏同步进本地库，或嫌 ima 模型选择太死的。

只想开箱即用、不想运维服务的，用 ima；连 Docker 都不想碰的，两个都别装，用回网盘 + 通用 AI。
