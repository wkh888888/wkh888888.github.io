Open Design：把「你已有的 coding agent」变成设计引擎

它不造 agent、不托管你的数据，只做一件事：让「描述意图 → 拿到可交付文件」这一步跑在你自己的机器上。

它是什么

Open Design（仓库 nexu-io/open-design，Apache-2.0）是一个 agent-native 的「vibe design workspace」。名字容易让人以为是个设计软件，其实它更准确的定义是：把你本地已有的 coding agent 接进一套完整设计工作流的编排层。

它自己不做模型、不训练、不托管。启动后扫描你 PATH 上的 21 种 coding agent CLI（Claude Code、Codex、Cursor Agent、Gemini CLI、OpenCode、Qwen 等），你用哪个都行，密钥也是你自己的（BYOK）。产出物是真实文件，落在你的项目目录里。

三个设计决定值得说

Skills 是文件，不是插件。 每个 Skill 是一个文件夹（SKILL.md + assets/ + references/）。丢进目录、重启 daemon，就出现在选择器里。想改就改，想 fork 就 fork —— 这点和我自己维护 skill 的习惯很合：能力沉淀成可读可改的文本，而不是黑盒配置。

Design System 是可移植的 Markdown。 它不用主题 JSON，而是 9 段的 DESIGN.md（色彩、字体、间距、布局、组件、动效、语气、品牌、反模式）。内置 150+ 套（Linear、Stripe、Vercel、Apple、Notion 等），切换一套，后续生成自动换 token。这比「换个配色」更接近真正的设计系统。

流程先锁方向再动手。 第一轮是表单式提问（载体、受众、语气、品牌、规模），定好视觉方向后才生成，预览在沙箱 iframe 里可就地编辑，最后导出 HTML / PDF / PPTX / ZIP。这个「先问清楚再画」的顺序，比让模型自由发挥省事得多 —— 返工成本从「做完一版」降到「多聊一轮」。

适合什么场景

  • 需要快速出可运行的原型页、落地页、Dashboard（不是图片，是真文件）；
  • 做 PPT / 幻灯片（内置 html-ppt skill 有 36 主题、31 布局、47 动画，等于一个浏览器里的 PPT 引擎）；
  • 想把设计产出的所有权留在自己手里，不经过第三方云；
  • 已经在重度用某个 coding agent CLI，想让它顺手干设计的活。

注意事项

  • 需要本地有 coding agent CLI。没有的话也能用，但要填 OpenAI 兼容的 baseUrl + apiKey。
  • 它是桌面/daemon 形态（Electron 打包 + 本地 HTTP daemon + CLI），不是网页服务，数据不出本机（除你所选模型厂商收到的 prompt）。
  • 项目迭代很快（GitHub star 数高、贡献者多），文档与功能都在变，遇到问题先看仓库 issue。
  • 定位是「设计引擎编排」，不是 Figma 替代品 —— 精细的像素级调整仍然要人工。
