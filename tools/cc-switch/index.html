CC Switch：给八个 AI 编程工具装一个「总闸」

它不写代码、不调模型，只管一件事——让你在多个 AI 编程工具和供应商之间一键切换。

先说清楚它不是什么

第一次听说 CC Switch 的人，十个里有八个以为它是 Anthropic 官方出的、或者是 Claude Code 的某个组件。都不是。

它是一款社区开源桌面应用（作者 Jason Young，MIT 协议，Tauri 2 构建，更新很勤，写这篇时最新版 v3.20.2），本身不写代码、不调模型、不执行任何 AI 推理。它只做一件事：帮你管理那些 AI 编程工具的配置——供应商地址、API Key、模型名、MCP 服务器、Skills。

所以先把预期摆正：装了它不会凭空多出模型能力，API Key 还得自己准备；它也不是 Claude Code 的替代品，而是 Claude Code 们的「总闸」。

它解决什么痛点

如果你只装一个 Claude Code、只用官方 API，可以直接划走，你不需要它。

但只要你同时用两三个以上的 AI 编程工具，痛点就来了。我自己的机器上就常年跑着 Claude Code、Codex、Gemini CLI、OpenClaw 好几个 agent，每个工具一份配置文件，格式还各不相同：

  • 想把 Claude Code 从官方 API 切到某个国产模型，得手改 settings.json 里的 Base URL、API Key、Model ID 三处；
  • Codex 和 Gemini CLI 又是另外两套文件；
  • MCP 配置更麻烦，同一批 MCP 服务器要往每个工具里配一遍；
  • 改错一个逗号，整个配置加载失败，还得自己排查。

CC Switch 把这些全收进一个界面。

核心功能（README 实锤，非营销稿）

功能 说明
供应商管理 50+ 内置预设，点一下导入；一键切换，系统托盘快捷切换
多工具支持 一款应用管八个：Claude Code、Claude Desktop、Codex、Gemini CLI、Grok Build、OpenCode、OpenClaw、Hermes
MCP / Prompts / Skills 统一管理，跨工具双向同步，不用每个工具配一遍
代理与故障转移 本地代理热切换、格式转换、自动故障转移与熔断
用量与成本追踪 仪表板看花费、请求数、Token 趋势，多家供应商一对比就知道钱花在哪
会话管理器 浏览、搜索、恢复各工具的对话历史
其他 云同步配置（Dropbox/OneDrive/iCloud/WebDAV）、原子写入防配置写坏、深链接 ccswitch://

其中我认为最值钱的是两个：供应商一键切换和 MCP/Skills 统一管理。前者把「切模型」从一次十分钟的手改 JSON 变成一次点击；后者解决了「同一套 MCP 配置在 N 个工具里重复维护、改一处漏一处」的经典问题。

平台与安装

原生桌面应用，Tauri 2 构建，三平台都有包：

  • Windows 10+；macOS 12+（已签名公证，不会卡 Gatekeeper）；Linux（Ubuntu 22.04+ / Debian 11+ / Fedora 34+ 等主流发行版）
  • 开源协议 MIT，直接去 GitHub 仓库 下载对应平台的安装包即可

边界与注意

  • 它不管模型服务。切换供应商只是改「请求发去哪」，那条供应商线路通不通、质量好不好，是供应商的事。切完记得跑个小任务验证。
  • API Key 集中在一处，等于风险也集中。配置支持云同步是便利，但同步盘里躺着各家 Key，盘的账号安全要自己上心。
  • 社区项目，非官方。Anthropic、OpenAI 等厂商的配置格式变了，得等它跟进；好在更新很勤。
  • 桌面 GUI 的思路是「可视化优先」，纯命令行党如果只想脚本化切换，它也有深链接等入口，但整体还是面向「愿意开个窗口管理配置」的用户。

适合谁

  • 同时用两个以上 AI 编程工具、经常在多家供应商之间切换的人——这是它的主场；
  • 想统一管理 MCP / Skills、不想在各个工具里重复配置的人；
  • 想搞清楚自己 AI 编程开销都花在哪的人（成本仪表板）。

只有一个 Claude Code、只用一家供应商、配置从不折腾的，不用装，少一个常驻应用。
