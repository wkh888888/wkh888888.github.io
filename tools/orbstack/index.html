OrbStack：换掉 Docker Desktop 之前，先读那行「个人非商用」

上一期 ToDesk 的免费版卡在「个人非商用」，这一期 OrbStack 的免费档也写着同一句话——免费的边界，有时比功能表更值得先看。

先说清楚它不是什么

这期有点特别：它不是「我天天用的主力工具」，而是装在机器上、但尽量不去依赖它的那一类。先把边界摆正：

  • 它不是开源软件。官网、App、CLI 都是闭源商业产品；想「看得见、改得动」的容器运行时，该看 Colima / Lima / Podman 那条线。
  • 它不是普通的虚拟机软件。Parallels / UTM / VMware Fusion 卖的是「跑一个完整桌面系统」；OrbStack 的定位是 Docker Desktop 的 drop-in replacement，附带能一分钟起一台 Linux 机器，重心在开发环境而不是通用虚拟化。
  • 它不是 Docker 本身。它是兼容 Docker CLI / Compose 的运行时与 Linux 机器管理器，「drop-in」是官方措辞，不等于行为逐字节一致——bind mount、网络模式、volume 权限这些边缘行为仍要实测。
  • 它不是免费给公司用的。官方定价页把 Free 档写成 Personal, non-commercial use；Business & commercial use 要 Pro，$8/用户/月（$96/年）。这条跟上一期 ToDesk 用户协议第 1 条是同一类限制，值得放在功能表之前读。
  • 它不是跨平台工具。macOS only，且针对 Apple Silicon 做了大量优化；Windows / Linux 上不存在这个问题，也就不需要这个答案。
  • 它不是「坚决不碰容器」的人需要装的东西。这点我得对自己诚实：本机的部署偏好是纯裸机进程 + OpenResty 反代，第 10 期写 WeKnora 时还把「Docker 是事实门槛」列为硬伤。OrbStack 在这里的角色是偶尔需要的兼容层，不是部署依赖。

预期摆正：它卖的是「Mac 上跑容器别那么难受」，不是「让你重新喜欢容器」。

数据来源说明：闭源无 GitHub 仓库。一手材料是官网 orbstack.dev 首页、官方定价页 orbstack.dev/pricing，加本机 App 实测，均为 2026-11-11 15:04 拉取。官网的性能数字一律标「官方口径」，且注明其测试时间。

它解决什么痛点

  • Docker Desktop 太重：启动慢、后台常吃 CPU 与电量、磁盘占用随镜像涨，还有商业授权要求；对只是偶尔 docker compose up 的人，代价和收益不成比例。
  • Mac 上想要一台真 Linux：编译、跑 systemd、验证只在 Linux 复现的问题，SSH 进去比装一整套 VM 轻。
  • 文件共享与网络别扭：bind mount 慢、容器与宿主互访、DNS / VPN / IPv6 冲突，是 Docker Desktop 长年被吐槽的地方。
  • Apple Silicon 上要跑 x86 镜像：Rosetta 模拟如果没有运行时配合，得自己折腾。

OrbStack 的答案是把容器和 Linux 机器放进同一个轻量虚拟化层：原生 Swift App、VirtioFS 文件共享、动态磁盘、本地域名、双向 CLI 集成，官方称 Apple Silicon 上后台 CPU 占用 <0.1%、开箱初始磁盘 <10 MB。

核心能力

以下为官网列出的功能与官方口径：

模块 说明
容器 Docker CLI / Compose 兼容，快速构建、bind mount 与端口转发、卷调试、Rosetta 跑 x86 容器
Linux 机器 16 种发行版、1 分钟起一台、SSH 与 SSH agent 转发、VS Code 远程编辑、可在 Apple Silicon 上跑 Intel 机器
Kubernetes 官网列为内置能力，与容器、Linux 机器统一管理
网络 本地域名、容器与机器互访、IPv6、VPN 友好、ICMP / ping / traceroute、host networking
集成 菜单栏 App + Activity Monitor、双向 CLI（Mac ↔ Linux 跑命令/拷文件）、通知与打开文件链接、USB 直通、声音
效率 原生 Swift、动态磁盘、低初始内存、低后台 CPU；官方口径 Apple Silicon 后台 <0.1% CPU、初始磁盘 <10 MB
免管理员 官网明确列「Works without admin」
性能对比 官网 benchmark 称 Open edX 开发环境准备 17 分钟 vs Docker Desktop 45 分钟，页面自己标注 as of August 2023

我认为最值钱的两个：把容器和 Linux 机器收进同一个运行时（不用为了跑一条 Linux 命令再开一个 VM 软件）和双向 CLI 集成（Linux 里直接调用 Mac 侧命令、开文件链接，这种贴合度是通用 VM 给不了的）。至于 17 vs 45 分钟那张对比图，是 2023 年 8 月的官方自测，看方向就好，别当现时结论。

最该先读的就是 Free 那行小字：个人非商用。公司笔记本上拿它跑项目容器，按官方口径属于 Pro 的范围。这跟第 15 期 ToDesk 免费个人版「仅限个人非商用、法人设备上使用需付费授权」是同一类条款，两期连着看特别清楚：国产商业远控和美国开发工具，在免费边界上用了几乎一样的措辞。

两个如实记录的观察：App 本体 679 MB，和官网「初始磁盘 <10 MB」并不矛盾（后者说的是运行时/动态磁盘的初始占用，不是应用包体积），但查数据时别把两者混成一个数字；以及它会改 PATH，卸载或切换运行时时要检查 shell 配置里残留的路径。

一个本机踩过的坑

第 10 期写 WeKnora 时记过一笔：本机 80 / 8080 被 OrbStack 和 homebrew nginx 占用，最后把 WeKnora 改成 Web 18000 / API 18080。容器运行时和裸机 nginx 抢同一批端口，是「本地同时跑两套服务栈」最常见的冲突——不是 OrbStack 的错，但值得在装之前就规划好端口表。

边界与注意

  • 授权边界：Free 仅限个人非商用。团队/公司使用按官方定价页应上 Pro（$8/用户/月）；这跟「开源替代品随便用」的预期不同，采购前先确认。
  • 闭源不可审计：容器运行时是系统级组件，闭源意味着你只能靠厂商信誉与更新节奏。对供应链有要求的环境，Colima / Lima / Podman 更符合口径。
  • macOS only，且优化偏向 Apple Silicon：Intel Mac 与跨平台团队不适用；官方自己把「为 Apple Silicon 优化」列成卖点。
  • 官方性能数字有保质期：17 vs 45 分钟是 2023 年 8 月的自测；<0.1% CPU、<10 MB 初始磁盘是官方口径，不是我在本机跑过的结果。本机这轮只做了安装状态取证，没有做性能实测。
  • 端口与网络会互相抢：容器端口转发、本地域名、VPN-friendly 这些能力，在同时跑裸机 nginx / 反代 / 其他虚拟化的机器上要提前规划；上面的 80/8080 冲突就是实例。
  • 会改环境：~/.orbstack/bin 注入 PATH，CLI 与 Docker 兼容层可能和已有 docker 命令指向不同实现，切换前用 which docker 确认一下当前生效的是谁。
  • 不是部署方案：它能让本地开发舒服，但不该成为线上部署的前提。本机偏好「纯裸机进程 + OpenResty 反代」，容器在这里是兼容层；把开发环境当生产架构照搬，会多一层不必要的运行时依赖。

适合谁

方案 开源 商用授权 范围 适合
Docker Desktop 否 商业使用需付费 容器为主 要官方标准栈、团队已采购
Colima / Lima 是 无此限制 容器 / VM，CLI 驱动 不想装商业软件、愿意敲命令
Podman 是 无此限制 容器（无 daemon） 要 rootless、贴近生产
UTM / Parallels 部分/否 视产品 通用虚拟机 要跑完整桌面系统
OrbStack 否 Free 仅个人非商用，Pro $8/用户/月 容器 + K8s + Linux 机器 Mac 上要最省事的 Docker Desktop 替代
  • Mac 上偶尔要跑容器、又受不了 Docker Desktop 的人：启动快、后台轻、菜单栏管理，个人非商用免费；
  • 需要一台顺手 Linux 的开发：SSH、VS Code 远程、Rosetta 跑 x86，一分钟起机器；
  • Apple Silicon 用户：官方优化集中在这里，x86 镜像与 Intel Linux 机器都有路径。

不适合谁：公司环境里想免费用的（先买 Pro）；坚持开源/可审计运行时的（去 Colima / Podman）；Windows / Linux 用户（用不上）；纯裸机部署、根本不需要容器的（别为一个偶尔的 docker run 多养一层运行时）；以及把官网 2023 年 benchmark 当采购依据的——自己用真实 workload 跑一遍更实在。

一句话收尾：这六期里，OrbStack 是唯一一个我装了却希望少用它的工具。它对「不碰容器」的偏好不是背叛，而是承认现实——有些项目（比如第 10 期那个 WeKnora）就是只给了 Compose 这一条路，与其跟工具链较劲，不如留一个轻的兼容层，然后记得两件事：别让它变成部署依赖，也别忽略免费档那行「个人非商用」。
