ego lite：把浏览器分一半给 AI Agent，标签页还是你的

上一期 Pinky 让 Agent 碰真手机、关键一步必须你点头；这一期让 Agent 用你的浏览器。共同点是「别抢我的设备」，但刹车装的位置完全不同。

先说清楚它不是什么

浏览器自动化这个赛道已经很挤，ego lite 容易被当成又一个 Playwright 封装，先把边界划清：

  • 它不是自动化框架，它本身就是一个浏览器。browser-use、agent-browser、playwright-cli 是「桥接工具」——得另外找一个浏览器来驱动，登录态很难完整带过去，连接也不稳，最后你和 Agent 还得抢同一个窗口。ego lite 是从内核开始按「人和 Agent 共用一个浏览器」设计的 Chromium。
  • 它不是浏览器扩展，也不是云浏览器。前者（Claude/Codex in Chrome）绑死自家 Agent，后者（Browserbase / Browser Use）把数据放在云端、拿不到你本机登录态。
  • 它不是 Comet / Dia 那类 AI 浏览器。那类把 Agent 内置进产品，你只能用它的模型；ego lite 不带模型，谁都能来驱动它。
  • 它不是 MCP server。这点对已经用惯 MCP 的人容易踩空：ego lite 走的是 Agent Skill + ego-browser CLI，仓库里放的是 skill、CLI 包、Claude/Codex/Cursor 插件清单和文档，没有 MCP 端点。
  • 它不是「开源浏览器」——最容易误读的一条。仓库是 MIT 没错，但开源的是 skill / CLI / docs；浏览器本体是从 cdn.ego.app 下载的免费闭源二进制，Chromium 源码不在仓库里。想自己编译一个出来，做不到。

预期摆正：它解决的是「Agent 该用哪个浏览器、能不能别抢我的」，不是「怎么把一个网站稳稳地爬完」。而且它是个热度很高但问题也不少的年轻项目（2026-04 建库，写这篇时 274 个 open issue）。

一手数据（2026-11-11 14:03 从 GitHub API 拉）：citrolabs/ego-lite，22,475 star / 1,274 fork / 274 open issue，语言 JavaScript + TypeScript，MIT，最新 release v2.2.0（2026-11-05），官网 lite.ego.app。网上流传的 17.5k、21.9k 都是旧快照。

它解决什么痛点

用过 Agent 跑网页任务的，基本都吃过这三记闷棍：

  1. 登录态带不过去。新开一个干净的自动化浏览器，结果每个站点都要重新登录，CAPTCHA 一拦一个准；
  2. 浏览器被抢走。Agent 一开工，你的标签页、光标、焦点全乱了，只能干等；
  3. 工具调用绕圈。「调两条命令 → 看结果 → 再调两条」，多步任务在一来一回里把 token 烧光。

ego lite 的答案是三条一起改：把浏览器数据留在本机并让 Agent 直接继承、给每个 Agent 一个隔离的 Space、把工具做成页内 JavaScript 函数让 Agent 一次写完整段脚本。

核心能力

模块 说明
Agent Space 每个 Agent / 每个任务一个完全隔离的工作区，Agent 在后台跑，你在自己的 Space 里照常浏览；随时能看到哪个 Space 在跑，可接管或停止
并行多任务 一个浏览器里多个 Space 同时工作——Claude Code 在 10 个 Space 补全 10 条线索、Codex 在另外 5 个抓竞品站，互不碰撞、不抢标签页
共享登录态 首次启动问一句「要不要迁移 Chrome 数据」，选是即继承登录态、Cookie、扩展、书签；官方口径因此「更少触发人机验证」
Snapshot 页面转成结构化文本给纯文本模型看；因内核级定制，官方称能稳定处理深层嵌套 iframe 这类其他方案常翻车的场景
以代码为本 能力封装成页内 JavaScript 工具：snapshot / fill / click / wait / navigate / capture。Agent 写一段脚本一次执行完，而不是逐条 CLI 往返
连接层 ego-browser CLI，任意 Agent 可调用（Claude Code / Codex / Cursor / 自己写的）；仓库带各家插件清单
数据与遥测 浏览数据、Cookie 全留本机；官方称只收集「是否设为默认浏览器」这类简单产品信号
经验积累 （coming soon） 把成功操作沉淀成可复用工具与工作流，宣称类似任务最高快 5 倍——尚未上线，别算进现有能力

我认为最值钱的两个：Space 隔离（第一次把「人和 Agent 并行」做进浏览器结构里，而不是靠约定谁先别动鼠标）和以代码为本（让 Agent 干它最擅长的写码，把多步任务压成一次输出）。共享登录态是双刃剑，下一段专门讲。

平台与安装

支持情况

macOS（Apple silicon / Intel）与 Windows x64 都已可用（Windows 是 2026-10-19 补上的），Linux 还在路线图。社区有第三方非官方的 Linux/WSL 桥接仓库，但都是个位到几十 star 的玩具级，别当官方支持。

三条安装路径

# 只装 Skill，第一次跑浏览器任务时它会带你装 App
npx skills add citrolabs/ego-lite

也可以直接下载 .dmg / .exe 安装，或者把仓库地址丢给 Agent、让它读 skills/ego-browser/references/install.md 自己装完。无论哪条路，安装都会把 ego-browser Skill 写进机器上各个 Agent 的 Skill 目录——这是它「Zero config」的代价，装之前值得知道。

装好后首次启动只问一个问题：是否迁移 Chrome 数据。用起来是在 Agent CLI 里敲 /ego-browser 加一句大白话；更底层的方式是：

ego-browser skill        # 打印与当前版本匹配的完整用法指南（必读）
ego-browser nodejs <<'EOF'
const task = await taskSpace("inspect example page");
const page = task.page("p1");
await page.goto("https://example.com");
console.log(await page.snapshot());
EOF

两个值得记的观察：

  • 版本号是双轨的。应用 bundle 是 0.6.2.9，而仓库 release 与 Skill 指南都是 2.2.0。查版本时别只看一处，也别拿 App 版本号去对 GitHub Releases。
  • 「写进每个 Agent 的 Skill 目录」不完全成立。本机三家有、Codex 那家没有。按各宿主只扫自己 skill 目录的惯例，没覆盖到的宿主需要手工补一次链接或复制。

边界与注意

  • Space 隔离的是标签页，不是权限。这是最要紧的一条：Agent 继承的是你全部已登录站点的身份，它能以你的名义发消息、下单、改设置，而 ego lite 没有 Pinky 那种网关级人工审批——「不抢你浏览器」不等于「不乱点」。真要跑涉及资金/账号的任务，得自己在任务边界上把关。
  • 对照上一期更清楚：Pinky 把审批、屏蔽、录屏放在中间层，代价是重流程；ego lite 把共享和并行做到极致，代价是信任面扩大。一个管「手机」，一个管「浏览器」，思路正好互补，安全模型却走了两个方向。
  • 不是开源浏览器。仓库 MIT 只覆盖 skill/CLI/docs，本体闭源。对供应链有要求的团队，这一点直接决定能不能用。
  • 857 MB。它是完整 Chromium，跟上一期 Pinky 那个 16–22 MB 下载、51 MB 落盘的 Go 原生应用不是一个量级；想装个「轻量工具」的要有心理准备。
  • benchmark 是官方自测。Real-World Bench 宣称 31 个真实网站任务、5 个工具，同一 Agent（pi）、同一模型（gpt-5.6-sol，thinking max）、同一评审，结论是快 47%–63%、成功率与成本全面领先。方法写得挺规范，但由项目方自己跑、自己发布，当作方向性参考就好，别当第三方结论。
  • 「经验积累最高 5x」还没上线，README 明确标着 coming soon。
  • Linux 用户暂时没戏，路线图不等于可用。
  • 年轻且迭代快。7 个月涨到 22k star，同时 274 个 open issue；接口和行为可能随版本变，Skill 指南也要求每次 upgrade 后重跑 ego-browser skill。生产依赖前先读 release notes。

适合谁

工具 定位 登录态 抢不抢浏览器 接入方式
browser-use / agent-browser 自动化框架，需外挂浏览器 难带过去 抢 Python / CLI
playwright-cli / Browser Harness 浏览器 CLI 不带 抢 CLI
Browserbase / 云浏览器 云端托管浏览器 不带 不抢 API
Claude/Codex in Chrome 浏览器扩展 带 部分 锁自家 Agent
Comet / Dia AI 浏览器 带 不抢 锁自家模型
ego lite 人和 Agent 共用的浏览器 带 不抢（Space 隔离） Skill + CLI，任意 Agent
（上一期）Pinky 手机 MCP 网关 — 主屏归你 MCP + 人工审批
  • 已经在用 Claude Code / Codex 跑网页任务的人：省掉反复登录和 CAPTCHA，也不用再跟 Agent 抢窗口；
  • 需要多 Agent 并行干活的人：批量补全线索、竞品页抓取、多站点 QA，Space 是目前最干净的隔离方案；
  • 在意数据不出本机的人：Cookie、扩展、书签、浏览数据全在本地，比云浏览器方案合口径。

不适合谁：只用 Linux 的；要求浏览器本体开源可自建的；只想跑无状态、可重复的爬虫（Playwright 更直接、更可控）；以及打算把全部已登录账号交给一个没有审批层的 Agent、又不做任务边界约束的——这种情况下「不抢标签页」给你的安全感，跟 Pinky 那期提到的「有 shell 权限就能绕过 adb」是同一类错觉。

一句话收尾：ego lite 真正回答的问题不是「怎么让 AI 点网页」，而是「当人和 Agent 要用同一个设备时，边界画在哪」。它把边界画在了标签页上；Pinky 把边界画在了操作权限上。两期连着看，比单独看任何一个都清楚。
