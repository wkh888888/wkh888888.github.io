cmux：为「同时跑好几个 agent」这件事重新设计的终端

iTerm2 是为人类设计的终端，cmux 是为「一排 agent 在等你」设计的终端 —— 这不是升级，是换场景。

它解决的那个具体瞬间

你现在应该有过这个体验：同时起了三个 agent 跑不同任务，屏幕上一排标签页，每隔几分钟挨个切过去看进度。突然来一条系统通知「Claude is waiting for your input」—— 但不知道是哪个在等、等什么，只能挨个点开看。

传统终端（包括 iTerm2）没有为这个场景设计过。cmux 就是冲着它来的。

它是什么

cmux 是 manaflow-ai 开源的 macOS 原生终端工作区管理器，用 Swift + AppKit 写、基于 libghostty 渲染（不是 Electron，也不是 Ghostty 的 fork —— 是把 libghostty 当渲染库用，类似 App 用 WebKit）。

四个我最看重的点：

通知环：某个 pane 里的进程需要输入时，pane 会亮起高亮环、侧栏出现未读徽章，还能带上上下文文字。配合 agent hooks 或标准 OSC 转义序列，Claude Code、Codex、OpenCode 都能自动触发。这是它和「一个好终端」最大的区别。

垂直标签侧栏：每个 workspace 旁边直接显示 git 分支、工作目录、端口、通知内容 —— 不用点进去就知道这一格在干什么。

内置可编程浏览器：可以分屏出一个真实浏览器 pane，通过同一套 socket API 导航、抓 DOM、点击、执行 JS、读 console 和网络请求。agent 能自己验证自己改的页面效果，不用你截图喂给它。

完整 CLI + Unix socket：创建 workspace、分屏、发输入、读屏幕内容、截图、驱动浏览器，全都能脚本化。比如批量起三个 agent：

cmux create-workspace --name "frontend"
cmux send-input --workspace "frontend" --input "claude"
cmux send-input --workspace "frontend" --input "重构登录页组件"

它还能把远端 SSH 会话当本地会话用（attach 到远程 tmux），让 agent 跑在远程机器上、你在本地驱动。

现在的边界

  • 只有 macOS（Linux / Windows 在路上）；有 iOS 伴侣 app 处于 beta。
  • 会话恢复能还原窗口布局、工作目录、滚动历史，但进程本身不自动恢复（Claude Code、vim 不会自己活过来）。
  • 浏览器 pane 还在成熟中；整体功能面比 iTerm2 小。
  • 它不是通用终端替代品。只跑一个 agent 的人，装它意义不大。

上手

brew tap manaflow-ai/cmux
brew install --cask cmux

终端渲染读你的 Ghostty 配置（主题、字体、光标直接继承），cmux 自己的设置在 ~/.config/cmux/cmux.json。建议先只做一件事：把「同时跑三个任务」的场景搬进去，看通知环能不能替你省掉那些来回切换。
