现象

本机 150+ 个 git 仓库，全局 [user] 一直是公司身份 吴科桦 <walker.wu@eoitek.com>。要求「个人项目统一用 walker <walkerhua@vip.qq.com>」时，第一反应是逐仓库 git config --local，但：

  • 个人仓库分散在 ~/projects/{server-apps,open-source,agent-skills,local-server}、~/docs、~/codebuddy，逐个设漏一个就是一个坑；
  • 未来新建仓库还会漏；
  • 已经有一批仓库设了 local（mind-harbor、walkerhua.com 等），再来一遍容易设歪。

排查时还撞到两个反直觉点：

检查项 实际结果 直接原因
~/projects/local-server/ai-upgrader 设了 walker 但仍是 Claude <claude@anthropic.com> includeIf 不生效 该仓库有 local [user]，local 优先级最高
~/Code/blog 看着像个人博客，该不该改个人身份 不能改 remote 是 git@192.168.1.18:eoi/up-frontend.git，公司项目，目录名骗人

根因

一句话：Git 的 [user] 是“最后读取者胜”的单值覆盖模型，不是继承合并模型；要让身份随目录自动变化，只能用 includeIf 在全局层做条件注入，而 .git/config 的 local 值永远压在最上面。

展开：

  • 直接原因：全局 gitconfig 只有一个 [user] 兜底，没有按路径分流的机制。谁后写谁生效 —— 所以 includeIf 段落必须放在 ~/.gitconfig 末尾，写在 [user] 之前会被覆盖回去（这是最容易犯的错）。
  • 根本原因：Git 配置有 4 层，system < global < local < 命令行 -c。includeIf 注入的内容算在引入它的那一层（写在 global 里就属于 global 层），因此任何 local 值都能盖掉它。这不是 bug，是设计。
  • 认知坑：目录名 / 仓库名不可作为归属判据。公司代码可能被 clone 到叫 blog、test 的目录下（本机 ~/Code/blog 就是 eoi/up-frontend）。

解法

1. 备份（改全局配置前必做）

cp ~/.gitconfig ~/.gitconfig.bak.$(date +%Y%m%d)

2. 建个人身份文件 ~/.gitconfig-personal

[user]
	name = walker
	email = walkerhua@vip.qq.com

3. 在 ~/.gitconfig 末尾（注意是末尾）追加条件包含

# 个人项目统一身份：walker <walkerhua@vip.qq.com>
# 放在文件末尾，确保覆盖上面的全局 [user]
[includeIf "gitdir:~/projects/**"]
	path = ~/.gitconfig-personal
[includeIf "gitdir:~/docs/**"]
	path = ~/.gitconfig-personal
[includeIf "gitdir:~/codebuddy/**"]
	path = ~/.gitconfig-personal

Git ≥ 2.13 支持。本机 2.39.1。

4. 清掉挡路的 local（关键一步，只加 includeIf 不清理等于白做）

# 找出所有仍带 local user 的仓库
for d in $(find ~/projects ~/docs -maxdepth 4 -type d -name .git -not -path "*/node_modules/*" | sed 's#/.git$##'); do
  n=$(git -C "$d" config --local --get user.name 2>/dev/null)
  [ -n "$n" ] && printf "%-40s %s <%s>\n" "${d#$HOME/}" "$n" "$(git -C "$d" config --local --get user.email)"
done

# 确认是个人项目后清掉，让它继承 includeIf
git -C <repo> config --local --unset user.name
git -C <repo> config --local --unset user.email

本机 2026-09-08 已执行完毕：~/projects / ~/docs / ~/codebuddy 下 8 个带 local 的仓库（cc-switch、mind-harbor、mind-helper、mindstack-deploy、services-hub-v2、skillhub/react-vite、walkerhua.com、wkh888888.github.io，另含一个卡着 Claude <claude@anthropic.com> 的 ai-upgrader）local 全部清除，个人项目区已无 local user 残留。

5. 验证：不只看配置值，要分三组对照（个人目录 / 公司目录 / 兜底新仓库）

git -C ~/projects/server-apps/mind-harbor config --get user.email   # → walkerhua@vip.qq.com
git -C ~/Code/ccdc/ucenter config --get user.email                  # → walker.wu@eoitek.com
mkdir -p /tmp/_t && cd /tmp/_t && git init -q && git config --get user.email  # → 兜底值

6. 盘一遍全机仓库（可选，但建议做完）

for d in $(find ~/projects ~/Code ~/codebuddy ~/docs -maxdepth 4 -type d -name .git -not -path "*/node_modules/*" | sed 's#/.git$##' | sort -u); do
  printf "%-8s | %-20s | %-28s | %s\n" \
    "$(git -C "$d" config --local --get user.name >/dev/null 2>&1 && echo LOCAL || echo global)" \
    "$(git -C "$d" config --get user.name)" "$(git -C "$d" config --get user.email)" "${d#$HOME/}"
done

历史提交改写法（含统计口径坑）

坑：统计“某仓库有没有公司邮箱提交”时不能用 git log --all。

--all = refs/heads + refs/remotes + refs/stash + refs/original（历史 filter-branch 备份）。本机 mind-helper 统计出「31 commit 里 8 个公司邮箱」，实际 8 个全在 refs/stash 和 refs/original，main 分支历史本来就是干净的 —— 虚惊一场，白改一遍。

git log --branches --format='%ae%n%ce' | grep -c eoitek   # 只看分支历史，正解
git log --all --format='%ae%n%ce' | grep -c eoitek        # 含 stash/original/remote，会虚高

脏工作区下安全重写（工作区一个文件都不碰）：filter-branch 拒绝在未提交改动的仓库上跑，git stash 又有风险。解法是在临时裸克隆里重写，再回灌 refs：

REPO=~/projects/xxx; NAME=$(basename "$REPO"); BR=$(git -C "$REPO" symbolic-ref --short HEAD)
git clone --bare "$REPO" /tmp/gitid-rewrite/$NAME.git -q
cd /tmp/gitid-rewrite/$NAME.git
FILTER_BRANCH_SQUELCH_WARNING=1 git filter-branch --env-filter '
  if [ "$GIT_AUTHOR_EMAIL" = "walker.wu@eoitek.com" ]; then
      export GIT_AUTHOR_NAME="walker"; export GIT_AUTHOR_EMAIL="walkerhua@vip.qq.com"; fi
  if [ "$GIT_COMMITTER_EMAIL" = "walker.wu@eoitek.com" ]; then
      export GIT_COMMITTER_NAME="walker"; export GIT_COMMITTER_EMAIL="walkerhua@vip.qq.com"; fi
' --tag-name-filter cat -- --all
git for-each-ref --format='%(refname)' refs/original | xargs -n1 git update-ref -d   # 关键：否则验证时新旧 commit 混在一起，看着像没改

# 回灌：先留备份 ref，再 soft reset（不动工作区）
cd "$REPO"
git update-ref refs/backup/pre-rewrite-20260908 $(git rev-parse HEAD)
git fetch /tmp/gitid-rewrite/$NAME.git '+refs/heads/*:refs/rewritten/*' --force
git reset --soft refs/rewritten/$BR

验证三件事：① git log --branches 里 eoitek 归零；② git rev-parse HEAD^{tree} 与旧值一致（证明只改元数据、内容零变化）；③ git status --porcelain | wc -l 回灌前后数字相同（证明工作区未损）。

本机 2026-09-08 执行结果：9 个个人仓库中 5 个实际改写（wkh888888.github.io 6 commit、agent-skills 5、ccb-web 1、port-manager 1、wkh/ai/test4 1），另 4 个（mind-helper、services-hub-v2、skillhub/react-vite、walkerhua.com）分支历史本就干净，HEAD hash 未变。未 force-push，本地与 origin 已分叉（如 wkh888888.github.io 为 6/6）。备份 ref：refs/backup/pre-rewrite-20260908；临时裸克隆留在 /tmp/gitid-rewrite/*.git。

回退：git reset --soft refs/backup/pre-rewrite-20260908。

预防规则（已上浮 L1）

抽象成检查项，精简后写入 ~/.workbuddy/MEMORY.md：

  1. 个人项目统一 walker <walkerhua@vip.qq.com>，公司项目保持 吴科桦 <walker.wu@eoitek.com>。
  2. 新增个人项目目录 → 往 ~/.gitconfig 末尾加一条 includeIf，不要逐仓库设 local。
  3. 优先级：local > includeIf > 全局。发现身份不对，先查 git config --local --get-regexp '^user\.'。
  4. 判归属不看目录名，一律先 git remote -v。
  5. includeIf 段落必须放在全局文件末尾，否则被前面的 [user] 覆盖。
  6. 统计提交身份用 git log --branches，不要用 --all（后者混入 stash 与 refs/original，数字虚高）。

边界提醒

  • 改身份只影响之后的提交，历史 commit 的作者信息不变。要改历史得重写 + force-push，会改变所有 commit hash。
  • 重写后本地与远端完全分叉，推送必须用 git push --force-with-lease（比 --force 安全，远端有新提交时会拒绝）。多人协作仓库推之前先打招呼。
  • stash 和 refs/original 里的旧身份不建议改：stash 是未完成的活，refs/original 是历史备份，动了得不偿失。
  • 提交要在 GitHub 贡献图显示，邮箱必须已加进 GitHub → Settings → Emails。否则提交能推，但绿格子不算。
