P017 · 项目级 Skill 跨宿主不可见

把项目专属 Skill 建在 项目/.workbuddy/skills/<name>/，只有 WorkBuddy 能发现并调用。Claude Code、Codex、Gemini 全部看不见。

踩坑于 2026-09-15约 2 分钟
目录
现象原因我当时的误判决策树检查项顺带修掉的两个问题迁移操作（可复用）

记录日期：2026-09-15 触发：《一念·正传》连载版续写 skill 建完后，用户问「放 workbuddy 里不是只能自己用吗」

现象

把项目专属 Skill 建在 项目/.workbuddy/skills/<name>/，只有 WorkBuddy 能发现并调用。Claude Code、Codex、Gemini 全部看不见。

实测：

✅ workbuddy 项目级可见
❌ claude   看不到
❌ codex    看不到
❌ gemini   看不到

原因

各宿主只扫自己的 skill 目录，彼此不交叉：

宿主 用户级 项目级
WorkBuddy ~/.workbuddy/skills/ 项目/.workbuddy/skills/
Claude Code ~/.claude/skills/ 项目/.claude/skills/
Codex ~/.codex/skills/ 项目/.codex/skills/
Gemini ~/.gemini/skills/ 项目/.gemini/skills/

放 项目/.workbuddy/skills/ 等于只挂了一个入口。

我当时的误判

建 skill 时只权衡了「会不会污染那 438 个全局 skill」，据此判定「项目专属 → 放项目级」，完全漏掉了跨宿主可见性。

「项目专属」和「放项目级」是两回事：

  • 项目专属 = 内容绑定该项目的路径与设定 → 决定它的适用范围
  • 放项目级 = 只挂单一宿主入口 → 决定它的可见范围

两者没有因果关系。我想当然地把它们绑在一起了。

决策树

新建 Skill
├─ 内容绑定具体项目（绝对路径 / 项目设定）？
│   ├─ 是 → 仍可放用户级：name 加项目前缀（如 yinian-）、
│   │        description 写死触发条件就不会误触发
│   └─ 否 → 通用 skill，直接用户级
└─ 是否需要跨 agent 调用？
    ├─ 是 → 真实源 `~/.agents/skills/<name>/`
    │       + 软链到 .workbuddy/.claude/.codex/.gemini/.cc-switch
    └─ 否 → 放对应宿主的项目级目录即可（如 `项目/.claude/skills/`）

默认推荐「用户级 + 软链」。全局已有 400+ 个 skill，多一个有前缀的不改变什么；但放错位置会直接少五个入口。

检查项

改完 Skill 位置后必验三条：

  1. 入口可见性——逐个宿主查，别只看一个：

    for h in workbuddy claude codex gemini cc-switch; do
  f="$HOME/.$h/skills/<name>/SKILL.md"
  [ -r "$f" ] && echo "OK .$h" || echo "MISS .$h"
done

  2. realpath 零漂移——所有入口解析到同一真实源：

    realpath ~/.$h/skills/<name>   # 应全部等于 ~/.agents/skills/<name>

  3. 文档路径同步——SKILL.md、使用说明、custom-skills-registry.md 三处的旧路径要清干净：

    grep -c '旧路径' 上述三个文件   # 应全部为 0

顺带修掉的两个问题

  • POLICIES.md 的 AGENT-SKILL-ROOT-POLICY 块里，P002 路径写成 ~/docs/踩坑与经验/P002-...，实际是 ~/docs/踩坑经验/P002-...（多一个「与」字），死链。已修正。
  • 该块原本 705 字符，借这次重写压到 448（合并冗余条目 + 补入本条新规），~/.workbuddy/MEMORY.md 从 4407 降到 4151。

迁移操作（可复用）

REAL="$HOME/.agents/skills/<name>"
mv "项目/.workbuddy/skills/<name>" "$REAL"        # mv，不用 rm
for h in workbuddy claude codex gemini cc-switch; do
  [ -d "$HOME/.$h/skills" ] && ln -s "$REAL" "$HOME/.$h/skills/<name>"
done
python3 ~/.agents/bin/sync-agent-policies.py --apply   # 若改了策略块

前置：先查各宿主是否已有同名实体目录——有则不覆盖，先报冲突（AGENT-SKILL-ROOT-POLICY 明文规定）。
