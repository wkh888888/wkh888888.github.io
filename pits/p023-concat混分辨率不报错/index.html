P023 · ffmpeg concat `-c copy` 混分辨率**不报错**：成品流参数以首段为准，播放器抽风

一个 AI 漫剧项目 E01 合成"成功"（无任何报错），

踩坑于 2026-10-14约 2 分钟视频合成ffmpeg
目录
现象根因定位处置教训
元信息
日期 2026-10-14
领域 视频合成 / ffmpeg
严重度 高（无声产出错误文件；抽帧抽查单段看不出问题，只有 ffprobe 全集参数才暴露）
关键词 ffmpeg、concat demuxer、-c copy、分辨率不一致、1920x1080、2112x1188、zoompan s=、视频参数闸门、漫剧组装
状态 有效（已加拼接前断言闸门；所有多段合成管线复用）

现象

一个 AI 漫剧项目 E01 合成“成功”（无任何报错）， 但 ffprobe 成品显示 width=2112 height=1188，而分镜段明明是 1920×1080。 单段抽帧（片头卡、分镜、动画段）看起来都正常——只有查全集流参数才发现。

根因

11 个面板段里，片头/备忘录/片尾 3 个卡片段走的是 scale=2112:1188 后直接输出 （漏了 zoompan 的 s=1920x1080），图段和动画段是 1920×1080。 concat demuxer + -c copy 不校验分辨率一致性：它按第一个文件的流参数 声明输出轨，后续不同分辨率的段被原样塞进去——容器层“合法”，播放层错乱。

定位

for f in build/seg*.mp4; do ffprobe -v error -select_streams v:0 \
  -show_entries stream=width,height -of csv=p=0 "$f"; done   # 逐段量，立即见混
ffprobe -v error -show_entries stream=width,height 成品.mp4  # 全集参数 = 首段参数

处置

  1. 卡片分支统一走 zoompan 链（...scale=2112:1188,zoompan=...:s=1920x1080...）， 与图段输出一致（顺便获得缓推运镜）。
  2. 加拼接前闸门（治本，防复发）：
for av in panel_avs:
    probe = sh(["ffprobe", "-v", "error", "-select_streams", "v:0",
                "-show_entries", "stream=width,height", "-of", "csv=p=0", av]).stdout.strip()
    assert probe == "1920,1080", f"分辨率不一致: {av} -> {probe}"

教训

  1. concat -c copy 是“信任式”拼接：不校验、不转码、不报错。多段合成的管线， 拼接前必须逐段断言参数（分辨率/帧率/像素格式），不能等成品出来再看。
  2. 分支遗漏（某个 kind 少走一级 filter）在这种静默模式下永远不报错—— 按 kind 分叉的合成脚本，每个分支的出口参数都要显式对齐。
  3. 验收不能只抽帧：抽帧验画面，ffprobe 验参数，两件事都要做。
