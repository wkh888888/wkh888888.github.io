现象

用 web2md 存一篇 15 节公众号长文，存档只覆盖约一半章节：缺 一/五/六/九/十三/十四 整节 + 9 个二级小节（二缺第二步/第三步、三缺 3.1/3.4、七缺 7.1/7.3/7.4、八缺 8.1、十缺 10.1）。WebFetch 返回里多处出现 [...] 占位，不报错只省略。

附带踩到第二个坑：第一次想加载 web2md 时 Skill 工具报 disabled via skillOverrides，匹配也不触发。

根因

直接原因：WebFetch 是模型抽取（生成式），对长文会“挑重点”跳过中间整段，表现为输出插 [...] 或整节消失——它不会像爬虫那样确定性返回全文。

根本原因：把“网页转 Markdown”误当成确定性抓取。WebFetch 本质是“读后总结/转写”，长文保真度无保证；而 skillOverrides: "off" 是之前手动禁用的残留，导致 skill 根本不加载。

解法

1. 启用被禁用的 skill：编辑 ~/.workbuddy/settings.json，删掉 skillOverrides 里的 "web2md": "off" 一行（删后务必 python3 -c "import json;json.load(open(...))" 校验 JSON 合法）。该改动即时生效，无需重启。

2. 长文防遗漏（已固化进 web2md SKILL.md v1.0.2，步骤 2「长文防遗漏」）：

  1. 先取大纲：一次 WebFetch，prompt 只列所有一/二级标题原文（按序），不要正文；末尾说明一级标题从几到几、共几个。
  2. 判断是否分批：大纲一级标题 ≥ 5 个，或全文抓取出现 [...] / 缺标题 → 分批；短文（<5 节且无 [...]）直抓即可。
  3. 分批抓取：按 3–5 个一级标题一组切片，逐批 WebFetch，prompt 明令“只输出指定节全部正文，保留标题层级/列表/代码块/表格，不要省略、不要用 […]”，各批结果按原序拼接。
  4. 补齐缺口：拼接后逐条核对大纲，缺失标题单独再抓一次，直到与大纲一致；重复标题去重只留一处。

3. 兜底：jina reader（https://r.jina.ai/<URL>）保真度更高，但本沙箱实测被网络拦截（SSL 错误），当前只能走 WebFetch 分批。

预防规则（判断是否上浮 L1）

  • 铁律：长文网页存档，绝不一抓即存——先取大纲、按需分批、拼接后核对缺口。
  • 检查项：某 skill 匹配却触发不了，先看 ~/.workbuddy/settings.json 的 skillOverrides 是否被设成 off / user-invocable-only。
  • 这两点偏“操作纪律 + 配置排查”，留 L2 即可；web2md 的「长文防遗漏」策略已直接写进 skill 正文（运行时约束），无需上浮。

相关文件
