P004 · git/curl 直连 GitHub hang 死：proxy_env 是按需注入，不是全局 export

git clone github.com/... 直连 hang 住直到超时。

现象

git clone github.com/... 直连 hang 住直到超时。

根因（2026-09-03 实测修正）

⚠️ 原 L1 记忆写的是「环境变量只设了大写 HTTPS_PROXY/HTTP_PROXY，小写为空；git 不读大写变量、也不读小写」。该描述不成立，实测：当前会话大写、小写 proxy 变量均为 0 个，且 git config --global http.proxy 未配置。

真实情况：

~/.zsh/functions.zsh      ← proxy_env 数组定义在【这里】
      ↓ source
~/.zshrc (cxa/cxb/gemini/kiro/agy 等函数)
      ↓ env "${proxy_env[@]}" <命令>
命令才带上代理

proxy_env 定义在 ~/.zsh/functions.zsh 第 8 行，含 8 个变量（大小写齐全 + no_proxy）：

proxy_env=(
  http_proxy=http://127.0.0.1:7890
  https_proxy=http://127.0.0.1:7890
  all_proxy=socks5://127.0.0.1:7890
  HTTP_PROXY=http://127.0.0.1:7890
  HTTPS_PROXY=http://127.0.0.1:7890
  ALL_PROXY=socks5://127.0.0.1:7890
  no_proxy=127.0.0.1,localhost,::1
  NO_PROXY=127.0.0.1,localhost,::1
)

关键：它只在封装函数里按需注入，不全局 export。 所以：

场景 是否有代理 结果
普通 git clone ❌ 无 直连 hang 死
cxa / gemini / kiro 等封装函数 ✅ 有 正常走 7890
WorkBuddy Bash 工具 ❌ 无 需手动内联

这是个合理设计（按需代理、不污染全局），不是配置疏漏。只是“全局没代理”这件事需要知道。

解法（按可靠性排序）

1. 显式 git -c（最可靠，不依赖任何环境变量）

git -c http.proxy=http://127.0.0.1:7890 -c https.proxy=http://127.0.0.1:7890 clone <url>

2. 命令前内联环境变量

http_proxy=http://127.0.0.1:7890 https_proxy=http://127.0.0.1:7890 git clone <url>

3. 给新 CLI 套封装函数（沿用既有模式，加到 ~/.zsh/functions.zsh）

mycli() { env "${proxy_env[@]}" command mycli "$@"; }

WorkBuddy 特别注意

Bash 工具默认沙箱会阻断网络，即便配了代理也连不出去。下载外部仓库需显式 dangerouslyDisableSandbox: true。

验证

lsof -nP -iTCP:7890 -sTCP:LISTEN     # 代理在不在
env | grep -i proxy                   # 当前有没有代理变量（正常应为 0 个）
git config --global --get http.proxy  # git 自身有没有配（正常应为空）

2026-09-03 实测：FlClashCo 监听 7890 ✅ / 会话内 proxy 变量 0 个 / git 未配置 http.proxy。

预防规则（已上浮 L1）

git clone 走 git -c http.proxy=... 显式指定，不要假设环境里有代理变量 —— 本机的代理是按需注入的。
