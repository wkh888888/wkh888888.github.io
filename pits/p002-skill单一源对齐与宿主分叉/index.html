背景

用户有多个 AI 工具目录（.claude .workbuddy .codex .gemini .openclaw .cc-switch），每个都有自己的 skills/。若各自存一份真实目录，会出现多副本漂移（同一 skill 在 A 工具是新版、B 工具是十天前的旧版，更新静默丢失）。

解法：单一源 + 软链。

约定

  • 自定义/模型创建的 skill 真实源统一放 ~/.agents/skills/（与 port-check、ab-test-analysis 等同级）。
  • 各工具目录只放符号链接指向 ~/.agents/skills/<name>，不存放真实源。
  • 两档真实源（2026.09.04 起）：上两条对绝大多数 skill 不变——~/.agents/skills/<name> 仍是真实目录。但本机自建、需跨机 git 同步的 15 个 skill（agnes-image-video、agent-skill-root-policy、aihot、bt-panel-ops、ccusage-monthly-screenshot、edge-tts-remotion-sync、my-gitlab、offline-social-video-render、port-check、ab-test-analysis、skill-genericize、skill-maintenance、skill-symlink-align、timefill2、add-local-service）其真实源上移到专属 git 仓库 ~/projects/agent-skills/，~/.agents/skills/<name> 改为指向该仓库的软链（中间聚合层），6 宿主仍指向它不变。即：这 15 个“唯一真身在仓库、其余全软链”的单一源原则不变，只是真身位置从 ~/.agents/skills 挪到了 ~/projects/agent-skills。
  • 需覆盖的链接目录：6 处 —— ~/.claude/skills/、~/.workbuddy/skills/、~/.codex/skills/、~/.gemini/skills/、~/.openclaw/skills/、~/.cc-switch/skills/（早期文档记的“4 处”已过时，以 6 处为准）。
  • 自定义 skill 的 SKILL.md frontmatter 须带 agent_created: true（系统判定可跨会话/跨 agent 复用的依据）。

历史对齐记录

  • 2026.09.01 全量对齐后：源 487 个，6 目录共 2929 条目 / 2406 条指向 .agents，零漂移零断链；剩余 518 个真实目录（.claude 81 + .cc-switch 435 + .workbuddy 1 + .codex 1）。

🔴 宿主适配分叉（2026.09.01 血泪，最重要的一条）

差异 ≠ 版本新旧。 .agents 源里存的是 Codex 版，.claude/skills 保留 Claude 版 —— 同一 skill 针对不同宿主的适配。

实例（只差 1 字节，换成链接 = 该工具直接失效）：

Skill Claude 版引用 Codex 版引用
gsd-fast .claude/gsd-core/ .Codex/gsd-core/
port-check 「Claude 可直接调用」 「Codex 可直接调用」
omc-reference ${CLAUDE_PLUGIN_ROOT} ../../skill-bodies/

差异三分法

  1. md5 全等 → 可安全换成链接。
  2. 内容含 .claude / .Codex / CLAUDE_* / CODEX_* / Claude Code / Codex → 宿主适配，永久保留真实目录，不要换链接。
  3. 其余内容差异 → 人工判新版在哪边。

判定新版靠 grep -c "关键新内容"（1 vs 0），不要看 mtime 或字节数。 历史教训：vue-best-practices 曾 mtime 不同但内容完全一致；docx-interface-fill 的 .agents 版是增强版（87 vs 66 行，可安全切）；edge-tts-remotion-sync 的 .agents 版含更多实战记录（45 vs 39 行）。

操作规范

建立/更新链接前

必须先查旧链接指向。 多次出现某工具目录残留指向 .cc-switch 的旧链接（如 ~/.codex/skills/timefill2），导致该工具读到旧版、更新静默丢失。

readlink ~/.codex/skills/timefill2   # 先确认
rm ~/.codex/skills/timefill2         # 已存在则先删
ln -s ~/.agents/skills/timefill2 ~/.codex/skills/timefill2

迁移流程

  1. tar 备份原目录
  2. mv 真实目录到 ~/.agents/skills/（旧副本 mv 到 /tmp 保留可回滚，不用 rm）
  3. 在 6 处各建符号链接
  4. 跑下方巡检

禁用/移除流程（2026-09-03 实战于 3 个邮件 skill）

BK=/tmp/skill-backup-<日期>
tar -czf "$BK/<name>.tar.gz" -C ~/.agents/skills <name>
mv ~/.agents/skills/<name> "$BK/<name>"
for d in ~/.workbuddy ~/.claude ~/.codex ~/.gemini ~/.openclaw ~/.cc-switch; do
  rm -f "$d/skills/<name>"
done

回滚：mv $BK/<name> ~/.agents/skills/ && for d in <6 目录>; do ln -s ~/.agents/skills/<name> "$d/skills/<name>"; done

漂移巡检命令（改完链接后必跑）

for d in ~/.claude ~/.workbuddy ~/.codex ~/.gemini ~/.openclaw ~/.cc-switch; do
  for l in "$d"/skills/*; do [ -L "$l" ] || continue
    if [ ! -e "$l" ]; then echo "断链: $d/$(basename $l)"; else
      case "$(realpath "$l")" in /Users/kehua/.agents/skills/*|/Users/kehua/projects/agent-skills/*) ;; *) echo "漂移: $d/$(basename $l) -> $(realpath "$l")";; esac
    fi
  done
done

判断漂移必须用 realpath 解析后再比对。直接字符串匹配 readlink 结果会把相对路径（../../.agents/skills/x）误报为漂移。

残留扫描（确认某 skill 已彻底清除）：

for d in ~/.workbuddy ~/.claude ~/.codex ~/.gemini ~/.openclaw ~/.cc-switch ~/.agents; do
  { [ -e "$d/skills/<name>" ] || [ -L "$d/skills/<name>" ]; } && echo "残留: $d/skills/<name>"
done

易错点清单

  • 按 name 字段查重，不要按目录名。 目录名可中文化（智能体邮箱 的 frontmatter name 仍是 agentmail，是 agent-mail 的马甲）—— 2026-09-03 差点漏掉。
  • 批处理必须跳过 . 开头目录：.omc / .system / .backup-* 是运行时状态或备份，不是 skill。
  • 估算分叉影响时排除 .DS_Store：diff -rq 会把无关文件计入，曾高估为 136 个分叉/55 个回退，实际全仓库只有 84 个差异/1 个回退。
  • shim 类 skill：retro 的 SKILL.md 本身是 symlink，指向 ~/.claude/skills/gstack/retro/SKILL.md，依赖 gstack 真实目录存在。
  • 两个不同 skill 不要合并：vue-best-practices（154 行/vuejs-ai MIT 版）与 codex-vue-best-practices（43 行/聚焦 vue-tsc）仅 name 字段重名，实为两个。
  • .cc-switch 的 435 个真实目录保留作第二源/回滚素材，只补缺失链接不动它们。
  • 已知无害断链：add-local-service（.claude/.workbuddy），指向已删除的 ~/projects/local-services-hub。
