现象

做《我能闻到所有人的秘密》AI 漫剧，字幕条（Chrome 渲染的透明 PNG）叠加到分镜图上， 抽帧发现两种连环故障：

  1. 字幕整条消失：单独看字幕 PNG 正常（透明底 + 底部名条），合进视频后什么都没有。
  2. 修了第 1 个后整帧变白布：给字幕输入加 -loop 1 后字幕出现了， 但整个画面被一块白色盖住——原来 Chrome 截图把透明页合成了白底 rgb24（无 alpha）。

根因（两层，各自独立）

坑 1：单帧输入 + fade=alpha=1 + overlay 默认 eof_action=repeat = 永久定格在 t=0 帧。 字幕 PNG 作为第二个输入只有 1 帧（t=0），fade=t=in:st=0:d=0.25:alpha=1 在 t=0 时 alpha=0；输入流随即 EOF，overlay 的 framesync 按默认 eof_action=repeat 永远重复这一帧——于是字幕全程透明，表现为“字幕没合成上”。 （不是 overlay 语法错、不是 PNG 坏，是时间维坏了。）

坑 2：Chrome headless --screenshot 默认把透明背景合成为白底。 CSS background:transparent 的页面截出来是 rgb24 白底 PNG，没有 alpha； overlay 上去就是一块不透明白布。

修法（两行，都已实测）

# 1) Chrome 截图加透明参数，产出 rgba PNG
CHROME ... --default-background-color=00000000 --window-size=1920,1080 --screenshot=sub.png ...

# 2) 字幕输入必须 loop 成连续流，fade 才有时间轴可依
ffmpeg -loop 1 -framerate 30 -i panel.png -loop 1 -framerate 30 -i sub.png \
  -filter_complex "[0:v]...,zoompan=...[base]; \
    [1:v]fade=t=in:st=0:d=0.25:alpha=1,fade=t=out:st=D-0.2:d=0.2:alpha=1[sub]; \
    [base][sub]overlay=0:0:format=auto[v]" ...

教训

  1. overlay 的第二路是单帧图时，任何带时间的滤镜（fade/alpha）都会坏—— 单帧流没有“后续”，repeat 会把 t=0 的状态冻成永久。给单帧图当 overlay 素材， 一律 -loop 1 -framerate N。
  2. Chrome 无头截图的透明不是默认的，要显式 --default-background-color=00000000； 用 ffprobe -show_entries stream=pix_fmt 验证（rgb24 = 没透明，rgba = 有）。
  3. 这类“素材单独看都对、合起来错”的问题，先拆开验证每一环 （PNG 单独读 → 单帧 overlay 手动复现 → 加 loop），别在整条管线上猜。
