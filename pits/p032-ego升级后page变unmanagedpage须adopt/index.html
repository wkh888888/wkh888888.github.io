P032 ego-browser 升级后 page 变 UnmanagedPage：agent 必须先 adopt

日期：2026-11-21。场景：timefill2-ego 填 OA 工时，从 ego lite 0.6.2.8 升到 0.6.3.14 后首个脚本直接挂掉。

踩坑于 2026-11-21约 2 分钟

日期：2026-11-21。场景：timefill2-ego 填 OA 工时，从 ego lite 0.6.2.8 升到 0.6.3.14 后首个脚本直接挂掉。

一句话现象

升级前能跑的 ego 脚本，升级后第一行浏览器操作就报 TypeError: page.goto is not a function；拿到的 tab.page 只有 spaceId/targetId/openedBy 三个字段，没有任何 goto / evaluate。

具体表现

# 现象 实际输出／证据
1 旧 API 直接失效 taskSpace(1).tabs() → 取 tab.page → page.goto(...) 抛 TypeError: page.goto is not a function
2 page 对象退化成壳 Object.keys(tab.page) = ['spaceId','targetId','openedBy']，原型上只有 constructor，constructor.name = UnmanagedPage
3 空间 id 也不见了 listTaskSpaces() 里原先写死的 id 2 已消失（被清理），OA 标签页跑到 id 1，名字还叫别的任务名
4 任务已结束的空间无法 takeOver 对 task ended 的空间调 takeOverTaskSpace 无效，报 “This task space is no longer assigned to the agent”，须改 claimTaskSpace

根因

0.6.3.x 引入了 managed / unmanaged 页模型：

  • task.tabs() 返回的是浏览器里的全部标签，其中用户自己开的标签 label 为空 → 属于用户，agent 只有只读元信息。
  • 只有 task.pages() 返回的、或经 task.adopt(tab.page) 领养的页，才是带 label（p1、p2…）的 managed page，才具备 goto / evaluate / click 等操作能力。
  • 同时空间所有权细分为 user（须 claim）、agentDelegatedToUser（控制权在用户，须 takeOver）、其余（taskSpace 直接用），不再能一个 taskSpace(id) 打天下。

决策树 / 检查项

  1. ego lite 每次升级后，第一步跑 ego-browser skill > /tmp/guide.md 读新版指南，不要照旧代码猜 API。指南末尾有 [ego-browser:skill] end of guide vX.Y.Z，缺这行说明输出被截断。
  2. 拿页面的正确姿势（固定模板，别自己拼）： 
    const entry = (await listTaskSpaces()).find(s => s.id === SPACE_ID);
const task = !entry ? await taskSpace('goal name')
  : entry.ownership === 'user' ? await claimTaskSpace(SPACE_ID)
  : entry.ownership === 'agentDelegatedToUser' ? await takeOverTaskSpace(SPACE_ID)
  : await taskSpace(SPACE_ID);
const tabs = await task.tabs();
const hit = tabs.find(t => (t.url || '').includes('目标域名'));
const page = hit.label ? task.page(hit.label) : await task.adopt(hit.page);
  3. 别用 if (!page) 判缺失：task.page(label) 的 handle 永远 truthy，标签不存在也不会返回假值。
  4. 空间 id 一律 listTaskSpaces() 现查，不硬编码；判断依据是“哪个空间里有目标域名的标签”。
  5. openedBy: "unknown" 等同用户所有，决定能不能关页时按用户算；release(label) 把页还给用户而不关标签。
  6. 把上面这段封成一个 acquirePage(spaceId) 函数，所有脚本共用 —— 否则每加一个脚本就要重踩一次。

关联

  • timefill2-ego 2.2.0（scripts/ego_fill.mjs 的 acquirePage()），SKILL.md「2.2.0 适配」节。
  • P014（DOM 自动化的两类假成功）——同属“回执/对象存在 ≠ 真的可用”。
  • ego-browser skill 本体：~/.agents/skills/ego-browser/SKILL.md，升级后重读。
