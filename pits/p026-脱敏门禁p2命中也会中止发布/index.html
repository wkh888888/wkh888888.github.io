P026 · 脱敏门禁「只拦 P1」的注释与实际行为不符：P2 命中照样中止发布

发布 AI 日报前预扫，命中 1 处 P2：

踩坑于 2026-10-28约 3 分钟发布链路脱敏
目录
现象根因解法预防 / 检查项相关文件
元信息
日期 2026-10-28
领域 发布链路 / 脱敏
严重度 中（发布被卡在门禁；脚本已推 GitLab 会留半推送状态）
关键词 redact-sensitive、P2、level P1、退出码、publish.sh、脱敏门禁、class_ip、169.254.169.254、RFC 3927、IMDS、误报、skip-redact
状态 有效

现象

发布 AI 日报前预扫，命中 1 处 P2：

P2 待确认  公网 IP  ai-daily-2026-10-28.html:324  169.254.169.254  <服务器IP>

该地址是云厂商实例元数据服务（IMDS）的标准地址，日报正文在讲模型探测裸云元数据，属于公开且无害的引述。以为 P2 不会拦发布，于是跑了完整脚本，结果被卡住：

[redact] 检出敏感内容（P0/P1），已中止发布：先 apply 脱敏再重跑，或加 --skip-redact 绕过

根因

publish.sh 的门禁段跑 redact.py check ... --level P1，判据是退出码：

python3 "$REDACT" check src/content src/pages public/ai-daily --level P1
RC=$?
if [[ $RC -eq 1 ]]; then echo "[redact] 检出敏感内容（P0/P1），已中止发布"; exit 1; fi

而 redact.py 的 main() 结尾是：

if args.mode == "check" or not per_file:
    ...
    return 1 if all_rows else 0

all_rows 不按等级过滤 —— --level P1 只影响「哪些规则参与扫描」，不影响「命中后算不算数」。所以只要扫出任何一行（哪怕是 P2），退出码就是 1，门禁照样中止。

脚本注释写的是错的：

# 只拦 P0（凭证）和 P1（内网设施/身份/私有词）；P2 是待确认项（公网 IP 之类，
# 已知 about 页 SVG path 会被误报），不拦，避免误伤发布。

注释与 redact.py 的实际行为不符。别信注释，去看退出码怎么来的。

顺带一个坑：--level P1 时，被 probe「降级」的 P2 也会算命中 —— class_ip 对公网 IP 返回 ("公网 IP", "P2")，probe 降级后的等级仍进了 all_rows。

解法

改门禁的分类规则，不改文章，不长期 --skip-redact。 给 class_ip 加 RFC 保留段跳过（与既有的 DOC_NETS、RFC 6598 CGNAT 同理）：

if a == 169 and b == 254:
    return None   # RFC 3927 link-local（169.254.0.0/16）：云元数据服务标准地址，永不是真实公网 IP

169.254.0.0/16 是 RFC 3927 link-local，不可路由、且 IMDS 地址本身早已公开，不可能是真实公网 IP 或内网设施，与 100.64.0.0/10（RFC 6598 CGNAT）是同一类问题。

改完必须做回归，确认真内网仍判 P1、真公网仍报 P2。回归样例本身不能把 IP 字面量写进文档 —— 脱敏门禁会把它当真实地址命中（本文档就是这么把自己卡住的）。用变量拼接或直接查 class_ip 的行为描述：

# 回归矩阵（地址字面量请在本地拼好再跑，别写进要发布的文档）
#   内网三段（10.x / 172.16-31.x / 192.168.x）→ 内网 P1
#   文档段（RFC 5737）→ skip
#   CGNAT（RFC 6598）→ skip
#   link-local（RFC 3927，本例新增）→ skip
#   真公网 → 公网 P2
#   非 link-local 的 169.x → 公网 P2

同步更新脚本头部变更日志（≤10 行，每行「日期 / 改了什么 / 回归结果」）与 ~/docs/skill使用说明/redact-sensitive使用说明.md 的「自动放过」清单。

预防 / 检查项

  1. 发布前预扫必须真的看退出码，不能只看「命中等级是 P2」。redact.py check 退出码 1 = 会中止发布，不管命中什么等级。
  2. 凡有公网 IP 类误报，先查能不能按 RFC 保留段跳过，别改文章、别 --skip-redact：RFC 3927（link-local）、6598（CGNAT）、5737（文档网段）、5735、4193 等都是同类。
  3. 门禁中止后先看 GitLab 是否已推（脚本第 1 步先推 GitLab 再同步再构建），中止会留半推送状态；重跑用完整脚本，别加 --skip-gitlab。
  4. 预扫要放在跑脚本之前。门禁在构建前，publish.sh 却已经把改动推上 GitLab 了 —— 中止等于「推了源码、没上线站点」，比一开始就预扫失败更被动。
  5. 预扫除了门禁范围，还要单独扫当日日报源文件（~/WorkBuddy/每日 AI 新闻推送/ai-daily-<日期>.html），它此时还没同步进 public/ai-daily/，不在门禁扫描范围内。
  6. 改 redact.py 后同步更新使用说明文档（~/docs/skill使用说明/redact-sensitive使用说明.md），并在脚本头部留变更日志 —— 该 skill 不在 git 下，变更日志是唯一的可追溯手段。
