P005 · openclaw 升级后 config invalid / gateway 崩溃循环

现象

openclaw update 直接报 OpenClaw config is invalid，两条 error：

plugins.load.paths: plugin path not found: /Users/kehua/Code/TencentDB-Agent-Memory/MemoryCore/openclaw-plugin
plugins.slots.memory: plugin not found: memory-tencentdb-client

修完路径、升级到 2026.8.2 后，gateway 起不来且崩溃循环（launchd KeepAlive 反复重启），日志尾部：

Gateway failed to start: Legacy session store requires migration:
/Users/kehua/.openclaw/agents/main/sessions/sessions.json.
Run "openclaw doctor --fix" against the same state/config before starting OpenClaw.

openclaw doctor --fix 跑完仍报 could not complete maintenance + 同一句 sessions.json requires migration，不解决问题。

根因

一句话：升级链路里有 3 个独立坑叠在一起——① 仓库搬家导致插件绝对路径失效；② openclaw 的 Node 门槛把 WorkBuddy 默认 node 挡在门外；③ 2026.8.2 的启动守卫把「已迁移完的」旧 sessions.json 当成未迁移而拒绝启动，且 doctor --fix 自己有 bug 修不了。

层 直接原因 根本原因
配置 插件路径指向已删除目录 TencentDB-Agent-Memory 仓库从 ~/Code/ 迁到 ~/projects/open-source/，配置里的绝对路径没跟着搬
node 命令报 Node.js >=22.22.3 <23 ... required (current: v22.22.2) WorkBuddy managed node 是 v22.22.2，差 0.0.1 即拒启；且用 nvm node 跑 update 会造出「nvm 旧副本 vs /opt/homebrew 新版」二进制分叉
gateway assertSessionStoreMigrationComplete 检测 sessions.json（非 .sqlite）存在即抛错 会话数据早已迁进 agents/main/agent/openclaw-agent.sqlite；doctor --fix 内部 session-transcripts 诊断步抛 artifact is not an unaliased issue，导致整体中断、没机会删残留文件

解法

1. 修失效插件路径

~/.openclaw/openclaw.json 的 plugins.load.paths[0]： /Users/kehua/Code/TencentDB-Agent-Memory/MemoryCore/openclaw-plugin → /Users/kehua/projects/open-source/TencentDB-Agent-Memory/MemoryCore/openclaw-plugin

2. 用正确的 node 跑（常驻用 homebrew node）

# 临时排障/升级/doctor —— 不要前置 nvm，否则二进制分叉
export PATH="/opt/homebrew/opt/node@22/bin:$PATH"   # v22.23.2
openclaw --version          # 应显示 2026.8.2
openclaw config validate    # Config valid
openclaw update             # 走 /opt/homebrew 那一份

3. 清两个 warning（config validate 后才暴露）

  • feishu 缺 channelConfigs：编辑 ~/.openclaw/extensions/feishu/openclaw.plugin.json，照 ~/.openclaw/npm/.../openclaw-weixin/openclaw.plugin.json 的 channelConfigs 结构补一个 feishu 键。
  • openclaw-weixin 重复 id：旧副本 ~/.openclaw/extensions/openclaw-weixin（v2.0.0）与 npm 全局 @tencent-weixin/openclaw-weixin（v2.4.6）并存 → mv 旧副本到 ~/.openclaw/tmp/removed-plugins-$(date +%s)/。

4. gateway 崩溃循环：移走残留 sessions.json

先验证数据已在 .sqlite（关键，避免丢会话）：

openclaw sessions cleanup --dry-run --all-agents
# 输出应含: Session store: .../openclaw-agent.sqlite   Entries: 1 -> 1 (remove 0)
# 且 agent:main:main 状态为 keep —— 说明索引已迁移

确认后备份并移走残留文件，gateway 即起：

cd ~/.openclaw/agents/main/sessions
mv sessions.json sessions.json.migrated-$(date +%s)
launchctl load ~/Library/LaunchAgents/ai.openclaw.gateway.plist
sleep 5
lsof -nP -iTCP:18789 -sTCP:LISTEN && echo "✅ gateway up"

⚠️ 不要指望 openclaw doctor --fix 自动迁移：2026.8.2 在 Mac 上该步会因内部 session-transcripts 诊断 bug 中断。手动移走残留文件是当前唯一稳妥 workaround。

预防规则（判断是否上浮 L1）

  • 跑 openclaw 一律用 homebrew node：export PATH="/opt/homebrew/opt/node@22/bin:$PATH"。WorkBuddy 默认 node v22.22.2 差 0.0.1 就被拒；用 nvm node 跑 update 还会造二进制分叉让后续 update 自检失败。
  • 仓库搬家要同步改 openclaw 插件绝对路径：plugins.load.paths 是写死路径，git 挪窝必断。
  • gateway 起不来先查 sessions.json 是不是旧版残留：2026.8.2+ 启动守卫见到非 .sqlite 的 sessions.json 即拒启；sessions cleanup 能确认数据是否已进 .sqlite，已迁就直接移走残留文件。

相关文件

  • 配置：~/.openclaw/openclaw.json（备份 openclaw.json.bak.manual-*，含 plugins.load.paths 与 agents.defaults.sessionStore.agentId: "main" 两项增补）
  • 会话：~/.openclaw/agents/main/sessions/（备份 sessions.bak-*；残留 sessions.json.migrated-*）
  • 插件：~/.openclaw/extensions/{feishu,openclaw-weixin}、~/.openclaw/tmp/removed-plugins-*
  • 启动：~/Library/LaunchAgents/ai.openclaw.gateway.plist（用 /opt/homebrew/opt/node@22/bin/node 跑 /opt/homebrew/lib/node_modules/openclaw）
  • 日志：~/Library/Logs/openclaw/gateway.log、~/.openclaw/logs/stability/*.json
