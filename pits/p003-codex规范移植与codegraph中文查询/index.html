现象

用户要求把 ~/.codex/AGENTS.md 中「Skill 使用说明文档」与「CodeGraph」两节移植到 WorkBuddy。直接照搬会踩一个坑：CodeGraph 节原文写的是 codegraph explore "<symbol names or question>"，暗示可以传自然语言问题；实测中文自然语言查询返回 No relevant code found。

根因

CodeGraph 的语义检索基于标识符匹配 + 英文语义，不支持中文自然语言。

cd /Users/kehua/projects/local-server/ai-probe
codegraph explore "轮询"   # → No relevant code found for "轮询"
codegraph explore "poll"   # → Found 16 symbols across 3 files（成功）

危险之处：返回结果看起来像“这个仓库没索引/没这段代码”，极易误导 Agent 退回 grep，规则形同虚设。与 P001 同类 —— 不了解参数格式，就会把工具失败误判为数据不存在。

解法

L1 ~/.workbuddy/MEMORY.md 中加入两个带 HTML 注释标记的可管理区块，其中 CodeGraph 节显式写入中文查询的坑。

区块一：Skill 使用说明文档（L1 精简版）

创建 / 重命名 / 实质更新任意 Skill 时，必须在 ~/docs/skill使用说明/ 同步 <skill-name>使用说明.md（用户明确要求不生成时除外）。 内容含：用途、适用场景、前置条件、调用方式、至少一个实例、配置或文件位置、边界与注意事项。 Skill 改名 → 同步重命名说明文档并更新其中的路径与调用名；文档不放入 Skill 目录，也不以 Skill 内部说明替代。 完成后验证：Skill 本体有效 + 说明文档存在 + 文档内路径与调用名与当前一致。

Codex 原文（英文，便于日后对照同步）

Skill 使用说明文档

创建、重命名或实质更新任意 Skill 时，除非用户明确要求不生成文档，否则必须同步在 ~/docs/skill使用说明/ 创建或更新一份面向人的 Markdown 使用说明。

  • 文件名使用 <skill-name>使用说明.md；Skill 改名时，同步重命名说明文档，并更新其中的路径和 $skill-name 调用。
  • 文档说明 Skill 的用途、适用场景、前置条件、调用方式、至少一个实际示例、配置或文件位置，以及主要边界或注意事项。
  • 文档面向用户，使用清晰的中文；不要将此文档放入 Skill 目录，也不要以 Skill 内部说明替代它。
  • 完成后验证：Skill 本体有效、说明文档存在，且文档中的路径和调用名称与当前 Skill 一致。

区块二：CodeGraph（L1 精简版，已加中文查询警示）

在已索引仓库中定位或理解代码，先 CodeGraph，后 grep/find/读文件：

  • 命令：codegraph explore "<符号名>"（/Users/kehua/.local/bin/codegraph v1.5.0）。WorkBuddy 无 codegraph MCP，explore 输出与 MCP 版一致。
  • 🔴 查询必须用英文标识符（poll、HealthAppServiceImpl），中文查询一律返回 No relevant code found —— 那是查询语言问题，不是索引失效，别据此退回 grep。
  • 输出含依赖半径（blast radius）与「无覆盖测试」警告，改代码前先看这个。
  • 另有两个子命令：query <符号> 搜索、node <符号> 看单符号调用链。
  • 已建索引 5 处：~/.codegraph、mind-harbor、mind-helper、ai-probe、refiner-5.6。
  • 仓库无 .codegraph/ 则跳过 —— 是否索引由用户决定，不要擅自创建。

前置条件检查（移植前必做）

python3 -c "import json;print(list(json.load(open('$HOME/.workbuddy/mcp.json'))['mcpServers'].keys()))"

实测结果：CLI v1.5.0 ✅ / 索引 5 处 ✅ / codegraph MCP ❌ / 文档目录已存在且用户已在执行该规范 ✅

用户虽已有大量 <name>使用说明.md，但规范未写进 WorkBuddy 的 L1，属于“人在执行、系统不知道”。制度化后进 L1 才会每次会话自动提醒。

可管理区块的价值（本次顺带落地）

两个区块均用 <!-- BLOCK:START --> / <!-- BLOCK:END --> 包裹，沿用 Codex 的做法：

  • 工具/脚本可精准替换区块内内容，不误伤人工编写的其他章节。
  • 日后 Codex 侧更新了这两节，可直接对照替换，不必逐行 diff 整个文件。
  • 校验命令（列出所有区块及体量）：
import re
t = open(path, encoding='utf-8').read()
for m in re.finditer(r'<!-- (\S+?):?START -->(.*?)<!-- \1:?END -->', t, re.S):
    print(m.group(1), len(m.group(2).strip()))
