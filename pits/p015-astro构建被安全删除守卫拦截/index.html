P015 · Astro 构建被本机安全删除守卫拦截：清理自己的临时目录也要过阈值

在 WorkBuddy 会话里执行 npm run build（Astro 5.x），构建到一半报错退出：

踩坑于 2026-09-12约 2 分钟构建Agent 沙箱
目录
现象根因解法预防 / 检查项相关文件
元信息
日期 2026-09-12
领域 构建 / Agent 沙箱
严重度 中（构建中断，发布链路卡死；非数据风险）
关键词 astro build、safe-delete、SAFE_DELETE_BULK_CONFIRM_REQUIRED、dist/.prerender/.vite、CODEBUDDY_SAFE_DELETE_BULK_THRESHOLD、blog-publish、阈值、批量删除守卫
状态 有效

现象

在 WorkBuddy 会话里执行 npm run build（Astro 5.x），构建到一半报错退出：

[ERROR] [vite] ✗ Build failed in 475ms
[safe-delete][SAFE_DELETE_BULK_CONFIRM_REQUIRED] {"count":50,"threshold":50,"scope":"turn",
  "targets":["~/projects/server-apps/astro-blog/dist/.prerender/.vite/"],"targetCount":1}
  at deleteViteFolder (node_modules/astro/dist/core/build/vite-plugin-ssr-assets.js:89:23)

[content] Syncing content、[types] Generated 都已通过，卡在 Building static entrypoints 之后。

根因

Astro 构建会在 dist/.prerender/ 下生成一套预渲染产物，构建结束时由 deleteViteFolder() 调 fs.rm 清掉 .vite 子目录。

WorkBuddy 的 CLI 在 Node 层挂了 node-safe-delete-shim，拦截 fs.rm 并调用批量删除守卫；守卫对单个 turn 内的删除总数计数，总数 ≥ 阈值（默认 50）就抛错阻断。Astro 那个临时目录的文件数正好在 50–92 之间，必然越线。

关键点：清缓存无效。 先把 dist/.prerender 删掉再构建，构建过程中照样会重新生成，触发时文件数反而更多（实测第二次 92 个）—— 这不是“残留导致的偶发”，是 Astro 构建流程与本机守卫的结构性冲突，每次构建都会撞。

解法

守卫没有路径白名单，唯一正规出口是它自己的阈值环境变量（CODEBUDDY_SAFE_DELETE_BULK_THRESHOLD，默认 50）：

CODEBUDDY_SAFE_DELETE_BULK_THRESHOLD=500 bash ~/.agents/skills/blog-publish/scripts/publish.sh -m "AI 日报 2026-09-12"
  • 只对这一条命令生效，不改全局配置、不动宿主设置。
  • 删除动作仍然走回收站路由，只是不再因“文件多”被拦；安全语义没变。
  • 相关开关（.cjs 里读到的）：CODEBUDDY_SAFE_DELETE_ENABLED、CODEBUDDY_SAFE_DELETE_BULK_GUARD、CODEBUDDY_SAFE_DELETE_BULK_STATE_DIR。守卫无路径白名单，别指望加例外。

预防 / 检查项

  1. 凡是跑前端构建（Astro / Vite / Next）都预判这一条，尤其是构建产物目录被清理时。
  2. 报错关键词认准 SAFE_DELETE_BULK_CONFIRM_REQUIRED —— 看到它就知道是守卫，不是内容或依赖问题，别去翻文章 diff。
  3. 失败后重跑要把三路走全：blog-publish 是「先推 GitLab → 再同步日报 → 再构建」，第一次在构建阶段挂掉时，日报文件并未进 GitLab 源码仓。重跑必须用完整脚本，不要加 --skip-gitlab，否则源码仓会永远缺这一期。
  4. 重跑时日志打印「工作区干净，跳过 commit」+「Everything up-to-date」是正常的（上次已提交），判断发布真伪看 xxx..yyy main -> main 这一行（参见 blog-publish skill 的踩坑实录）。
