P033 · agentctl 报 bad interpreter：Homebrew 升走 python@3.14，6 个 venv 同时断链

踩坑于 2026-11-25约 3 分钟工具链运维
目录
现象根因解法预防规则相关文件
元信息
日期 2026-11-25
领域 工具链 / 运维
严重度 中（多个 CLI 集体失效，但一条命令可全修）
关键词 agentctl、bad interpreter、python3.14、Homebrew、venv、断链、符号链接、pyvenv.cfg、pipx、codex-dual、ccb-web、brew install python@3.14、扩展排查
状态 有效

现象

zsh: ~/.local/bin/agentctl: bad interpreter:
~/projects/local-server/agentctl/.venv/bin/python3.14: no such file or directory

看起来只是 agentctl 一个工具坏了，实际是全局性环境故障。

检查 结果
~/.local/bin/agentctl 软链 → 项目 .venv/bin/agentctl，其 shebang 指向 .venv/bin/python3.14
.venv/bin/python3.14 软链存在，但目标 /opt/homebrew/opt/python@3.14/bin/python3.14 不存在
brew info python@3.14 Not installed；Cellar 里只剩 3.11 / 3.12 / 3.15
时间线 venv 建于 9/18（3.14.7）；10/30 Homebrew 把 opt 切到 3.15.2，3.14 从 opt 消失

根因

直接原因：venv 里的 python3.14 符号链接指向已被 Homebrew 移除的解释器，所有入口脚本（agentctl / pip / pytest）的 shebang 都跟着失效。

扩散原因：机器上 6 个 venv 都建立在 python@3.14 之上，agentctl 只是第一个被触发的，其余同一时刻全坏：

# 断链路径
1 ~/projects/local-server/agentctl/.venv/bin/python3.14
2 ~/projects/local-server/ccb-web/.venv/bin/python3.14
3 ~/projects/local-server/ccb-web/tests/.venv/bin/python3.14 → python（间接断链）
4 ~/.local/pipx/venvs/browser-use/bin/python3.14
5 ~/.local/pipx/shared/bin/python3.14
6 ~/.local/share/codex-dual/.venv/bin/python3.14

“为什么 3.14 会消失”—— 时间相关但因果未证实，不要写成定论（2026-11-25 补查）：

证据 结论
zsh/bash history 全量检索 无任何 brew uninstall python@3.14；当天 17:51 只有一条全量 brew upgrade，之后 3 天无 brew 命令
cmd/upgrade.rb 源码 只升级 + 出 deprecated/disabled 报告，没有卸载 formula 的逻辑；默认会跑 brew cleanup（第 50 行），但 cleanup 只清旧 keg 和下载缓存
brew info --json=v2 python@3.14 当前 deprecated=false / disabled=false，仍属 homebrew/core，能正常装回 3.14.10
keg mtime 10/30 18:11 重装的是 python@3.12 和 python@3.15；opt 软链 18:07 重置

所以“Homebrew 升级自动移除了 3.14”不成立——那是只看时间戳的推断。删除动作发生在 10/30 14:58（venv 还能重建）到 18:07（软链重置）之间，但由谁/什么触发没有留痕。见 P001「工具选型」与 P016「假成功」的同族教训：时间相关 ≠ 因果成立。

解法

首选：恢复 formula，不要逐个重建 venv。 独立大版本 formula 之间不冲突，brew install python@3.14 不会动现有的 3.15：

brew info python@3.14          # 先看 formula 还在不在（Not installed 但有 bottled = 可恢复）
brew install python@3.14       # 装回 3.14.10，6 个断链瞬间全恢复

验证：

# 全盘扫同版本断链，输出为空即全恢复
for d in ~/projects ~/.local; do
  find "$d" -type l -name 'python3.14' -maxdepth 6 2>/dev/null |
  while read -r l; do [ ! -e "$l" ] && echo "BROKEN: $l"; done
done

agentctl --help
cd ~/projects/local-server/agentctl && .venv/bin/python3.14 -m pytest -q
# 本次：断链 0 处，agentctl 正常，197 passed

别走的两条歪路：

  1. 手改符号链接指向 python3.15 —— pyvenv.cfg 的 home / version / executable 仍写 3.14，启动路径与 ABI 都不保证，属于“糊”不是修。
  2. 逐个 python3 -m venv 重建 —— 6 个环境要重装依赖，pipx / codex-dual 尤其麻烦，且丢掉原有环境状态。

预防规则

遇到 bad interpreter 类报错，按这个决策树走：

  1. 先扩展排查同类：find 扫全盘同版本 python3.* 断链，别只修当前脚本。
  2. 断链目标是 Homebrew 路径 → brew info <formula>：
    • formula 还在（bottled）→ brew install <formula> 恢复，一次全修；
    • formula 已删 → 才考虑重建 venv / 迁移解释器，并同步改 pyvenv.cfg。
  3. 判断是“单个工具坏”还是“环境集体坏”，先看断链数量再决定修法。
