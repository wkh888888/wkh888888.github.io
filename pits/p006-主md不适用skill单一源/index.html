P006 · 主 md 文件不适用 Skill 单一源：内容相同 ≠ 同一资产的拷贝

现象

盘点本机 AI agent 主 md 时，用 md5 比对找出 3 组内容完全相同的文件，随即按 P002 的「单一源 + 软链」约定提议收敛。逐组查证文件性质后发现：三组全部不该改。

组 文件 判定
A ~/.claude/AGENTS.md ≡ ~/.everything-claude-code/AGENTS.md 不动
B ~/.gemini/GEMINI.md ≡ ~/.config/opencode/AGENTS.md 不动
C ~/.cloudbase-mcp/web-template/AGENTS.md ≡ .../CLAUDE.md 不动

错误已写入 ~/docs/AI-Agent主MD文件清单.md（2026-09-03 初版），2026-09-04 已更正并记录推翻理由。

根因

把「内容相同」等同于「同一资产的多份拷贝」，混淆了两类对象。

Skill 目录 主 md 文件
性质 同一份可复用资产 各工具的独立配置入口
存在多份的含义 冗余拷贝 → 应收敛 每个工具本就该有一份 → 正常
内容相同说明什么 指向同一资产 只是「碰巧引用了同一段公共规范」
软链后果 ✅ 消除版本漂移 ❌ 强制两个工具永远不能分叉

P002 的软链约定是针对 Skill 建立的。类比推广到主 md 时，只比对了 md5，没有检查对象性质——这是典型的类比误用。

各组查证依据

A 组：~/.everything-claude-code/ 是完整第三方仓库（含 LICENSE/CHANGELOG/VERSION/CONTRIBUTING）。更关键的是——Claude Code 读 CLAUDE.md，不读 AGENTS.md，所以 ~/.claude/AGENTS.md 是随仓库带来的、无人读取的副本。软链它：零收益，却把 ~/.claude/ 挂到了一个可能被删除的第三方仓库上。

B 组：两者都是各自工具真实读取的主入口。内容 1181 字符全部由 CODEGRAPH + AGENT-SKILL-ROOT-POLICY 两个公共规范块构成，无任何宿主专属内容——这是「多入口共享公共片段」，不是「同一文件两份拷贝」。软链后，给 Gemini 加专属配置会直接污染 opencode。

C 组：文件正文自述 “This file is a compatibility projection of the CloudBase routing contract” —— 第三方模板刻意设计的双名兼容投影，供不同工具按各自约定的文件名读取。改软链会破坏模板复制：copy 到新项目时软链指向错乱或悬空。

铁律

md5 相同只证明「内容一样」，不证明「该合并」。合并前必须回答：这是同一资产的多份拷贝，还是多个消费者各自持有的一份？

判定检查项（动手前逐条过）：

  1. 看文件自述：有没有 “compatibility projection”、“generated”、“do not edit” 之类的声明？有 → 不动。
  2. 看所属目录性质：是不是第三方包/仓库（含 LICENSE/VERSION/CHANGELOG）或模板目录？是 → 不动。
  3. 看宿主归属：各工具实际读哪个文件名？（Claude→CLAUDE.md、Codex→AGENTS.md、Gemini→GEMINI.md、opencode→AGENTS.md）若某份根本不被读取 → 收敛零收益。
  4. 看内容构成：是否全部由公共规范块构成、无宿主专属内容？是 → 属于「共享片段」，应当抽取公共源，而非软链。
  5. 问分叉风险：将来会不会给其中一个加专属配置？会 → 软链就是埋雷。

正确做法

针对「公共规范在多处重复」这个真问题，收敛方式不是软链，而是：

  1. 公共源 + 导入：把公共规范块抽成单一源文件（如 ~/.agents/shared/agent-norms.md），各工具主 md 用 @ 导入（Codex 支持 @绝对路径）引用。
  2. 生成脚本：从单一源生成各工具主 md，改源后跑一次脚本重写所有投影。

两者都能消除重复，且保留各工具主 md 的独立性。软链做不到后者。
