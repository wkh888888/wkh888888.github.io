这篇整理我给自己技术博客选定的方案：内容归自己、源码归 GitHub、域名归自己，未来想换平台也比较自由。

推荐技术栈

Astro
+ Markdown / MDX
+ GitHub
+ Cloudflare Workers
+ 自定义域名

这套方案适合长期维护技术博客：内容归自己、源码归 GitHub、域名归自己，未来迁移平台也比较自由。

推荐架构

your-blog/
├── src/
│   ├── content/
│   │   └── blog/
│   │       ├── ai/
│   │       ├── backend/
│   │       ├── architecture/
│   │       └── devops/
│   ├── layouts/
│   ├── pages/
│   └── components/
├── public/
├── astro.config.mjs
├── package.json
└── README.md

文章可以直接保存成：

src/content/blog/2026/astro-blog.md

核心资产实际上是：

GitHub Repo
    │
    ├── Markdown 文章
    ├── 图片
    ├── Astro 源码
    └── Git 历史

网站只是这些内容的一种展示方式。

域名建议

如果已经有个人主域名，例如：

walkerhua.com

推荐直接使用根域名：

walkerhua.com

并规划：

/about
/blog
/projects
/notes

如果主域名另有用途，再使用：

blog.walkerhua.com

长期做个人技术品牌时，根域名通常更合适。

本站的实际选择：walkerhua.com 根域已经用于「产品工作台」，所以博客使用 blog.walkerhua.com。

发布流程

本地写 Markdown
     ↓
git commit
     ↓
git push
     ↓
GitHub
     ↓
Cloudflare 自动构建
     ↓
blog.walkerhua.com

这样不需要登录博客后台复制粘贴文章。

第一版建议功能

第一版建议只做核心功能：

  • 首页
  • 博客列表
  • 文章详情
  • 分类
  • Tag
  • About
  • Projects
  • RSS
  • Sitemap
  • 代码高亮
  • 深色模式
  • 全文搜索
  • SEO

技术博客建议额外加入：

  • Mermaid
  • LaTeX / Math
  • Markdown / MDX
  • 复制代码按钮
  • 文章目录 TOC
  • 上一篇 / 下一篇
  • 阅读时间
  • GitHub Edit Link

第二阶段功能

后续可以逐步加入：

  • 评论
  • Newsletter
  • 访问统计
  • 中英文
  • AI 搜索
  • 知识库
  • MCP

博客与 AI 知识库一体化

可以让博客和 AI 知识库使用同一个 Markdown 数据源：

                ┌→ Astro Blog → 人阅读
Markdown → GitHub
                └→ MCP / RAG → AI 阅读

例如文章可以按这些主题组织：

Zookeeper/
EventBus/
Port Scanner/
Agent/
MCP/
LLM/
Architecture/

这些内容既可以作为公开博客，也可以进一步成为个人 AI Agent / 数字分身的知识库。
