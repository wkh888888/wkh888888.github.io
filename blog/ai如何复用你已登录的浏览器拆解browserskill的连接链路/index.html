AI 如何复用你已登录的浏览器？拆解 BrowserSkill 的连接链路

日期：2026-09-30

让 AI 处理内部网站，第一道障碍往往就是账号。

网页你已经打开，验证码你已经输过，权限也在当前浏览器里。自动化工具却可能启动另一套配置，让同一件事从登录重新开始。

腾讯开源的 BrowserSkill 提供了一条扩展连接路径：Agent 通过命令行调用本地后台服务，后台服务把操作传给浏览器扩展，扩展再控制目标网页。模型负责理解任务，这套工具负责把动作送到正确的浏览器。官方架构说明

一个窗口背后，是五个环节

flowchart LR
    A[AI Agent] -->|bsk 命令| B[CLI]
    B <-->|本地 IPC| C[Daemon]
    C <-->|WebSocket| D[浏览器扩展]
    D -->|CDP 与扩展 API| E[网页]

CLI 是 Agent 调用的入口，后台服务（daemon）负责连接与会话路由，扩展在目标浏览器里执行操作，网页返回变化后的状态。模型读取结果，再判断是否继续。

这里需要区分两段通信：CLI 与 daemon 使用本地 IPC；daemon 与扩展通过 WebSocket 通信。浏览器侧使用 CDP 与扩展 API，并不等于所有动作都是注入页面脚本。官方架构说明

这也解释了为什么它不限定于 WorkBuddy。能调用对应工具的 Agent 都可以接入；BrowserSkill 不自带理解业务任务的模型。官方中文说明

登录态怎么复用？先选对 Profile

扩展安装在浏览器配置中，任务绑定所选实例。代理窗口与该 Profile 共享网站登录态，因此可以继续使用已有账号权限。已有标签页则需要显式借用，用完归还。官方说明

这并不是 BrowserSkill 才能做到的事。Playwright 支持保存和复用认证状态，也可以通过其他接入方式操作已有浏览器；无头运行本身不意味着无法登录。Playwright 认证文档

BrowserSkill 的价值是把目标浏览器选择、任务窗口和标签页借用组织成一套面向 Agent 的工作流。对已经登录的内部网站，这种接入方式很直接。

但窗口独立不等于账号权限独立。Agent 使用的仍是所选账号的权限，登录态复用也不能被描述成“不会泄露任何敏感信息”。页面正文、截图和调试证据都可能含业务数据。

AI 如何知道该点哪个按钮？

页面观察结果可以包含文字、控件和元素引用，例如 @e3。Agent 通过引用指定目标，省去在每条命令里重新描述位置。

引用是一种工具管理的句柄，不是网页的永久身份证。导航、节点替换或页面变化后，需要根据新观察重新确定目标。不能因为有 refs，就推导出它总能抵抗 DOM 变化。

一次典型交互是：观察页面，找到保存控件，执行点击，再观察结果。点击成功与业务保存成功是两件事；页面可能报错，也可能进入处理中。

代理窗口解决的是操作范围

把 Agent 工作放在独立可见窗口里，可以减少它与用户日常浏览之间的干扰。借用原标签页则明确了任务接管的对象，结束会话后应归还。

遇到登录、验证或本人参与的步骤，还可以请求人工协助。具体是否允许借用和请求帮助，由扩展设置及宿主规则控制。官方中文说明

这些机制帮助约束流程，但不能代替业务授权。用户让它查单据，不表示允许它提交申请；任务窗口也不是隔离所有风险的安全沙盒。

本地首用记录说明了什么？

原稿记录了 bsk 0.3.2、daemon protocol 1.3 的 macOS 首用情况：扩展连接一个浏览器，协议检查通过，example.com 读页后结束会话。

这条记录验证的是连接、读页和收尾。它没有证明复杂 OA 填表、文件上传或审批流都能完成，也没有与 CUA 做同任务 Token 对比。本文保留该记录，但本次编辑没有重新运行首用验收。

真正接入业务前，更有价值的验证是使用一张可核验的草稿：选对账号，填写少量字段，保存，再重新打开检查。不要从“能读 example.com”跳到“所有业务都支持”。

Token 花在观察与决策上

扩展本身不会自行调用 AI 提供商，模型调用发生在 Agent 一侧。工具返回多少页面信息、截图和调试正文，以及模型需要多少轮判断，都会影响用量。官方说明

因此，扩展连接不天然比 CUA 更省 Token。读取任务相关字段、避免无关长正文和重复全量观察，通常比更换工具名称更有帮助；必要的结果核验仍然要保留。

适合谁使用？

经常让 AI 操作已登录的 Chrome 或 Edge 内部网站，或者希望保留网页调试证据的人，可以重点考虑 BrowserSkill。涉及浏览器之外的原生界面时，则需要电脑操作工具配合。稳定的高频回归任务，也可以进一步沉淀成脚本。

选型时先验证三件事：它是否连接了正确的账号，是否能准确操作目标控件，是否能回读业务结果。每个环节都通过，真实登录态才从一个产品卖点，变成一条可用的自动化流程。
