用 Syncthing 加已有私有组网，让 macOS、Windows、Linux 共用同一套文件：Linux 常在线做枢纽，两端都能编辑，历史版本交给独立快照备份。

日期：2026-10-10

适用环境：macOS 工作机、Windows 个人机、Linux 24 小时在线服务器；三台机器已通过异地组网互通。
目标：所有指定文件夹在 Windows 及 Linux 保存完整当前副本；macOS 和 Windows 均可编辑；今后可增加目录和设备。

1. 架构与原则

采用 Syncthing + 已有私有组网 + Linux 独立快照备份：

  • Linux 是 常在线同步枢纽，不是必须接管文件修改的集中式文件服务器。
  • macOS 和 Windows 均采用 Send & Receive，可在任一端修改资料。
  • Linux 作为不直接编辑文件的镜像节点可采用 Receive Only；如果以后也需要在 Linux 直接编辑，再调整为 Send & Receive。Receive Only 仍会接收其他设备的修改，并能将已接收的内容提供给其他节点；它不阻止远端删除同步到 Linux。
  • 星型连接：Mac ↔ Linux ↔ Windows。两台个人电脑无需同时在线，即可通过 Linux 交换最新修改。
  • 每个独立资料目录对应一个 Folder ID。不要同时同步相互包含的父子目录。

重要区分：“Linux 永久保留完整副本”是长期保留当前数据镜像，并不代表保留全部历史版本。删除和覆盖会同步。若要长期保留删除前文件和历史版本，必须使用独立快照备份与明确的保留策略。

2. 目录规划

Folder ID macOS Windows Linux 用途
dcos ~/dcos D:\Sync\dcos /srv/sync/dcos 文档与资料
notes ~/notes D:\Sync\notes /srv/sync/notes 笔记
resources ~/resources D:\Sync\resources /srv/sync/resources 资源素材
books ~/Books D:\Sync\books /srv/sync/books 电子书

路径仅为示例；Windows 无 D 盘时改用 %USERPROFILE%\Sync。Folder ID 在三端保持一致，路径可以不同。

Linux 规划：

/srv/
├── sync/                    # 实时同步副本（数据盘）
│   ├── dcos/
│   ├── notes/
│   ├── resources/
│   └── books/
└── backup/                  # 独立磁盘/NAS 的挂载点，不是普通同盘文件夹
    └── kopia-repository/

3. 安装与开机启动

macOS

brew install syncthing
brew services start syncthing
syncthing --version

本机打开 http://127.0.0.1:8384。

Windows

从 Syncthing 官方 Releases 下载适合架构的 Windows 版本，解压至固定路径，如 C:\Tools\Syncthing，运行 syncthing.exe。使用 任务计划程序 设置当前用户登录后自动启动（普通用户权限），随后打开 http://127.0.0.1:8384。

Linux（Debian/Ubuntu 示例）

sudo apt update
sudo apt install syncthing
systemctl --user enable --now syncthing.service
sudo loginctl enable-linger "$(whoami)"
systemctl --user status syncthing.service

建议创建专用非 root 同步用户并将 /srv/sync 赋予该用户读写权限；上面的命令应以该用户执行。发行版仓库版本可能滞后，可根据需要使用项目官方安装渠道。

如果 Linux 没有图形桌面，从 Mac 通过 SSH 端口转发打开管理页：

ssh -N -L 8385:127.0.0.1:8384 user@LINUX_OVERLAY_IP

浏览器访问 http://127.0.0.1:8385。Syncthing 管理界面不要直接开放到公网。

4. 组网与设备配对

以下为示例私网地址，替换为实际组网 IP：

节点 地址 设备名
macOS 100.64.0.10 mac-work
Windows 100.64.0.20 win-home
Linux 100.64.0.30 linux-hub
  1. 三端分别在 Syncthing 中复制自己的 Device ID。
  2. macOS 与 Linux 双向添加设备；Windows 与 Linux 双向添加设备。无需 Mac 和 Windows 直接配对。
  3. 在远程设备的 Addresses 中填固定地址，例如 Mac、Windows 均填写 Linux 的 tcp://100.64.0.30:22000；Linux 给 Mac 填 tcp://100.64.0.10:22000，给 Windows 填 tcp://100.64.0.20:22000。
  4. 在组网访问控制规则和主机防火墙中，允许这些授权节点访问 TCP 22000。
  5. 验证 Syncthing 显示已连接。已有组网固定且稳定时，可以关闭全局发现、局域网发现、转发中继与 NAT 穿透；如果 IP 变化频繁，请保留合适的发现机制。

传输由 Syncthing 使用 TLS 保护；设备 ID 必须人工确认无误。

5. 首次迁移：避免误合并

  1. 先备份 macOS 原始 ~/dcos；Windows、Linux 如已有同名内容也单独备份。
  2. 新建小型测试目录，先验证新增、修改、重命名、删除和离线重连。
  3. Mac 添加 ~/dcos 文件夹，设置 Folder ID 为 dcos，类型选 Send & Receive，分享给 Linux。
  4. Linux 接受目录，共享到 /srv/sync/dcos，可设 Receive Only。确保目标目录空且磁盘容量充足。
  5. 待 Linux 与 Mac 均显示 Up to Date 后，Linux 把 dcos 分享给 Windows。
  6. Windows 接受并映射到 D:\Sync\dcos，模式选 Send & Receive。等待同步完成后核对文件数、总容量及关键文档。
  7. 再逐一添加 notes、resources、books 等其他独立文件夹。

注意：Linux Receive Only 的“本地更改”可能需要人工处理，不要在 Linux 的 /srv/sync 直接编辑同步文件。

6. 日常运行与冲突规则

  • 三台机器启用 Watch for Changes；完整扫描间隔可从 3600 秒起步，余下参数先用默认值。
  • Office、PDF、Markdown 等文档正常同步；不要同步正在运行的数据库、缓存和临时锁文件。
  • 在一个设备编辑同一个 Word/Excel 文件后，保存并关闭，等待 Syncthing 显示 Up to Date，再换另一台设备编辑。
  • 两台设备未收到对方修改前同时编辑同一文件，Syncthing 可能产生 *.sync-conflict-* 冲突副本。它不能自动合并 Word/Excel 内容；先对照并人工合并，不要直接删除冲突副本。
  • 检查 Mac/Linux 冲突文件：
find ~/dcos -type f -name '*sync-conflict*' -print
  • Windows PowerShell：
Get-ChildItem 'D:\Sync\dcos' -File -Recurse | Where-Object Name -Like '*sync-conflict*' | Select-Object FullName

可选忽略规则

在每台机器的同步根目录分别创建 .stignore（该文件本身不会作为规则自动分发）：

(?d).DS_Store
(?d)._*
(?d)Thumbs.db
(?d)desktop.ini
(?d)~$*
(?d).~lock.*#

应用前检查规则：例如 ._* 是 macOS 的 AppleDouble 元数据，在某些 Mac 文件工作流中可能有价值；若依赖相关元数据，应删除该规则。不要默认忽略真正需要同步的文件。

7. Linux 完整副本、历史版本与独立备份

建议启用 Linux 文件夹的 Staggered File Versioning，例如最大年龄 180 天；它主要保存接收端遭远端修改、覆盖或删除时的旧版本，不能取代系统级备份。

如果“永久保留”也包括历史记录，建议：

  1. 使用 Kopia 或 Restic 对 /srv/sync 建立每天一次的快照备份。
  2. 备份写到独立磁盘、NAS 或远程对象存储；为备份仓库设置加密密码。
  3. 每日/每周快照可以设置有限保留期，但另设永久归档快照（或至少明确多年保留政策），避免历史文件自动被清理。
  4. 对备份目标启用访问隔离或不可变策略，降低误删、勒索软件的影响。
  5. 每月随机恢复几个文件，验证备份可用；定期检查磁盘空间和失败告警。

容量规划：Linux 当前同步数据至少要容纳全部目录之和；备份和版本存储需要额外空间，实际取决于文件修改频率和保留周期。真正无限期历史保留意味着存储量可能持续增长，需要扩容策略。

8. 安全基线

  • 所有设备的 GUI 默认保持 127.0.0.1:8384 本机监听，并配置 GUI 用户名与高强度密码。
  • 仅允许私有组网中可信设备访问 TCP 22000；不用公网端口映射。
  • Linux 上用专用非 root 用户运行 Syncthing，最小化文件系统权限。
  • Mac 开启 FileVault，Windows 开启 BitLocker（如系统版本支持），Linux 数据盘可使用 LUKS。
  • 工作机文档若包含公司资料，先确认单位政策是否允许同步到个人 Windows/Linux 设备。
  • 不要在同一目录上叠加 OneDrive、iCloud Drive 等多个自动同步引擎。
  • 定期更新 Syncthing、OS 和备份工具；设备丢失后从所有剩余节点移除其 Device ID。

9. 新增文件夹的固定流程

例如未来要同步 Mac 的 ~/manuals：

  1. 在 Mac 建立 manuals 文件夹，Folder ID manuals，共享给 Linux。
  2. Linux 接受，路径 /srv/sync/manuals，类型 Receive Only。
  3. Linux 再把 manuals 共享给 Windows，路径 D:\Sync\manuals，类型 Send & Receive。
  4. 确认两端完成全量接收，再将 /srv/sync/manuals 纳入 Linux 的快照备份范围。
  5. 避免 Folder ID 重复、目标路径重叠及同步父目录与子目录。

10. 验收清单

  • 三端安装 Syncthing 并能自动启动
  • Mac ↔ Linux、Windows ↔ Linux 均成功连接
  • Mac 已保存同步前独立备份
  • dcos 在三端正确映射，Folder ID 相同
  • Linux 收到完整资料并显示 Up to Date
  • Windows 收到完整资料并显示 Up to Date
  • Mac 与 Windows 修改不同文件，另一端均能更新
  • Mac 关机后，Windows 修改可以上传到 Linux
  • Mac 重连后能够获取 Windows 的修改
  • 已确认冲突文件的检查、合并流程
  • 已配置 Linux 版本保留及独立快照备份
  • 已完成一次备份恢复演练
  • Syncthing GUI 未暴露公网
